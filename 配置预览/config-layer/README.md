# 配置层（layers）

这是「建材报价系统」的配置层，是**未来正本**——等各方面抽象的规则、书写形式、层级都定稿后，
这套目录结构会**直接移植到项目里做完全整改替换**。

现在这个阶段，它只是**草稿 + 一个可视化预览页**，用于边写边看、所见即所得。

## 目录结构（标准项目结构，将来整体移植）

```
layers/
├── 物理层/       physical-layer.yml     —— 数据库表结构与字段（原材料：有什么）
├── 关系层/       relation-layer.yml     —— 表与表怎么串（通路图）
├── 差异层/       difference-layer.yml   —— 有意偏离标准推导的补丁（补丁本）
├── 推导规则/     derivation-rules.yml   —— 推导规则【条目数据】，一条一条、字段固定（会持续增长）
├── 解释器/       （暂空）               —— 将来放真正的解释器代码
├── 分层契约.md                          —— 契约：层定义、参数归属、键级 schema、禁写清单
├── 概念纲领.md                          —— 纲领：方面清单与解释器覆盖
└── README.md                            —— 本说明
```

**文档 vs 数据**：根目录放**文档**（契约/纲领，讲规矩）；子目录放**结构化数据**（物理层/关系层/差异层/推导规则，一条一条）。
推导规则之所以是数据不是文档：条目会膨胀到几十上百条，必须结构化（字段固定），由预览面板用与物理层/关系层**同一套表格框架**渲染、按类别横向导航。

## 怎么预览（一条命令）

在项目根目录执行：

```bash
npm run layer
```

浏览器打开 http://localhost:8899。

## 数据与显示框架完全解耦（口径）

```
结构化配置数据（本目录各文件 = 唯一真相源）
      +  固定展示渲染框架（表格 / 列宽 / 分组 / 中文映射 = 预置，沿用既有样式）
      =  可视化预览界面
```

- **框架预先约定好**：表格形式展示；固定列与列宽（字段表 880px 六列、域总览 1160px 七列、关系体 1000px 四列等）、字段分组方式、界面中文映射规则（英文标识 → 中文业务名）。
- **只拿数据套框架**：源文件数据不变，框架只规定「怎么画出来」。渲染框架沿用之前成型的表格样式与布局，不重新设计展示规则、不改原表格外观/列排布/分组逻辑。
- **边界**：① 渲染仅视图转换，绝不回写、不修改底层真源；② 无监听、无轮询，改完源文件手动刷新页面；③ 换目录只改面板里的 `SRC` 路径，渲染框架原样保留。
- **零生成器**：定稿前不跑任何生成/验证/体检/门禁（gen-layer-preview 等停用未删），打开时一次性读取真源在浏览器里渲染。

## 约定

- **一个层级 = 一个独立文件夹**，层级内部文件自包含，互不干扰、干净。
- 文件内容用中文描述业务事实，键值对形式（yml）或说明文档（md）。
- 将来移植时，整个 `layers/` 文件夹作为整体搬进项目，结构不变。

## 与「验证生成器」的关系

现在这个阶段**零生成器**：预览面板自己 fetch 真源 + 轮询刷新（`tools/dev-layer.mjs` 只做静态 serve），
不跑任何生成、验证、体检、门禁、对拍。等配置定稿、接入项目时，再补真正的解释器
（物理层→建表 SQL 等）；gen-layer-preview 等生成器停用未删，届时按需启用。
