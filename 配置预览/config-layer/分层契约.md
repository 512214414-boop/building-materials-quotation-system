# 配置分层契约（分层配置范式 · v8）

> 本文件是 `配置预览/config-layer/` 配置的**宪法**：每一层是什么、写什么、禁写什么、
> 参数该归谁、怎么保证互不污染。改配置前先读本文件。
> **概念正本（对外讲/复述一律以它为准）**：见同目录《概念纲领.md》——五条正本 + "层数不是定死的 2/3 层、该增就增"与"差异层是补丁本不是垃圾桶"判据；本文只写参数细则。概念说岔了翻纲领纠，参数记岔了翻本文纠。
> 配套可视化（所见即所得）：由 `配置预览/配置预览面板.html` 实时读三层真源直接渲染（**零生成**，刷新即最新）。原 `配置分层总览.html`（gen-layer-map 生成）已于 2026-09-07 退役——与实时面板内容重叠。
> 预览：`配置预览/配置预览面板.html` 实时读三层真源（fetch + 浏览器端解析，**零生成**，刷新即最新；gen-layer-preview.mjs 定稿前停用未删）。
> **v7 顶层定调（物理层 = 表结构与索引的唯一业务描述源）**：建表与索引脚本**不再手工编写/维护**——物理层配置是它们唯一的业务描述源，结构解释器读全量物理层 → **幂等输出建表语句与各类索引创建语句**（IF NOT EXISTS，重复执行安全，不重复建表/建索引），用于库初始化与结构变更。
> 边界 ①凡是数据库默认行为 / 项目全局统一约定（存储引擎、默认字符集、系统审计字段、主键聚簇索引、外键列自动索引、唯一约束自带索引、类型零值默认）→ 不在单表配置里重复声明，解释器统一补齐；
> 边界 ②凡是需**人工业务决策**的结构与索引规则（字段定义、独立去重/联合去重→数据库是否强制唯一→推导唯一索引、字段级普通 B-tree 索引、表级全文索引）→ 全部显式收敛到物理层；
> 边界 ③解释器输出自带幂等；边界 ④检索级别/是否参与检索保留在同一份物理层字段配置里，但属**应用层规则**——交给业务检索解释器使用，**不是建表输出内容**（结构解释器不消费它）。
> **表达总纲：配置只描述【业务事实】，不描述【机器动作】——机器动作一律由引擎推导/执行。事实的兜底成员归各自字典表的唯一名称字段（缺省值）；检索只出级别（配了即参与、小者优先、同级并列），不逐字段复读。**

## 0. 一句话总纲

**物理层 = 原材料库（只描述"有什么"——数据库表结构与索引的**唯一业务描述源**，见顶部 v7 四边界）；关系层 = 通路图（只描述"怎么串"）；差异层 = 补丁本（只描述"有意偏离了什么"）。**

### 0.0 改配置工作量铁律（2026-09-07 用户追问后立，P16）

> **病因复盘**：「缺省值」这一个键，AI 反复改了三个方向、横跳三次，光同步就动了 6 个文件 40+ 处，暴露的病根是——**概念没定稿就急着"四处联动"，边改边试导致返工翻倍**。用户点破："预览不是从源文件生成的吗？为什么改这么多文件、这么多处？"
>
> **铁律（以后改配置，工作量必须这么小）：**
> 1. **分两种改动，别混为一谈**：
>    - **改一个已有的值**（如「未分类」改成「其他」）→ **只改 `physical-layer.yml` 一处**，重跑生成器，完事。这是正常改动，工作量必须极小。
>    - **新增一种键**（第一次引入 `缺省值` 这类新键）→ 属"扩展系统能力"，天生比"改值"重，**但重在一次、不是三次**。
> 2. **新增键 = 先定稿、再一次性落地，禁止边改边试**：流程固定为「先在契约定死键的语义（一条）→ 一次性改 4 处（物理层 yml + 结构解释器 + 体检器 + 预览生成器）→ 跑 `--check` 验证 → 完」。**不许**"改了 yml 再回头改契约、再回头改生成器"的乱序横跳。
> 3. **真相源与生成物严格分离，人只碰真相源**：真相源只有 `配置预览/config-layer/` 下 3 个 yml（+ 契约定规则）；`.html` / `.sql` 都是生成物，**一个字都不手改，重跑生成器即变**。改了真相源，预览页自动跟着变——这就是"预览依据源文件生成"的本意，别再把生成物当第二份真相去维护。
> 4. **同一概念，只允许在「契约定义一次 + 各生成器各消费一次」**：不许同一段规则说明在契约、概念纲领、体检器、预览生成器里各抄一遍（那是散落病根，改一处漏一处）。规则的定义归契约，生成器只"读键 + 出结果"，不重复写规则文案。
三层各自独立成文件、单向依赖，**合并起来才推导出完整业务模型**；任何一层都不该包含"另一层该说的话"。

| 层 | 文件 | 使命 | 一句话角色 |
|---|---|---|---|
| 物理层 | `physical-layer.yml` | 客观全部原材料：所有表 + 所有字段 + 字段固有参数 | **有什么** |
| 关系层 | `relation-layer.yml` | 把物理层已有外键按业务场景串成通路 | **怎么串** |
| 差异层 | `difference-layer.yml` | 登记"标准推导做不到、必须有意偏离"的地方 | **偏在哪** |

依赖方向（只允许这样指，禁止反向）：
`差异层 → 物理层`（override 的对象必须是物理层真实存在的表/字段）
`关系层 → 物理层`（串通路的表、检索主字段必须是物理层已有外键/字段）
`物理层` 谁也不依赖 → **物理层是唯一地基**。改它要谨慎，但改关系层/差异层绝不允许反向动物理层结构。

**层数不是定死的"三层"，而且"层数"不是坐标、"方面有没有家"才是**（v8）：物理/关系/差异 = 当前从**建模**方面抽象的三份文件，不等于系统全貌；从已实现业务（基础数据管理 + 订单协作工作台）还可认出与建模并列的方面（呈现 / 录入 / 场景组织…），各自待建"家"。认法见概念纲领 §2.3。**加新家前先"用尽现有层"（纲领 §4.3 消费端多源解读）**：层级展开/下钻子集、分组视图由关系层推导；CRUD 接口由 物理+关系 组合推导（resourceController 已是雏形）；表格默认列集/默认列序/固定列由 物理层+约定 推导——呈现方面真正要人工声明的只剩**列序覆盖 / 列形态接管 / 编辑器指定 / 标题微调**薄残量，其"家"随 O4 消费端切换按当时残量定、不提前立项；届时依赖方向扩为 `关系层/呈现层 → 物理层`、`差异层 → 各已落盘层`（差异层=横切补丁，不占方面数）。

## 1. 层定义与职责边界（当前实盘三份文件：物理/关系/差异=建模方面；更多方面见概念纲领 §4 与 §6 P14）

### 1.1 物理层（原材料 · 唯一地基 · 表结构与索引的唯一业务描述源）

- **文件**：`physical-layer.yml`，键全中文 + 每条带英文 `标识`（双语桥接，标识给机器/数据库，人不用改不用记）。
- **使命（v7 顶层定调）**：**物理层 = 数据库表结构与索引的【唯一业务描述源】。** 建表 SQL 与索引脚本不再手工编写/维护，结构解释器读全量本文件 → 幂等输出建表语句 + 各类索引创建语句（IF NOT EXISTS，重复执行安全）；新增一张表 = 在本层注册表 + 字段（类型/独立去重/联合去重/检索级别/全文检索/索引），建表结构、索引、检索参与集、接口、前端全链派生。库自动行为（存储引擎/字符集/审计字段/主键聚簇/外键列自动索引/唯一约束自带索引/类型零值默认）一律不在此重复声明，解释器统一补齐。
- **管辖参数（只有这层能写）**：
  - 表级：表名、`标识`、字段清单（**无表级去重键**——组合唯一不写语法，见铁律 3）
  - 字段级：`类型`、`独立去重`（值只许 `是` = 该字段在本表内自己那一列不重复）、`联合去重`（正整数 **N** = 同号字段组合不重复、分开看各自允许重复；**与 `独立去重` 互斥**）、`缺省值`（**只配在字典表（基础数据）的唯一名称字段上** = 本表世界里的兜底成员，如 分类.分类名称 → `未分类`，见铁律 2）、`全文检索`（值只许 `是` = 本列内容要全文级检索能力，见铁律 5）、`索引`（值只许 `是` = 该列需要普通 B-tree 索引——人工决策，见铁律 7）、`检索: { 级别: 正整数 }`（**1级索引/2级索引…**，配了=参与本表检索匹配；**应用层规则，喂检索引擎、不进建表输出**；**无字段级 `缺省` 键**——P7 已整体退役，见铁律 2；**无 `本表权重: 主·次·辅`**——P8 已退役，见铁律 4）
- **禁写**：通路、层级、模式、主字段、槽、提级、聚合、颜色、显示拼接——这些不属于原材料；也不许写 `组合(...)` / `全局唯一` / `确保引用` / 字段级 `缺省` / `检索: {本表权重: 主·次·辅}` 等**机器语法或已退役键**。
- **铁律**：
  1. `缺省值` ≠ `检索级别`。缺省值 = 本表世界里空外键兜底引用的**成员**（分类表里叫"未分类"那一行）；检索级别 = 该字段是否参与本表检索、命中的优先级。两件事。
  2. **兜底词只属于它自己的表，字段级 `缺省` 已整体退役；业务缺省成员用字段级 `缺省值`**：曾逐字段复读 `启用/0/否/""` = 复读 DB 早已有的 `@default`，是第二份真相；且把"未分类"这种**被引用表世界里的成员**写进产品表外键上 = 让产品表替分类表记家事。正确范式：被引用字典表的**唯一名称字段**声明 `缺省值`（分类.分类名称: 未分类 / 品牌.品牌名称: 普通品牌，声明一次全系统受益）；外键引用本表留空时，引擎按缺省值名称【直接写入】该字典表（**先写**）→ 写入撞上唯一约束（同名已存在）→ 直接取用已有那条记录的 id；写入成功 → 用新记录的 id → 关联上（**先写再用**，2026-09-07 定稿：兜底记录后续常被改名/补全，"先查再用"多数扑空，先写路径更短）——动作在引擎，配置只声明成员。
  3. **唯一约束 = 两个字段级标记，互斥**（不写语法、不数个数推导）：
     · `独立去重: 是` = 该字段**在本表内**自己那一列不重复（单列唯一）。唯一作用域是**本表**，不是"全系统"——关联表存外键、引用方自然不重复，别处无需再声明。
     · `联合去重: N`（正整数组号，同 N 则联合）= 同号字段**组合**不重复，分开看各自都允许重复。**联合去重不能只配一个字段**——要配就配在参与组合的**每一个**字段上（同号 ≥2 个字段才是联合）。
     · 两个键**互斥**：一个字段只能标其中一个；两个都标 = 体检标红。**写什么就是什么**——不再靠"同表有几个去重字段"自动推导、不再靠组号分组，所见即所得。
     · 覆盖形状：① 单列唯一 = `独立去重: 是`；② 多列联合 = 同号 `联合去重: N`（N 任意正整数）；③ 一张表多条独立唯一 = 多个 `独立去重: 是`（不用组号，如客户：编码 与 名称 各自独立去重 → 两条 UNIQUE，与真实库两个独立 `@unique` 一致）。一个键覆盖全部形状、**不给单张表开特例**。
     · **怎么选（业务语义判据）**：问"这几个字段分开看允许重复吗？"
       · **允许重复 → 联合去重**：它们合起来才构成一条记录的身份（如 产品×品牌 = 外键产品+外键品牌、品牌规格 = 外键产品×品牌+规格名称、单位换算 = 规格+单位、售价/进价 = 单位换算+价格类型/渠道）。例 `售价`（规格+单位+价格类型）：同一规格可以有零售价、批发价两条（价格类型不同），但"同一规格+同一单位+零售价"只能一条。若拆成三个独立去重 → 一个规格只能有一个单位、一种价格，直接把业务写死错。
       · **不许重复 → 独立去重**：每个字段**单独**就是一条记录的身份，都要能唯一精确定位（如 客户：编码是业务编号、名称是按名找人的入口，两条路都必须唯一）。若合成联合去重 → 允许 ("C001","张三") 与 ("C001","李四") 并存，编号 C001 出现两次失去标识作用；"张三"也可重复，按名称反查/兜底"散客"会撞多条。
     · 曾用表级 `组合(...)` / 字段级 `全局唯一` 包装 = 可推导机器语法，v3 废除（DB 的 @@unique 正是此推导结果）；**曾用 `去重: 是` + `唯一组: N` 两键**（靠分组推导），2026-09-07 末被 `独立去重` + `联合去重` 取代——后者更直接、不靠数个数、不靠组号分组，配置里出现即红。
  4. `检索: { 级别: N }` = 字段级【索引级别】：**配了（非空）= 该字段参与本表检索匹配**；**数字小 = 命中优先**（1级=主索引，2级=子索引/别名补充…）；**同表同级别 = 同级并列**（多字段同为 1级 = 并列主索引，可扩展不封顶）。它只描述**本表内**、不模拟关系层级全局排序；它不是"排序权重"——排序分由检索引擎按级别映射，配置只出级别。曾用 `本表权重: 主/次/辅` 文言三档 = 不可扩展、又像排序权重，P8 退役为级别制。关系层每层 `主字段` 应指向该层主实体 **1级索引**（"凭什么按产品名称搜不按备注"的答案：产品名称配了 1级）。
  5. `全文检索` = 字段级【标记】`是`：**本列内容需要"全文级"检索能力**（如 备注/描述 这类正文列——输词进内容里找它）。引擎提取同表所有标 `是` 字段：1 个 = 单列全文索引；多个 = 组合全文索引（与 独立去重/联合去重 同构），建表声明出 FULLTEXT。**它不是检索级别能推导的**：级别只说"该字段参与匹配"，不说数据库该用什么索引——故必须显式声明，有就有、没有就没有（不需要的列不标）。数据库怎么实现全文（分词/匹配语法）是引擎职责，配置只声明"这列内容要全文级搜得到"。
  6. 与数据库的关系：**以本文件为正确模型**。若与 `schema.prisma` 冲突，本文件为准（表内注释写明理由），后续 DB 反向收敛。
  7. `索引` = 字段级【标记】`是`：**该列需要数据库普通 B-tree 索引**（业务常按它精确过滤/排序/关联 → 查得快）。**建哪些普通索引 = 人工业务决策**，显式标、有就有没有就没有（P13）。引擎提取同表所有 `是` 字段：1 个 = 单列普通索引；多个 = 组合普通索引（按字段在表中出现顺序；与 独立去重/联合去重/全文检索 同构——三种索引三种键：`独立去重`/`联合去重`→唯一、`全文检索`→全文、`索引`→普通）。**库自动的不用标**：主键(聚簇) / 外键列(库自动补索引) / 唯一约束(自带索引) / 被唯一键左前缀覆盖的组合索引（引擎推导省去）。分工：`检索级别` 管"搜得到"（应用层规则，不进建表输出）；`索引: 是` 管"查得快"（结构声明，进建表输出）；模糊全文搜归 `全文检索: 是`（B-tree 对中文中间片段无效，全文归 FULLTEXT）。
- **演进规则**：只增不删、只加字段不改字段语义；改名 = 改 `标识` + 全文件注释同步（机器名改动影响面大，须跑对拍）。

### 1.2 关系层（通路图 · 只串不造）

- **文件**：`relation-layer.yml`。
- **管辖参数（只有这层能写）**：关系体（一个业务场景一条通路）、`层级`（序号 / 标题 / 表 / `检索: { 模式, 主字段 }`）、横切字典清单、通路速览行。
- **禁写**：任何字段定义、`缺省`/`缺省值`、`独立去重`/`联合去重`、`类型`、权重数字、颜色——统统不许出现在关系层。
- **铁律**：
  1. **引用不许重定义**：每段连接都引用物理层已有外键/字段，绝不在关系层重新定义。
  2. **层级权重天然得出**：L1 最高 → L5 最低，由序号映射（`naturalTier`），非配置、不引用物理层检索级别。检索级别（本表字段谁参与+谁优先）与层级权重（通路哪层更中心）是**两件独立的事**，配置上互不依赖。
  3. 检索只写 `模式 + 主字段`：模式定范围，主字段指向物理层标记参与检索的字段。**不带权重数字**。
- **演进规则**：一个关系体一段；新增业务场景 = 新增关系体（照抄现有结构），不塞进旧通路。

### 1.3 差异层（补丁本 · 第一等公民，不是逃逸口）

- **文件**：`difference-layer.yml`。
- **管辖参数**：标准推导覆盖不了的有意偏离。每条 = `对象`（物理层真实存在的 表 或 表.字段）+ override 参数（如 提级到 / 聚合 / 槽）+ `说明`（为什么偏离）。
- **禁写**：`缺省`/`缺省值`、`独立去重`/`联合去重`、`检索级别`、检索参数——凡标准推导能覆盖的（兜底成员 / 独立去重·联合去重 / 检索级别 / 权重 / 颜色 / 推算）一律**不**写在这里。
- **铁律**：差异是"第一等公民"，不是"越空越好"的垃圾桶。宁可多一条带说明的差异，不许把偏离偷偷写进物理层或代码里不留痕。
- **（v8）"表达不了的"不许塞差异层**：差异层只收**同一统一模型标准推导下的业务特例**（偏离）。常态表达（如 列顺序/分组/场景入口 = "实体怎么被看见"）不是偏离 → 不许进差异层；没有层收的常态表达 = 该开新层（呈现层，见 §6 P14）或回 §3 判定归属。塞差异层 = 垃圾桶化。
- **演进规则**：增删都行，但每条的 `对象` 必须能在物理层找到（找不到 = 断裂引用，审计标红）；对象改名必须同步改差异层。

## 3. 新参数放哪：判定流程

拿到一个新参数/新需求，按顺序问：

1. **它是"标准推导能出来的"吗？**（颜色、层级权重、宽松检索的 text 集、唯一键视图、统计口径）→ 是 → **不配置**，进引擎/代码，配置零新增。行为（事务/状态机/对账/金额算法）永远在代码里，硬塞配置 = 返工入口。
2. **它是表或字段固有的吗？**（结构/类型/独立去重·联合去重/检索级别/顺序；兜底成员 → 字段级 `缺省值`，配在字典唯一名称字段上）→ 是 → **物理层**。
3. **它描述"这条业务通路怎么串、怎么被检索"吗？**（层级/通路/模式/主字段/横切）→ 是 → **关系层**。
4. **它是"标准推导之上的有意偏离"吗？** → 是 → **差异层**，必须带说明。
5. 全都不像 → **停下来问**：可能是新概念（例如新的字段类别），先立项再落地，禁止顺手塞进某层。

**判定口诀：能推导的不配置 · 固有属性归物理 · 组织用法归关系 · 有意偏离归差异 · 行为永远留代码。**

## 4. 防污染三律

1. **一个参数只有一个家**：任何参数类别（§2 表）只能出现在一行里。审计器对三层做键白名单扫描，越界即红。
2. **可推导就不配置**：预览里能算出来的列（唯一键列、层级权重列）就不是第二份真相。文件里写了 = 冗余 = 必然漂移的种子。
3. **引用不许重定义**：关系层说"表"只能是物理层的表，说"主字段"只能是物理层的字段。引用可以，再造一份不行。
4. **机器动作不入配置**：`组合(...)` / `全局唯一` / `确保引用` / 表级 `去重` / 字段级 `缺省` 等可推导包装词一律禁止——兜底只写字段级 `缺省值`（配字典唯一名称字段）、独立去重/联合去重只标其一，反查/建行/关联与提取组合是引擎的事。表级 `去重` 与字段级 `去重`/`唯一组`（旧分组推导模型）出现即红（已被 独立去重/联合去重 取代）。

审计器（原 `tools/gen-layer-map.mjs` 内，该工具已于 2026-09-07 退役，体检逻辑折入实时预览面板「体检」区）自动执行：白名单扫描 / 跨层禁写键扫描 / 引用存在性校验（关系层·差异层指向的表与字段必须在物理层找得到）/ 可推导项校验（通路与层级标题一致、唯一键由 `独立去重`/`联合去重` 字段提取）/ **机器语法体检**（表级 `去重`、字段级 `去重`/`唯一组`（旧分组推导模型）、`组合(...)`、`全局唯一`、`确保引用` 一律标红）/ **缺省值体检**（必须配在字典唯一名称字段上——该字段须 `独立去重: 是` 或 `联合去重: N` 且为文本；**同一联合去重组内只要有一个字段配了缺省值，组内其余字段必须都配**——配其一漏其一即红（否则兜底行插不进去）；字段级 `缺省` 出现即红——P7 退役键）/ **标记体检**（`独立去重` 值非 `是` 即红、`联合去重` 非正整数即红、两键同标即红，`全文检索` `索引` 值非 `是` 即红；`检索: 级别` 非正整数即红；`全文索引`/`FULLTEXT` 等库实现词进配置即红）。

## 5. 稳定性规则（怎么长期不乱）

- **每层独立演进**：物理层只增；关系层按关系体增；差异层带说明增删。一层改动不波及其他层——依赖是**段对段**的事实链，不是全文隐式耦合。
- **伴生可视化（已退役）**：原 `配置分层总览.html`（gen-layer-map）于 2026-09-07 删除——与实时预览面板（fetch 真源、零生成）内容重叠。纠缠审计 / 体检改为面板内「体检」区（实时、零生成）。**配置改动不再需要重跑任何生成器。**
- **对拍门禁**：生成物进 `gen-entity-meta.mjs` 的 `emit()` 漏斗，`--check` 逐字节对拍，不一致即中断。
- **不留无声的历史**：物理层表注释写明与 Prisma 的已知偏离（例：单位换算以本文件为准，Prisma 拆表系历史错误待收敛）。

> **参数是层的最小单位**。本目录把每一层"到底能用哪些键、值域是什么、谁消费"锁死。
> 只有本目录登记的键允许出现；未登记键 = 体检标红（不是禁止创新，是提醒"登记或放错层了"）。

### 7.1 物理层（文件根：`表` 块，每表一个中文表名键）

| 位置 | 中文键 | 值域 / 示例 | 必填 | 谁消费 / 语义 |
|---|---|---|---|---|
| 表级 | `标识` | 英文机器名（下划线小写）如 `product` | ✅ | 生成 DB 表名 / TS 类型 / 接口 |
| 表级 | `字段` | 块：字段中文名 → 参数 | ✅ | 全字段载体 |
| 字段级 | `标识` | 英文机器名如 `categoryId` | ✅ | 生成 DB 列名 / 代码属性 |
| 字段级 | `类型` | **P15 精度值域（必须可建表）**：`主键`(=长整数自增，平台默认) / `主键(整数)`(历史特例显式) / `文本(N)` / `文本(不限)` / `整数` / `小数(10，2)`(全角逗号) / `布尔` / `枚举`(状态型整数) / `外键→表.编号`(列型自动跟随目标主键) / `外键→表.编号(逻辑)`(不建库级外键约束，如 进价→供应商 v11 解耦) | ✅ | 数据类型；`外键→` 同时是关系引用声明（关系层串通路的数据来源）。**裸 `文本`/`小数` 已退役**——长度/精度是推不出的结构事实，必须显式（P15） |
| 字段级 | `独立去重` | 只许 `是`（该字段在本表内自己那一列不重复 = 单列唯一）；**与 `联合去重` 互斥，两键同标 = 体检红** | 条件 | 引擎直接按标记提取：单列 UNIQUE KEY，作用域本表（非全系统）；关联表存外键不需再声明（DB @@unique 即此） |
| 字段级 | `检索` | `{级别: 正整数}`（1级索引/2级索引…，可同级重复）；**禁 `{本表权重: 主·次·辅}` 文言（P8 退役）** | 条件 | 配了（非空）= 参与本表检索匹配；数字小 = 命中优先（1级主 / 2级子补充）；关系层主字段应指向本表 1级 |
| 字段级 | `联合去重` | 正整数 **N**（组号）：同号 N 字段**组合**不重复、分开看各自允许重复；**与 `独立去重` 互斥** | 条件 | 要配就配在参与组合的**每一个**字段上（同号 ≥2 个才是联合，只标 1 个等同独立去重）；覆盖"产品×品牌/品牌规格/单位换算/售价/进价/产品图片"等组合唯一（DB @@unique([a,b]) 即此推导） |
| 字段级 | `缺省值` | 字典表【名称字段】的兜底成员名，如 分类.分类名称 → `未分类`、品牌.品牌名称 → `普通品牌`、客户类型.类型名 → `个人业主` | 条件 | **只配在字典表（基础数据）的唯一名称字段上**（该字段须 `独立去重: 是` 或 `联合去重: N`）。外键引用该字典留空 → 引擎按缺省值名称【直接写入】该字典表 → 撞唯一约束（同名已存在）→ 取用已有那条 id；写入成功 → 用新记录 id → 关联（**先写再用**）。详见 §8.5.1「缺省值兜底的落地约定」。 |
| 字段级 | `全文检索` | 只许 `是`（本列内容需全文级检索能力）；**禁 `全文索引`/`FULLTEXT` 等库实现词** | 条件 | 引擎提取同表所有 `是` 字段：1 个 = 单列全文索引；多个 = 组合全文索引（建表出 FULLTEXT）；级别推不出它，须显式声明（P12） |
| 字段级 | `索引` | 只许 `是`（该列需要普通 B-tree 索引：业务常按它精确过滤/排序/关联 → 查得快）；**库自动的不标** | 条件 | 建哪些普通索引=人工业务决策（P13）。引擎提取同表所有 `是` 字段：1 个 = 单列普通索引；多个 = 组合普通索引（按字段出现顺序，建表出 CREATE INDEX）；主键聚簇/外键列自动索引/唯一约束自带索引/唯一键左前缀覆盖的组合 由解释器补齐或推导省去，不用标 |

> **字段级 `缺省` 已从目录删除（P7）**：曾在此登记的值域（`启用/0/否/""`）逐字段复读 DB `@default` = 第二份真相；外键留空的兜底改由目标字典名称字段的 `缺省值` 承担。出现字段级 `缺省` 键 = 体检红。
>
> **字段定义 = 字段名 + 类型 +（需要业务决策时的）缺省值（v7 边界②）**：默认值分两档——① **类型零值 / 平台全局约定**（`""` / `0` / `false` / `status=启用` / 审计字段）属边界①，解释器统一补齐、配置零书写（P7 因此退役"复读类型零值"的字段级 `缺省`）；② **业务缺省成员**（字典名称字段的 `缺省值`，如 分类→未分类 / 品牌→普通品牌 / 客户类型→个人业主）是"没选时落字典哪一行"的业务决策，用字段级 **`缺省值`** 显式声明。**两档别混**：`缺省`（退役）= 复读机器零值；`缺省值`（现行）= 声明的业务缺省成员。
>
> **解释器统一补齐、单表零声明（边界①）**：存储引擎与默认字符集（平台全局）、审计字段（create_time / update_time / deleted 等系统约定）、主键聚簇索引、外键列自动索引、唯一约束自带索引、类型零值默认。结构解释器输出 = 表定义 + 唯一索引（`独立去重`/`联合去重` 推导）+ 普通索引（`索引: 是`）+ 全文索引（`全文检索: 是`），全部 IF NOT EXISTS 幂等；`检索级别` 是应用层规则——喂检索引擎，**不进建表输出**（边界④）。

## 8. 表达力兜底链（这一层表达不了的，明确交给下一层）

**机制（你说的一句话，固化成纪律）**：每层"能确定的参数就锁死在本层"；**这一层表达不了的，不许原地硬塞该层不支持的键，必须显式溢出到下一层，并登记一句理由**。

表达力与溢出顺序（从最确定到最不确定）：

```
标准推导(引擎)  →  物理层(是什么)  →  关系层(怎么串)  →  差异层(怎么偏离)  →  代码(行为)
```

- **标准推导能算的**（颜色、层级权重、宽松检索集、统计口径、命中排序分）→ 交给引擎，配置零新增。
- **参与检索的字段集与命中优先级** → 物理层字段配 `检索: {级别: N}`（配了即参与、小者优先、同级并列），检索引擎据此生成 search.fields 与打分——主/次/辅文言与"取全部 text"已退役（P8）。
- **组合唯一** → 不在表级写 `组合(...)`；引擎从字段级 `独立去重: 是` / `联合去重: N` 标记直接提取（1 个 `独立去重` = 该列单列唯一，多个同号 `联合去重` = 组合唯一）。
- **全文索引** → 检索级别推不出库索引类型，不猜；某列内容要全文级搜（备注/描述类）→ 字段标 `全文检索: 是`，引擎提取 1 个=单列 / 多个=组合 出 FULLTEXT（P12）；不需要的列不标。
- **普通 B-tree 索引** → 检索级别（搜得到=应用规则）与 全文检索（内容里搜）都替代不了它；业务常按某列**精确过滤/排序/关联**（如 图片按内容哈希反查去重、进价按供应商反查）→ 字段标 `索引: 是`，引擎提取 1 个=单列 / 多个=组合 出 B-tree 索引（按字段出现顺序，P13）。库自动有的（主键聚簇 / 外键列 / 唯一约束自带 / 唯一键左前缀覆盖的组合）不必标——解释器补齐或推导省去。
- **外键空值兜底** → 兜底成员属于**被引用表自己的世界**：在目标字典表的唯一名称字段写 `缺省值`（`分类.分类名称: 缺省值 未分类`，声明一次全系统受益），引擎保存时空外键按缺省值名称【直接写入】字典表 → 撞唯一约束（同名已存在）→ 取用已有那条 id；写入成功 → 用新记录 id → 关联（**先写再用**）。字段级 `缺省` 已整体退役（P7）——曾逐字段复读 DB `@default` = 第二份真相。
- **物理层表达不了的**（如"图片真相在规格、显示要提到产品行"）→ 溢出到差异层登记：`产品图片.显示 → 提级到 产品`。
- **普通字段表达不了的集合形态**（售价/进价是 recordSet，不是单值）→ 溢出到差异层登记：`产品.价格槽 → 槽: 价格槽`。
- **常态呈现表达（"实体在页面上怎么被看见"）** → **不是偏离，不许进差异层**；且**大部分本就可由现有层组合推导（纲领 §4.3，用尽现有层）**：分组/下钻/展开子集 = 关系层层级；默认列集 = 物理层字段；默认列序 = 物理层字段声明序+主字段优先；固定列（操作/序号/状态）= 约定推导；CRUD 接口 = 物理+关系 组合（resourceController 声明驱动已是雏形）。**呈现方面的人工声明残量只剩：列序覆盖 / 列形态接管（价格槽类）/ 编辑器指定 / 标题微调**——其"家"随 O4 消费端切换按残量定。差异层只收真偏离：图片真相在子表却要在产品行显示 = 数据归属偏离 → 差异层；售价/进价是 recordSet 渲染入口 = 渲染接管偏离 → 差异层。
- **物理层与 Prisma 冲突**（单位换算拆表是历史错误）→ 物理层写正确模型 + 注释登记，DB 收敛单独排（O3）。

**反向禁止**：发现"某层表达不了"就立刻想"放代码里算了"——先查 §7 本层有没有已登记键能表达；能推导的参数不许写死进代码（行为/算法除外）。

## 8.5 推导规则（唯一真相源 = `推导规则/derivation-rules.yml`）

> **规则条目已结构化落盘，本契约不再重复列条目**——写了就是第二份真相、必然漂移。
> 真源：`推导规则/derivation-rules.yml`。一条一条、字段固定（编号 / 类别 / 名称 / 解决什么业务问题 / 落点 / 配置方法 / 应用规则 / 大白话），条目会持续增长，故必须结构化、由预览面板用与物理层/关系层同一套表格框架渲染。
> **用法**：做解释器时照该 yml 逐条对账；遇到"某结果该不该配置"先查它——**表里有的 = 引擎推导、配置零新增、禁止另加键**。
> **四类**（预览面板按它做横向分类导航）：`自动补齐`（引擎零声明自动给）/ `标记推导`（单一标记直接应用）/ `关系层推导`（配置零书写）/ `组合推导`（跨层级多源才推得出，最易被误判成"缺配置"）。

### 8.5.1 缺省值兜底的两个关键约定（2026-09-07 定稿）

1. **声明位置 = 被引用字典表的【唯一名称字段】**（`分类.分类名称: 缺省值 未分类`）。兜底成员属于分类表自己的世界：声明一次、全系统受益，引用方（产品.外键分类）零书写。
2. **"查哪一列"没有歧义**：外键本身已指明目标表；目标表内"哪个字段算名字"由**唯一名称字段**约定确定 = 该表中 `独立去重: 是` 或 `联合去重: N` 的**文本字段**（如 `分类.分类名称`）。缺省值就配在这个字段上——**声明处即匹配处**，所以不存在"这一行字段这么多、不知道拿哪个去比"的问题。若目标表有多个 `联合去重` 组，取**配了缺省值那一组**中的文本字段（缺省值落在哪列，就拿哪列比）。若将来某表出现多个唯一文本字段，须先显式登记名称字段（属新增键，按 §0.0 P16 走）再用。
3. **应用路径 = 先写再用**：外键留空 → 按缺省值名称【直接写入】被引用表 → 撞上唯一约束（同名已存在）→ 直接取用已有那条的 id 关联；写入成功 → 用新记录 id 关联。理由：兜底记录后续常被改名/补全，"先查再用"多数扑空，先写路径更短。
4. **生效时机 = 仅新增**：只有**新增记录、外键留空**才兜底。编辑时字段有原值，没改动就是不改——不需要兜底（2026-09-07 定稿）。读取/列表/统计一律不兜底。
5. **三个硬前提**：① 目标表名称列必须**单列唯一**（否则同名会插出多条）；② 必须**捕获 DuplicateKey** 取已有，禁止"先 SELECT 再 INSERT"；③ 兜底行与主记录**同一事务**，主记录失败则回滚。

> **2026-09-07 范式修正（客户表）**：手机号 / 微信号 原放在客户主表 = 多值联系信息塞主表，不遵范式 → 已移入子表 `客户联系人`（`外键联系方式` + `联系值`，可多条）。主表只留客户自身单值属性；按手机号找客户走 `客户联系人.联系值`（已标 1 级检索 + 普通索引，与真实库 `@@index([value])` 一致）。这条修正同时消除了"客户表三个去重文本字段导致名称字段判据失效"的问题。

### 8.5.2 缺省值落地的五条确定规则（2026-09-07 逐条拍板）

| # | 规则 | 内容 |
|---|---|---|
| 1 | **必填判定** | **外键字段（含 `外键→X.编号(逻辑)` 逻辑外键）一律视为必填**——不允许提交空值。不需要新增 `必填` 键：外键的语义就是"必须指向某条记录"。 |
| 2 | **三态生效**（区分"没提交"与"提交为空"） | ① **字段未提交**（编辑时没改动）→ 保持原值，不触发任何规则；② **提交为空 + 目标表配了缺省值** → 自动补兜底成员（新增、编辑清空都补）；③ **提交为空 + 目标表没配缺省值** → **直接拦截、给提示**"请先选择 X"，不允许保存。 |
| 3 | **联合去重全配** | 分组口径：同号 `联合去重: N` 的字段**组合唯一、分开看各自允许重复**。同号组内字段**要么都配缺省值、要么都不配**——配其一漏其一即体检标红。理由：兜底行要插进去就得该组每个列都有值（用户定稿："既然要联合唯一去重，那就都得配上"）。 |
| 4 | **兜底行全局一条** | 兜底成员（未分类/散客/待指定渠道…）**全系统只有一条**，不按租户各建一份。理由：它是占位，任何人看到真值都可以改它（用户定稿）。多租户真正启用时若需拆分，届时按 P16 新增键处理。 |
| 5 | **三个硬前提** | 目标表名称列必须**单列唯一**（否则撞不到唯一、会插出多条）／必须**捕获 DuplicateKey** 取已有（禁止先 SELECT 再 INSERT）／兜底行与主记录**同一事务**（主记录失败则回滚，不留垃圾兜底行）。 |

> **与"编辑不兜底"的关系**：二者不矛盾。"编辑不兜底"指**字段没提交、没改动**时不动它（有原值）；若用户**主动清空**并提交，则按第 2 条走补值或拦截。

> **唯一键模型演进（2026-09-07）**：字段级唯一约束先后用过 `去重: 是/独立`（二值语义不直观，退役）、`唯一组: N`（分组推导，P17 登记）——当日末统一为**互斥双键** `独立去重: 是` / `联合去重: N`（见铁律 3）。**当前唯一正确键 = `独立去重` 与 `联合去重`**，其余（`去重` / `唯一组` / `去重: 独立`）出现即红。

> **残量**（推不出、需人工声明/代码）：打分公式=引擎写死；权限码/可写白名单=资源登记；多表事务/状态机=代码；呈现薄残量（列序覆盖/列形态接管/编辑器指定/标题微调）= O4 阶段 2 按残量定。
>
> **条件唯一（2026-09-07 裁定：不新增配置键，走代码守卫）**：形如"同一规格**只能有一个**基准单位 / **只能有一条**默认售价 / **只能有一条**默认进价 / **只能一张**主图"这类**带条件的唯一**（部分索引 `UNIQUE(specId) WHERE isBase=1`）——
> ① 它**推不出**：不是结构事实，是业务基数约束，层级/关系组合交叉也得不出；② 但按"能覆盖就不新增配置项"原则，**不为它新增 `条件` 键**（一旦开键，商城式配置就收不住）；
> ③ 归口 = **代码守卫 + 本残量清单**：由 CRUD 解释器在写路径按"同规格已有一条 isBase/isDefault/isMain=1 则拒绝或自动把旧的置 0"实现，规则登记在此，不在配置里。
