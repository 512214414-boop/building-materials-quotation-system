## 关键澄清：18 个「未建模外键」系 v11.0 解耦设计，非建模缺口
- 续接文档原把「schema.prisma 未建模 19 个关系」列为「关系建模缺口」待补 `@relation`。核查 schema.prisma 头部注释（v11.0 解耦策略）后推翻该判断。
- 事实：documents.customer_id / documents.created_by·salesperson_id / document_lines.brandId·productId·unitId / audit_logs.* / cost_lines.* / allocation_lines.* / payment_records.created_by / refund_lines.created_by / reimbursement_bills.created_by（共 16 个在解耦清单明示）+ access_requests.reviewedBy / authorization_codes.createdBy（同策略，未单列）= **18 个真实外键在 DB 层保留，但 Prisma `@relation` 刻意不建模**（保留物理外键保参照完整性，仅移除 Prisma 级联，使基础数据可物理删除而不破坏业务历史）。
- 后果：prisma migrate diff 把这两类 FK 判为「漂移」列 155 行 DROP FK —— 是解耦的预期副产物，无害（migrate deploy 走 baseline，不会触发 DROP）。
- 决策：**不补 `@relation`**（补会违背解耦、重新引入级联耦合，破坏既有设计）。`migrate diff` 噪音接受为设计代价。
