# MEMORY.md — 建材报价系统 · 长期项目记忆

## 架构总纲
- **配置分层（三层配置范式）**：物理层 `physical-layer.yml`（原材料：表/字段/类型/**去重=字段级`是`标记(1=全局唯一/多=联合唯一，禁`组合()`语法)**/**检索=字段级`级别`标记(正整数：配了即参与本表检索匹配、数字小=命中优先、同级并列；1级=主索引、2级=子补充；禁`主·次·辅`文言；**应用层规则喂检索引擎、不进建表输出**)**/**全文检索=字段级`是`(列要全文级搜→FULLTEXT)**/**索引=字段级`是`(列要普通 B-tree 索引=人工决策，库自动的不标)**/表级`缺省行`(本表兜底成员)）· 关系层 `relation-layer.yml`（通路图：关系体/层级/横切字典/检索{模式,主字段}，**主字段应指向该层主实体1级索引**；**禁写`通路`键由标题串联推导**）· 差异层 `difference-layer.yml`（补丁本：对象+说明+override）。**总纲：配置只描述业务事实、不描述机器动作（机器动作入配置=第二份真相必漂移）**。依赖单向：差异层→物理层、关系层→物理层；物理层是唯一地基。宪法：`data-source/layers/分层契约.md`（v8：**顶层定调「物理层=数据库表结构与索引的唯一业务描述源，只人维护配置、解释器幂等输出建表/建索引 SQL（IF NOT EXISTS）」+四条边界** · §2 归属判定表 · §7 每层参数全目录 · §8 表达力兜底链 · §9 O4 迁移排期）。**概念正本=同目录 `概念纲领.md`**（对外讲/复述以它为准：五条正本+该增就增+差异层是补丁本不是垃圾桶+样板自动化个性留代码）。**P14（v8，三校）认层方法论**：层≠数文件——物理/关系/差异只是当前从「建模」方面抽象的文件；层从业务行为认「互不相干的方面」（每方面=静态声明家+解释器+行为留代码），「第几层」不是坐标、「方面有没有家」才是；差异层=横切补丁机制、不占方面数；**加新家前先「用尽现有层」（消费端多源解读，纲领 §4.3 派生矩阵）**：层级展开/分组下钻=关系层推导、CRUD 接口=物理+关系组合（resourceController 声明驱动已是雏形）、默认列序/固定列=物理层+约定推导；呈现"家"收缩为薄残量（列序覆盖/形态接管/编辑器指定/标题微调），随 O4 阶段2 消费端切换按残量定、不提前立项。**用户红线认知：不可把当前抽象写成封顶结构；要拿业务行为全景主动认方面，不是等他报层数。**
- **四域试验田（2026-09-06 深夜）**：物理层 12→34 表（产品/供应商/客户/库存 4 域登记完，其余域验证后接入）；新类型 `长整数`(跨域引用占位：单据/员工域未登记)与`时间`(DATETIME)；新差异键 `按名引用`（字典按名引用非外键 id，契约 §2 #14 已登记）；表标识必须用真实库表名（customers/inbound_tasks 等复数）。**预览页 gen-layer-preview v6 架构定案**：统一范式=**每层都是「横向子导航 + 总览入口」，导航项 100% 配置派生**（物理层=[总览|各域]、关系层=[总览|各关系体]→选关系体再分级、差异层/解释器内容少不设子导航）；加域/关系体=配置加行→导航自动加项、零 UI 改动；"总览"永远在第一位；物理层与关系层对称（同一种"总览+横向子项直达"模式，不再纵向折叠堆叠）。框架到位标准：四域稳定后物理层→60+表/8+域、关系层→12+关系体、差异层→20+条都能横向滚动承载，不需要回头调可视化。**方向：这套配置=未来正本，先四域验证表达力，稳定后解释器派生替代散落实现+浏览器对拍。**
- **检索链抽象（P9 定稿）+ 索引划界（P13 顶层定调，v7）**：模式切换=关系层切到第几层；切到后参与集与优先=物理层检索级别集；打分=引擎唯一规则（写死规则不写死业务，公式不进配置、特例走差异层调级别）。**O4 目标态：物理层 yml=业务模型唯一画布 → 两条消费链：结构链=推导建表+各类索引（生成 schema.prisma，降为生成物）；检索链=推导检索参与集喂引擎——级别是应用层规则，不进建表输出**。索引划界：主键(聚簇)/外键列(库自动补)/唯一约束(自带索引)=库自动，解释器补齐、单表零声明；需要人工决策的索引显式标，三种索引三种键、全与 去重 同构（1=单列/多=组合）：`去重:是`→唯一索引、`全文检索:是`→FULLTEXT（列要全文级搜，P12）、`索引:是`→普通 B-tree（列要"查得快"，P13，组合按字段出现顺序）。级别管「搜得到」（应用层规则，喂检索引擎，不进建表输出）；索引管「查得快」（结构声明，进建表输出）；B-tree 对中文中间片段无效（模糊全文走 FULLTEXT，物理事实不变）。**P11「普通 B-tree 不进配置」已翻案（P13）**：建哪些普通索引=人工业务决策，有就有没有就没有。当前启用 2 处普通索引（产品图片.内容哈希 hash / 进价.外键供应商 supplierId——与库 @@index 一致）；全文检索 0 启用（表达位就绪）。`全文索引`/`FULLTEXT` 等库实现词进配置=红。**P15 类型精度值域（裸 文本/小数 退役）**：`文本(N)`/`文本(不限)`/`小数(10，2)`全角逗号/`主键`(=长整数自增默认)/`主键(整数)`(category 特例)/`外键→表.编号(逻辑)`(不建库级外键，进价→供应商 v11 解耦)；外键列型自动跟随目标主键；**结构解释器 `tools/gen-db-ddl.mjs` 已落地**：物理层→幂等 MySQL DDL（data-source/generated/database-schema.sql）+ 自动对账 schema.prisma（对账报告，漂移分[O3]/[微]，8/12 全一致 7 处 O3 已知）+ `--check` 门禁。
- **兜底成员范式（P7 定稿，用户两次纠错磨出）**：字段级 `缺省` 键已整体退役（曾逐字段复读 DB @default=第二份真相；外键背"未分类"=让产品表替分类表记家事）。兜底成员属于**被引用表自己的世界**：目标表写表级 `缺省行`（分类: 未分类/品牌: 普通品牌，声明一次全系统受益），声明者必须恰有 1 个唯一标记字段；外键留空→引擎按缺省行查/建行取 id。体检器对退役键/机器语法一律标红。
- **检索索引级别范式（P8 定稿，用户四连问磨出）**：`检索: {级别: N}` 正整数，非空即参与本表检索匹配、数字小=命中优先、同表同级=并列；1级=主索引（关系层每层主字段须指向它，体检黄项）、2级=子补充（备注/别名）。曾用 `本表权重: 主·次·辅` 文言=不可扩展+与排序权重撞词，已退役即红。后端 resourceController search.fields 缺省 ['name'] 死规则，将来由级别集生成。
- **分层判据（核心，用户 2026-09-06 追问后定稿）**：层数不是"说几层就几层"，是**业务上互不相干的"改动理由"的个数**逼出来的。验法：拿一个真实改动问"要动几个文件"——恰好 1 个=分层最优；≥2 个=两层该合一或依赖没理清；0 个=该让引擎推导，不配配置。假层=从不独立变化的层；散乱的病根是"同一理由散在多个文件 / 一个文件塞多种理由"。
- **AI 在分层中的职责（用户明确期待）**：不附和、做反方——把用户直觉翻译成可检验规则（参数归属/禁写/体检工具），用户说 2 层/5 层时主动验算指出"会散/是假层"。能自己决定的按裁决链定，看得见的形态先摆选项。
- 双语桥接：配置键/值中文 + 每字段 `标识` 英文；翻译映射只存在一张表，禁第二份"翻译真相"。配置为准、Prisma 历史错误后续 DB 收敛（O3 唯一待拍板·需点头，收敛清单见契约 §6：单位换算拆表合并 + status×3/唯一键左前缀冗余/product_image 缺 @@unique）。

## 用户画像与协作
- 非技术用户、英文识别困难：配置/文档用中文大白话；验收落到行为（打开哪页/点什么/看到什么）。
- 提 UX/架构问题时常带方向性判断但委托取舍；深层动机=要"稳定、共性、不各写各的"。
- **专业取舍全权委托 AI（2026-09-06 定稿）**：用户反感被反问技术选择题（"别逼到我后面"）。纯技术取舍 AI 依据裁决链直接定案并在契约 §6 登记理由；只有 动 DB / git push 红线 与 会改变用户可见形态 两类才请他点头，且给结论让他说"行/不行"，不是让他选方案。验收话语=行为清单（打开哪页/点什么/看到什么）。
- **用户纠错即范式升级信号**：他每次"怎么会配在这里/怎么会这样写"的追问，都揪出 AI 把机器动作或别家事实塞进了配置。处理顺序固定：先查系统真实用法（entity-meta 主输入/Prisma/后端消费）→ 以"解释器只读事实"为准重写 → 四件套同步（yml+map+preview+entity-meta⑥）→ 对拍 0 红。回话别问选项，给结论。
- 环境约束：沙箱易 SIGTERM 重进程（tsc 全量约 9min 能过，vitest/esbuild 被杀）；DB 结构变更/git push 曾需确认，2026-09-06 已撤销"每项确认"红线授权 AI 收口（DB 迁移仍先备份+dryrun）。
