# 项目长期记忆（MEMORY.md）

## 项目概况
建材报价系统（门店用，React19+TS+Vite 前端 / Express+Prisma+MySQL 后端）。非技术用户 100% 用
中文自然语言驱动开发与改需求。核心域：建材报价 / 单据体系 + 产品档案（SKU 定价）。

## 关键约定（务必遵守）
- **两个文档体系**：人看、项目对齐，都以 `文档可视化/` 为准（当前进行时，必须最新）。`用户项目开发文档/` 是旧基线给 AI 读，很多还没搬过来；该更新的同一轮两边都更新，免得 AI 按旧基线做错。先改可视化，再改用户文档。可视化还没写到的才只改用户文档。两边打架以可视化为准。
- 新需求先归本项目对应线；禁止从页面反推。档案五段出发点只指回，不重写长文。
- 用户不懂代码：AI 必须用业务语言沟通、给选项而非技术术语；索引等实现细节自己判断不问用户。
- 项目设计哲学是**开发约束**来源（`用户项目开发文档/项目设计哲学.md`）：6 大约束（含历史单据
  法律事实/快照不可变、Excel式无保存按钮、索引驱动性能、算力在前端）、6 大原则、3 种交互范式
  （A 行内 / B 弹窗不叠弹窗 / C 下钻）、权衡优先级。
- 复用优先：UnifiedTable（唯一页面表）、EntityPanel(C65，浮层表网格基座)、MatrixTable/UnitManagePanel 为适配器、
  ProductPicker/UnitPicker 为开单选用链（禁止删掉再造）、DictRefField、COL_WIDTHS、
  设计令牌（tokens → .ds-* → 组件）、请求层——禁重复造轮子。
- 源码唯一权威：src 下禁 .js，引用统一 .js 后缀，见到同名 .js 先删。
- 文档与代码同一轮同步；业务本源在 `文档可视化/` 指导思想，落地细则在 `用户项目开发文档/`。

## 交互载体三层模型（2026-08-14 洞察推演定稿，权威见《AI协作/洞察结果文档.md》）
全系统浮层类交互收敛为三类，按"交互意图"派发，禁止第四种范式：
- **消息通知**：非阻断、角落提示、不参与交付（antd message / 统一通知）。
- **模态框**：相对 1200px 画布居中、阻断式、承载复杂表单交付（`DsDialog` C07）。
- **悬浮定位框**：锚定触发元素（贴其下方/旁侧展开）、非阻断、辅助输入；业务统一关键词
  「悬浮定位框」↔ 代码 `FloatPanel`(C60) + `smartPopupContainer`。**基座稳定不变，内容由调用方
  注入**（固定组件 / 组件+参数配置驱动 / 一次性内联）。C20/C28/C29/C61 等均为其"内容组件"。
- **Drawer（DsDrawer C08）判定废弃**：遗留"下钻递进"不适用；客户侧下钻等改用「模态框+悬浮定位框」
  组合；表格回归纯表格，复杂编辑只走模态框+悬浮定位框两种方式。
- 用户偏好用「悬浮定位框」而非旧称"浮动面板/悬浮面板"，因"锚点+展开"联想好记。
- 该洞察结果产出为独立《洞察结果文档.md》，由用户转发执行 AI 整改代码/文档（非本人直接改）。
- **现行浮层内容**：C65 EntityPanel 是网格基座；C19 UnitManagePanel / C29 MatrixTable / C20 UnitPriceExpandPanel **没有删除**（适配器）。开单选品=ProductPicker，开单选单位=UnitPicker，档案维护=UnitManagePanel/UnitPriceExpandPanel + RecordFieldColumn。禁止把三条链合成一套 UI。
- **画布定位约束（v2 补完「定位层」）**：模态框+悬浮定位框均须相对**同一画布**=主内容区
  `.ds-app-shell`(1200px) 渲染、不得超出画布外。模态框居中天然在内；悬浮定位框**边界避让=平移
  夹紧**（超右/左界整体平移使不超画布内边距，不翻转）；**极小屏不兜底**（手机靠拖动可视窗口看
  画布）；**推翻 FloatPanel 旧 v10.27「水平不避让、靠横向滚动」规则**（配货面板飘出画布的根因）。
- **执行状态追踪机制（v2 新增，长效）**：《洞察结果文档》=任务书+执行台账合一。执行 AI 每完成一项
  巡检，在文档「执行状态总览」回写「✅ 已执行(日期+改动文件/PR)」；洞察 AI 下次定稿覆盖前先读该
  总览，已执行项保留标记、仅把新增项入任务，避免重复劳动。
- **唯一任务书纪律（v3 强化，用户严令）**：全项目**只有一份任务书**=`用户项目开发文档/AI协作/洞察结果文档.md`；
  任何主题（交互载体/画布约束/浮层全场景/开单MVP/信息层）的洞察结果**全部并入这一份**，严禁为不同
  主题另建第二份任务书文件。更新方式为**增量覆盖**：叙事层可刷新，但已执行项(✅)标记原样保留、新
  需求追加为新巡检项（不删除旧项）。该纪律已同步写进 `topdown-doc-governance` 技能提示词（删"独立成
  篇"漏洞、改"完整覆盖"为"增量覆盖"）。原开单MVP独立文件已归档 `_归档/开单MVP与信息层配置洞察_已并入任务书.md`。
- **执行层自决纪律（2026-08-14 校准，长效）**：任务书只定义"做什么+验收标准+不变量"，执行方法(拆解/并行串行/顺序)由执行 AI 自决、单对话闭环。但**分层**——执行策略类(顺序/优先级/是否确认计划)**严禁问用户**；业务澄清与真实阻塞类(需求歧义/规则不清/范围冲突/缺关键信息)**允许且应当主动提问**，属正常交付协作。该纪律已写进任务书「执行状态追踪机制」章节+同步进 `topdown-doc-governance` 技能硬约束第7条。
- **执行层自决纪律（2026-08-14 用户明确，长效）**：任务书只定义"做什么 + 验收标准 + 不变量"，**绝不规定执行顺序 / 并行串行 / 拆解方式**；执行 AI 接到任务书即视为完整任务，自行决定如何拆解与执行、一个对话内闭环整改所有待执行项；**严禁执行 AI 在执行过程中回头问用户"先做哪条/后做哪条/怎么做/要不要确认优先级"**（仅遇真实硬阻塞可一次性汇总疑问）。该纪律已写进任务书「六、执行状态追踪机制」章节，并同步进 `topdown-doc-governance` 技能硬约束第 7 条。

## 浮层全场景抽象（2026-08-14 v3 洞察定稿，权威见《AI协作/洞察结果文档.md》§1.3/§2.5）
悬浮定位框(C60)在多场景（主画布/模态框内/浮层内再开浮层/表格单元格）使用，内容组件（列表/矩阵/输入框）
分散多处。统一抽象为 **6 方面，全部「不硬编码、由挂载链+配置自动处理」**（用户明确反对硬编码）：
- **A 挂载层链**：`smartPopupContainer` 在 modal/drawer/body 基础上**新增识别父浮层 `.float-panel`**，形成
  body→modal→drawer→父浮层 四级链；内层面板自动挂父浮层内部（继承 stacking+裁剪）。
- **B 层级自动派生**：**消灭字面 z 常量**（含 `PANEL_POPPER_Z_INDEX`），改 `z=Z_BASE+depth*STEP`，depth 由
  挂载链深度自动算，绝不手写；取消"面板低于弹窗"特例。
- **C 定位参照系**：`calculatePosition(anchorRect, containerRect)`，clamp 基准=当前挂载容器矩形（body 取
  `.ds-app-shell`、modal 取 modal rect、父浮层取其 bounds），随挂载链自动切换，无硬编码边界。
- **D 关闭级联**：`parentId`/PanelTree 统一契约，嵌套浮层默认级联关闭；取消 `CustomerPicker` 内嵌 Modal 特例。
- **E 内容契约(mode 驱动)**：所有内容组件统一接收 `config:{mode:'manage'|'pick', dataSource, columns, onPick, allowCreate,...}`；
  档案管理侧 vs 数据使用侧差异只由 config 表达，不换壳。
- **F 壳归一**：内容组件(ProductPicker/UnitPicker/PricePicker 等)**永不自建壳**，壳由宿主(PickerCellEditor/DsInputDropdown)提供；
  ProductPicker/UnitPicker 双路径合并为内容-only，PricePicker 补浮层壳。
- 现状发散点（待整改）：`UnitPriceExpandPanel` 仍用 antd Popover+PANEL_POPPER_Z_INDEX（与 `PriceChoicePanel` 的
  FloatPanel 壳分裂）→ 全迁 FloatPanel 消灭 Popover 分支。巡检项 18-25 已入任务书。
