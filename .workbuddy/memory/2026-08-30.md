  按 `nodes` 数组顺序堆叠，**子节点不跟随父** → 连线交叉，没有分叉感。
- **分叉感来源是「子节点 y 跟随父」(tidy tree)，不是「横过来」**。

### 调试坑（再补一条）
agent-browser 测静态站点时，**改完文件后 `agent-browser open ?cb=...` 仍复用 `?v=29` 缓存**，
连 `location.replace` 都不行。两条路：(1) 起 python server 时在 `end_headers` 加
`Cache-Control: no-store, no-cache, must-revalidate`；(2) `eval` 改所有 `script[src]` +
`link[rel=stylesheet]` 的 href 加 `?v=Date.now()` 强制重新拉。
下次直接用 (1)，干净。

### 关键洞察（值得记入方法论）
**「分叉感」= 子节点 y 跟随父节点**。这个洞察可以升维到一条布局范式：
任何「层级数据想看出分支」的诉求，都该走 tidy tree（子跟随父），不是分层 DAG（子按数组顺序堆）。
分层 DAG 适合"看层数 / 看跨层引用 / 看共享"，但**看不出"谁是谁的分支"**。
18-graph.js 注释里写"树只画结构边"是有道理的——树布局天然不支持共享节点。
下次遇到类似布局需求，先问：用户要的是"看出分支"还是"看出层数"？决定走 tidy tree 还是分层 DAG。
