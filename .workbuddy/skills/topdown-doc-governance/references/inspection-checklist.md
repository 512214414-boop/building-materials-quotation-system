# 检查清单：四类病灶逐项对照

> 配套 `SKILL.md` 第 ② 步。扫描器已自动初筛，这里人工判定是否真问题、定整改优先级。

## 一、膨胀（Expansion）

- [ ] 架构原则类文档是否 ≤ 300 行？（硬上限，超了即不合格）
- [ ] 其余文档是否 ≤ 300 行（预警）/ ≤ 500 行（严重）？
- [ ] 同一主题是否散落多份、未收敛到单一信息源？
- [ ] 文档里是否残留变更记录 / 版本沿革（违反"历史由 Git 负责"）？
- [ ] 是否靠"加小节"而非"抽公共"来增长？

## 二、断链（Broken traceability）

- [ ] 每张功能文档是否至少引用一份顶层文档（详见《项目设计哲学》/《顶层设计规范》/《架构原则·xx》）？
- [ ] 所有 `详见《文档名》` 指向的文档是否真实存在（文件名匹配）？
- [ ] 顶层理念是否有下层承载？有无"悬空理念"无人实现？
- [ ] 是否存在任何文档都不引用、也不被引用的**孤儿文档**？

## 三、越权（Scope violation）

- [ ] 架构级文档（架构原则 / 顶层设计规范 / 哲学）是否含：组件名、函数名、`=>`, 代码块 ```` ``` ````、CSS 颜色/`px`、文件路径、接口签名？
- [ ] 架构文档是否描述了"某个功能内部"的细节（应退回功能文档）？
- [ ] 功能文档是否越权去规定"跨功能通用规则"（应上提到架构原则）？

## 四、重复（Duplication）

- [ ] 同一规则是否在 ≥2 处完整描述、未 `详见` 引用？
- [ ] 同一张表结构 / 字段定义是否在多处定义？
- [ ] 是否有复制粘贴式段落可收敛到单一信息源？

## 五、一致性（来自《文档编写规范》）

- [ ] 标题是否语义化（无 `## 一、` `### 1.1` 数字编号）？
- [ ] 跨文档是否用 `详见《文档名·章节》` 而非复制？
- [ ] 术语是否一律指向《术语表》，本地无重定义？
- [ ] 业务语言优先，技术术语首次出现有中文解释？

## 整改优先级建议

1. **断链 / 越权**：破坏"顶层↔细节"关系的硬伤，最高优先级。
2. **重复**：引发后续膨胀的温床，次高。
3. **膨胀**：在不破坏自包含前提下抽公共、收敛。

> 任何整改必须"文档 + 代码同一轮同步"，不留悬空项。
