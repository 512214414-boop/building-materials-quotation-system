## 1. 系统是什么

**先分清写法和本项目的正文。** 怎么写出能指导开发的指导思想：独立组「知识沉淀」（一类活起头，六条线写满，实地检测）。这家店填满的正文：
`文档可视化/`「系统业务设计指导思想」。新需求先问属于哪一条线；细节从场景推，不要从页面反推。

**建材报价系统**：建材门店用的报价/开单/对账/配货/交付/成本/售后/归档一体化系统。部署在门店
普通笔记本上，最多 10 人并发，算力/网络有限。用户是 **Excel 资深用户**，操作习惯是"点格子直接敲、
回车下移、改数立刻出结果、没有保存按钮、不弹打断人的窗"。

**中心域 = 建材报价 / 单据体系 + 产品档案（SKU 定价）**。一切围绕"单据"展开。

**本项目一类活**（作业，不要和工作台八个视图混）：销售开单、配货履约、进货管货、收付款往来、售后。对象/过程/角色/看数/工具习惯见指导思想其余页。8 档状态机是「一张单怎么过手」，不是八类活。

**人不必人人建档。** 问到名字或电话就写在单上；什么都没有也先开。建档是给回头、以及按这个人看数。散客一样能退。售后对着已经卖掉的行去对（柜台上货顺序是乱的），对上了才落到那张或那些原单；只能退本店当时卖过的数量；退价是当时卖给这个人的价，不是名册现价。

## 2. 六大根本约束（不可改变的客观现实，任何实现都不能违反）

1. 开发者不懂代码，100% 靠中文自然语言 + AI 对话完成 → 系统必须皮实（改一处不崩全局）、一致
   （相同交互处处一样）、规则显式化（写在文档里 AI 读得到）。
2. Token 极贵 → 能复用绝不重复；同样规则只写一次；文档是唯一真理源。
3. 部署在门店笔记本，算力/网络有限 → 算力往前放（前端计算），后端只存数据、做最终校验，不做高
   并发架构。
4. 用户是 Excel 资深用户 → 表格是终极交互载体；双端一套界面；表上无保存按钮。开单表走档案点值：格子只展示，确认层确认才写（取消不写），不再失焦保存。
   **手机是高频使用场景**（不是配角）：屏窄只是可视范围小，靠挪画布看；点格必须出系统键盘；滑动画布不关浮层；缩放是远程桌面式整幅画面等比，浮层少留白。细则见质量闸门第六节 / P-016 / P-017 / P-018。
5. **历史单据是法律事实** → 开出去就不能变；档案改名/删除/停用不影响历史；业务数据快照存储、
   ID 解耦、禁止基础档案 CASCADE 到业务数据。
6. **数据量级巨大**：用户几十个（并发极低），SKU 几十万，业务行几千万 → 索引驱动一切检索、
   候选集受控（几百内）、宽表承载、列表索引分页、统计走聚合索引；任何"按几千条设计"都不合格。

## 3. 核心数据关系（用户说的"数据关系"，AI 必须懂）

```
分类 category
  └─ 产品 product            (产品档案主记录)
       └─ 规格 spec          (v14 拆分：规格变体)
            └─ 规格×品牌 spec_brand  (规格×品牌 多对多)
                 └─ 品牌 brand       (全局档案)
单位 unit（v16.5 全局字典）/ spec_unit（规格引用）/ brand_unit_conversion
价格 sale_price / purchase_price / price_type
产品图片 product_image
SKU = 规格 × 品牌 × 单位  (最小可售/可存单元)
宽表 product_sku_search   (SKU 检索扁平宽表，keywords 拼接 + FULLTEXT ngram 索引)

单据 documents  1 : N  document_lines        (单据行：产品快照+数量+单价+金额，售价/金额在行上)
  ├─ payment_records / allocation_lines / delivery_records
  ├─ cost_lines / refund_lines                (标注表)
库存/采购：warehouse / inventory / inventory_ledger / supplier /
  supplier_point_rule / supplier_payable_lines / inbound_tasks(+lines) / backorders
定档冻结：archived_orders(+lines) / archived_logistics / archived_costs / archived_refunds
  reimbursement_bills(+lines) / audit_logs / system_config / field_change_logs
RBAC/客户：roles / users / user_roles / customers / authorization_codes /
  access_requests / customer_sessions / customer_addresses
```

**关键概念**：
- **快照**：开单时把当时的名称/价格抄到单据行上。档案后来改了，已开的行不自动跟；只有再点插入（或换绑产品）才重抄当时内容。改数量、改单价、只换单位，都不去档案里刷产品名。历史单据不能错（约束 5）。
- **标准行 / 非标行**：规格、牌子、单位都认上了为标准行（能回仓、能带默认价）。只写下口述、没认全的为非标行：正常保存、正常算金额，钱可以退，不能当标准库存收。不要只用 productId 判断。
- **8 档状态机**（单据整体进程，任意双向可逆）：demand_pending→quote_confirmed→payment_settled
  →allocation_in_progress→delivery_completed→cost_verified→after_sales→archived。权威定义见
  `功能文档/单据与状态机.md`。
- **视图锁 view_locks**：documents.view_locks JSON，键名 snake_case（payment_reconcile /
  purchase_quote / delivery / refund_after_sale）。
- **点位规则**：库里存面价和点位，用的是乘完的实际价。进价、售价两套互相独立。改全局 = 同一品牌+同一分类这一批（售价再加类型，进价再加渠道），不是整个品牌。确认修改 = 只改当前这一条规格。已经单独改过的规格，整批再调时不跟着变。读：实际价 = 面价 × 点位，点位 = 规格例外 → 组默认 → 1。
- **选品主行 / 选用检索**：所有档案最终都走这一槽。顶栏由树派生：宽松=当前树能打到的字并成横表；精准=一层一颗按钮。切档不改字。包含与被包含。产品默认名称（认货）；客户/供应商/单据头默认宽松。渠道档问这货谁可能供：已进价 ∪ 经营范围。客户私有：点中后挑一条联系。售后两个独立格子：单据格找单（点格进确认层，空词按日翻），已卖行格对当时名称。写入当前行只走插入（客户/供应商点行回填）。工作台表 = 档案点值表：格子只展示，点开确认层；能打字的格（含数量/备注）确认才写。选用检索挂在确认层输入上。订单中心各过程页的槽位以 `文档可视化/`「订单中心」为准。
- **成本三段分层**：internal（仓库出库，单价=加权平均进价）/ external_agreed（外部刚需直发）/
  external_excess（外部超额入库）。
- **欠库**：内部出库库存不足时缺口挂 backorders，补货入库自动冲抵。
- **候选集受控**：任何"取候选再算"先索引粗筛压到几百内，再应用层精细打分。

## 4. 三种交互范式（数据形态决定交互，绝不靠拍脑袋）

| 数据形态 | 范式 | 触发 | 展示 |
|---------|------|------|------|
| 主体单字段 | **A 行内编辑** | 单元格点击 | Excel 式表格行内直编；关联字段面板内"检索+选择+新建"，不离开主表 |
| 同一主体多维+交叉矩阵 | **B 编辑弹窗** | 点击主体全名列 | 弹窗内业务区块并行（非下钻），矩阵化，单元格直编；**弹窗内不再嵌套弹窗**，事务一次提交 |
| 父+独立子实体列表 | **C 下钻** | 点击子实体计数列/父名下钻 | 同一区域**整页重渲染为子表格**（非抽屉非弹窗）+ 顶部上下文栏 + 可回跳面包屑 |

**判定**：先判是否父+独立子实体（线性一对多）→ 是则 C；否则是否多一对多+交叉矩阵 → B；否则 A。
**红线**：B 与 C 不可互相替代；C 内禁用抽屉/弹窗/遮罩切换层级（逐层下钻、同时只显示一层）。

## 6. 当前已知架构缺陷（见 `AI协作/架构缺陷台账.md`，改动时勿重演）

- **P-002** 全局去业务编号（用户已拍板全链路移除）。业务档案身份只用数据库 id，禁止仓库编码/客户编号/用户编号给人填。角色代码、授权码除外。
- **P-010** 编辑弹窗上叠模态弹窗（ProductEditDialog 之上又叠独占模态层）——违反 B 范式，勿再犯。
- **P-011** 页面硬编码样式与列宽绕过令牌（552 处像素 + UnifiedTable 列宽 85 处绕过 COL_WIDTHS）——新增代码一律走令牌。
- **P-012** 功能文档实现细节与历史印记泛滥——写文档时聚焦规则，不堆实现细节与历史版本号。
- **P-014** 开单翻页空行序号撞车 / 提交甩到表尾 / 选品与失焦双提交 —— 主路径已落地；`documentLineInvariants` + 单测锁插入位置。
- **P-015** 选品落库单位须取自已加载真实单位，unitId+unitName 非空；ID 落库前剥离 0/''/null —— 主路径已落地；`toNullableId` 单测锁定。
- **P-018** 画布缩了但浮层/字号不跟。缩放必须元素级等比；浮层住在舞台叠加层里一起缩。浮层少留白。

## 7. 一句话

**这是一个"表格即主体、Excel 式流式录入、历史单据不可变、算力在前端、索引驱动性能"的门店系统。
用户用大白话描述"想达到什么效果"，AI 负责判断"用什么符合本系统常识的方式实现"，并主动复用、
抽象、重构、扫清影响面。**
