## 产品概述

用户发现一套系统性问题：从数据层表关系设计、数据关系管理层、表格 UI 使用层，到架构蓝图定义的平台资产层，各层「关系组织不清晰」，且缺少「在业务目标下如何得到最优架构与代码实现」的推导方法。以产品管理为例：用户自设计的宽表 + 为满足「产品唯一」自造的产品名称字典，事后发现范式设计本可覆盖，属弯路。

用户进一步澄清：系统自下而上（数据模型层 → 元数据驱动 → 共享组件 → UI 装配）实际已清晰，真正缺失的是自上而下（业务目标 → 范式选择）的推导环节，两个方向完整性不对称。

1. 定稿《根因分析与预防措施.md》：补入「自下而上清晰（机制强制）、自上而下缺推导（仅有软纪律）」的双向不对称认识；落定裁决 A——product_name 独立字典属弯路（1:1 拆表 + 无共享引用证据），予以撤销；产品名唯一收口为全局唯一；订正文中过期行号与状态；附落地动作表，DB 步骤标注待用户单独确认。
2. 《架构蓝图.md》升版 v3（双向架构，指导全局开发的架构主文档）：上半部新增「自上而下推导链」（业务目标 → 归类 → 范式判据：字典抽离须满足共享/多实体引用、纯唯一用唯一索引、1:1 不拆表、宽表读缓存须声明派生 → 层落点）；下半部保留 L1–L5 纵向栈、红线与门禁作为层落地指南；记录本次裁决。

4. 产品名唯一收口：product 唯一键从 [categoryId+name] 收紧为 [name] 全局唯一；saveProduct/catalog 冲突检查改为按 name 全局查重。
5. DB 迁移（用户单独确认闸门）：编写唯一索引切换 SQL，经用户确认后 deploy。
6. 门禁全绿 + 回写 docs-coverage v23 段为「字典已撤销」口径 + 刷新掌控台。

## 技术栈

沿用项目既有体系：Prisma + MySQL（L5）、`data-source/entity-meta.yml` 唯一真相源 → `tools/gen-entity-meta.mjs` 生成前后端 `*.generated.ts`（L1→L2）、后端 TypeScript 服务（L4）、verify 门禁（S0 对拍/S1 类型/S2 lint/S6 冒烟）。

## 实现思路（先文档后代码）

按方法论「先文档后代码」与用户裁决，分四段推进：① 复核改动面 → ② 文档收口（根因定稿 + 蓝图 v3）→ ③ v23 字典回退 + 名唯一收口代码 → ④ DB 迁移（闸门）与门禁。

关键判断：

- 磁盘现状取证（已对账）：schema.prisma 含 v23 三段新增（product_name 模型、product_category 模型、product 的 productNameId/productName/productCategories）；entity-meta.yml 含 product_name 三处（entities 字典段、fieldDefs、resources）；但**前后端生成物（*.generated.ts）均不含 product_name/productNameId**，且 saveProduct/catalog 冲突键仍是 `categoryId_name`（P2b 代码不在工作树）——即当前是「meta/schema 超前、生成物与代码滞后」的中间态，回退面干净：改两处真相源 + 重生成即可一致，无历史代码需回滚。
- 名唯一收口：schema `@@unique([categoryId, name])` → `@@unique([name])`（实证 290 产品名两两不同，索引可安全建立）；`categoryId` 列与 `@@index([categoryId])` 保留。受影响冲突检查共 5 处：`saveProduct.ts` 214/233/1007、`catalog.ts` 348/407，由 `findUnique({ categoryId_name })` 改为 `findUnique({ name })`，提示语改为「已存在同名产品（产品名全局唯一）」。
- DB 迁移策略：已知 `migrate dev` 因影子库重放失败被堵，改用**手写迁移 SQL + `prisma migrate deploy`**（deploy 不需影子库，只应用未执行的迁移文件）。SQL 需先按实际索引名 DROP 复合唯一索引（以 v14 迁移或 information_schema 实测为准，勿假设 Prisma 默认名），再 ADD name 全局唯一索引。
- 运行时一致：findUnique({name}) 依赖 DB 全局唯一索引存在，故**代码与迁移须在用户确认后同批落地**，先 deploy 再起服务验证，避免 create/edit 产品运行时 500。
- 爆炸半径控制：不清理 37 处历史 `product_sku_search` 字符串引用（多为迁移/注释/诊断脚本，宽表已 v30 物理删除）；不触碰 Task 5 产品页统一化在途文件（ProductSkuSubTable.tsx 孤儿文件不纳入本任务改动）；ProductEditDialog/ProductManage 等前端不改（前端本就无 product_name 消费）。
