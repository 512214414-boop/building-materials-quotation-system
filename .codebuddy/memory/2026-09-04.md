## 三、文档体系三层解耦 · 侧栏全生成（提交 7e75313）★架构级

**起因**：用户质疑「文档一膨胀就改结构、调导航、全部重做一遍」的循环已发生三次，且已影响项目开发。

**根因**：身份 / 存储 / 呈现三层绑死——内容存哪决定怎么读，怎么读决定导航怎么排，导航决定 UI。
次级根因：文档只有加法（只增不减、只加不合）。

**架构**：
- L1 身份层（id / 标题 / 副标题 / 触发条件）—— 永不改变
- L2 存储层（存 1 个文件还是 100 个文件）—— 随时可换
- L3 呈现层（侧栏 / 加载清单 / 技能索引 / 执行卡）—— 全部生成
- **核心不变量：L2 怎么变，L1 与 L3 一个字都不用改**
- 因此「分片依据什么规则」这个问题消失：分片退化为随时可切、无人察觉的实现细节

**落地**：
1. `05-nav-groups.js`（259 行 / 68 登记项）数组段改由 `gen-docs` 第 ⑥ 段产出，手写注释头原样保留
2. 排版由组的 `style: compact 或 expanded` 声明驱动（呈现参数留声明层，不污染内容层）
3. **加一篇从三步变两步**：建 `items/<navId>.yml` → `_index.yml` 的 groups 加一行
4. `order`（NN 序号）与 `groups`（阅读顺序）是**两套顺序，不可合并**；order 设为可选，新篇不写自动追加
5. 六项守卫全部拦在写入之前；跨篇重复规则文本告警（只告警不阻断）

3. **全仓一次性开 strict 是结构性失败**：3400 errors → 分支被放弃 → 18 个月后仍在 backlog 且又长两万行松散代码（正是"循环"）。正解 = allowlist + 棘轮。
4. Spec-Driven（Spec→Plan→Tasks→Implement）：验收标准必须**动手前写定**，否则 AI 自创宽松标准。

三项定案（已写入蓝图 v2）：
- **A 通用vs业务判据** = Martin Fowler **三次原则** + AI 特化补丁「**第二次出现必须登记**」（AI 会话无记忆，不登记则第三次永不触发收敛）；例外：安全/权限/金额第 2 次即统一。理由：过早抽象养出上帝框架。
- **B tsc 存量策略** = **allowlist + 棘轮**（拒绝全修，也拒绝放任）：① 跑基线冻结存量 ② 建 tsconfig.strict.json（files 白名单，初始仅干净 leaf 模块）③ 棘轮三规则：strict 失败即挂 / guard 防白名单被删减 / **任何被本次改动触碰的文件必须同次加入白名单**。allowlist 下直接开全 strict（含 strictNullChecks），不按"便宜 flag 优先"。我们仅 260 文件，收敛快。
- **C 逃逸口** = **允许显式逃逸、禁止隐式绕过**：须写 `@escape: 原因+到期条件`，登记 docs-coverage.md + 掌控台可见；同类需求第二次出现自动升级为 L3 候选。
