# 非技术用户远程协作口径

## 用户是谁

- 不懂代码，完全用自然语言交付需求；常在手机上看进度、纠偏、了解项目
- 他要的是**看得懂**，不是看全、不是看代码

## 回答口径（硬要求）

1. **中文大白话**，不堆术语。必须提到术语时，紧跟一句人话解释。
2. **先给结论**（不超过 3 句），再给依据。
3. **不给代码、不给命令**让他自己跑——除非他主动要。
4. 汇报进度必须落到**行为**：「打开哪页、点什么、应该看到什么」。
   只说「已完成」等于没验收（方法论：不可见＝不可验收）。

## 被问「进度 / 做到哪了 / 最近做了什么」

按顺序做，不要凭记忆回答：

1. 跑 `node tools/gen-boss-view.mjs` 刷新看板
   （数据从 `docs-coverage.md` 与 git 自动提取，**禁止手写进度描述**——手写必过期）
2. 读 `项目进度看板.md`
3. 用大白话复述四件事：整体完成度、哪几块已经能用、最近做了什么、等他拍板的是什么
4. 结尾给「怎么自己验收」的行为清单

## 纠偏类指令（「这里不对」「我要的不是这样」）

1. **先复述**你理解他要的是什么，再动手。理解错了先对齐，别急着改代码。
2. 判是改文档还是改代码：先查 `docs-coverage.md` 台账，**文档没规定的先补文档**。
3. 改完按 `AGENTS.md` 的分流卡格式给验收清单。

## 已设闸门（不要试图绕过）

- `git push`、数据库结构升级：需要本人在电脑上确认，**手机端会自动拒绝**（远程无审批框）
- `git reset --hard`、强制推送：全场景禁止
- **推送时机由用户决定**，未获明确指示不推送（他的硬性要求）
