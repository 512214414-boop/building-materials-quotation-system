# 方法论体系执行卡（强制）

本项目的规范源是「文档可视化」站点 + `文档可视化/data-source/methodology.yml`（唯一真相源）。
改方法论只改真相源，跑 `node tools/gen-docs.mjs` 重新生成站点与 `AGENTS.md`。

## 第 0 步：先读执行卡（禁止跳过）

任务类对话开始前必须先读这两个文件，再动手：

- `AGENTS.md`（项目根）——执行卡全文：分流五步、裁决链、技能索引、硬纪律、组件资产清单
- `docs-coverage.md`（项目根）——文档↔代码覆盖台账，判产物前先查
- 需要细节时再读真相源 `文档可视化/data-source/methodology.yml` 对应条目

## 对话分流五步（每轮任务对话都走）

1. **判类型**：需求整理 / 变更调整 / 纠错反馈 / 澄清问答 / 闲聊（按用户原话形态，不猜意图）
2. **判产物**：查台账 → 文档任务（先补文档）/ 代码任务（禁止重复生成文档）/ 双任务 / 无任务
3. **查方法论**：按 AGENTS.md 技能索引命中对应篇，读完再动手
4. **干活**：按该篇流水线与否决项执行
5. **报验收**：可操作的行为验收清单（打开哪页、点什么、应看到什么），并回写台账

轻量对话（纯澄清/追问/闲聊）只定性、直接回答，不输出分流仪式。

## 输出必须可见（用户要能确认你是按体系工作的）

每轮任务对话的回复**开头**必须给出分流卡，格式：

```
【分流】类型：<…> ｜ 产物：<文档任务/代码任务/双任务/无任务> ｜ 方法论：<篇名 · 第几步>
【验收】1. … 2. …（可操作的行为清单）
```

干完活后必须给验收清单，不许只说"做完了"。改前端代码后必须跑 `npm run build`（8080 是生产包，8081 是 dev）。

## 操作不中断（任务一口气做完）

- **该做的全部做完**：不允许做完一段停下来问"要不要继续"
- **需要用户决策的**：先记下、继续做完其余，最后用 **IDE 的选项提问面板**一次性给出让用户点选——不占对话回合、不中断流程
- **能自己决定的不要问**：有依据就按裁决链自行决定，并在验收清单里说明

## 硬纪律（摘要，全文见 AGENTS.md）

- **先升维再动手**：没说出"这属于哪一类问题"就动手＝没升维。归类到类型 → 查该类通用最优 → 定位现状版本（雏形/低配/误用/正确）
- **查同类先查组件资产清单**（AGENTS.md 第七节），邻近实现只能校验、不能当参照物
- **确认层范式**：可编辑单元格一律点值→确认层→应用，禁止常驻输入框；空行确认无条件晋升
- **门禁用提示不用静默**：前置未满足的格子视觉保持一致，点击提示"请先 X"
- **看得见的东西先摆选项**：交互/导航/布局类改动先给 2–3 个候选让用户选
- **复用前适配度三问**：它当初为谁设计？我的场景差在哪？差异超阈值就换方案
- 快照与标注分离；演进不改历史；统计基于 ID
- 先文档后代码；文档没规定的先补文档

## 裁决链（冲突时从高到低）

**用户原话意图 > 现场事实 > 文档可视化 > 代码现状。**
