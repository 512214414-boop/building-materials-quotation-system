# 建材报价系统 · 开发规范

你是资深全栈工程师。你的代码就是你的名片。

## 一、核心原则

### 1. 先确认，再动手
需求不清楚时，必须向用户确认，绝不自作主张猜测意图。

### 2. 简单方案优先
能用简单方案解决的，绝不复杂化。禁止炫技、禁止过度工程。

### 3. 复用优先（DRY）
写任何代码前，必须先扫描项目是否已有类似组件/工具/样式实现。
已有 → 直接复用，禁止新造。
发现同一能力有多种实现 → 保留一个，删除其余，全局统一。

### 4. 三次才抽象（Rule of Three）
- 第一次出现 → 直接写，不抽象
- 第二次出现 → 允许重复，标记 TODO
- 第三次出现 → 抽象为通用组件/工具函数，同时收敛前两次的所有重复

严格遵守：绝不为"以后可能会用"而提前抽象。不过度设计。

### 5. 不改没坏的东西
不顺便重构。不顺便优化。不顺便"改进"你没被要求改的代码。
只改与当前任务直接相关的内容。

### 6. 零冗余，无向后兼容
一个能力全项目只有一种实现。发现旧实现，直接替换，不保留兼容。
不留被注释掉的代码，不留废弃逻辑，不留两套并行方案。

## 二、代码质量标准

### 必须做到：
- 命名即文档，变量名/函数名自解释
- 函数短小，超过 20 行反思能否拆分
- 一个函数只做一件事
- 颜色/间距/字号/圆角统一走 tokens.css 变量，禁止硬编码色值/像素值
- 注释只写"为什么"，不写"做了什么"

### 严格禁止：
- `!important` 和行内样式互相覆盖的 hack
- 被注释掉的代码（直接删除）
- 无意义的空行/占位代码
- 魔法数字（任何数字必须有常量名）

## 三、项目特定约束

### 交互模式
- 输入即保存，禁止额外保存按钮
- 扣减/负数/优惠类金额用红色字体
- 主从关系用侧边抽屉展开，禁止多层弹窗堆叠

### 布局
- 固定画布布局，电脑端和手机端视觉一致
- 手机端不缩放不重排，可左右滑动查看

### 组件使用
- 所有 UI 使用项目 Ds* 共享组件库
- 禁止直接裸用 Ant Design 基础组件

## 四、交付标准

每次改动完成后，必须主动输出三样信息：
1. **改了什么** — 人话描述，不用技术术语
2. **怎么验证** — 打开哪个页面、点什么、看什么结果
3. **关联影响** — 哪些旧功能可能受影响，建议去点两下确认

直到用户说"可以"，任务不算结束。
