# 项目架构收敛治理规范（建材报价系统）

本 Skill 是**唯一最高依据**。凡是动手写代码、改样式、加功能、重构之前，必须先对照本规范推演，确保改动与顶层逻辑闭环、不引入冗余、不破坏既有抽象。

## ⚙️ 强制执行流程（先读这里）

**每次处理任何需求，必须按 `WORKFLOW.md` 的六阶段端到端工作流执行**：

`需求理解 → 可视化确认(dynamic-ui) → 收敛自查 → 质感交付(frontend-design) → 架构体检 → 收敛重构 → 自检闭环`

**关键纪律（必须内化）**：
1. **先可视化再编码**：交互复杂/说不清的功能，先用 dynamic-ui 渲染可点击原型给用户看，得到确认后再写真实代码。
2. **交付后必做架构体检**：每次补丁式修改后，扫描是否出现"同能力第 2 种实现 / 硬编码 / CSS 冲突 / 性能退化 / 有更优重做方式"。
3. **体检命中即收敛重构**：发现架构级变动信号，暂停糊补丁，对整维度做全域收敛重构（无向后兼容、删除旧实现），而不是继续补丁。
4. **自主执行不反问**：用户已授权自主决策，能自决就自决，做完自检后交付，不逐步问"要不要做"。

完整细节见同目录 `WORKFLOW.md`。

## 一、项目基本信息

- 系统：建材报价系统（包含 staff 员工端 + customer 客户端的报价/采购/配货/对账/成本/售后全流程）
- 技术栈：前端 `frontend/`（React + Ant Design + Vite，独立 8080 端口），后端 `backend/`（Node + Prisma + MySQL，独立 3000 端口）
- 前端组件底座：`frontend/src/shared/`（styles 设计系统 + components 组件库），业务页面在 `frontend/src/apps/`
- 唯一逻辑轴心：**以已存在的顶层闭环逻辑文档为唯一设计源头，自上而下演绎，严禁自创规则、严禁简化删减、严禁折中适配**

## 二、八条顶层执行规则（强制）

1. **唯一逻辑轴心**：全程只以顶层闭环逻辑文档为唯一最高依据、唯一设计源头、唯一真理标准；所有架构/层级/结构/规则/代码从该文档设计初衷自上而下演绎推导，严禁自创规则、简化删减、偏离本源、折中适配。
2. **强制逻辑演绎补全**：顶层文档是演绎型大纲，只定义上层因果与框架。必须自动向下演绎、延伸、拆解、补全所有下层必备内容（分层规范、目录结构、文件体系、流程逻辑、依赖关系、基础设施、闭环链路），不依赖人工逐条吩咐。
3. **固定闭环循环执行流程**：本层顶层逻辑对标 → 推演细化本层完整开发规范 → 全局扫描现状差异与缺失 → 同层级全量统一整改重构 → 补全隐含必备模块与依赖 → 自检逻辑闭环 → 进入下一层级。**严禁跳层、严禁跨级、严禁无规范修改、严禁碎片化单点修补**。
4. **全域全量治理**：放弃零散局部修改，每一层级作业覆盖该维度全部内容；统一规整目录/文件/命名/分层/封装/通信/环境适配/公共底层能力；自动清理老旧结构、废弃逻辑、不符合顶层设计的遗留内容，**严格遵循无向后兼容的底层设计原则**。
5. **长任务无限自持运行**：大型全域工程重构按无间断连续执行模式推进，不主动停止、不缩减范围、不压缩深度、不省略关键基建。
6. **全链路自主补全**：主动识别架构断点、链路缺口、基础设施缺失、模块依赖缺失、环境适配漏洞，凡顶层逻辑隐含必备的全部自主补齐。
7. **完全无人干预自治**：全程自主决策、自主拆解、自主划分层级、自主把控节奏、自主校验完整性，无需阶段性确认、无需细节问询。
8. **单焦点专注串行**：同一时间只聚焦当前唯一层级/领域/任务块，完全吃透本层再切换；禁止多模块并行铺摊子、泛化浅改造。

## 三、防打补丁·全域收敛原则（本规范核心）

> 根本目标：**杜绝"每加一个功能就新开一条路、从不对照抽象收敛"的熵增**。判定标准是——**同一种能力必须只有一种实现，其余全部删除**。

### 3.1 单一信息源（SSOT）
- 同一种能力（颜色、间距、字号、半径、浮动面板、输入框、表格列宽、挂载策略）**只允许一个权威定义**。
- 任何新代码出现"第二种实现"，即为违规，必须收敛到既有权威实现。

### 3.2 无向后兼容
- 底层设计变更时**不保留旧实现做兼容**。发现废弃逻辑/旧结构/不符合顶层设计的遗留内容，直接删除而非并联。
- 不允许为了"不破坏现有功能"而保留两套并行实现。

### 3.3 统一抽象（抽象组件统一使用）
- 所有 UI 必须走共享组件库，禁止在业务页面裸用 Ant Design 基础组件或自造等价组件。
- 同一种交互模式（如行内编辑、浮动面板、下拉展开）必须复用同一组件，禁止每个页面各写一份。

### 3.4 收敛检查清单（新增/修改代码前必须自查）
- [ ] 是否复用了既有抽象组件，而非新造实现？
- [ ] 是否所有颜色/间距/字号/半径都走 CSS token，而非硬编码像素/色值？
- [ ] 是否有 `!important` / 全局 CSS 与行内样式互相覆盖的 hack？必须消除。
- [ ] 是否引入了第二套组件体系 / 第二套浮动面板 / 第二套挂载策略？
- [ ] 是否产生了与既有能力重复的实现？重复即删除。
- [ ] 是否遵守固定画布布局模式（见 4.1）？

## 四、前端具体硬性约定（当前已固化的权威实现）

### 4.1 布局模式：固定原始画布 + 容器局部滚动（v10.27）
- 整体采用固定画布，排版以电脑端调好的原始尺寸为准；移动端**不自动压缩重排**，开启局部滚动拖动查看，保证两端视觉一致。
- 核心实现：`body overflow-x: auto`；内容容器 `overflow: auto`；所有尺寸用固定 px（不用 vw/vh/% 缩放）；`flex-wrap: nowrap`；grid 列用固定 px（不用 1fr 防收缩）；`flexShrink: 0`；`whiteSpace: nowrap`。
- **严格禁止**：`@media` 改变任何尺寸/字号/布局结构、`useIsMobile` 三元切换组件树、双端渲染不同组件、vw/vh/% 缩放、flex-wrap: wrap 改变结构、grid 用 1fr/minmax 收缩列宽。
- 允许例外（仅限运行时计算）：`visualViewport.height` 算键盘弹出可用高度、ResizeObserver/滚动方向检测。

### 4.2 设计系统 token（tokens.css）
- 权威定义：`frontend/src/shared/styles/tokens.css`（radius/spacer/font/bg/text/border/status/shell 变量）。
- **所有颜色、间距、字号、半径必须引用 token，禁止硬编码色值/像素值**。状态色走 `--status-*`，禁止写 Ant 原生色（如 `#ff4d4f`、`#faad14`）。
- 骨架行高/间距/层级统一走 `--shell-*` 变量（AppShell 全局骨架 + ViewFrame 视图骨架）。

### 4.3 组件体系：`Ds*` 共享组件库
- 权威实现：`frontend/src/shared/components/` 下 `DsButton/DsInput/DsSelect/DsTable/DsDialog/DsDrawer/DsTag/DsSegmented/DsNavButton/DsNavLink/DsShellRow` 等。
- 业务页面一律复用 `Ds*`，**禁止裸用 Ant Design 基础组件**、禁止新造等价组件。

### 4.4 浮动面板：FloatPanel 为唯一基座
- 权威实现：`frontend/src/shared/components/FloatPanel.tsx`（position: absolute + portal 到 body，智能上下定位）。
- 浮动面板能力（下拉价格面板、单位切换、规格列表等）**统一以 FloatPanel 为底层**，收敛 Ant `Popover/Dropdown` 与自定义 SuggestList 等路径。
- 挂载策略统一走 `frontend/src/shared/utils/smartPopupContainer.ts`（Modal 内挂 `.ant-modal-wrap`、Drawer 内挂 `.ant-drawer`、其他挂 body），**禁止各页面手写 getPopupContainer 造第三种策略**。

### 4.5 表格：UnifiedTable 为唯一表格底座
- 权威实现：`frontend/src/shared/components/UnifiedTable.tsx` + `frontend/src/shared/components/table/`（DataViewLayer/InteractionLayer/cell-editors/colWidths）。
- 所有表格列宽必须从 `colWidths.ts` 的 `COL_WIDTHS` 预设常量获取，**禁止硬编码像素值**。
- 列宽三原则：内容决定宽度、换行优于截断（仅 name 列 `wrap:true`）、尾部弹性填充。
- 禁止通过 `!important` 打补丁覆盖全局表格样式；样式冲突要从数据层/样式层统一收敛。

### 4.6 交互模式（已固化的权威交互）
- **Excel 式即时保存**：表单输入后当场生效，无需额外保存按钮（尤其配货等手机端场景）。
- **浮动面板锚定**：点击字段触发浮动面板，面板相对触发元素定位，默认下方、空间不足切上方；不破坏行高、不影响其他行布局；约束在父容器内。
- **行内编辑**：同 CategoryManagePanel 模式，行级编辑/删除/新增按钮，Enter 保存、Esc 取消。
- **扣减类字段（整单优惠等）用红色字体**，区分订单金额计算关系。
- **一对多关系**：父级主页面 Excel 行编辑表格，子明细侧边抽屉（DsDrawer）逐级递进，禁止多层弹窗堆叠。
- **规格/分类录入**：输入框（快速检索匹配 + 唯一性校验）+ 独立下拉按钮（查看全部/切换/新增/删除），双保险。

### 4.7 前后端
- 前后端严格分离、独立端口独立服务（前端 8080、后端 3000）。
- 后端地址类型只有两种：本机回环地址（localhost/127.0.0.1）→ 前端 Node 服务代理转发；公网地址 → 前端直接请求。**绝不使用硬编码 IP 段识别规则**。
- CORS/监听地址等核心配置硬编码在代码中，仅用户相关设置进配置文件。

## 五、启动/交付 SOP

- 启动脚本：项目根目录 `dev.sh`，提供 4 种模式（reload 快速更新 / start 完整启动 / tunnel 修隧道 / stop 停止）。
- 禁止降级策略：任何环节失败立即终止输出错误日志，绝不静默降级。
- 交付必须浏览器模拟真实用户操作验证，output 三种访问地址（本机/局域网/公网）。

## 六、遇到冲突时

- 用户最新指令 > 顶层逻辑文档 > 本 Skill 约定。用户当前对话中最新指令与既有文档/规范不一致时，**以用户最新指令为准**，并按本规范收敛原则落地。
