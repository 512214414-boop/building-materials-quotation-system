# 建材报价系统 · 端到端自持工作流（唯一操作模型）

> 本文件定义**我对你（零基础、纯自然语言）开发请求的完整处理流程**。它把三个能力拧成一个闭环：
> **dynamic-ui（让你看得见） + frontend-design（交付有质感） + 收敛治理（不越堆越乱）**。
> 核心特色：**主动发现"补丁堆积 → 该架构级重做"的信号，而不是继续糊补丁**。

## 一条主线

```
你的一句话 → 我理解 → 画给你看 → 收敛自查 → 优质交付 → 架构体检 → 该重做就重做 → 自检交付
```

## 阶段 0 · 需求理解（自然语言 → 业务目标）
- 接收你的自然语言描述，自动翻译成**业务目标**，不逐字照搬表述。
- **自动补全**：你没想到、但业务逻辑必然要的（单据/权限/对账/快照/统计链路），按顶层逻辑演绎补齐，不依赖你说明。
- **不反问琐碎细节**：能合理推断就直接决定，只在真正二选一且影响大局时才让你拍板。

## 阶段 1 · 可视化确认（dynamic-ui）
- 凡是**交互复杂 / 你容易说不清**的功能，动手写代码前先渲染**可点击原型**给你看。
- 你只需说"对 / 不对，这里要怎样"，我据此精准实现。
- 目的：把你的"感觉"翻译成代码，替代你精确描述。

## 阶段 2 · 收敛自查（防打补丁·防重复）
动手前对照检查清单：
- 复用既有抽象组件（`Ds*` / UnifiedTable / FloatPanel），禁止新造等价实现
- 颜色/间距/字号/半径全部走 token，禁止硬编码色值/像素
- 无 `!important` / 全局 CSS 与行内样式互盖的 hack
- 单一信息源：同一种能力只有一种实现

## 阶段 3 · 质感交付（frontend-design）
- 用专业设计标准做**质量底线**：排版层级、间距规范、视觉克制、文案语气（"保存"不说"提交"）、空状态/报错引导、可访问性。
- **不照搬创意**：它主张的"审美冒险、特色字体"只用于真正需要表达的页面；**数据密集型业务的一致性和信息密度永远优先**。

## 阶段 4 · 架构体检（★ 核心，防"补丁堆积"）
**每次补丁式修改交付出后，我自动跑一次架构体检**，扫描是否出现"架构级变动信号"：
- [ ] 同一种能力是否出现了第 2 种实现？（组件/浮动面板/挂载策略/表格）
- [ ] 是否新增了硬编码值、CSS 冲突、`!important` hack？
- [ ] 是否性能退化？（表格未虚拟化、高开销重渲染、重复请求）
- [ ] 是否存在"用一种更优方式重做"的可能？（合并实现、降低复杂度、减少代码量）
- [ ] 是否出现了**你感知不到但长期会拖垮项目**的隐患？

## 阶段 5 · 收敛重构（★ 不糊补丁，整体重做）
- 体检发现任一"架构级变动信号" → **暂停补丁式推进**，对整维度做**全域收敛重构**。
- 原则：无向后兼容、删除旧实现、合并到唯一权威实现、清理废弃逻辑。
- **宁可多花一次重构，也不让系统继续熵增。**

## 阶段 6 · 自检闭环
- 逻辑闭环校验：数据流 / 交互 / 状态 / 边界全部走通。
- 浏览器真实用户操作验证（贴近真实使用，非静态检查）。
- 输出三种访问地址（本机 / 局域网 / 公网），交付完整。

## 运行纪律
- **不逐步问你"要不要做"**：你已授权我自主执行，能自决就自决，做完再让你看结果。
- **遇到冲突**：你最新指令 > 顶层逻辑 > 本工作流。
- **长任务自持**：一个功能从需求到交付一条龙走完，不中途停。
