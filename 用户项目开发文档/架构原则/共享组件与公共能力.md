# 共享组件与公共能力（SSOT 索引）

> **定位**：前端共享层（`frontend/src/shared/`）的**能力清单**。任何需要复用组件、函数、配置、工具的场景，**先查本清单**再动手——同一种能力只有一种实现（见《代码与工程规范》），禁止重复造轮子、禁止各页面另写等价实现。
> **权威出口**：组件统一从 `shared/components/index.ts` 导出；API 统一从 `shared/services/api/index.ts` 导出；业务页面禁止裸用 Ant Design 基础组件。
> **更新规则**：新增/修改共享能力时，同步更新本清单（代码与文档必须同步）。

### 如何查看共享组件（标识模式）

每个共享组件分配**稳定编号（C01+）**，开启**标识模式**后**全量直接显示，无需拾取**：

- **开启方式**：任意页面右下角「c」圆形按钮（点击变黄「C」即开启，再点关闭；开关状态本地记忆）
- **显示形式**：每个共享组件实例被绿色虚线框框住（body 最顶层浮层，弹窗/抽屉内组件也完整标识、不被遮罩压暗、不被容器裁切），并直接显示编号——
  - **叶子组件**（内部未嵌套共享组件，如按钮/输入框）：编号以**居中水印**显示在元素上——**红底白字粗体**（#F65A5A 红底 + 白字 + 加粗 + 白描边），辨识度最高，页面背景再深再花也清晰可读；不占布局、不遮内容
  - **容器组件**（内部嵌套了共享组件，如骨架/表格/抽屉）：编号显示在**框内左上角小标签**（同红底白字），与内部子组件的居中水印天然错位 → 大组件套小组件不会互相遮盖
- **同编号 = 同一共享组件**：界面多处出现 `C01` 水印 = 它们用同一个共享组件；右下角**聚合清单面板**还列出 `编号 · 名称 × 实例数`（按实例数降序）汇总
- **定位具体实例**：点击清单某行 → 该编号全部标识**琥珀黄呼吸高亮**，再点取消（非必需，仅辅助定位）
- **聚焦同类**：点击页面上的某个编号标识 → **只显示该编号的全部实例（同类都留），其余编号全部隐藏**（琥珀黄呼吸高亮），一眼看清这个共享组件被复用在哪些地方；再点同一标识或按 **ESC** 恢复全部显示
- **悬浮任一元素** → 显示 `编号 · 中文名` + 分组
- **判断标准**：界面元素带框和编号 = 已抽象共享组件实例（哪怕只是一个小图标按钮）；不带 = 未抽象，可考虑抽象后复用
- **沟通方式**：说「C05 标签」/「C20 价格展开面板」即可精确定位，无需贴代码路径
- 纯逻辑层（无 DOM 根，如 `InteractionLayer`/`RecordFieldColumn`/`SkuPriceColumns`/`PermissionGuard`/`SaveStatusProvider`）无法在界面标记，表中以「无独立 DOM」注明

## 六、快速新建 + 自动补充确认（v15.x 核心能力）

> 这是「缺省值兜底 + 按值去重 + 保存前确认」的统一机制，**所有涉及自动补充的保存路径必须接入**。

| 编号 | 模块 | 用途 |
|------|------|------|
| C30 | `QuickCreateConfirmDialog` | 快速建档弹窗（字段分开编辑 + 缺省确认 + 相似档案候选决策） |
| C31 | `DefaultFillsPreview` | 保存前「完整档案字段清单」预览（分层展示字段 + 自动补充标记） |
| — | `confirmFillsBeforeSave` | **统一自动补充确认入口**：有补充项 → 弹确认；无 → 直接放行·无 UI |
| — | `quickCreateConfig` | 配置 SSOT：数据层注册表（产品信息层/价格信息层）+ 字段兜底值 + 去重键 |

### 去重键规则（A/B 两类，前后端同构）

- **A 类全局字典**（分类/品牌/价格类型/供应商）：`name` 全局唯一 → 纯名称去重
- **B 类父级从属**（产品/规格/单位）：父级 id + 名称唯一 → 必须携带父级上下文，不能纯名称去重

### 如何接入「自动补充确认流程」（标准步骤）

> 场景：某保存路径涉及缺省值自动补充（如"没选价格类型就补零售价"），要求保存前提示并确认。

```tsx
import { confirmFillsBeforeSave } from '...shared/components/index.js';
import { QUICK_CREATE_LAYERS } from '...shared/config/quickCreateConfig.js';

// 1. 从配置层取兜底值（禁止硬编码"零售价/面价渠道"等文案）
const priceLayer = QUICK_CREATE_LAYERS.price;
const priceTypeCfg = priceLayer.fields.find((f) => f.key === 'priceType')!;

// 2. 检测本次保存是否有自动补充项
const saleNoTypeCount = salePrices.filter((p) => p.price.trim() && !p.priceTypeId).length;
const notes: string[] = [];
if (saleNoTypeCount > 0) notes.push(`售价 ${saleNoTypeCount} 行自动补充价格类型「${priceTypeCfg.fallback}」`);

// 3. 保存执行前统一确认（无补充项会自动放行，不打扰）
const confirmed = await confirmFillsBeforeSave(modal, { groups: [], notes });
if (!confirmed) return; // 取消 → 不保存

// 4. 确认后执行真正保存
await saveProduct(input);
```

**规则**：任何保存路径（手动/失焦/静默触发）只要涉及自动补充，保存执行前必须走 `confirmFillsBeforeSave`；补充文案的兜底值一律来自 `QUICK_CREATE_LAYERS`，禁止硬编码。

## 附：新需求接入流程（防重复造轮子自查）

1. **查本清单**：需求能力是否已有共享实现？有 → 直接复用，禁止另写。
2. **无共享实现** → 先在 `shared/` 落地为共享能力，**同步更新本清单**，再在业务页面引用。
3. **不确定归属** → 按清单目录归类（组件→components/、配置→config/、工具→utils/、状态逻辑→hooks/、算价→engines/）。
