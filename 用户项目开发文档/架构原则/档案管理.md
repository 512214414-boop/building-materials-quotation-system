# 档案管理

> **职责**：所有基础档案（产品 / 供应商 / 库房 / 客户，以及以后新增）**应该怎么做**。这是全局规则，不是某一页的私有说明。
> 顶层依据：详见《项目设计哲学·约束2 / 约束4》《顶层设计规范·理念4 / 理念8》。
> 关系怎么画、各档案五段填空：仓库根目录 `文档可视化/` 侧栏「档案管理 · 全局规则」与各档案页。
> 字段下拉如何从关系推导：详见《实体关系面板体系》。表格铁律：详见《表格与交互规范》。
> 各功能文档只写**这棵树的表**和**本页私有差异**，禁止再写一套「档案应该怎么做」。

## 全文结构

```
├─ 一份档案五段
├─ 两套检索
├─ 选用检索
├─ 管理界面
├─ 点值改库
└─ 新增档案
```

## 一份档案五段

任何档案都走同一条推法。侧栏每个档案页就是这五段填空，不是五种互不相干的页面。

| 段 | 回答什么 | 推什么 |
|----|----------|--------|
| 出发点 | 这份档案为哪一类活备弹药 | 指向指导思想对应环节（作业或「货和人怎么存在」）。缺了这一段，检索就会做成「有表才搜得到」 |
| 要支持到 | 经营上必须同时成立的事、不能串的事 | 必须拆到哪一层 |
| 关系 | 名单 / 挂载 / 这一行自己的数 | 表怎么挂、谁改名全局生效 |
| 管理界面 | 这棵树摊平之后怎么管 | 列表列、表头筛、子表 ▾、点值改库 |
| 选用检索 | 开单或引用处怎么从这棵树上取一条 | 存字的层放进模型，顶栏自动出宽松+精准。切档是换看法 |

产品档案的出发点：为销售开单备弹药（开单混写、存储分层）。柜台为什么一格跟着嘴走、没货为什么打电话：正文以 `文档可视化/`「销售开单」为准。货怎么分层、点位圈组：正文以可视化「货和人怎么存在」为准。客户档案的出发点：问到名字或电话就写在单上，不必为此建档；建档是给以后还要找这个人、以及按人看数。售后对着已经卖掉的行去对：正文以可视化「售后」为准。本页五段只写这份档案怎么拆、怎么管、怎么选用。可视化还没写到的细则，才看本文件其余节。

不要从界面按钮倒推表。少写一条「出发点 / 要支持到」，后面的表和检索就会假。新档案先把五段写清，再动页面。

## 两套检索

两套不要合成一个框。

| 套 | 用在哪 | 打法 |
|----|--------|------|
| 管理筛 | 档案列表页 | 关键词独立框 + 表头按列收窄 + 右侧状态下拉。禁止查询/重置按钮，禁止一个框兼所有列 |
| 选用检索 | 开单 / 引用格子 | 点格进确认层（空词也开）。表格格只展示。输入+下拉挂在确认层输入框（默认展开，可收起）。顶栏切入口。dateFilter 开则带按日翻 |

管理筛是「在已经摊平的表上收窄」。选用检索是「从树上取一条（宽松或某一层精准）」。产品列表怎么筛，详见《表格与交互规范》；开单怎么选，详见本节「选用检索」。

## 选用检索

选品不是产品私有面板。所有档案最终都通过选用检索被使用。管理页的 `slots[]` 是这棵树摊平后的列/弹窗；选用检索是同一棵树的另一插槽：只配存字的层，顶栏由模型派生。

| 模式 | 从树怎么来 | 打哪些字 | 结果粒度 |
|------|------------|----------|----------|
| 宽松 | 多层才出 | 当前这棵树能打到的字并成横表（可另并编号/标题这类钉在主体上、不单独切层的身份字） | 仍是这次要取的主体（一个客户 / 一家供应商 / 一个产品 / 一张单） |
| 精准 | 每一层存字的层一颗按钮 | 只打这一层 | 跟这一层走（产品切到规格就是规格行）；客户/供应商切到子表，回填仍是这个人/这家 |

- **一层**不出宽松。**多层**默认宽松；产品默认停在「名称」（认货最常用的精准层，避免国标从规格备注刷出一大片）。不知道打在哪一层再切宽松。
- **同一格子同一串字**。切档不改字。切档是换看法，不是把关键词裁成只剩这一层。
- **包含与被包含**。字段在输入里，或输入在字段里，都算中。词比字段长也要中。
- **到那一层有什么就搜什么**。不要按词做黑名单。产品名里写了「国标」，名称层就能搜到；「国标」只写在规格备注里，精准要到执行标准层——宽松也能中。
- 点顶栏：词还在确认层输入框里，立刻按新入口重打。不清字、不关面板。
- 切档后列顺序：入口层最左，其余已经走到的层各占一列。禁止把产品名/品牌叠成规格列上方一行灰字。说明默收起：档位一排宽度不变；再点当前档或顶栏右侧 ?，在按钮下方展开一行。列顺序、验收词以 `文档可视化/` 为准。
- 单据格已经锁到哪一层（名称列 / 单位列 / 单价列）和面板打在哪一层是两件事。单位列、单价列已经锁规格，不出现入口切换。
- **配货来源是两枝**（内部仓 / 供应商），不是一层层切，不要套宽松+精准。
- **不能从树推的私有**仍写在各面板：产品列顺序/brandN、渠道档=已进价∪经营范围、客户点中后挑一条联系、单据按日翻单预览、选品插入 vs 点行回填。
- **工作台选用格点开确认层**：产品名/单位/单价、客户信息、售后单据格/已卖行，以及数量/备注，点一下进入确认层（空词也开）。表格格只展示、不挂下拉箭头。要打字就在确认层输入框。选用检索挂在这只输入上。点空白=取消，不写。确认才 commitCell。细则见可视化「订单中心 · 全局规则」。

写入当前行只走插入；点格子改的是档案。细则详见《实体关系面板体系》。

## 管理界面

本页列表是关系树摊平，不是另一棵树。

- **名称列是主标识**：每个档案必须有。点击打开范式 B 弹窗，弹窗内是该主体**全部字段**（标量点值确认 + 一对多矩阵，末尾空行可追加）。列表上的 ▾ 是同一子表的快捷入口，不能把子表只放在 ▾、弹窗里没有。产品名、供应商名、库房名、客户姓名都走这一槽；不要写成「有的点名称弹窗、有的只行内改几个标量」。
- **运行时宿主**：供应商 / 库房 / 客户把关系树摊平后的字段写成 `slots[]`，交给 `ArchiveSlotHost`。名称弹窗、N 矩阵、点值、检索由宿主渲染。`ArchiveListPage` 只是壳。不要再为每个管理功能抄一份同构页面。产品宽表暂不迁。
- **禁止业务编码**：身份只用数据库主键。不要再给人填仓库编码、客户编号之类。P-002 覆盖所有业务档案。角色代码、授权码除外。
- **N 必须能追加**：关系树标了 N，界面就是可追加矩阵。禁止主档一个输入框顶替 N；列表摘要可以拼接或显示默认，不能看起来像只能填一条。
- **N 矩阵列跟这一层字段走**：有默认才出默认列，有值/价格/联系方式才出值列。单字段 N（库房区位只有名称）= 名称列 + 删除 + 空行追加。不要因为「和地址同构」就把售价/联系人的价格列、默认列硬套进去。`MatrixTable` 用 `showPrice` / `showDefault` 关掉，不要另写一张表。`sortOrder` 跟行序，不占格子。
- 关键词、表头列筛、状态、勾选、批量是共用规则，禁止各页另写检索条。
- 可按列收窄的列，筛做在表头：点选是标准条件，失焦手输是非标条件，两种都升到关键词旁，两边擦同步。选项来自当前结果，不是全局字典 dump。
- 列形态由数据决定：名称走主标识弹窗；其它标量点值或弹窗内点值；一对多走 ▾ 子表（与弹窗矩阵同一组件）。不要为单列发明第二套交互。
- 各页只写差异：列字段、子表长什么样、这棵树存字的层（顶栏由模型派生）、真正并入不了的私有（如经营范围双栏）。名称弹窗、无编码、N 可追加、宽松/精准按钮不是私有。

## 点值改库

凡改库的字段：格子只展示 → 点开确认 → 确认才写。禁止在弹窗或矩阵里挂常驻输入（逐键刷新会跳格、挡住贴格面板）。

开单单据行不再除外：和档案值同一套点值确认层，确认才写、取消不写。浏览用的筛选框不是改库字段。订单中心槽位见可视化「订单中心」。

确认修改默认只改当前这一条；名单类（单位 / 品牌 / 分类等）可改全局并到已有档案。点位改全局按圈组，已经单独改过的规格不跟着变。确认层原值/新值用卡片对（原弱、新强、中间 →），不要「」包成一句。详见《实体关系面板体系》。

## 新增档案

按序对照，缺一步就容易各页各写一套：

1. 写清五段（出发点 → 要支持到 → 关系 → 管理界面 → 选用检索）。关系树标了 N，后面界面就必须是可追加矩阵；矩阵列跟这一层字段走，单字段 N 不要套默认/价格列。
2. 把这棵树摊平后的字段写成 `slots[]`，交给 `ArchiveSlotHost`（名称弹窗、N 矩阵、检索自动出）。不要再抄一页管理文件。
3. 不要业务编码列。改库字段走点值确认。
4. 若开单/引用处要按这棵树取一条：把存字的层放进选用检索模型（同一棵树的另一插槽）。顶栏自动出宽松+精准。禁止手写一遍按钮，禁止另写面板。配货来源两枝不要套这套切层。
5. 只写本树私有差异；先改《档案管理》和可视化「档案管理 · 全局规则」，再改该档案五段。
