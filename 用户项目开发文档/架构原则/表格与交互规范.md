# 表格与交互规范

> **职责声明**：本文档是数据怎么被操作（显示/录入/编辑/浮动面板/组件抽象与复用/枚举字段组件选用）的唯一依据。表结构与字段定义见《数据规范》；缺省值定义见《数据规范·缺省值注册表》，本文档只引用不重复；画布与令牌见《视觉与布局规范》；三范式、常驻输入框、操作列首列等顶层理念见《顶层设计规范》，本文档只写展开规则。

## 表格唯一

表格是业务信息的直接操作面——一列一条完整信息、点开见全部、改动即生效、同质同一形态。统一表格组件 = 三层架构的组合体实现（内部组合显示层+交互层，对外统一接口），业务页面属交付层：

| 层 | 职责 | 强制约束 |
|----|------|---------|
| 显示层 | 纯渲染：行列单元格、虚拟滚动、分页、固定列、排序、筛选、空行填充 | 零编辑态 / 零输入渲染 / 零业务回调 / 行高固定 / DOM 可控 |
| 交互层 | 常驻输入框、编辑态（焦点失焦切换）、键盘导航、失焦保存、面板触发器 | 常驻输入框 / 编辑态零挂载卸载 / 零业务逻辑 / 零后端调用 / 行回收自动提交或取消 |
| 交付层 | 业务：面板内容、提交后端、乐观更新、空行升级、业务条汇总、实时刷新 | 零显示层侵入（回调注入）/ 零交互层侵入（注册表注入）/ 事务快速新建 / 失败显式回滚 |

### 固定列宽规则（内容不参与列宽计算）

- **列宽 = 设计值**：列宽永远等于该列设计值（按该列常规最长内容信息承载推演定宽，各字段独立推演不套死档位），任何内容（文本态/编辑态/超长内容）都不改变列宽——固定布局（`tableLayout:'fixed'`），杜绝「文本态被内容撑开、编辑态回落」的列宽跳变。
- **名称类列 = wrap 换行列**：固定宽度 + 自动换行，超长内容完整可见、行高自适应——信息永远完整，绝不省略号截断（完整呈现）。
- **其他数据列**：固定宽度 + 不换行 + 溢出裁切兜底——绝不以撑开列宽为代价换完整显示。
- **内部控件不得反向改变单元格尺寸**：编辑态输入控件撑满原本内容区（与文本态显示区一致）、辅助图标（清空/箭头/收起）悬浮叠加在单元格边缘不占流式宽度、输入控件不带额外内边距/边框改变视觉宽度——状态转换前后列宽不变。
- 次要长文本（备注/描述）摘要 + 点击展开；重要长文本（名称/地址/单号）给足宽度全显示。

### 性能分级（数据量决定策略，不过度优化）

10 万级只读检索 → 后端分页+虚拟滚动；千行级编辑 → 前端全量+虚拟滚动+分页（默认每页 13，可选 10/20/50/100）；百行级档案 → 前端全量+分页；十行级子表 → 前端全量即可。

## 录入交互

- **常驻输入框**：可编辑单元格始终渲染输入控件，无文本态↔输入态切换——列宽不抖。
- **状态转换不影响原本大小**：文本态↔编辑态切换时单元格/列宽保持不变（规则见「固定列宽规则」），辅助反馈由单元格光晕统一提供。
- **失焦/关闭即存**：行内失焦/回车/Tab 即提交；面板内改动本地累积、关闭面板统一落库（一次面板 = 一次事务）。
- **原子更新**：内容真正变化才提交——没变化不提交，不产生冗余保存。
- **末尾完整空行**：表格/矩阵末尾始终保留空行，且必须是「完整空行」（所有可编辑列都渲染输入控件）；名称列输入有效值 → 回车自动追加新行；无效输入清空但空行保留——想敲就敲，不用点「新增」。
- **键盘导航**：Enter 提交+下移 / Tab 右移 / Esc 回滚 / 方向键移动——手不离键盘。
- **数字列禁用原生数字控件**：统一普通输入框 + 数字键盘（原生控件光标跳、滚轮误改），等宽字体 + 右对齐。
- **操作列固定首列**：操作是最高频动作，必须固定第一列、始终可见，禁止放表格末尾（字段多时整行很长，放末尾等于每次操作先翻到最后）。
- **扣减类字段红色**：整单优惠/抹零/行优惠用红色 + 负号前缀——与加项一眼分清。
- **基础数据管理页必须行内直接编辑**（供应商/客户/分类/单位）——看到不能编辑还要去弹窗，编辑效率为零。
- **关系表字段强约束 + 价格字段无约束**：档案字段（产品/单位/供应商…）填入值必须已存在档案，否则提示新建补全，禁止脏数据；价格字段可直接手输修改，仅更新当前行、不强制写回档案（价格频繁变动，写回会污染档案）。
- **录入宽松、保存透明**：前端不做输入框必填限制（先录主要后补次要）；保存时收集「未填必填项 + 将自动补充的缺省值」清单弹确认框——确认按补全后保存，取消返回继续编辑。缺省值由《数据规范·缺省值注册表》统一登记，前后端同一套映射。

## 三种交互范式

| 数据形态 | 范式 | 触发 | 展示形态 |
|---------|------|------|---------|
| 主体单字段 | **A 行内编辑** | 单元格点击 | Excel 样式表格，行内直接编辑；关联字段面板内「检索+选择+新建」，不离开主表 |
| 同一主体多维 + 交叉矩阵 | **B 编辑弹窗** | 点击主体全名列 | 弹窗内业务区块并行（非下钻），矩阵化，矩阵单元格直接编辑；弹窗内不再嵌套弹窗，事务一次提交 |
| 父 + 独立子实体列表 | **C 下钻** | 点击子实体计数列/父名下钻 | 同一页面区域**整页重渲染为子表格**（非抽屉非弹窗），顶部上下文栏（业务名不显示 ID）+ 可回跳面包屑，子表同样行内编辑 |

**判定流程**：先判断是否为父+独立子实体（线性一对多）→ 是则 C；否则是否多个一对多+交叉矩阵 → 是则 B；否则 A。

**边界红线**：B 与 C 不可互相替代——同主体多维属性用 B，父-独立子实体用 C。三种范式可同一模块组合使用。

**状态管理边界**：B 的弹窗开关状态与 C 的下钻层级状态（联合类型，每层携带父级上下文）互不混用；C 内禁止用抽屉/弹窗/遮罩实现层级切换，多层级逐层下钻、同一时间只显示一层。

### 分支场景

- **树形自引用**：树形表格展示（子节点缩进、可展开收起），行内编辑，新增子节点自动挂到当前展开的父节点下。
- **全局扁平视图**：层级深度 ≥ 3 的模块必须提供扁平视图 tab（全局治理、批量核对、数据完整性检查）。

### 通用约束

- **底层数据库**：保持多表 ID 关联，不因 UI 表格化改成单表存储文本。
- **ID 不可见**：页面只展示业务文本名称，UI 永不展示数据库 ID（例外：客户档案页可显式展示 ID 列便于人工核对）。
- **基础字典独立档案页**：分类/品牌/供应商/客户档案保留独立档案管理页（数据核对、批量治理、跨业务复用），不可仅依附于业务子表。
- **行内自动新增档案**：行内输入全新名称 → 后端自动新增字典档案并绑定 ID；关联字典字段 = 「下拉选择（已有）+ 自由输入（新增）」。
- **快速新建「先存后用」**：先建档案拿 ID 再挂关联（事务）——禁止先建临时对象再批量落库；权限遵循《权限与职责规范》。

### 公共交互底座（服务所有范式的通用规则）

- 录入宽松、保存透明（见「录入交互」）。
- 关系表字段强约束 + 价格字段无约束（见「录入交互」）。
- 数字列禁用原生数字控件（见「录入交互」）。
- 更多菜单列统一第一列（固定），内容 = 下方插入 / 删除（二次确认）/ 视图特定动作。
- 扣减类字段红色（见「录入交互」）。
- 浮动面板（见「浮动面板」）。
- 快速新建「先存后用」+ 权限遵循《权限与职责规范》。

### Excel 超级表格（录入的终极形态）

- 录入不再用「弹窗表单 + 添加物料」，改为**分页器 + 末尾空行**：每页数据行末尾自动追加空行（至少 1 个），点空行直接录入、录入完成自动落库；连续录入无需手动添加；翻页空行销毁、新页重新生成；页大小可切换（默认 13，可选 10/20/50/100）。
- **快速新建全局化**：凡有下拉匹配的地方，列表第一行永远是「[+] 快速新建: [输入内容]」，不管有没有匹配结果；最小必填（名称类），其他信息后续在档案页维护。

## 浮动面板

- **非模态**：失焦不关、支持嵌套、手动关闭。
- **相对触发元素定位**：下方优先、不足切上方；**水平左对齐锚点、不做边界避让**——面板在画布中什么位置就是什么位置，超出视口由用户滚动查看（画布基准见《视觉与布局规范·画布模型》）。
- **嵌套互斥**：父关级联关子、子触发器阻止冒泡。
- **列表与编辑弹窗共用同一面板组件**（同质同构）。
- **面板宽度分治**：集合弹窗（多列矩阵）可拉伸；单功能编辑面板必须紧凑——禁止无意义拉长。

## 数据补全

录入是渐进的，系统来补全，且补全不污染业务。**用户只填此刻知道的最小必填信息，其余系统补全**。四层补全逻辑：

```
├─ ① 占位兜底：可缓必填字段用占位默认值（示例：规格→通用、单位→件；完整清单见《数据规范·缺省值注册表》）
├─ ② 推导计算：关联数据由既有数据推导（未录单位价→基准价×换算率；进价=面价×点位），推算不写库仅展示
├─ ③ 快速建档：使用处提供快速新建入口，边用边补全档案（走档案标准接口、事务创建）
└─ ④ 预置快速选项：高频率枚举值面板底部提供快速选项条，点击直接填入——抽象为通用配置参数（不传不渲染）
```

**补全边界（强制）**：占位值必须可辨识（不伪装成真实数据）；推导值标注来源；真正必填的只有关联 ID，展示类字段一律可空。

### 输入辅助：什么时候给「检索 + 快速新建」

**是否启用「检索 + 快速新建」辅助，由字段的录入特征决定，不靠拍脑袋。**

```
├─ 启用 ⟺ 录入场景 且 满足任一：
│   ├─ ① 字段值有复用价值（历史可复用：单位「米」、规格「dn25」）
│   ├─ ② 关联字段需要选 ID（分类/供应商/价格类型）
│   └─ ③ 有标准化需求（分类名、单位名）
├─ 不启用 ⟺ 筛选场景（只过滤展示）· 无复用价值的即时输入 · 唯一性强的标识 · 数字/日期
├─ 检索方式四种（按场景选）：
│   ├─ 单字段检索：单字段录入（分类/供应商/单位/规格…）
│   ├─ 父实体下全量加载 + 本地过滤：已知父实体时加载其下全量子集（如某产品的全部单位）
│   ├─ 专门的多列检索：复杂结构化数据（如 SKU 检索，多列展示多字段回填）
│   └─ 混合列表选择：值来源多个表且数据量有限
└─ 快速新建三条件（全部满足才启用，否则降级）：
    ├─ ① 关联字段（需先建档拿 ID）
    ├─ ② 关联表能独立建档（不依附父实体）——依附父实体的随父事务创建（如单位）
    └─ ③ 建档只需名称单字段——需要多字段的走独立选择器（如产品）
```

**组件形态分层**：表单字段用「常驻输入框 + 检索 + 快速新建」；表格单元格用「点击触发浮动面板」；业务页面按场景选用。具体字段的启用判定（哪些字段快速新建、哪些仅检索、哪些随父事务）由各功能文档定义；关联字段的引用编辑统一走档案引用组件，档案按名称唯一复用见《数据规范》。

## 组件抽象

**一条总原则 → 五个侧面**：

> 先向上抽通用基座，再向下适配业务差异化——所有固定结构锁死在基座，业务差异全部做成配置参数。

| 侧面 | 内容 |
|------|------|
| 抽象顺序 | 横向拉通全业务提取通用能力/固定结构/统一交互 → 封进基座（全局锁死）；业务差异做成可选配置（开关/排序）——严禁为单业务特例改基座 |
| 基准唯一 | 产品管理模块是唯一基准原型，所有后续模块同类组件完全对齐基准（按钮位置/尺寸/样式照搬），仅业务独有字段靠参数区分；基准自身也接入公共基座，杜绝「基准手写一套、其他页面另一套」 |
| 拆分粒度 | 按功能原子拆分（弹窗外壳/单选内核/列表内核/操作按钮组/拓展模块），参数自由拼装——绝不按业务场景拆（单位组件/价格组件/联系人组件各做一套） |
| 迭代方式 | 一处修改全域生效：通用逻辑只改源头一份；业务适配问题优先调配置参数，绝不写补丁代码；配置无法表达才新增拓展模块，不侵入基座 |
| 边界划分 | 全局固定层（基座）不可挪动/不可改位置；业务可变层（字段/拓展）可配置。允许配置：绑定表/字段映射/功能开关/展示条数；绝对禁止改：控件布局/按钮位置/弹窗层级/开闭方式/换行规则/默认生成逻辑/枚举增删交互 |

**四铁则**（抽象动作的验收标准）：

- 拆解抽离即对齐：封装出的组件与基准完全一致——不精简、不私自改版、不简化功能。
- 基准自身同步替换：抽象完成 → 基准页面立即改用公共组件，禁止两份代码并存。
- 同构必复用：「同质同构」 = 复用同一份实现，绝不是「重新实现一个一模一样的组件」。判断：形态一致 → 先找共享组件的配置扩展点；确实无法表达才新增抽象，且新抽象必须收进共享层。反面教材：为品牌/供应商/分类各写一份同构管理面板——收敛为单一配置驱动组件 + 集中配置。
- 一处修改全域生效：只改公共组件一处源码，所有引用页面同步更新。

**两种禁止模式**：① 基准保留手写、另封装一套给其他页面 → 两份同源代码必跑偏；② 同类场景不调公共组件、独立重写 → 冗余且参差。

**自检三问**：该功能是全场景通用能力？→ 写基座。仅单业务需要？→ 做成配置开关。改了固定布局？→ 无全局理由即驳回。

### 枚举字段：结构的两种形态

**枚举字段** = 选项限定在固定集合内的字段（字典关联/布尔状态/固定枚举）。按两个结构维度归入两类组别，**不随意新增组别**（新增只发生在组别内部条目）：

- **维度一·上级依附**：所在最小行数据单元内是否存在其他前置枚举作为载体？有 → 嵌套组。
- **维度二·下级承载**：选中后其下是否可挂多条子数据？可 → 嵌套组；不可 → 基准组。

**判定靠结构特征，不靠命名、不靠场景**。同一组别交互/操作/结构完全统一，只靠配置参数适配不同业务表：

| 组别 | 结构特征 | 共享形态 | 对标业务 |
|------|---------|---------|---------|
| 基准组 | 无上级依附、无下级多子数据 | 行内输入框（实时检索）+ 侧边按钮展开管理面板（检索/选用/新增/编辑/删除），枚举存独立数据表 | 产品分类、价格类型、供应商通讯方式 |
| 嵌套组 | 有上级依附 或 可挂多条子数据 | 结构化矩阵面板：上下级绑定、多行子数据增删改查、行内编辑、默认标记、末尾常驻空行 | 产品单位（下挂售价/进价）、售价/进价明细 |

**通用约束**：同组别全程一致（外壳/层级/开闭/滚动/交互），业务差异仅靠入参；通用行为同样封装（如「主体名称点击唤起全量编辑弹窗」全表统一）；新增枚举用双维判定归入已有两组，禁止私自开发新面板；面板内通用配置（切换显示解耦/条目排序/完整空行/快速选项）遵循本文档第二层权威定义，不重复制定。

## 反模式

每条反模式标注它断掉了哪条链：

| 反模式 | 断掉的链 |
