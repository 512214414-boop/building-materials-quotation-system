# 权限与职责规范

> **适用**：设计或修改任何权限控制（可见性/三段式/权限集）、前后端职责切分（谁算/谁存/谁把关）。做权限前先读本文档。
> **定位**：全系统权限控制与前后端职责域的**知识库条目**。只讲跨功能通用规则，不写实现细节（登录路径、接口由代码承载，见[文档编写规范](./文档编写规范.md)）。
> **顶层依据**：项目设计哲学（约束 1 用户不懂代码、约束 3 算力有限、原则 2 分层隔离、原则 3 操作不被打断）。

---

## 全文结构（一眼看全貌）

```
用户不懂代码（约束1：按钮藏起来就找不到入口，还会以为功能没了）
  ↓
可见性原则：所有按钮对所有人显示，无权限时给提示
  ↓ 写操作怎么执行
三段式：前端入口展示 → 前端无权提示 → 后端拒绝（最后一道防线）
  ↓ 权限从哪来
导航层级 = 权限树 → 权限集（按导航层级 + 操作类型组合）→ 角色勾选 → 账号取并集
  ↓
笔记本算力有限（约束3：谁离用户近谁算）
  ↓
前后端职责：前端负责即时反馈与体验，后端负责存储、校验、把关
```

## 权限设计：从"用户不懂代码"推导

### 可见性原则

- **所有页面与功能按钮对所有账号开放**：废除"可见不可见"控制，按钮一律显示，不因角色隐藏。
- **无权限时显示统一的无权限提示**：用户点击无权操作时，前端给出提示，后端拒绝写操作。
- **理由**：按钮藏起来 = 用户找不到入口、以为功能丢了；让用户清楚知道"这个功能存在但我无权使用"，便于申请权限或联系管理员。

### 三段式权限执行模式

所有写操作按三段式执行，**前端管体验、后端管底线**：

| 阶段 | 行为 | 为什么 |
|------|------|--------|
| 前端入口展示 | 按钮永远显示、可点击（不置灰、不禁用），进入页面正常拉取数据展示 | 操作不被打断（原则 3）；不因无权限挡住入口 |
| 前端无权提示 | 点击无权按钮时前端先校验权限（基于登录时拉取的权限集），无权限则提示「无权限：请联系管理员开通 [权限名]」，不进入下一步 | 给用户即时、明确的反馈 |
| 后端拒绝写操作 | 即使绕过前端直接调 API，后端必须再次校验并拒绝（返回无权限错误），前端收到后提示用户 | 最后一道防线——前端提示可以绕过，后端必须兜底 |

### 权限集原则

```
├─ 权限集生成：根据导航路径定位功能模块，按导航层级生成树形权限集（如「产品管理.新增」「产品管理.删除」）
│   └─ 权限项粒度 = 导航层级 + 操作类型组合（查看 / 新增 / 编辑 / 删除 / 审核）
└─ 角色定义：管理员创建角色 → 每个角色自由勾选权限集组合 → 一个账号可关联多个角色，权限集取并集
```

### 只读权限的特殊处理

- 只读权限账号仍可改数预览即时算价（失焦/防抖不落库）——预览体验不因权限打折。
- 主动写操作时提示「只能查看」。
- 数据展示与有权限账号一致。

### 权限项清单的归属

本文档只约束权限设计的通用模式，不展开具体功能的权限项清单——各功能文档自包含定义本功能的权限项，与三段式执行模式配合使用。

## 前后端职责：从"笔记本算力有限"推导

### 总则

门店一台笔记本兼作服务器与终端，多设备同时访问。性能预算按笔记本封顶：**能放前端的计算尽量放前端；后端只做必要的存储、校验与广播。** 依据：项目设计哲学约束 3——算力往前放：谁离用户近谁算、谁有闲算力谁算，后端只做最后把关和存数据。

### 前端负责（离用户近，负责即时反馈与体验）

```
├─ 界面与交互、路由与导航记忆、乐观更新
├─ 实时算价与毛利等即时反馈——改价即见结果，不回打后端重算
├─ 表单校验体验、防抖合并提交、本地缓存与索引检索
├─ 权限入口体验（无权限/只读提示）；写操作仍提交，最终以后端为准
├─ 表单即时算价：改数量/单价/税率等界面立刻重算（哪怕当前无写权限、结果存不了）
└─ 实时通道增量消费与断线重连
```

### 后端负责（最后把关，只做必要的事）

```
├─ 认证授权、权限最终校验
├─ 持久化、事务、并发控制、必要业务规则校验（如超退、状态合法性）
├─ 接收前端算好的结果并校验后落库（不做全单据重算引擎）
└─ 实时通道广播、文件与审计、统一接口
```

### 不做清单

- 服务端不承担实时算价、大范围重计算、为每个按键开事务。
- 不为「多门店高并发」设计；以单店约 50 人在线为上限。
