# 视觉与布局规范

> **适用**：设计或修改任何页面的画布模式、骨架结构、行盒子参数、移动端适配。调布局前先读本文档。
> **定位**：全系统视觉与布局域的**知识库条目**。只讲跨功能通用规则，不写实现细节（CSS 类名、具体样式代码由代码承载，见[文档编写规范](./文档编写规范.md)）。
> **顶层依据**：项目设计哲学（原则 1 复用优先、原则 4 双端一致）→ 顶层设计规范（理念 1 画布固定、理念 2 骨架即规范、理念 5 行内元素统一）。
> **关联文档**：导航层级与底栏见 [导航与路由规范](./导航与路由规范.md)；编辑范式与浮动面板见 [表格与交互规范](./表格与交互规范.md)。

## 全文结构（一眼看全貌）

```
画布模型（唯一轴心 · 自上而下一切规则的源头）
  ├─ 元素大小 = 真实物理大小：只相对画布计算，绝无任何相对屏幕/视口的计算
  ├─ 设备屏幕 = 可视范围：电脑看全貌、手机看部分；超出部分 = 移动画布查看
  ├─ 画布缩放 = CSS zoom 统一缩放：任何设备同一套，固定步长 + 界面底部固定按钮，
  │   画布变多小内部所有元素同步变多小
  └─ 稳定性：元素看到多大就是多大——状态转换（编辑/激活/展开）不改变原本大小
    ↓
布局框架（画布内的骨架）→ 行盒子统一 → 令牌 = 唯一参数源
    ↓
交互浮层（画布为基准）：独立模态画布居中 / 定位浮层锚定原位 / 消息通知顶部
    ↓
壳子常驻、内容替换（换单据/换视图不整页卸载，点一下就要有反馈）
    ↓
移动端本质 = 画布物理大小 + 小可视范围（等比缩小版：格局不变 + 横向滚动 + 压缩密度）
```

## 画布模型：界面 = 固定物理大小的画布

**顶层定义**：整个项目界面是一块**固定物理大小的画布**，画布在不同设备、不同大小的屏幕上，显示效果、布局、交互弹窗**完全一致**——界面和界面内的元素大小永远是**真实物理的大小**，**没有任何相对屏幕计算的大小**；所有计算依据只能是**画布的相对值**。

把不同设备/屏幕理解为设备的**实际可视范围**：可视范围大（电脑）就可以完整看清全貌；可视范围小（手机）就只能看清部分，超出的部分只有靠**移动画布位置**来查看。

```
固定物理大小画布（1200px 原始画布，任意设备渲染完全相同的 DOM/CSS）
  ├─ 元素大小 = 真实物理大小
  │    └─ 所有尺寸用固定单位，相对画布布局；禁止视口单位、禁止相对屏幕计算
  ├─ 设备屏幕 = 可视范围（视口）
  │    ├─ 可视范围大 → 完整看清全貌
  │    ├─ 可视范围小 → 只能看清部分，超出的靠移动画布位置查看
  │    └─ 设备大小只决定"能看见多少"，绝不决定"元素多大/在哪"
  ├─ 画布缩放 = CSS zoom 统一缩放（查看层，任何设备同一套）
  │    ├─ 界面底部上下文植入固定的放大缩小按钮：每次按固定步长比例放大/缩小
  │    ├─ 效果：画布变多小，内部所有元素同步变多小（等比例）
  │    └─ 缩放是查看辅助，不改变画布设计的物理大小
  └─ 稳定性（一切状态转换的前提）
       └─ 元素看到多大就是多大：进入编辑态/激活态/展开面板都不改变原本大小
```

- **画布物理大小**：固定 1200px 原始画布，任意设备渲染完全相同的 DOM 和 CSS，不做自适应重排。主容器自身居中，内边距 + 浅灰细边框确认边界；内部内容最小宽 = 1200 减去两侧边距与边框。
- **设备大小只决定可视范围**：小屏幕靠移动画布（滚动）查看超出部分，大屏幕可看全貌。**设备大小不干预**元素尺寸、位置、布局——"布局锚死画布，全端一套位置；设备大小不干预，滚动交由用户"。
- **严格禁止**：响应式断点改变尺寸/字号/布局、视口单位按比例缩放（vw/vh/rem 相对屏幕）、flex 换行改变结构——所有尺寸用固定单位、禁止收缩、禁止换行，移动端只做画布内局部滚动。
- **画布缩放（查看层能力，不违反上述禁止）**：禁止的是**系统自动**响应式缩放布局；**用户主动**缩放查看已开放——通过画布壳子上的 CSS `zoom` 实现**布局级缩放**（非 transform 视觉缩放 → 浮动面板锚点/表格滚动定位自动正确），固定步长，**界面底部固定放大/缩小按钮**（缩小 / 百分比点击重置 / 放大）+ Ctrl/⌘+滚轮。画布变多小内部所有元素同步变多小。用途：小屏看不清、向他人展示信息时放大。缩放是**局部临时查看**，不持久化到画布设计。
- **稳定性：状态转换不影响原本大小**：所有元素"看到多大就是多大"——文本态 ↔ 编辑态、面板展开/收起等状态转换，**不得改变元素/单元格/列宽原本大小**；辅助图标（清空/箭头/收起）悬浮叠加、不占流式宽度；输入控件撑满原本内容区、不带额外内边距/边框改变视觉宽度；浮动面板锚定画布原位（详见下节「交互浮层定位」）。
- **禁止浏览器文字自动调整（v11.18）**：全局锁定 `text-size-adjust: 100%`——iOS Safari / Android Chrome 在聚焦 input（字号 < 16px）时自动放大文字，会破坏"元素看到多大就是多大"（输入框显示字数骤减）；任何元素不得依赖浏览器自动文字缩放。
- **画布缩放的引擎差异（v11.19 已知差异，不实施强制适配）**：CSS `zoom` 的「文字是否随缩放」行为因引擎而异——Chromium 内核（Chrome/Edge/安卓浏览器）**文字随画布严格等比缩放**；Safari/WebKit 内核**布局（列宽/间距）等比缩放、文字通过字号反向补偿而视觉尺寸基本不变**。这是浏览器引擎行为差异，非代码缺陷；当前设计以 Chromium 行为为基准（等比例缩放承诺成立），Safari 下缩小画布时文字保持原视觉大小属引擎限制，不做 transform 替代（transform 会破坏浮动面板锚定/表格滚动定位，v11.10 已论证）。

## 交互浮层定位：画布为基准，两类分明

**顶层依据**（v11.16 用户更正）：一切以画布为基准——之前「弹窗相对视口居中」是错误理解且过度扩散；现在明确，凡是**需要用户交互确认的独立模态**相对**画布**居中，**定位型浮层**（实时匹配等）在哪就在那里，位置与大小都是画布特性、不随屏幕变化；消息通知（toast）保持顶部位置，不参与居中。

```
交互浮层（portal 到 body，画布外不随 zoom 缩放）
  ├── 独立模态（需要用户交互确认） → 相对画布居中（弹窗中心 = 画布中心）
  │     └─ 确认/提示/编辑弹窗 Modal（含二次确认、modal.confirm）
  ├── 消息通知（toast） → 保持顶部位置，不参与居中（不过度扩散）
  └── 定位型浮层（输入辅助，非模态） → 锚定触发元素原位（在哪就在那里）
        └─ 实时匹配/下拉/悬浮面板（FloatPanel 类）
```

- **画布中心基准**：确认类弹窗中心对齐画布中心（画布固定 1200px + margin auto 水平居中 → 水平方向画布中心 ≈ 视口中心；垂直方向画布内容从顶部流式，画布中心与视口中心可偏移，弹窗须跟画布而非视口）。
- **画布中心出视口不用管（v11.17 删除钳制）**：画布中心滚动出视口时，弹窗**不做视口钳制**——弹窗中心永远是画布中心（画布中什么位置就是什么位置）；画布中心在不在视口内都由用户自行滚动画布查看，系统不做任何设备大小干预。
- **位置与大小是画布特性**：所有浮层（独立模态、定位浮层）在画布中什么位置就是什么位置、什么大小就是什么大小，**不随屏幕大小变化**；用户缩放画布是**等比例缩放**（CSS zoom），浮层作为画布一部分稳定跟随，不做双端差异化定位。
- **消息通知不扩散**：toast 类消息通知保持正常顶部位置，**不**参与画布居中——画布居中只适用于需要用户交互确认的独立模态。
- **不得扩散**：此规则只约束独立模态与定位浮层两类，**不**扩散到表格、内容区、导航、底栏等主体层级——主体层级永远以画布布局为唯一基准，不做浮层式居中。
- **实现边界**：独立模态居中由全局定位工具（canvasModalCentering）统一接管，禁止各弹窗各自定位；定位浮层由 FloatPanel 统一锚定，禁止把定位浮层改成居中。
- **定位浮层锚定画布（v11.17 修复）**：FloatPanel 定位只依据**锚点在画布中的绝对坐标**（getBoundingClientRect + scrollX/Y），**禁止视口边界避让**（水平右边界不超出视口/垂直按视口高度换向/maxHeight 按视口压缩——v10.34 曾引入视口避让，导致手机视口窄时面板被钳制到视口边缘或尺寸被压缩，与电脑不一致）。手机上画布 1200px 超出视口的部分，由 body 横向滚动查看（固定画布模式），面板在画布中的位置/大小不变。键盘弹出（visualViewport 收窄）是唯一允许的运行时避让例外。
- **定位浮层关闭契约（v11.18 修复）**：FloatPanel「锚点移出可视区 → 关闭面板」的判定一律以**布局视口**（`window.innerHeight`，键盘弹出不改变）为基准——真机键盘弹出时 `visualViewport.height` 骤减（且浏览器自动滚动 input 到键盘上方有延迟），用收窄高度判定会误判「锚点移出可视区」→ 面板打开即闪关。**键盘弹出不触发关闭**；只有用户滚动页面（布局视口内锚点位置变化）才触发关闭。visualViewport 仅用于面板垂直避让计算（键盘例外）。

> 为什么不用响应式：维护两套布局 = 改一处要改两遍 = 容易不一致 = 小白用户修不起 bug；且用户用了十几年 Excel，Excel 就是固定画布、所见即所得，固定画布最符合直觉。

## 骨架层级：结构固定，内容替换

登录后页面结构自上而下固定（全部包裹在固定画布内）：

```
固定画布（1200px）
  ├── 一级导航行（24px）
  ├── 二级导航行（24px）
  ├── 三级/视图导航行（24px）      ← 自动生成，见导航与路由规范
  ├── 单据标签行（24px）           ← 多单据切换，工作台
  ├── 内容区（高度不确定，自动铺满剩余）
  └── 底部操作栏（24px）           ← 员工端，见导航与路由规范
```

### 行盒子：所有行一个模子

除内容区外，所有行 div 使用统一的行盒子组件（**两层嵌套**）：

```
├─ 为什么两层：外层固定可视窗口不被内容撑开；内层独立滚动（超出横向滚动、隐藏滚动条、鼠标可拖动）
│   └─ 单层结构时任意一行被撑宽 → 整列父容器一起变宽 → 单行滚动失效
├─ 统一参数（全部由令牌控制）：高度 24px、字号 11px、水平 padding 8px、元素 gap 4px、行间无间距
└─ 样式自动拆分：视觉属性归外层，布局属性归内层；导航按钮同样用行内按钮样式
```

### 一级/二级导航

一级导航在顶部承载系统主要功能模块；二级导航在其下承载当前模块的子功能。导航路径与权限的关系见 [导航与路由规范](./导航与路由规范.md)。

### 内容区域

固定在导航与底栏之间，只放业务内容，高度自动铺满剩余空间。内容区内区分**壳子（常驻）**与**业务内容（可换）**，见下节。

## 壳子常驻：点一下就要有反馈

**一句话：壳子常驻、内容替换；切换业务实体时，不得用整页加载卸掉壳子。** 会话级 UI 被整页卸掉再挂上会闪一下——这是低级性能事故，也是结构错误。

```
├─ 什么是壳子（常驻）：员工端导航 + 底部操作栏、工作台多单据标签栏、单据上下文栏占位、列表页筛选条与表格外框
│   └─ 一次使用会话内保持挂载、只改状态不卸 DOM
├─ 什么是内容（可换）：当前视图组件、上下文栏字段值、表体行数据、弹层抽屉
└─ 正确做法：
    ├─ 同一会话页用可选参数或单路由承载——不为壳子开第二个页面实例
    ├─ 加载中只盖住内容区，壳子继续渲染（可用骨架占位）
    ├─ 切实体先订新目标再拉数——不要先清空再整页转圈
    └─ 仅在离开该会话页时清理——不要在"标签 A→B"的切换里拆壳
```

**检查口诀**：用户只是换了一个业务对象或子视图时，导航/标签栏是否还在同一棵树上？应在。

## 令牌：唯一参数源

所有布局与视觉参数集中在**统一令牌文件**中定义（代码内全局共享），禁止各页面散落硬编码。核心令牌：

| 令牌 | 用途 |
|------|------|
| 画布宽度 / 内边距 / 边框 | 固定画布模式（1200px 体系） |
| 行高 24px | 除内容区外所有行（导航/底栏/分页行） |
| 骨架行 padding / gap | 骨架行统一水平内边距与元素间距 |
| 字号梯度 | 表头 10px / 表体 11px / 正文 13px / 标题 16px |
| 元素高度 20px、圆角 4px | 行盒子内所有可操作元素 |
| 语义色 | 品牌色 / 状态色（启用绿·停用橙）/ 扣减红 / 系统补全醒目色 / 文本层级色 |

行盒子内的所有可操作元素（按钮、输入框、标签）使用统一的**行内元素样式常量**：高度 20px（24px 行高内留上下边距）、字号 11px、内边距水平 6px、圆角 4px、统一边框背景与过渡。表格与输入框的行高/字号/内边距通过 UI 框架的主题令牌统一配置，不做 CSS 覆盖。

## 移动端：等比缩小版

> **本质**（承接「画布模型」总纲）：移动端 = **画布物理大小 + 小可视范围**——元素大小不变（真实物理大小），只是设备可视范围小，靠移动画布 + 等比缩小版密度适配查看。

### 格局不变原则

移动端与桌面端保持同一套界面格局，**不转换视图形态**（表格不转卡片、弹窗不转页面），通过**横向滚动 + 缩小字体行高 + 压缩间距**适配窄视口：

- 表格保持表格形态，横向滚动查看溢出列；弹窗/抽屉保持形态与**设计宽度**（v11.17 修正：禁止「移动端全屏化」旧规则——弹窗/抽屉在画布中什么宽度就是什么宽度，不随设备全屏化）。
- 浮动面板保持画布定位形态（v11.17 修正：禁止「改底部抽屉式」旧规则——浮动面板全端一套位置，手机上面板在画布中什么位置就是什么位置、什么大小就是什么大小，超出视口由用户滚动查看）。
- 列结构、列顺序、列字段在双端完全一致。

> 本节所有规则均为**画布固有属性**，不随设备大小切换（「布局锚死画布、全端一套位置；设备大小不干预、滚动交由用户」）。

### 横向滚动全覆盖

所有"一行行的容器"都必须支持横向超出滚动：表格、信息条、工具栏、面包屑、导航按钮组、表单字段行、品牌/单位/价格矩阵行。实现方式：不换行 + 横向滚动容器。

### 放大版/缩小版原则

移动端是桌面端的"等比缩小版"，布局结构完全一致。**不允许用设备检测做视图形态切换**；仅允许切换 CSS 类名等纯样式层面处理。

### 信息密度三重约束

```
├─ 字号：仅 10/11/12/13px 四档，优先小档
├─ 间距：仅 2/4/6/8px 四档，禁止大间距
└─ 行高：仅 28/32px 两档（除触摸目标外）
```

### 禁止项

- 禁止 flex 换行破坏单行结构；禁止大间距 / 大行高 / 大字号。
- 禁止大面积留白（可见区域白屏占比 ≤ 20%）。
- 禁止汉堡菜单 + 抽屉式导航；禁止客户端底部标签栏。

## 变更记录

- **v15.9（2026-08-11）**：「画布模型」稳定性规则补充「禁止浏览器文字自动调整」——全局锁定 `text-size-adjust: 100%`（iOS Safari / Android Chrome 聚焦小字号 input 会自动放大文字，破坏"元素看到多大就是多大"，输入框显示字数骤减）；全域扫描确认无响应式断点（@media 仅 print）、无组件级视口单位/视口尺寸计算元素大小（页面级容器 100vh 最小高度属可视范围适配，元素不受影响）。
- **v15.8（2026-08-11）**：文档系统化重构——「固定画布」章节升级为「**画布模型**」总纲（用户指令：界面布局框架缺乏系统性整理，需从上而下连贯整体）。确立唯一轴心四要素：①元素大小 = **真实物理大小**（只相对画布，绝无相对屏幕计算）；②设备屏幕 = **可视范围**（电脑看全貌、手机看部分，超出移动画布查看，设备大小不干预）；③画布缩放 = **CSS zoom 统一缩放**（任何设备同一套、固定步长、界面底部固定放大缩小按钮、画布内所有元素同步缩放）；④**稳定性**（元素看到多大就是多大，状态转换不影响原本大小）。全文结构重写为四层推导链（画布模型 → 布局框架 → 交互浮层 → 壳子常驻 → 移动端本质），移动端章节补充总纲承接注。缩放控件同步移至界面底部右下角（v11.18 代码落地）。
- **v15.7（2026-08-11）**：「移动端：等比缩小版·格局不变原则」清除两处旧规则残留——①「弹窗/抽屉移动端全屏化」→ 保持形态与设计宽度（v11.17 已删抽屉 100vw 全屏、弹窗保持设计宽度）；②「浮动面板可改底部抽屉式」→ 浮动面板全端一套画布定位形态（禁止改抽屉式）。章节补充总注：本节所有规则均为画布固有属性、不随设备大小切换。全库「避让/钳制/全屏化/变形态」旧描述至此统一。
- **v15.6（2026-08-11）**：「交互浮层定位」补充「定位浮层关闭契约（v11.18 修复）」——FloatPanel「锚点移出可视区关闭」判定一律以布局视口 `window.innerHeight` 为基准，禁止用 visualViewport 收窄高度判定（键盘弹出时骤减 → 面板打开即闪关）；键盘弹出不触发关闭，visualViewport 仅用于垂直避让计算；并修正「画布中心出视口时钳制」残留描述（v11.17 已删除钳制，改为画布中心出视口不用管、用户自行滚动查看）。
- **v15.5（2026-08-11）**：「交互浮层定位」补充「设备大小不干预（v11.17 全面整改）」——独立模态弹窗删除视口钳制、弹窗保持设计宽度、抽屉不随设备全屏化、maxHeight 禁用 vh/vw、删除全系统 `@media (max-width:767px)` 移动端特判；用户操作习惯 = 电脑手机同一套位置/大小，屏幕小了自己滚动。
- **v15.4（2026-08-11）**：「交互浮层定位」补充「定位浮层锚定画布（v11.17 修复）」规则——FloatPanel 定位只依据锚点画布绝对坐标，禁止视口边界避让（水平右边界/垂直换向/maxHeight 压缩）；手机上画布超出视口由横向滚动查看，面板位置/大小不变；键盘弹出为唯一避让例外。
- **v15.3（2026-08-11）**：新增「交互浮层定位：画布为基准」章节（用户顶层更正：一切以画布为基准）——需要用户交互确认的独立模态（确认/提示/编辑弹窗）相对**画布**居中，定位型浮层（实时匹配等）锚定触发元素原位，位置与大小均为画布特性、不随屏幕变化（缩放画布为等比例缩放）；**消息通知（toast）保持顶部位置不参与居中，不扩散**到表格/内容区等主体层级。同步更正画布缩放段残留的「视口居中」表述为「画布居中」。
- **v15.2（2026-08-10）**：「固定画布」章节新增**画布缩放开放（查看层）**规则——禁止的始终是系统自动响应式缩放布局，用户主动缩放查看已开放（CSS zoom 布局级缩放，浮动面板锚点/表格滚动定位自动正确，弹窗/消息在 body 层不随缩放）。
- **v15.1（2026-08-10）**：呈现方式升级——从"并列规则清单"重构为"推导式"（双端一致 → 固定画布 → 骨架/行盒子/令牌 → 壳子常驻 → 移动端缩小版）。规则不变，组织与呈现重构。
