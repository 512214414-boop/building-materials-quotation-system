# 视觉与布局规范

> **职责声明**：本文档是画布/骨架/行盒子/令牌/双端适配的唯一依据。浮动面板与录入交互的展开规则见《表格与交互规范》；导航层级与底栏见《导航与路由规范》；像素值、CSS、组件名等实现细节由代码承载。

## 画布模型

整个项目界面是一块**固定物理大小的画布**：画布在不同设备、不同大小的屏幕上，显示效果、布局、交互弹窗**完全一致**。四要素：

```
├─ ① 元素 = 真实物理大小：所有尺寸只相对画布计算，绝无任何相对屏幕/视口的计算
│     └─ 禁止视口单位、禁止响应式断点改变尺寸/字号/布局、禁止换行破坏结构
├─ ② 设备屏幕 = 可视范围（视口）
│     ├─ 可视范围大 → 完整看清全貌；可视范围小 → 只能看清部分
│     ├─ 超出的部分靠移动画布位置查看
│     └─ 设备大小只决定「能看见多少」，绝不决定「元素多大/在哪」——布局锚死画布，全端一套位置；设备大小不干预，滚动交由用户
├─ ③ 画布缩放 = CSS zoom 查看层（任何设备同一套）
│     ├─ 固定步长 + 界面固定缩放按钮（缩小/百分比点击重置/放大）+ 快捷键
│     ├─ 效果：画布变多小，内部所有元素同步等比例缩小
│     └─ 缩放是查看辅助，不改变画布设计的物理大小；缩放是局部临时查看，不持久化
└─ ④ 稳定性：元素看到多大就是多大——状态转换（编辑/激活/展开）不改变原本大小（见「稳定性」）
```

**引擎差异（已知差异，不实施强制适配）**：CSS zoom 的「文字是否随缩放」行为因引擎而异——Chromium 内核（Chrome/Edge/安卓浏览器）**文字随画布严格等比缩放**；Safari/WebKit 内核**布局（列宽/间距）等比缩放、文字通过字号反向补偿而视觉尺寸基本不变**。这是浏览器引擎行为差异，非代码缺陷；以 Chromium 行为为基准（等比例缩放承诺成立），不做替代实现（替代会破坏浮层锚定与表格滚动定位）。

### 移动端本质：等比缩小版

移动端 = **画布物理大小 + 小可视范围**——元素大小不变（真实物理大小），只是设备可视范围小，靠移动画布 + 密度压缩适配查看：

- **格局不变**：移动端与桌面端保持同一套界面格局，不转换视图形态——表格不转卡片、弹窗不转页面、浮动面板保持画布定位形态；弹窗/抽屉在画布中什么宽度就是什么宽度，不随设备全屏化；列结构、列顺序、列字段双端完全一致。不允许用设备检测做视图形态切换，仅允许纯样式层面处理。
- **横向滚动全覆盖**：所有「一行行的容器」都必须支持横向超出滚动——表格、信息条、工具栏、面包屑、导航按钮组、表单字段行、品牌/单位/价格矩阵行（不换行 + 横向滚动容器）。
- **信息密度三重约束**：字号仅几档小档（优先小档）、间距仅几档（禁止大间距）、行高仅两档（除触摸目标外）。
- **禁止项**：禁止换行破坏单行结构；禁止大间距/大行高/大字号；禁止大面积留白；禁止汉堡菜单 + 抽屉式导航；禁止客户端底部标签栏。

## 骨架与行盒子

登录后页面结构自上而下固定（全部包裹在固定画布内）：

```
固定画布
  ├── 一级导航行
  ├── 二级导航行
  ├── 三级/视图导航行（自动生成，见《导航与路由规范》）
  ├── 单据标签行（多单据切换，工作台）
  ├── 内容区（高度自动铺满剩余）
  └── 底部操作栏（员工端，见《导航与路由规范》）
```

### 行盒子：所有行一个模子

除内容区外，所有行使用统一的行盒子（**两层嵌套**）：

```
├─ 为什么两层：外层固定可视窗口不被内容撑开；内层独立滚动（超出横向滚动、隐藏滚动条、鼠标可拖动）
│   └─ 单层结构时任意一行被撑宽 → 整列父容器一起变宽 → 单行滚动失效
├─ 统一参数（全部由令牌控制）：行高、字号、水平内边距、元素间距、行间无间距
└─ 样式自动拆分：视觉属性归外层，布局属性归内层；导航按钮同样用行内按钮样式
```

### 壳子常驻：点一下就要有反馈

**壳子常驻、内容替换；切换业务实体时，不得用整页加载卸掉壳子。** 会话级 UI 被整页卸掉再挂上会闪一下——这是低级性能事故，也是结构错误。

```
├─ 什么是壳子（常驻）：员工端导航 + 底部操作栏、工作台多单据标签栏、单据上下文栏占位、列表页筛选条与表格外框
│   └─ 一次使用会话内保持挂载、只改状态不卸 DOM
├─ 什么是内容（可换）：当前视图组件、上下文栏字段值、表体行数据、弹层抽屉
└─ 正确做法：
    ├─ 同一会话页用可选参数或单路由承载——不为壳子开第二个页面实例
    ├─ 加载中只盖住内容区，壳子继续渲染（可用骨架占位）
    ├─ 切实体先订新目标再拉数——不要先清空再整页转圈
    └─ 仅在离开该会话页时清理——不要在「标签 A→B」的切换里拆壳
```

**检查口诀**：用户只是换了一个业务对象或子视图时，导航/标签栏是否还在同一棵树上？应在。

## 令牌：唯一参数源

所有布局与视觉参数集中在**统一令牌**中定义（代码内全局共享），禁止各页面散落硬编码裸值。核心令牌：

| 令牌 | 用途 |
|------|------|
| 画布参数 | 画布宽度/内边距/边框（固定画布模式） |
| 行高 | 除内容区外所有行（导航/底栏/分页行） |
| 骨架行参数 | 行盒子统一水平内边距与元素间距 |
| 字号梯度 | 表头/表体/正文/标题分档 |
| 元素参数 | 行盒子内所有可操作元素的高度与圆角 |
| 语义色 | 品牌色 / 状态色（启用绿·停用橙）/ 扣减红 / 系统补全醒目色 / 文本层级色 |

行盒子内的所有可操作元素（按钮、输入框、标签）使用统一的**行内元素样式常量**（高度、字号、内边距、圆角、统一边框背景与过渡）。表格与输入框的行高/字号/内边距通过 UI 框架的主题令牌统一配置，不做样式覆盖。

## 稳定性

- **状态转换不改大小**：所有元素「看到多大就是多大」——文本态↔编辑态、面板展开/收起等状态转换，**不得改变元素/单元格/列宽原本大小**；辅助图标（清空/箭头/收起）悬浮叠加、不占流式宽度；输入控件撑满原本内容区、不带额外内边距/边框改变视觉宽度（展开规则见《表格与交互规范·录入交互》）。
- **禁止浏览器文字自动调整**：聚焦输入框（小字号）时浏览器会自动放大文字，破坏「元素看到多大就是多大」（输入框显示字数骤减）；全局锁定禁止，任何元素不得依赖浏览器自动文字缩放。
