## 顶层抽象 ← 用户约束

| 顶层设计理念 / 架构原则 | 由哪条用户约束推导（详见《项目设计哲学》） |
|------------------------|------------------------------------------|
| 表格是主体，其他都是辅助 | 约束4 Excel 用户·流式录入 |
| 三层分工各管各的 | 约束2 系统必须皮实、一致、规则显式 |
| 三种数据形态三种交互 | 约束4 + 原则「形态决定载体」 |
| 快照解耦（单据不改写档案） | 约束5 历史单据是法律事实 |
| 宽表承载高频列表 | 约束6 数据量级巨大·索引驱动 |
| 令牌是唯一视觉参数 | 约束2 改一处全域生效、界面像同一套设计 |
| 边用边扩充（关系面板） | 约束1 自然语言开发 + 约束4 录入不打断 |
| 档案管理五段（出发点 → 要支持到 → 关系 → 本页 → 选用检索） | 约束4 流式录入；出发点指向可视化指导思想（一类活或货和人怎么存在） |
| 单位全局字典 + 规格引用 | 约束2 同类只留一套；选品默认换本规格引用，改全局才改字典名或并到已有档案 |

## 功能文档 ← 顶层抽象

| 功能文档 | 锚定的顶层设计理念 | 锚定的架构原则 |
|----------|-------------------|---------------|
| 产品数据层 | 组合去重建档 / 宽表检索 | 数据规范 |
| 产品管理 | 表格唯一 · 范式 A/B | 档案管理 · 表格与交互 · 实体关系面板 · 视觉与布局 |
| 采购报价 | 表格是主体 / 快照解耦 | 档案管理（选用检索）· 表格与交互 · 实体关系面板 · 数据 |
| 单据与状态机 | 快照解耦 / 8 档流转 | 数据 · 表格与交互 |
| 供应商管理 | 档案引用 + 点位 | 档案管理 · 数据 · 表格与交互 |
| 客户管理 | 档案引用 + 快照 | 档案管理 · 数据 · 表格与交互 |
| 配货与成本 | 宽表 / 快照 | 档案管理（库房）· 数据 |
| 收款对账 / 发货 / 售后 | 单据生命周期 | 数据 · 表格与交互 |
| 系统管理 | 权限显式 | 权限与职责 |
