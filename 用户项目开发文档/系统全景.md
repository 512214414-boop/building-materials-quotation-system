# 系统全景（新人 2 分钟版）

> 一句话：这是一个**门店用的建材报价 / 进销存一体化系统**——员工在统一表格里建采购单、报价、配货、发货、核算成本、对账，客户可自助下单；所有数据以"单据快照"贯穿，历史不可改。
> 本文是新人视角的总览，基于真实代码（`extract_architecture.py` 事实底座）与既有顶层文档写成。想深究看《溯源映射》《项目设计哲学》《顶层设计规范》。

## 一、这系统是什么（30 秒版）

- **给谁用**：门店员工（建单/跟单/报价）+ 客户（自助采购清单）。
- **干啥用**：把"一张建材采购单"从询价到归档的全流程，在一个**统一表格交互范式**里跑完。
- **开单起点**：柜台前散客、信息糊、店里未必有货。系统贴近手写：一格跟着嘴走，用这行字去认货、找人打电话，找不到也不停单。问到名字或电话就写在单上，不必为此建人档；什么都没有也先开。作业切法见 `文档可视化/`「系统业务设计指导思想」（销售开单 / 配货履约 / 进货管货 / 收付款往来 / 售后）。八个工作台视图是同一张单的不同看法，不是八类活。
- **怎么不崩**：历史单据一律**快照**保存，任何改动不回溯改写旧单（详见《项目设计哲学·约束5》）；规则写文档、实现归代码，二者由本治理流程保持对齐。

## 二、分层全景

```
用户层      门店员工（报价/跟单）          客户（/customer 自助下单）
   │
业务域      基础档案 │ 五类活（开单/履约/进货/往来/售后）│ 过程视图 │ 系统管理
   │
能力层      页面表 UnifiedTable · 浮层表 EntityPanel · 档案引用 DictRefField
            · 工作台骨架 ViewFrame · 定价/状态机/检索 引擎
   │
技术基线    React19 + TS + Vite 前端 / Express + Prisma + MySQL 后端 / 单一表格交互范式
```

## 三、系统由哪几块组成（每块一句话管什么）

| 块 | 管什么 | 真实页面/模块（代码事实） |
|----|--------|--------------------------|
| **基础档案** | 产品/客户/供应商/库房 | `/staff/basic/{products,customers,suppliers,warehouses}` |
| **报价单据** | 一张采购单从建到归档；工作台八视图是过程不是一类活 | `/staff/documents` + `/staff/workbench/:id` |
| **配货履约** | 找货、调货、送出、欠库、三种成本口径 | 工作台统一配货/交付/成本；`/staff/basic/backorders` 欠库台账（菜单在配货运营） |
| **进货管货** | 点进仓、待入、按仓看库存 | `/staff/operation/purchase-inbound`；`/staff/basic/{inbound-tasks,inventory}`（菜单在进货管货） |
| **收付款往来** | 跟客户收、跟供应商付 | 工作台收款对账；`/staff/operation/payables` 供应商应付（菜单在收付款往来） |
| **售后** | 对着卖掉的行退；数量锁本店卖过的，价锁当时卖价；回仓要认全 | 工作台售后退款：勾原单 → 对已卖行打名称 → 插入 |
| **看数** | 一张单汇总、一段时间经营、定档只读 | 工作台销售汇总/定档；`/staff/ops` |
| **系统管理** | 权限 / 授权码 / 审计 | `/staff/system/{users,roles,auth-codes,access,audit}` |

## 四、关键抽象：代码里真实存在的复用能力（标注"用在哪"）

> 这是"向上抽象"的果实——代码已抽象出这些能力，文档应当明确它们用在哪些页面，避免重复造轮子。

- **`UnifiedTable`（页面表）**：所有业务主列表的底座 → 产品/客户/供应商/库存/单据行。
- **`EntityPanel`（浮层表网格基座）**：`.ds-grid-header/.ds-grid-row`；`MatrixTable`/`UnitManagePanel` 是适配器。开单选品/选单位仍走 ProductPicker / UnitPicker，不能合成一套 UI。
- **`DictRefField`（档案引用输入+管理一体）**：品牌/供应商/分类/价格类型/全局单位的选择与快捷建档。
- **`ViewFrame`**：订单协同工作台统一骨架，承载 8 个三级视图（采购报价/收款对账/统一配货/订单交付/成本标注/售后退款/销售汇总/定档归档）。
- **`SHARED_BADGES`（badge/registry.ts 共享组件编号注册表）**：跨页复用的徽标/组件统一编号。
- **引擎（4 个）**：`pricing-engine` 算价、`document-state-machine` 单据流转、`search-engine` 检索建议、`full-name-generator` 全称生成——跨单据复用。

## 五、核心数据流：一张采购单怎么流

```
建单（残缺也可存）→ 开单/报价（一格混写，对不上也先落行）
  → 配货履约（仓和渠道分开；不够当场欠着；三种成本口径）
  → 进货管货（点进仓 / 待入 / 看库存；多调的进库存不算这笔订单成本）
  → 交付 · 往来收款 · 售后（对着卖掉的行退；钱按当时卖价；回仓要认全）
  → 看数 / 定档只读
```
每一步都是**快照**：改下一段不回溯改写上一段（详见《架构原则·数据》《项目设计哲学·约束5》）。

## 七、对齐发现（文档 vs 代码）

- **现行基座**：页面表 = UnifiedTable；浮层表网格基座 = EntityPanel（`.ds-grid-header/.ds-grid-row`）。`MatrixTable` / `UnitManagePanel` 是适配器，**没有删除**。
- **三条交互链不能合成一套 UI**：开单选品 = ProductPicker；开单选单位 = UnitPicker；产品列表/编辑弹窗维护 = UnitManagePanel / UnitPriceExpandPanel（列表单元格仍是 RecordFieldColumn + Popover）。
- **视觉参数**：颜色/间距/字号只来自设计令牌 → 元素类 → 组件；antd 主题算法禁止塞入 `var(--*)` 字符串。
- **工作台**：8 档状态机 + 8 个三级视图（采购报价 / 收款对账 / 统一配货 / 订单交付 / 成本标注 / 售后退款 / 销售汇总 / 定档归档）。进货管货、收付款往来、经营分析是一级页面，不是工作台第 9 视图。
- **经营分析**：`/staff/ops`，区间总量走 SQL 聚合；明细只对当前页单据归集。应付账龄挂在供应商应付页。
- **单位（v16.5）**：`unit` 是全局字典（名称唯一）；规格引用与基准/显示标记在 `spec_unit`。解除规格引用不删全局字典行。
