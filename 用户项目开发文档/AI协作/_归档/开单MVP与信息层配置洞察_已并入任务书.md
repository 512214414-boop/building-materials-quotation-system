## 一、顶层抽象层

### 1.1 核心命题
把「**档案 → 开单 → 状态机 → 视图交付**」串成**明天能跑的最小闭环（MVP）**；同时把"信息层"（`QUICK_CREATE_LAYERS` 快速建档配置）从前端 TS 配置**升级为可配置 UI 功能**。两者都是用户明确拍板的范围，不得互相稀释。

### 1.2 范围边界（MVP 切片，已与用户校准）
- **开单 MVP = 核心开单路径**：散客（个人业主）建档 → 加产品行 → 报价确认 → 收款 → 简易交付。
- **信息层 = 独立 UI 功能（一期）**：前端管理界面 + 持久化，覆盖现有 `product / price / customer` 三层。
- **引用关系 = 打通建档↔单据关联**：快速建档后落到单据引用（customer_id / productId）+ 快照字段，走现有**快照解耦**方式，**不新建数据模型、不改动解耦原则**。

### 1.3 明确不做（防范围膨胀，已与用户确认）
- ❌ 全链路 8 档（成本/售后/归档视图不纳入本次 MVP）
- ❌ 统一配货 / 成本标注 / 售后退款视图（仅留简易交付）
- ❌ 新增档案类型（供应商/仓库层本次不加，信息层界面预留扩展位）
- ❌ Drawer / 第四种浮层（仍按《洞察结果文档》禁用）

## 二、模块规约层

### 2.1 开单核心路径（复用现有，打通引用）
> 目标：散客开单从建档到简易交付一条跑通，明天可给真实客户用。

1. **散客建档**：调用 `QuickCreateConfirmDialog`（customer 信息层）→ 落 `documents.customer_id` + 快照（customerName/customerPhone/customerCompany）。个人业主 customerType=personal。
2. **加产品行**：`MatrixTable`(C29) 行 + `DictRefField`(C15) 选/建产品（product 信息层）；售价落行（双层价格隔离：unitPrice 落行，不强制写回档案）。
3. **报价确认**：status 置 `quote_confirmed`（报价阶段完成，售价定稿落行）。
4. **收款**：status 置 `payment_settled`（收款核销完成；收款金额走现有收款逻辑）。
5. **简易交付**：status 置 `delivery_completed`（签收自动推进；MVP 不强制拦截，沿用状态机"≥allocation_in_progress 可用"宽松口径，但简易交付直接到 delivery_completed）。
- **引用关联（本次重点打通项）**：建档后通过 `customer_id` / `productId` / `specId`/`brandId`/`unitId` 关联档案，**同时写入快照字段**（名称/价格/图片）；档案改名/删除不影响历史——沿用《单据与状态机》快照解耦，不新增物理外键。
- **不破坏现有**：8 视图 / 8 档状态机 / ViewFrame 不被本次改动影响；MVP 只走 4 档（quote_confirmed→payment_settled→delivery_completed + 起点 demand_pending）。

### 2.2 信息层独立 UI 功能（一期）
> 现状：`QUICK_CREATE_LAYERS` 定义在 `frontend/src/shared/config/quickCreateConfig.ts`，纯 TS 配置，无 UI。
> 目标（用户拍板"现在完善立刻实现"）：做成**前端可配置管理界面**，持久化。

- **前端管理界面**（系统管理模块下新增「信息层配置」页）：
  - 列出 `product / price / customer` 三层；每层展示其字段清单（label / 必填 / 兜底值 fallback / 输入类型 inputType / 选项 options / 去重键 dedupeKey）。
  - 支持字段编辑（增/删/改字段配置）、保存。
  - 交互载体遵循《洞察结果文档》：编辑用**模态框**（C07），行内提示用**消息通知**，辅助录入用**悬浮定位框**（C60）。
- **持久化（一期目标）**：新增 `system_config` 最简表（key varchar PK, value JSON），key=`quick_create_layers`，value=完整 `QUICK_CREATE_LAYERS` 结构。前端加载时合并"持久化覆盖"到 TS 默认；保存写回 `system_config`。`QuickCreateConfirmDialog` 等读取改为"TS 默认 ← system_config 覆盖"。
- **降级路径（明天时间若紧）**：先实现前端界面 + **前端运行时覆盖**（localStorage / 内存合并），`system_config` 后端持久化后置为二期；MVP 验收以"界面可编辑 + 保存后快速建档生效"为准，不强制后端落库。
- **数据模型约束**：去重键语义（global / parent）保持不变；新增/修改字段不得破坏现有 A 类（品牌/分类/价格类型/供应商 name 全局唯一）与 B 类（产品/规格/单位 父级从属）去重逻辑。
- **扩展预留**：界面与存储结构按"层"组织，未来加供应商层/其他实体层只需加配置，不需改交互（沿用 v15.3「模型控制层」式抽象）。
