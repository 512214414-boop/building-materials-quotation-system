3. **验收必须跑通**：后端 `npx tsc --noEmit` + `npm test`；数据库迁移 `prisma migrate deploy`；涉及交互的改动需浏览器 e2e。

5. **完成后**：删除本文件对应章节，并在 [架构缺陷台账](架构缺陷台账.md) 移除对应 P 编号。

## §2 编辑弹窗上叠模态弹窗收敛（台账 P-010）

> **背景**：对照 [表格与交互规范](../架构原则/表格与交互规范.md)——**反对的是"模态弹窗叠模态弹窗"**（两个独占交互的窗叠在一起，用户打开一个又被另一个盖住，找不到北）；**不反对**编辑弹窗内的浮动面板展开（浮动面板非模态、明确支持嵌套互斥，单位/售价/进价等展开是产品编辑该有的多交互，一律保留）。

### 触点清单

| 位置 | 问题 |
|------|------|
| `frontend/src/apps/staff/pages/product-manage/ProductEditDialog.tsx`（品牌图片区 → 图片库选择） | 主编辑弹窗（模态）之上叠了裸 antd `<Modal>`（width:820）——两个模态窗叠在一起，主编辑上下文丢失 |
| `ProductEditDialog.tsx`（进价点位 → 批量调整） | 主编辑弹窗（模态）之上叠了第二个 `<BatchAdjustDialog>`（自身是 DsDialog 模态） |

### 整改方案

1. **图片库选择**：从裸 antd Modal 改为 `FloatPanel`（浮动面板，相对触发元素定位、非模态、失焦不关、不打断主编辑上下文）或 `DsDrawer` 下钻——保留按产品名/分类预筛选的上下文带入；这是"编辑弹窗内合理的面板展开"，与单位/售价/进价面板同一性质；
2. **批量调整**：消除模态叠模态——改为从编辑弹窗内用非模态方式承载（如抽屉/浮动面板），或把入口独立到产品列表页/操作栏（同层独立弹窗），二选一，不得再以第二个模态窗叠在主编辑弹窗之上；保留供应商/品牌/分类上下文带入；
3. **禁止误伤**：本次整改只动「模态叠模态」的两处，编辑弹窗内所有浮动面板（单位/售价/进价/图片库改面板后）一律不动、不"消灭弹窗"。

### 验收方式

浏览器 e2e：产品编辑弹窗内选图（图片库 → 复用 → 回填）、进价点位批量调整（预览 → 执行 → 重载价格）全流程无回归，且全程主编辑弹窗不被第二个模态窗盖住；grep 确认 ProductEditDialog 内不再嵌套第二个 DsDialog/Modal。

## §3 页面硬编码样式与列宽令牌收敛（台账 P-011）

> **背景**：违反「视觉令牌 = 唯一参数源」与「列宽 COL_WIDTHS 单一信息源」。

### 触点清单（按整改优先级）

| 优先级 | 触点 | 问题 |
|--------|------|------|
| 先做 | UnifiedTable 列定义 `minWidth` 硬编码约 85 处（CustomerManage 21 / InboundManage 15 / InventoryManage 13 / BackorderManage 8 / PurchaseList 8 / DocumentList 7 / SupplierManage 6 / 其他） | 绕过 `shared/components/table/colWidths.ts` 的 COL_WIDTHS 预设（仅 ProductManage 合规） |
| 后做 | 页面层 `style={{` 数字像素值 552 处 / 37 文件（fontSize / gap / width / margin 等） | 未走 `--body-*` / `--spacer-*` / `--shell-*` 令牌 |
| 顺带 | `ProductImageLibraryPicker.tsx` 遮罩 `rgba(0,0,0,0.55)` / `#fff` | 色值硬编码，应走 `--bg-overlay-*` / `--text-*` |

### 整改方案

1. 列宽收敛：逐列映射到 COL_WIDTHS 预设档位（语义不匹配时先扩展预设档位再替换，禁止页面写裸数字）；
2. 页面像素样式：按文件逐页收敛为令牌变量（字号 → `--body-*`、间距 → `--spacer-*`/`--shell-*`、行高 → `--*line-height`）；
3. 色值 → 语义 token。

### 验收方式

grep 计数显著下降（列宽裸数字零残留；页面像素按文件清零）；视觉回归（列表/弹窗/手机端截图对比无感知变化）。

## §5 浮层实现统一：Popover → FloatPanel 画布锚定

> **背景**：违反 [表格与交互规范](../架构原则/表格与交互规范.md)「同质同构：一种数据只有一种形态」——定位型浮层存在**两套实现**：① 表格单元格场景（采购报价产品/单位列等）用 **FloatPanel**（画布锚定、PanelTree 管理层级、定位标准）；② 产品管理编辑弹窗内（单位/售价/进价明细等）用**裸 antd Popover**（视口定位 + `getPopupContainer` 挂载）。两套视觉与定位逻辑并存，双端表现与维护成本不一致。已确认采购报价产品列**非重复实现**（复用 UnifiedTable/PickerCellEditor/DsInput/FloatPanel/ProductPicker 共享抽象），遗留点为产品管理侧未统一。

### 触点清单

| 层 | 位置 | 改动 |
|----|------|------|
| 前端 | `frontend/src/apps/staff/pages/product-manage/ProductEditDialog.tsx`（3 处 `<Popover>`：售价明细/进价明细/图片选择） | 迁移为 `<FloatPanel>`：`anchorRef` 用 `e.currentTarget` 捕获，`parentId` 声明父子关系（PanelTree 互斥/级联），zIndex 由 PanelTree depth 计算 |
| 前端 | `frontend/src/apps/staff/pages/ProductManage.tsx`（1 处 `<Popover>`） | 同上迁移 |
| 前端 | `frontend/src/shared/utils/smartPopupContainer.ts` | 迁移完成后若仅剩 Popover 使用则随触点一并清理 |
| 文档 | `用户项目开发文档/功能文档/产品管理.md` | 更新浮层实现描述为 FloatPanel 画布锚定 |

### 整改方案

1. 所有定位型浮层（下拉/明细/选择面板）统一由 **FloatPanel** 承载——锚定触发元素画布原位、PanelTree 管理嵌套互斥与级联关闭、zIndex 统一计算；
2. 产品编辑弹窗内单位价格明细（UnitPriceExpandPanel 载体）迁移后保持现有交互语义（点击触发、面板内可切换单位/价格），仅替换浮层容器；
3. 禁止新增裸 `antd Popover/Dropdown` 承载定位型浮层（消息类 Popover 除外）；grep 巡检纳入 `frontend/src/apps` 下 `<Popover|<Dropdown` 检查。

### 验收方式

grep 确认 `frontend/src/apps` 下 `<Popover|<Dropdown` 零残留（消息类除外）；产品编辑弹窗单位/售价/进价明细面板、图片选择面板改用 FloatPanel 且双端定位一致（1440×900 vs 390×844）；产品管理全流程浏览器 e2e 无回归。
