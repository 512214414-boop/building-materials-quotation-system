## 功能概述

### 发货管理在业务流程中的位置

发货管理（交付履约）是建材报价系统九视图工作台中的第五个视图，处于配货管理之后、成本核定之前：

```
采购报价 → 需求确认 → 收款对账 → 配货管理 → 交付履约 → 成本核定 → 销售汇总 → 退换售后 → 归档
                                              ↑
                                        （当前视图）
```

### 业务职责

发货管理的核心职责是：为单据记录每一批次的交付信息，包括配送方式、物流单号、收货人、联系电话等，并跟踪从待发货 → 已发货 → 已签收的完整交付状态流转。

**设计原则**：
- **分批交付**：一个单据可有多个交付记录，支持分批、分方式发货；
- **状态流转**：`pending`（待发货）→ `shipped`（已发货）→ `signed`（已签收），不可跳级、不可回退；
- **签收联动**：当该单据所有交付记录均已签收，自动推进单据状态到 `delivery_completed`；
- **快录行**：顶部常驻快录行，选择配送方式 + 输入运单号回车即新增，无需弹窗；
- **行内编辑**：次要字段（物流单号、收货人、联系电话、备注）在表格行内直接编辑，失焦或回车即保存；
- **视图级防误触锁定**：锁定后所有交付记录不可编辑，解锁需二次确认。

### 关联功能

| 功能 | 关联方式 |
|------|---------|
| 配货管理 | 配货完成后，交付履约视图记录发货信息 |
| 成本核定 | 交付完成后，成本核定视图基于交付记录进行内部进货成本核算 |
| 收款对账 | 交付履约在配货开始后（单据状态 ≥ `allocation_in_progress`）可用；录入宽松不强制状态拦截，全部签收后自动推进单据到 `delivery_completed` |
| 单据状态机 | 全部签收后自动推进单据状态到 `delivery_completed`（8 档状态机完整定义见 [收款对账.md·单据状态流转](./收款对账.md)） |

## 表结构

### delivery_records 交付记录表

交付履约视图标注表，关联 `documents`（单据），一个单据可有多个交付记录。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| document_id | BigInt | NOT NULL, FK → documents.id, ON DELETE CASCADE | 所属单据 |
| delivery_method | enum | NOT NULL | 配送方式：self_pickup=自提 / haulage=货拉拉 / special_van=专车配送 / logistics=物流托运 / site_delivery=工地送货 |
| tracking_no | varchar(100) | NULL | 物流单号 |
| receiver | varchar(100) | NULL | 收货人姓名 |
| receiver_phone | varchar(20) | NULL | 收货人联系电话 |
| status | enum | NOT NULL, DEFAULT 'pending' | 状态：pending=待发货 / shipped=已发货 / signed=已签收 |
| shipped_at | datetime(3) | NULL | 发货时间（status 改为 shipped 时自动设置） |
| signed_at | datetime(3) | NULL | 签收时间（status 改为 signed 时自动设置） |
| attachment_urls | JSON | NULL | 附件 URL 数组（签收凭证等） |
| note | TEXT | NULL | 备注 |
| freight | decimal(14,2) | NOT NULL, DEFAULT 0 | 运费（三源汇集源3：按行金额比例分摊到 cost_lines.freight） |
| created_at | datetime(3) | NOT NULL, DEFAULT CURRENT_TIMESTAMP(3) | 创建时间 |
| updated_at | datetime(3) | NOT NULL | 更新时间 |

**索引**：`@@index([document_id])` / `@@index([status])`
**外键**：`documents` 表通过 `document_id` 关联，ON DELETE CASCADE

### 枚举定义

**delivery_method（配送方式）**：

| 枚举值 | 中文名称 |
|--------|---------|
| self_pickup | 自提 |
| haulage | 货拉拉 |
| special_van | 专车配送 |
| logistics | 物流托运 |
| site_delivery | 工地送货 |

**delivery_status（交付状态）**：

| 枚举值 | 中文名称 | 标签颜色 |
|--------|---------|---------|
| pending | 待发货 | warning（橙色） |
| shipped | 已发货 | brand（品牌色） |
| signed | 已签收 | success（绿色） |

## 接口列表

全部接口挂载在 `/api/staff/` 下，需员工鉴权，按视图权限 `delivery_fulfill` 控制读写。

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/documents/:id/delivery` | `delivery_fulfill` ro | 查询单据的所有交付记录（按 created_at 升序） |
| POST | `/api/staff/documents/:id/delivery` | `delivery_fulfill` rw | 创建交付记录 |
| PATCH | `/api/staff/delivery/:id` | `delivery_fulfill` rw | 更新交付记录（含状态从 pending → shipped） |
| POST | `/api/staff/delivery/:id/sign` | `delivery_fulfill` rw | 签收确认（shipped → signed） |
| POST | `/api/staff/documents/:id/delivery/lock` | `delivery_fulfill` rw | 锁定交付履约视图（防误触） |
| POST | `/api/staff/documents/:id/delivery/unlock` | `delivery_fulfill` rw | 解锁交付履约视图 |

### 1. 查询交付记录列表

`GET /api/staff/documents/:id/delivery`

**参数**：无（路径参数 `id` 为单据 ID）

**返回**：`DeliveryRecord[]`

```json
[
  {
    "id": "1",
    "documentId": "100",
    "deliveryMethod": "logistics",
    "trackingNo": "SF1234567890",
    "receiver": "张三",
    "receiverPhone": "13800138000",
    "status": "shipped",
    "shippedAt": "2026-08-04T10:30:00.000Z",
    "signedAt": null,
    "attachmentUrls": null,
    "note": "注意轻拿轻放",
    "createdAt": "2026-08-04T09:00:00.000Z",
    "updatedAt": "2026-08-04T10:30:00.000Z"
  }
]
```

### 2. 创建交付记录

`POST /api/staff/documents/:id/delivery`

**请求体**：

```json
{
  "deliveryMethod": "logistics",
  "trackingNo": "SF1234567890",
  "receiver": "张三",
  "receiverPhone": "13800138000",
  "note": "注意轻拿轻放",
  "attachmentUrls": ["https://..."]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deliveryMethod | enum | 是 | 配送方式 |
| trackingNo | string | 否 | 物流单号，最大 100 字符 |
| receiver | string | 否 | 收货人，最大 100 字符 |
| receiverPhone | string | 否 | 联系电话，最大 20 字符 |
| note | string | 否 | 备注，最大 500 字符 |
| attachmentUrls | string[] | 否 | 附件 URL 数组 |

**返回**：`DeliveryRecord`（status 默认为 `pending`），HTTP 201

### 3. 更新交付记录

`PATCH /api/staff/delivery/:id`

**请求体**：

```json
{
  "trackingNo": "SF1234567890",
  "receiver": "张三",
  "receiverPhone": "13800138000",
  "status": "shipped",
  "note": "更新备注",
  "attachmentUrls": ["https://..."]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| trackingNo | string | 否 | 物流单号 |
| receiver | string | 否 | 收货人 |
| receiverPhone | string | 否 | 联系电话 |
| status | enum | 否 | 仅允许从 `pending` → `shipped`，不可通过 PATCH 改为 `signed` |
| note | string | 否 | 备注 |
| attachmentUrls | string[] | 否 | 附件 URL 数组 |

**状态流转约束**：
- `pending` → `shipped`：允许，自动设置 `shipped_at = now()`
- `shipped` → `shipped`：无操作（已是 shipped）
- 其他变更（如 `pending` → `signed`、`shipped` → `pending` 等）：返回 422 错误

**返回**：`DeliveryRecord`

### 4. 签收确认

`POST /api/staff/delivery/:id/sign`

**请求体**：无（仅路径参数）

**前置条件**：当前 status 必须为 `shipped`，否则返回 422 错误

**事务操作**：
1. 更新交付记录 `status = 'signed'`、`signed_at = now()`
2. 检查该单据所有交付记录是否都已签收
3. 若全部签收，best-effort 推进单据状态到 `delivery_completed`

**返回**：

```json
{
  "id": "1",
  "documentId": "100",
  "status": "signed",
  "signedAt": "2026-08-04T12:00:00.000Z",
  "allSigned": true,
  "statusTransitioned": true
}
```

| 字段 | 说明 |
|------|------|
| allSigned | 该单据是否所有交付记录均已签收 |
| statusTransitioned | 是否自动推进了单据状态到 `delivery_completed` |

### 5. 锁定/解锁视图

`POST /api/staff/documents/:id/delivery/lock`
`POST /api/staff/documents/:id/delivery/unlock`

**请求体**：无

**机制**：在 `documents.view_locks` JSON 字段中设置 `{ "delivery": true/false }`

**返回**：

```json
{
  "documentId": "100",
  "view": "delivery",
  "locked": true
}
```

## 保存逻辑

### 前端校验

- 配送方式（deliveryMethod）必选；
- 物流单号（trackingNo）最大 100 字符；
- 收货人（receiver）最大 100 字符；
- 联系电话（receiverPhone）最大 20 字符；
- 备注（note）最大 500 字符。

### 后端事务流程

**创建交付记录**：
```
- 校验单据存在性（documents 表）
- INSERT delivery_records
  - delivery_method = 传入值
  - status = 'pending'（默认值）
  - 其他字段按传入值或 null
- WS 广播 delivery.updated 事件
- 记录审计日志（delivery_create）
```

**更新交付记录**：
```
- 校验交付记录存在性
- 非 status 字段直接更新
- 若 status = 'shipped' 且当前 status = 'pending'：
  - 更新 status = 'shipped'
  - 若 shipped_at 为空，设置 shipped_at = now()
- 若 status 变更非法（如 pending → signed、shipped → pending 等）：
  - 返回 422 错误
- WS 广播 delivery.updated 事件
- 记录审计日志（delivery_update）
```

**签收确认**：
```
- 事务包裹（保证原子性）：
  1. 校验当前 status 必须为 'shipped'
  2. UPDATE delivery_records SET status='signed', signed_at=now()
  3. 查询该单据所有交付记录，检查是否全部为 'signed'
  4. 若全部签收，调用 applyTransition 推进单据状态到 'delivery_completed'
     - 校验当前单据状态（非 delivery_completed 且非 archived）
     - 使用乐观锁（lock_version）防并发
     - 事务内执行，失败不影响签收操作
- 事务提交后 WS 广播 delivery.updated 事件
- 若单据状态推进成功，额外广播 document.status_changed 事件
- 记录审计日志（delivery_sign）
```

## 交互细节

### 快录行

- 常驻页面顶部，仅在未锁定编辑时显示；
- 左侧配送方式下拉默认选中「自提」，可切换；
- 物流单号输入框为可选，不填也可提交；
- 回车或点击「添加」按钮提交；
- 提交后：清空物流单号输入框（保留配送方式选择），焦点回到输入框，方便连续添加；
- 提交中按钮 loading，防止重复提交。

### 行内编辑

- 可编辑列（物流单号、收货人、联系电话、备注）在未锁定时，单元格内渲染 `DsInput` 组件；
- `DsInput` 使用 `variant="embedded"` 嵌入模式，`size="sm"`，填满单元格；
- 编辑缓冲（`editBuffer`）以 `Record<deliveryId, EditBuffer>` 形式维护，与原始数据独立；
- 失焦或回车时触发 `commitEditLine`，比对缓冲值与原始值，无变化则跳过提交，有变化则调用 `updateDelivery`；
- 提交失败时自动回滚缓冲值为原始值；
- 使用 `trackSave`（来自 `SaveStatusProvider`）包裹保存操作，统一管理行级保存状态指示。

### 视图锁定

- 锁定按钮显示当前状态：锁定中显示「解锁编辑」（primary 样式），未锁定显示「锁定编辑」（secondary 样式）；
- 锁定操作：直接调用 `lockDeliveryView`，无需确认；
- 解锁操作：弹出 `Modal.confirm` 二次确认（「解锁后所有交付记录将恢复可编辑状态，确定要解锁吗？」）；
- 锁定后：快录行隐藏、所有可编辑列变为只读文本、操作菜单 disabled；
- 锁定状态存储于 `documents.view_locks` JSON 字段中 `delivery` 键。

### WebSocket 实时联动

- 监听 `delivery.updated` 和 `document.status_changed` 事件，触发 `loadAll` 重新加载；
- 签收确认后若触发单据状态流转，通过 `document.status_changed` 广播通知其他视图。

### 范式归属

- **表格范式**：使用 `UnifiedTable` 组件，符合 Excel 超级表格与边用边扩展范式；
- **编辑范式**：行内嵌入编辑（`DsInput` variant=embedded），失焦/回车提交，符合「列表即编辑」范式；
- **快录范式**：顶部常驻快录行，回车即新增，替代弹窗新建，符合效率文档改造要求；
- **锁定范式**：视图级防误触锁定，符合效率文档§4 视图级防误触锁定规范。

## 与其他功能的关联

### 单据状态流转

当该单据所有交付记录均已签收（`allSigned = true`）时，后端自动调用 `applyTransition` 推进单据状态到 `delivery_completed`。若单据状态已为 `delivery_completed` 或 `archived`，则跳过推进。

### 运费（freight）

`delivery_records.freight` 字段（`decimal(14,2)`，默认 0）是三源汇集源3：按行金额比例分摊到 `cost_lines.freight`。当前前端界面未直接暴露此字段的行内编辑，但后端已预留字段和相关逻辑。

### 交付角色

系统中存在 `delivery` 角色（`roles` 数组中包含 `'delivery'`），该角色在默认权限矩阵中对 `delivery_fulfill` 视图具有 `rw`（读写）权限，对其他视图（采购报价、配货管理等）仅具有 `ro`（只读）权限。
