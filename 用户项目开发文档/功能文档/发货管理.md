# 发货管理（交付履约）

> 顶层依据：详见《顶层设计规范·理念4（表格唯一·交互统一）》《项目设计哲学·约束5（历史单据是法律事实·快照）》《项目设计哲学·原则3（按数据形态选交互·父子一对多→抽屉递进）》。

> **职责**：交付履约（发货管理）功能的唯一设计依据与逻辑轴心。单据主表/单据行结构与 8 档单据状态机的权威定义见《单据与状态机》，本文档只引用、不重述。
> **配套**：UI 交互总规范见 [表格与交互规范.md](../架构原则/表格与交互规范.md)。

## 功能概述

### 在业务流程中的位置

发货管理（交付履约）是八视图工作台中的交付环节，处于配货之后、成本核定之前：

```
采购报价 → 收款对账 → 配货 → 交付（当前视图）→ 成本 → 销售汇总 → 售后 → 归档
```

### 业务职责

为单据记录每一批次的交付信息（配送方式、物流单号、收货人、联系电话、签收凭证等），跟踪交付记录从待发货 → 已发货 → 已签收的完整流转，并在全部签收后自动推进单据主状态。

**设计原则**：

- **分批交付**：一个单据可有多个交付记录，支持分批、分方式发货；
- **子状态解耦**：交付记录子状态（`pending`/`shipped`/`signed`）与单据主状态（8 档状态机）解耦、可回退，不强制单向锁定；
- **签收联动**：该单据所有交付记录均已签收时，自动推进单据主状态到 `delivery_completed`；
- **快录行**：顶部常驻快录行，选择配送方式 + 输入运单号回车即新增，无需弹窗；
- **行内编辑**：物流单号、收货人、联系电话、备注在表格行内直接编辑，失焦或回车即保存；
- **视图级防误触锁定**：锁定后所有交付记录不可编辑，解锁需二次确认。

### 关联功能

| 功能 | 关联方式 |
|------|---------|
| 收款对账 | 单据状态 ≥ `allocation_in_progress`（配货中）后交付履约可用；录入宽松不强制状态拦截 |
| 配货 | 配货完成后，交付履约视图记录发货信息 |
| 成本核定 | 交付完成后，成本核定视图基于交付记录进行内部进货成本核算 |
| 单据状态机 | 全部签收后自动推进单据主状态到 `delivery_completed`（8 档状态机权威定义见《单据与状态机》） |
| 退换售后 | 单据进入售后环节后，退换处理以交付背景为基础 |

## 交付流程

整体交付链路与单据状态机档位的对应：

```
采购报价 → 收款对账 → 配货 → 交付 → 成本 → 销售汇总 → 售后 → 归档
```

单据状态机档位对应：1/2 采购报价、3 收款对账、4 配货、5 交付、6 成本、7 售后、8 归档（销售汇总是汇总视图，无独立档位；完整定义见《单据与状态机》）。

- **进入条件**：单据状态 ≥ `allocation_in_progress`（配货中）即可进入交付履约视图操作；
- **宽松口径**：录入宽松，不强制状态拦截——未严格到达配货中的单据也允许记录交付，业务顺序由人工保证；
- **交付完成**：该单据全部交付记录签收后，自动推进主状态到 `delivery_completed`。

### 交付记录子状态

`delivery_records.status` 为交付层子状态，与单据主状态解耦：

| 子状态 | 中文名 | 说明 |
|--------|--------|------|
| pending | 待发货 | 默认值，交付记录已建立 |
| shipped | 已发货 | 发货确认后进入，自动记录 `shipped_at` |
| signed | 已签收 | 签收确认后进入，自动记录 `signed_at` |

- 正向路径 `pending → shipped → signed`；
- 子状态可回退（如已发货回退为待发货），不强制单向锁定；
- `signed` 仅通过签收接口进入，不通过更新接口修改。

## 签收

签收是交付履约的关键动作：交付记录须先发货（`shipped`）方可签收；签收后自动推进单据主状态。

**签收流程（后端事务）**：

1. 校验当前子状态必须为 `shipped`，否则返回 422；
2. 更新交付记录 `status = 'signed'`、`signed_at = now()`；
3. 查询该单据所有交付记录，检查是否全部为 `signed`；
4. 若全部签收，best-effort 调用 `applyTransition` 推进单据主状态到 `delivery_completed`：
   - 当前主状态非 `delivery_completed` 且非 `archived` 时执行；
   - 使用乐观锁（`lock_version`）防并发；
   - 事务内执行，失败不影响签收操作本身；
5. 提交后广播 `delivery.updated`；主状态推进成功时额外广播 `document.status_changed`；
6. 记录审计日志（`delivery_sign`）。

> 签收推进为宽松语义：推进失败不阻塞签收，人工可在工作台手动推进主状态。

## 表结构

### delivery_records 交付记录表

交付履约视图标注表，关联单据 `documents`，一个单据可有多个交付记录（分批交付）。

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | BigInt, PK, AUTO_INCREMENT | 1 | 主键 |
| document_id | BigInt, NOT NULL → documents.id（ON DELETE CASCADE） | 100 | 所属单据（外键：delivery_records.document_id → documents.id） |
| delivery_method | delivery_method 枚举, NOT NULL | logistics | 配送方式（五枚举见下） |
| tracking_no | varchar(100), NULL | SF1234567890 | 物流单号 |
| receiver | varchar(100), NULL | 张三 | 收货人姓名 |
| receiver_phone | varchar(20), NULL | 13800138000 | 收货人联系电话 |
| status | delivery_status 枚举, NOT NULL, DEFAULT 'pending' | shipped | 交付记录子状态 |
| shipped_at | datetime(3), NULL | 2026-08-11T10:30:00.000Z | 发货时间（改为 shipped 时自动设置） |
| signed_at | datetime(3), NULL | — | 签收时间（签收确认时自动设置） |
| attachment_urls | JSON, NULL | ["https://..."] | 附件 URL 数组（签收凭证等） |
| note | TEXT, NULL | 注意轻拿轻放 | 备注 |
| freight | decimal(14,2), NOT NULL, DEFAULT 0 | 20.00 | 运费（三源汇集源3：按行金额比例分摊到 cost_lines.freight） |
| created_at | datetime(3), NOT NULL, DEFAULT now() | 2026-08-11T09:00:00.000Z | 创建时间 |
| updated_at | datetime(3), NOT NULL, @updatedAt | 2026-08-11T10:30:00.000Z | 更新时间 |

**索引**：`@@index([document_id])` / `@@index([status])`
**外键**：`document_id → documents.id`（ON DELETE CASCADE，单据删除时级联删除交付记录）

**delivery_method（配送方式）枚举**：

| 枚举值 | 中文名 |
|--------|--------|
| self_pickup | 自提 |
| haulage | 货拉拉 |
| special_van | 专车配送 |
| logistics | 物流托运 |
| site_delivery | 工地送货 |

**delivery_status（交付子状态）枚举**：

| 枚举值 | 中文名 | 标签颜色 |
|--------|--------|---------|
| pending | 待发货 | warning（橙色） |
| shipped | 已发货 | brand（品牌色） |
| signed | 已签收 | success（绿色） |

> 单据主表 `documents`（含 `view_locks`）与单据行 `document_lines` 为通用结构，见《单据与状态机》。单据编号格式统一 `YY-MM-DD-序号`（如 26-08-11-001）。

## 接口

全部接口挂载在 `/api/staff/` 下，需员工鉴权，按视图权限 `delivery_fulfill` 控制读写（ro 只读 / rw 读写）。

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/documents/:id/delivery` | `delivery_fulfill` ro | 查询单据的所有交付记录（按 created_at 升序） |
| POST | `/api/staff/documents/:id/delivery` | `delivery_fulfill` rw | 创建交付记录 |
| PATCH | `/api/staff/delivery/:id` | `delivery_fulfill` rw | 更新交付记录（含状态 pending ↔ shipped） |
| POST | `/api/staff/delivery/:id/sign` | `delivery_fulfill` rw | 签收确认（shipped → signed） |
| POST | `/api/staff/documents/:id/delivery/lock` | `delivery_fulfill` rw | 锁定交付履约视图（防误触） |
| POST | `/api/staff/documents/:id/delivery/unlock` | `delivery_fulfill` rw | 解锁交付履约视图 |

### 查询交付记录列表

`GET /api/staff/documents/:id/delivery`

**参数**：无（路径参数 `id` 为单据 ID）

**返回**：`DeliveryRecord[]`

```json
[
  {
    "id": "1",
    "documentId": "100",
    "deliveryMethod": "logistics",
    "trackingNo": "SF1234567890",
    "receiver": "张三",
    "receiverPhone": "13800138000",
    "status": "shipped",
    "shippedAt": "2026-08-11T10:30:00.000Z",
    "signedAt": null,
    "attachmentUrls": null,
    "note": "注意轻拿轻放",
    "createdAt": "2026-08-11T09:00:00.000Z",
    "updatedAt": "2026-08-11T10:30:00.000Z"
  }
]
```

### 创建交付记录

`POST /api/staff/documents/:id/delivery`

**请求体**：

```json
{
  "deliveryMethod": "logistics",
  "trackingNo": "SF1234567890",
  "receiver": "张三",
  "receiverPhone": "13800138000",
  "note": "注意轻拿轻放",
  "attachmentUrls": ["https://..."]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| deliveryMethod | enum | 是 | 配送方式 |
| trackingNo | string | 否 | 物流单号，最大 100 字符 |
| receiver | string | 否 | 收货人，最大 100 字符 |
| receiverPhone | string | 否 | 联系电话，最大 20 字符 |
| note | string | 否 | 备注，最大 500 字符 |
| attachmentUrls | string[] | 否 | 附件 URL 数组 |

**返回**：`DeliveryRecord`（status 默认为 `pending`），HTTP 201

**后端流程**：校验单据存在性 → INSERT（status 默认 `pending`）→ 广播 `delivery.updated` → 记录审计日志（`delivery_create`）。

### 更新交付记录

`PATCH /api/staff/delivery/:id`

**请求体**：

```json
{
  "trackingNo": "SF1234567890",
  "receiver": "张三",
  "receiverPhone": "13800138000",
  "status": "shipped",
  "note": "更新备注",
  "attachmentUrls": ["https://..."]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| trackingNo | string | 否 | 物流单号 |
| receiver | string | 否 | 收货人 |
| receiverPhone | string | 否 | 联系电话 |
| status | enum | 否 | 子状态调整（约束见下） |
| note | string | 否 | 备注 |
| attachmentUrls | string[] | 否 | 附件 URL 数组 |

**状态流转约束**：

- `pending → shipped`：允许，自动设置 `shipped_at = now()`；
- `shipped → pending`：允许（子状态与主状态解耦、可回退）；
- `→ signed`：不允许通过 PATCH 修改，签收走专用签收接口；
- 其余非法变更返回 422。

**后端流程**：校验交付记录存在性 → 非 status 字段直接更新 → 状态按上述约束调整 → 广播 `delivery.updated` → 记录审计日志（`delivery_update`）。

### 签收确认

`POST /api/staff/delivery/:id/sign`

**请求体**：无（仅路径参数）

**前置条件**：当前子状态必须为 `shipped`，否则返回 422（事务逻辑见「签收」章节）。

**返回**：

```json
{
  "id": "1",
  "documentId": "100",
  "status": "signed",
  "signedAt": "2026-08-11T12:00:00.000Z",
  "allSigned": true,
  "statusTransitioned": true
}
```

| 字段 | 说明 |
|------|------|
| allSigned | 该单据是否所有交付记录均已签收 |
| statusTransitioned | 是否自动推进了单据主状态到 `delivery_completed` |

### 锁定/解锁视图

`POST /api/staff/documents/:id/delivery/lock`
`POST /api/staff/documents/:id/delivery/unlock`

**请求体**：无

**机制**：在 `documents.view_locks` JSON 字段中设置键 `delivery`（snake_case 键名，字段结构见《单据与状态机》）为 `true/false`。

**返回**：

```json
{
  "documentId": "100",
  "view": "delivery",
  "locked": true
}
```

### 操作菜单（moreMenuRenderer）

| 当前状态 | 菜单项 | 行为 |
|---------|--------|------|
| pending | 「确认发货」 | 调用 `updateDelivery(id, { status: 'shipped' })`，成功后刷新列表 |
| shipped | 「签收确认」 | 调用 `signDelivery(id)`，成功后重新加载全部数据（签收可能触发单据状态流转） |
| signed | 无菜单项 | 已签收，无可操作项 |

锁定编辑时，所有菜单项 disabled。

### 交互细节

**快录行**：

- 常驻页面顶部，仅在未锁定编辑时显示；
- 配送方式下拉默认选中「自提」，可切换；
- 物流单号输入框可选，不填也可提交；
- 回车或点击「添加」提交；
- 提交后清空物流单号输入框（保留配送方式选择），焦点回到输入框，方便连续添加；
- 提交中按钮 loading，防止重复提交。

**行内编辑**：

- 可编辑列（物流单号、收货人、联系电话、备注）未锁定时渲染 `DsInput` 嵌入模式（variant=embedded, size=sm），填满单元格；
- 编辑缓冲（`editBuffer`）以 `Record<deliveryId, EditBuffer>` 形式维护，与原始数据独立；
- 失焦或回车触发 `commitEditLine`，比对缓冲值与原始值：无变化跳过提交，有变化调用 `updateDelivery`；
- 提交失败自动回滚缓冲值为原始值；
- 使用 `trackSave`（`SaveStatusProvider`）包裹保存操作，统一行级保存状态指示。

**视图锁定**：

- 锁定按钮显示当前状态：锁定中显示「解锁编辑」（primary），未锁定显示「锁定编辑」（secondary）；
- 锁定操作：直接调用 `lockDeliveryView`，无需确认；
- 解锁操作：`Modal.confirm` 二次确认（「解锁后所有交付记录将恢复可编辑状态，确定要解锁吗？」）；
- 锁定后：快录行隐藏、可编辑列变只读文本、操作菜单 disabled；
- 锁定状态存于 `documents.view_locks.delivery`（snake_case 键名）。

**WebSocket 实时联动**：

- 监听 `delivery.updated` 与 `document.status_changed`，触发 `loadAll` 重新加载；
- 签收确认触发单据状态流转时，经 `document.status_changed` 广播通知其他视图。

**范式归属**：

- 表格范式：`UnifiedTable`，符合 Excel 超级表格与边用边扩展范式；
- 编辑范式：行内嵌入编辑（`DsInput` variant=embedded），失焦/回车提交，符合「列表即编辑」范式；
- 快录范式：顶部常驻快录行，回车即新增，替代弹窗新建；
- 锁定范式：视图级防误触锁定，符合效率文档§4 视图级防误触锁定规范。

## 与其他功能的关联

**单据状态流转**：该单据所有交付记录均已签收（`allSigned = true`）时，后端自动调用 `applyTransition` 推进主状态到 `delivery_completed`；若主状态已为 `delivery_completed` 或 `archived` 则跳过。完整 8 档状态机见《单据与状态机》。

**运费（freight）分摊**：`delivery_records.freight` 在订单交付视图行内可改，按行金额比例分摊到 `cost_lines.freight`。不录入则分摊为 0。

**交付角色**：系统 `delivery` 角色（`roles` 数组中含 `'delivery'`）在默认权限矩阵中对 `delivery_fulfill` 视图具有 `rw`（读写）权限，对采购报价、配货管理等其他视图仅 `ro`（只读）权限。
