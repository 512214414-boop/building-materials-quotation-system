## 设计哲学与方法论

### 核心方法论：列表即编辑

产品管理列表是**唯一操作核心**。用户在列表上的每一个字段都应能够直接交互、修改或新增数据，无需频繁进入二级弹窗。仅当需要同时管理产品主体、多个品牌、单位换算、价格矩阵等复杂关联时，才通过「产品全名」列进入产品编辑弹窗进行统一配置。

推导原则：

- **先有界面，后有数据结构**：根据列表每一列的点击行为、弹出面板的内容、可编辑的粒度，反向确定需要哪些数据库表、字段和关联关系。
- **扁平化编辑**：列表中每个单元格均支持就地编辑或下拉面板编辑，面板内必须包含「检索 + 新建」能力，确保操作不断点。
- **Excel 式即时保存**：单元格输入后当场生效，无需额外点击保存按钮；输入有效数据后按 Enter 或失焦自动提交。
- **浮动面板约束**：所有子级浮动面板（单位/价格/分类/图片库）约束在父容器内，不溢出到画布之外；垂直方向空间不足时自动切换至锚点上方。
- **收敛统一**：同一交互能力只有一种实现（如分类面板、价格面板在列表与编辑弹窗完全同款）。

### 变体归属（数据模型总纲，v14.0）

> 数据层完整表结构/字段/关联以 [数据库新设计·产品数据层.md](./数据库新设计·产品数据层.md) 为唯一权威，本节仅作交互层总纲。

产品数据模型按「产品 → 规格变体 → 品牌/单位 → SKU → 价格/图片」层级组织：

- **`product`（产品）只存产品名**（含分类/备注/状态），规格型号拆至独立 `spec` 表（规格变体），一个产品可有多个规格；
- **品牌为全局独立档案**（`brand`，name 全局唯一），通过 `spec_brand`（规格×品牌关联）挂到规格——**每个规格的品牌各自独立**；改名全局生效；
- **单位挂规格**（`unit.specId`），单位名规格内共享、**不按品牌独立**；
- **换算系数按「规格×品牌」独立**（`brand_unit_conversion` 挂 `specBrandId`）；
- **售价类型全局共享**（`price_type` 字典表），**价格值按规格×品牌 + 单位私有**（`sale_price`）；
- **进价按规格×品牌 + 单位 + 供应商私有**（`purchase_price`），供应商为独立档案表（`supplier`）；
- **图片挂在规格×品牌上**（`product_image`），内容寻址存储（SHA-256 hash，同 hash 物理文件仅一份，可跨规格×品牌复用）；
- **SKU = 规格变体 × 品牌 × 单位**，三者组合唯一确定一个定价单元。

### 定档不变量（数据闭环，v14.0）

以下不变量是产品管理数据层的**底层约束**，前端交互与后端事务共同保证，任何改动不得破坏：

| 不变量 | 规则 |
|--------|------|
| 产品唯一 | `(categoryId, name)` 唯一；规格唯一 `(productId, specModel)` |
| 品牌唯一 | `brand.name` 全局唯一（全局档案）；同规格×品牌 `(specId, brandId)` 唯一 |
| 单位唯一 | 同规格下 `unit.unitName` 不重复 |
| 基础单位 | 同规格 **有且仅有一个** `isBase=true`（库存核算基准，换算率恒 1.0000） |
| 默认显示单位 | 同规格 **有且仅有一个** `isDisplay=true`（无则取基础单位；决定列表默认展示） |
| 换算记录 | 基准单位必有记录（×1）；规格×品牌未配置换算率的单位**不创建记录**（有就有，没有就没有） |
| 售价唯一 | `(specBrandId, unitId, priceTypeId)` 唯一；同 SKU 有且仅有一个 `isDefault=true`（无标记则首条自动为默认） |
| 进价唯一 | `(specBrandId, unitId, supplierId)` 唯一；同 SKU 有且仅有一个 `isDefault=true` |
| 主图互斥 | 有图必有且仅有一张 `isMain=true`（前端唯一 + 后端 saveProduct 兜底） |
| 图片文件 | 物理文件引用计数感知清理：同 hash 仍被任一 `product_image` 引用时禁止删除磁盘文件 |
| 宽表同步 | 规格×品牌/单位/价格/图片/分类/状态任一变更 → `product_sku_search` 即时重建，无孤儿无陈旧 |
| 停用过滤 | 搜索默认 `status=1`（仅启用），「全部状态(-1)」才返回停用产品 |

│ └─────────────────────────┘                                                  │
├──┬──┬──────┬──────┬─────────────────────┬──────┬─────────┬─────────┬──────┬────────┐

页面结构说明：

- **工具行**：左侧为全局搜索框（防抖 300ms 实时检索）+ 分类/状态筛选；右侧为「批量改价」「新增分类」「新增产品」等全局按钮。搜索无结果时表格首行固定显示「创建包含"xxx"的产品」入口。
- **数据来源**：列表直接读取 `product_sku_search` 宽表（每「规格×品牌」一行），经 `searchProducts` 检索返回，含默认单位 + 默认价格 + 主图缩略图等冗余字段，无需逐行二次请求。
- **表格内部**：除第一列「更多菜单」外，其他列均通过直接点击、原地编辑或弹出面板进行交互。

| 更新时间 | 108px | 只读，宽表 `updateTime` |

#### 更多菜单（第一列）

- **创建入口行**（首行，无对应 SKU）：菜单仅一项「新建产品」，点击打开编辑弹窗并预填当前搜索关键词。
- **SKU 行**：菜单含「编辑」（打开编辑弹窗并预选该品牌）→「停用 / 启用」（按当前状态切换，停用需确认，启用无需确认）→ 分隔线 →「物理删除」（危险操作，红色）。
- 交互风格对齐全局「更多菜单收敛到第一列」规范。

#### 删除与停用（产品维度）

- **删除 = 删除整个产品**（productId 维度，不是单个品牌）：确认弹窗明示「将删除整个产品，包括 N 个品牌、M 个单位、所有售价/进价/图片数据」；若已被单据引用，二次确认提示「该产品已被 N 个单据引用，删除后单据内容不受影响，但产品档案将无法查阅」；二次确认后级联清理产品库内部全部子表（单据保留快照不受影响）。
- **删除单个品牌**：在编辑弹窗的品牌切换区操作（「删除品牌」按钮）。
- **停用 / 启用**：仅状态变更，不清理任何数据；停用后搜索默认过滤，可从「全部状态 / 停用」筛选恢复启用。
- 停用产品行显示「停用」标签（橙色），启用产品不显示。

### 分类交互面板（行内编辑 + 筛选，统一面板）

列表分类编辑与编辑弹窗**完全一致**（用户「编辑产品中的分类下拉才是最合理的方式」指令），面板 = 分类检索输入框（SuggestInput）+ 分类管理表格面板（CategoryManagePanel）：

```
┌───────────────────────────────────┐
│ [搜索/新建分类..........]         │  ← SuggestInput(field=category) 检索已有 + 快速新建
├───────────────────────────────────┤
│ [输入新分类名称] [➕]             │  ← CategoryManagePanel 顶部新增区
│ 分类名称    │产品数│ 操作         │
│ 给水管      │ 120 │ [选择][✎][🗑] │
│ 未分类      │  10 │ [选择]        │
└───────────────────────────────────┘
```

交互规则：

- 顶部输入框：键入文字检索已有分类（含「新建分类」项），选中即提交应用；也可直接输入新名称快速新建（同名幂等）。
- 表格面板：全量分类列表（分类名称 / 产品数 / 操作），点击分类名或「选择」直接应用；行内可重命名、删除；顶部可新增。删除时产品数 > 0 禁止（提示先迁移）。
- 分类为 SPU 级属性：修改后该产品所有品牌行同步更新；**分类改名会同步重算全部宽表行的 `categoryName` 与 `keywords`**（检索与展示即时一致）。
- **分类筛选同款面板**：工具栏「按分类筛选」弹出同样面板，选择后按钮回显 `分类：{名称}` 并附「清除筛选」；「未分类（categoryId=0）」可通过检索项筛选。

### 产品图片交互面板

- **列表缩略图**：点击 → 大图预览（原图），不再打开编辑弹窗（快速查看样式）。
- **图片管理**：在编辑弹窗「产品图片区」内完成（上传 / 设主图 / 删除 / 从图片库选择）。图片属于品牌，切换品牌显示不同图片。
- 上传链路：前端预压缩 → `uploadProductImage`（后端 sharp 生成 原图1280 / 中图600 / 缩略图200 三版本 WebP + 计算 SHA-256 hash）→ 元数据随 `saveProduct` 落库。
- 主图互斥：同品牌有且仅有一张主图；删除主图自动晋升第一张；后端保存兜底（多主图收敛为第一张、无主图首张自动晋升）。
- **物理文件安全**：删除图片/品牌/产品前检查该 hash 的剩余引用数，仅剩 0 引用才删除磁盘文件（图片库复用的共享文件不误删）。

#### 从图片库选择（内容寻址复用）

图片内容寻址存储（SHA-256 hash，同 hash 物理文件仅存一份）。编辑弹窗「图片库选择」打开选择弹窗，选择已有图片仅新建 `product_image` 记录指向相同 URL，无需重复上传。

```
┌──────────── 从图片库选择 ──────────────┐
│ [🔍 搜索 产品名/品牌/规格/分类] [分类▾] │  ← 关键词检索 + 分类筛选（含数量）
├────────────────────────────────────────┤
│ 给水管材 (12) ───────────────────      │  ← 默认按分类分组显示
│ [img][img][img][img]                  │
│ 排水管材 (5) ────────────────────      │
│ [img][img]                            │
└────────────────────────────────────────┘
```

- **上下文接入**（用户「从图片库选择优先填入当前分类 / 按当前产品名模糊匹配」指令）：从产品编辑弹窗打开时，分类筛选**默认置为当前产品所属分类**，检索框**预填当前产品名**（自动聚焦全选，直接输入即替换）——同款产品图片大概率同图，打开即看到最相关的图片；分类为 0（未分类/新建）不应用分类默认过滤；上下文仅为初始值，用户可随时清除/切换。
- **检索与分组**：**关键词检索复用产品检索同一套打分逻辑**（v1.5.6.3 定档）——前端 `scoreSkuByCustomWeights`（与后端 `search-scoring.ts` 双端 SSOT）三层打分（完整级 > 语义段级 > 2-gram token 级），支持乱序碎片（`弯25`→弯头）、跨字段组合（`伟星6分`）、规格点号（`25给水3.5`→en3.5）等松匹配，`score>0` 过滤 + 分数降序排列，最相关图片排最前；分类下拉含数量、未分类排最后；默认「全部分类」按分类分组展示（分类头 + 数量 + 图片网格）。
- **卡片**：缩略图（点击大图预览）+ 引用数徽标（同 hash 被多少品牌复用）+「使用此图」按钮。
- 数据源：`listProductImageLibrary` 按 hash 去重返回全部图片（代表记录 + 品牌/产品/分类信息），前端本地过滤（单一实现）。
- **统一原则**：**所有查询产品数据的检索点共用同一套打分逻辑**——服务端 `searchProducts`（后端 search-scoring）与客户端本地检索（图片库等，前端 search-scoring 双端 SSOT）逻辑完全一致，禁止为某处检索重新设计独立匹配规则。

### 单位下拉面板

```
┌─ 单位管理 (伟星 ppr DN25给水管) ─┐
│ 单位名：[   ] 换算系数：[   ] [添加] │
│ ─ 已存在单位 ────────────────── │
│ ┌────────┬─────────┬──────┬───┐ │
│ │单位名  │换算系数 │基准  │操作│ │
│ ├────────┼─────────┼──────┼───┤ │
│ │米      │1.00     │●基准 │    │ │
│ │根      │3.00     │○     │删除│ │
│ │捆      │75.00    │○     │删除│ │
│ └────────┴─────────┴──────┴───┘ │
│ (点击单位名称切换列表显示单位)    │
└───────────────────────────────────┘
```

交互规则：

- **单位名称 SPU 共享，换算系数按品牌独立**：面板展示的是**当前 SKU 品牌**的换算率；删除单位级联删除该单位下所有品牌的价格数据。
- **换算口语化**：列表单位下拉的换算文字按实际基础/中间单位名推导（米 →「一米」、根 →「3米每根」、捆 →「25根每捆」），不硬编码「米」——非管材产品（涂料按桶、瓷砖胶按包）同样口语化正确。
- **闭环不变量**：每个品牌 × 基准单位必有换算记录（×1）；品牌未配置换算率的单位不创建记录（列表据此隐藏）；切换基准单位时全部品牌换算率按各自新基准归一化。
- 基准单位不可删除（须先设置其他单位为基础）；基础单位用于库存核算，换算率固定 1。

### 售价 / 进价明细面板（UnitPriceExpandPanel）

售价列与进价列共用同一个价格明细面板（`UnitPriceExpandPanel`，列表与编辑弹窗同款），顶部左侧 Tab 切换「售价明细 / 进价明细」，右侧为当前行单位切换。

- **售价明细**：`价格类型 | 售价 | 默认 | 操作` 4 列 + 末尾空行。价格类型来自全局 `price_type` 字典（可检索/新建），价格值按品牌 + 单位私有；「默认」单选控制列表售价列展示（同 SKU 互斥）。
- **进价明细**：`供应商 | 面价 | 点位 | 进价 | 默认 | 操作` 6 列 + 末尾空行。
  - **面价列**（可编辑录入）：录入值即面价，点位变化永不改变；
  - **点位列**（点击按钮）：打开「批量调整进价」对话框，自动带入当前产品上下文（供应商+品牌+分类锁定），调整后重载当前产品价格；
  - **进价列**（只读展示）：`面价 × 点位`（点位来自 `supplier_point_rule`，无规则默认 1）；
  - **默认**：同 SKU 互斥，控制列表进价列展示。
- 价格面板数据：`getSkuOptions(specBrandId)`（v14.0）一次返回该规格×品牌全部单位 + 各单位全部售价/进价 + 换算率，前端行内独立维护（各行互不影响）。
- 面板关闭时自动保存修改（编辑弹窗内随 saveProduct 全量保存；列表内即时更新）。

## 批量调整进价（点位模式）

### 解决什么问题

供应商发来的是「面价表」（系列/名称 + 规格型号 + 单位 + 面价，如 PPR 报价表），**进价 = 面价 × 点位**（伟星×0.8、日丰×0.58）。面价很少变，**点位会变**；点位一变，对应供应商、品牌、分类的一整批产品进价全要跟着改。本功能按「**供应商 + 品牌名 + 分类名**」圈组，**只更新点位规则**，进价随新点位自动派生，不重算面价。

> **v12.0 定价语义（定档）**：`purchase_price.price` 存**面价**（录入值，点位变化永不重算）；进价 = 面价 × 点位（点位来自 `supplier_point_rule`，无规则默认 1）；面价录入入口在「进价明细」面板。

### 入口与交互流程

入口：列表页工具行「批量改价」按钮；或进价明细面板「点位」按钮（自动带入上下文，条件锁定）。

1. **圈组三条件**（均用 SuggestInput 检索选择，不允许新建）：供应商（必选）、品牌（必选）、分类（必选）。
2. **旧点位自动带出**：三条件齐了自动请求 `GET /purchase-prices/point-rule`，有规则自动填入旧点位。
3. **填新点位**：进价 = 面价 × 新点位（面价不变，进价自动派生）。
4. **预览**：显示「共 N 条进价」+ 前 5 条改前/改后示例（新价红色）。
5. **确认调整**：预览成功后才可确认；执行后只更新 `supplier_point_rule` + 刷新宽表 `purchasePriceDefault`，写 audit 日志，列表自动刷新。

### 点位规则（supplier_point_rule）

- 唯一键：**供应商 + 品牌名 + 分类名 → 点位**（挂供应商维度，无物理外键 + supplierName 快照，对齐解耦规范）。
- **品牌名/分类名粒度由人控制**（不增层级）：同品牌不同系列点位不同 → 品牌名录细；管材/管件点位不同 → 分类名录细；点位一致 → 名录粗，一个组一条规则。
- 调整成功后自动写入/更新该组规则，**下次旧点位自动带出**，只需输新点位。
- 前端/后端有效进价计算统一走 `calcEffectivePrice`（单一实现 SSOT）。

## SKU 检索宽表与产品搜索

### 宽表 product_sku_search

> **表结构与索引**：以 [数据库新设计·产品数据层.md](./数据库新设计·产品数据层.md)「product_sku_search 检索宽表」章节为准（v14.0：每「规格×品牌」一行，含 specId/specBrandId，唯一索引 specBrandId）。本节只描述检索行为。

- 默认单位取值：`isDisplay=true` 的单位；无则取 `isBase=true`

### 宽表同步时机（全量覆盖）

| 时机 | 操作 |
|------|------|
| saveProduct 事务提交 | 重建该产品全部规格×品牌宽表行 |
| 新增/删除/更新规格×品牌 | 重建该规格×品牌宽表行 |
| 产品名/规格/分类/状态变更 | 重建该产品全部宽表行 |
| **分类改名** | 同步该分类全部宽表行（categoryName + keywords 重算） |
| 单位 isBase / isDisplay 变更 | 重建该产品规格宽表（默认单位 + 价格） |
| 售价/进价 增删改 | 重算 retailPrice / purchasePriceDefault |
| 主图变更 | 更新 mainImageUrl / mainImageThumbUrl |
| 批量改价（点位变更） | 只更新点位规则 + 重算 purchasePriceDefault |
| 停用/启用产品 | 同步宽表 status（综合状态） |
| 删除品牌/产品 | 清理对应宽表行 |

### 产品搜索链路（searchProducts）

搜索返回：首条固定 `creation_prompt`（创建入口，不计分页）+ SKU 行列表。

**召回阶段**（候选集 LIMIT 500，应用层再精确排序）：

| 路径 | 触发条件 | 说明 |
|------|---------|------|
| LIKE 直达 | 单字符 / 纯数字+标点短规格（`3.5`、`253.5`）/ 短 ASCII 词（`ppr`、`dn25`、`pvc`） | 语义段 ∪ ngram token 参数化 OR 匹配（`%`、`_` 转义防通配符污染） |
| FULLTEXT 主路径 | 其余关键词 | `MATCH(keywords) AGAINST(? IN BOOLEAN MODE)`（无 50% 阈值；去除 BOOLEAN 操作符字符） |
| LIKE 回退 | FULLTEXT 0 召回 | 覆盖短 ASCII token 未入索引 / 词频过高 / 局部索引缺失 |

**打分阶段**（三层权重，`search-scoring.ts` 纯函数，27 例单元测试覆盖）：

1. **完整关键词级**（最高）：用户输入与字段 顺序一致/完全包含 → 品牌 8000/5000、产品名 7000/4000、规格 6500/3800、备注 3000/2000、分类 2500/1500；
2. **语义段级**（中）：输入按字符类型切段（中文/字母/数字含点号斜杠），任一段在 keywords 全串包含即加 段长×150——覆盖乱序碎片、跨字段组合、省略中间文字；
3. **2-gram token 级**（基础）：跨字段碎片命中累加，品牌 > 产品名+规格 > 备注 > 分类。

**关键规则**：

- **打分用原始关键词（保留点号）**：`3.5` 的点号是规格（en3.5）关键字符，仅 FULLTEXT 召回去标点，打分必须保留——保证「25给水3.5」精确命中 en3.5 排最前。
- **排序**：score DESC → updateTime DESC。
- **过滤 0 分行**：召回但未通过应用层匹配的噪声行剔除。
- **安全**：LIKE 全部参数化（防 SQL 注入）；纯标点关键词返回空结果。
- **公开端剥离**：员工端 `/api/staff/products/search` 与公开端 `/api/products/search` 共用实现，无员工身份时剥离 `purchasePriceDefault`。

## 保存逻辑（saveProduct 事务）

### 前端校验

- 产品名称、规格型号非空；规格与同产品名下其他规格不重复；
- 至少一个单位；必须有一个基准单位；
- **已存在品牌（有 id）名称为空时阻止保存**（防静默剔除导致级联整删品牌）；
- 全品牌为空时自动补默认品牌「普通品牌」。

### 后端事务流程

```
1. 前置校验：单位 ≥1；有且仅有一个基础单位；分类有效性
2. 编辑模式：查询"被删除的品牌/单位"差集 → 手动清理宽表孤儿行 → 级联删除
3. product 建/改：
   - 新建：应用层 generateProductId() 生成 BigInt 主键
   - 编辑/新建均做 (categoryId, name, specModel) 唯一性预检（编辑排除自身）→ 422 友好提示
4. brand 建/改（含品牌级 remark）：
   - 图片"先删后建"：强制主图唯一（尊重已选主图，多主图收敛第一张、无主图首张晋升）
   - 新建品牌冲突（@@unique）时查找既有（幂等）
5. unit 建/改：确保有且仅有一个 isBase、有且仅有一个 isDisplay（无则取基础）
6. brand_unit_conversion：
   - 删除该品牌旧换算记录 → 显式重建基准 ×1 → 按载荷重建非基准有效换算（拒绝空/非法率）
7. 售价/进价"先删后建"：
   - 客户端去重（同 brandIdx+unitIdx+priceTypeId/supplierId 仅保留首条）
   - isDefault 互斥：同 SKU 取首条标记为默认，未标记自动首条为默认
   - 进价填充 supplierName 快照
8. 事务提交 → 重建该产品全部宽表行
9. 图片文件差集清理：仅删除"旧 URL − 本次仍引用 URL"且整库 0 引用的物理文件
```

### 数据安全（定档加固）

- **图片文件保护**：差集 + 引用计数双重校验，编辑保存不误删仍被引用的图片；
- **单位删除重映射**：前端删除中间单位时剩余价格行 `unitIdx` 降位重映射，价格不挂错单位；
- **基准切换归一化**：切换基准单位时全部品牌换算率按各自新基准归一化；无换算率的品牌清空非基准率（不产生「1米=1根」矛盾语义）；
- **防重复提交**：前端 `savingRef` 同步锁 + 后端交互式事务回滚。

## 单据-产品库解耦设计

> 章节定位：v11.0 解耦在产品管理层面的设计依据；数据库层与接口契约以 [数据库新设计·产品数据层.md](./数据库新设计·产品数据层.md) 为准。

### 设计原则

1. **产品库仅作录入工具数据源**：核心作用服务于订单快速录入、价格自动带出，不是历史单据的依赖载体；
2. **历史单据闭环**：单据保存后即成为闭环交易记录，产品库后续修改/删除无法篡改过往单据内容与统计；
3. **双存储机制**：单据保存时同时存快照（产品名/规格/分类/进价等文字信息）+ ID 留存（产品全局唯一 ID），单据展示完全脱离产品库当前状态。

### 产品ID 生成规则

`product.id` 由应用层时间戳生成（Snowflake 简化版）：`epochMs × 1_000_000 + RND(6位)`，当前 19 位 BigInt（距上限有 80% 余量），全局永久唯一，删除后不复用；schema 保留 `@default(autoincrement())` 仅作 DB 兜底，应用层 `createProduct/saveProduct/quickCreateProduct` 显式覆盖。

### 停用 / 启用与物理删除

- **停用**：`product.status=0` + 宽表 `status=0`，搜索默认过滤，可恢复；
- **启用**：`product.status=1` + 宽表按「SPU启用 且 品牌启用」重算综合状态；
- **物理删除允许**：即便被单据引用也可删除（前端二次确认 + 引用计数提示），级联清理产品库内部全部子表，单据快照不受影响；
- **单据跳转容错**：产品已删除时显示「该产品档案已移除」空状态卡片，单据其他功能不受影响。
