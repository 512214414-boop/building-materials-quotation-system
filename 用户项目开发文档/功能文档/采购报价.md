# 采购报价

> **职责声明**：本文档是「采购报价」（需求确认 + 报价核算合并视图）的唯一设计依据。单据/单据行表结构、单据编号、8 档状态机见《单据与状态机》；选品建档见《产品数据层》；表格/录入/浮动面板通用交互规则见《表格与交互规范》；权限码唯一清单见《系统管理》。

## 功能概述

「采购报价」是**九视图协同工作台**的第一个视图（V1），也是整个单据生命周期的起点。需求确认与报价核算两个环节已合并为统一的采购报价视图：员工在此录入客户物料需求明细（产品名称、规格、数量、单位），并为每条物料行填写售价、汇总整单金额（含优惠、税额、应收）。售价直接落在单据行（`document_lines`）上，不存在独立的报价行表，消除冗余同步。

```
单据创建 → 采购报价（本文档范围）
  ├── 待确认（pending）：报价未完成，行可编辑
  └── 已确认（confirmed）：报价锁定，售价对客户可见 → 进入后续环节
        └── 配货 / 交付履约 / 成本核定 / 收款对账 / 退换售后 / 销售汇总
            （单据全局 8 档状态机见《单据与状态机》）
```

### 报价阶段状态

报价阶段状态（`stage_status` 三态）与单据全局状态的联动关系：

| 状态 | 枚举值 | 示例场景 | 说明 |
|------|--------|---------|------|
| 待确认 | `pending` | 单据创建、行明细录入中 | 行可编辑；单据全局状态同步为 `demand_pending` |
| 已确认 | `confirmed` | 报价定稿，售价对客户可见 | 行锁定；单据全局状态同步为 `quote_confirmed`，进入后续环节 |
| 作废 | `voided` | 单据作废 | 不可编辑；不同步全局状态 |

### 核心设计原则

- **单一事实源**：售价保存在单据行（`unitPrice`/`lineDiscount`/`amount`），无独立报价行表。
- **行内编辑即保存**：单元格失焦/回车即发起保存，无「统一保存」按钮。
- **空行即新增**：表格末尾常驻完整空行，输入有效值后自动升级为真实行。
- **价格可见性**：仅报价阶段已确认时客户端才可见售价，未确认前金额字段隐藏。
- **视图级防误触锁定**：支持手动锁定/解锁编辑，锁定后所有单元格不可编辑（作废单据自动锁定）。

## 单据行录入交互

- **行内编辑即保存**：数量/单价/备注列点击进入编辑态，失焦/回车即提交，无「统一保存」按钮；**Enter 只保存不自动展开**——提交文字后不再自动弹出任何面板，需要检索档案时由用户主动点下拉箭头（第一遍录入多为简略信息，先快录后核对）。
- **空行即新增**：表格底部空行 id 为空、序号为当前行数 + 1，编辑任意字段后失焦触发新增行，创建成功后追加到行列表末尾。
- **键盘导航**：Enter 提交+下移 / Tab 右移 / Esc 回滚 / 方向键移动；备注列 Enter 保存、Shift+Enter 换行；业务条与税额面板输入框 Enter 或失焦保存。
- **数字列普通输入**：数量/单价列用普通输入框 + 数字键盘，禁用原生数字控件（光标跳、滚轮误改）。
- **临时数据不清 ID**：价格/数量是临时数据，变更一律不清 SKU 关联 ID（仅产品全名列文字变更才清空，见「产品列交互」）。
- **保存状态提示**：所有 API 调用统一追踪保存中/成功/失败状态。
- **视图级锁定**：锁定后所有单元格不可编辑；作废单据自动锁定、不可解锁；锁定按钮文字动态切换「锁定编辑」⇄「解锁编辑」；锁定状态持久化于 `view_locks.purchase_quote`（`view_locks` 键名统一 snake_case，视图键清单见《单据与状态机》）。
- **实时同步**：通过实时通道监听行更新、状态变更事件自动刷新数据，支持多人多设备协同编辑同一单据。

## 产品列交互

产品名称/规格列是 `picker` 列，`dropdown` 触发模式——**自由输入 + 下拉箭头**，下拉触发选品面板检索产品库。

- **wrap 换行（超长完整可见）**：产品列声明换行模式，列宽恒为设计值（220px，内容不参与列宽计算），超长产品名**自动换行完整可见**（禁止省略号截断），行高自适应；短文本单行不增高，不影响密集录入。
- **编辑态列宽稳定**：编辑态输入框**撑满单元格原本内容区**（与文本态显示区一致），右侧辅助图标（清空/下拉箭头/收起）**绝对定位悬浮**在单元格右缘、不占流式宽度；输入控件不带额外内边距/边框改变视觉宽度，辅助反馈由单元格光晕统一提供——状态转换前后列宽不变。
- **展开箭头稳定性**：下拉箭头在展开前后保持原位置（单元格右侧）——非激活态显示展开图标，面板打开时变「收起」图标，点击即收起面板。**在哪里展开就在哪里收起**，箭头不因面板开关而消失/闪现（全局生效：产品/单位等所有 dropdown picker 列）。
- **非标行黄标「待确认」**：自由输入文字（非从产品库选择）→ 保存为 `productRef` 文字，同时清空 SKU 关联 ID 并标记非标；行内显示黄色提示图标「待确认：未匹配档案记录」。点击「待确认」图标或下拉箭头 → 打开选品面板 → 选中档案升级为标准行（ID 回填、快照刷新）。
- **清空 ID 唯一条件**：**仅产品全名列文字变更**才清空全部 SKU 关联 ID（`specId` 归 0、`productId`/`brandId`/`unitId` 置空）并标记非标；价格/数量/单位等临时数据变更一律不清 ID。
- **下拉箭头检索**：编辑态点下拉箭头 → 以**当前输入框文字**作为面板初始关键词（不先保存、不覆盖行内已保存值，选中档案后整行更新）；非激活态点箭头 → 以记录显示值作为初始关键词。
- **点击候选行 = 所见即所得**：实时匹配列表每行显示「产品全名 | 单位 | 售价 | 进价」，**点击行就插入行上显示的内容**（面板内单位/价格可切换，显示什么就插入什么）——**单价取值链：默认售价 → 推算售价 → 行上显示的进价（兜底）→ 0**。售价未录时单价不再插入 0，而是插入行上可见的进价数字（报价参考价，用户可再调整）；点售价/进价「插入」按钮用所选价。
- **单价来源着色**：单价单元格按**来源**着色（纯前端行状态，不落库）——进价（售价未录兜底/点进价插入）→ **红色**；推算售价（基准单位价 × 换算率）→ **推算色**；真实售价（档案默认售价/点售价插入）→ 普通色；手输单价 → 来源清除普通色。统一遵循「推算/非真实数据必须颜色区分」，防止把进价/推算价当真实售价报给客户。
- **清除按钮**：编辑态和非激活态均有清除按钮（有值即显示）。
- **非激活态**：显示商品全名，空值显示占位符。

## 单位列交互

单位列与产品列视觉/交互一致：**文本自由输入 + 下拉箭头**（dropdown 模式）。

- **文本自由输入（快速录入）**：点击单位文字进入编辑态直接输入，失焦/Enter 提交。
  - **标准行（有 `specId`）**：输入的单位名已在该规格单位列表内 → 自动绑定其单位 ID；不在列表内 → **建档前弹「新增单位」确认**（「该产品暂无单位『X』，确认新增到该产品档案？」）——确认 → 建档并绑定新单位 ID；取消 → 不建档不绑定，保留原值并提示。防止误录/乱输在不知不觉中给产品累积垃圾单位，让用户感知「输入的单位不存在，系统将新建档案」。
  - **非标行（无 `specId`）**：纯文字保存（不关联档案，无档案可挂，不涉及建档无需确认）。
- **下拉箭头展开单位面板**：
  - **标准行**：加载该规格**全部单位**（含价格/换算率）。从列表选已有单位 → 回填单位 + ID + 该单位对应价格；输入新单位名 → 面板「新增到该产品」/失焦/Enter → 建档前同样弹「新增单位」确认；该规格下同名单位已存在 → 直接绑定（**不再弹确认**，非建档无写行为）。
  - **非标行 → 常见单位列表**：产品未建档时全局检索档案单位没有意义（输入「米」返回一堆含「米」的单位全是已存在），改为展示**预设常见单位**（米/厘米/毫米/平方米/立方米/升/个/件/箱/包/卷/捆/张/套/台/公斤/千克/克/吨/支/根/条/块/片/副/对/双/次，共 28 个）：空关键词 → 显示全部直接点选（快速录入）；输入关键词 → 在常见单位内**本地过滤**（无网络检索）；无匹配 → 「快速新建」纯文字。冷门单位直接输入新建，无需滚动长列表。
- **展开显示全部单位**：面板打开时初始关键词 = 当前单位值，但**初始关键词不参与过滤**（仅用户修改过输入才过滤）——标准行展开展示该规格**全部单位**（当前单位「米」不再把其他单位过滤掉），非标行展示全部常见单位；用户输入新关键词后才过滤。
- **单位面板显示换算链**：非基础单位按**换算率逐级转换**显示——单级「1 根 = 3 米」；多级「1 捆 = 20 根 = 60 米」（相邻级 + 兜底绝对换算）；基础单位显示「(基准)」；只纳入已配置换算率的单位，换算关系未知的不显示。
- **换单位自动插入对应价格**：换单位 = 换该单位行情价，按取值链自动带出（对齐产品选品）：**该单位默认售价 → 推算售价 → 进价兜底 → 0**，并按来源着色（售价普通/推算色/进价红）——换单位后单价立即对齐新单位行情，无需再手动改；无价格单位 → 0（空待录）；新建单位（无价格）→ 0。
- **换单位绝不清空产品关联 ID**：仅产品全名列文字变更才清空关联 ID。

## 选品与建档

### 选品与快照填充

从产品库选择商品时：

1. 前端组装商品全名（`productRef` = 产品名 + 品牌 + 规格型号）、**SKU 关联四件套**（`specId`/`brandId`/`productId`/`unitId`）、单位文字、规格文字、缩略图，标记标准化。
2. **选品自动带出单价**：`unitPrice` 从该 SKU 售价矩阵带出（用户点击的具体售价 > 默认售价 > 推算价 > 0）。单价是**临时数据**（议价场景可改），选品只负责带出默认值，后续可随时调整。
3. 后端按四件套反查产品档案，将 5 个独立快照字段（产品名/品牌名/分类名/规格型号/单位名）写入单据行——**快照锁定**，产品档案后续修改或删除不影响单据行展示。

### 产品数据使用-引用-修改矩阵（权威定义）

单据行消费产品库数据的完整语义，后续环节（配货/成本/收款等）沿用此矩阵：

| 产品库数据 | 订单行用法 | 引用方式 | 可否修改 | 修改的影响 |
|-----------|-----------|---------|---------|-----------|
| 产品名/规格/品牌/单位 | 展示、打印、对账 | 快照锁定（独立快照字段） | 行内可改文字，改后清空关联 ID 变非标 | 仅当前行，不影响产品档案 |
| 产品/规格/品牌/单位 ID | 统计聚合、库存扣减、成本核算维度 | ID 留存（`specId` 兜底 0=未关联） | 随选品/补全绑定、随改名清空 | 仅当前行 |
| 默认售价 | 带入单价 | 快照带入后独立 | 可改（议价/行优惠） | 仅当前行，不带回档案 |
| 分类 | 统计维度 | 快照 + ID | 不改 | — |
| 缩略图 | 展示 | URL 快照 | 不改 | — |
| 行级附加字段 | 备注/行优惠/AI 识别原始描述 | 单据行自有，档案无对应 | 可改 | 仅当前行 |

**三条铁律**（本环节闭环验收标准）：
1. **引用锁定**：下单时快照产品库文字信息，产品库后续改名/删除不影响历史单据。
2. **ID 留存**：统计/扣减/核算一律基于行内 ID 聚合，不实时关联档案主表。
3. **仅产品名断链**：只有产品全名列文字被修改才清空全部 SKU 关联 ID 变非标；价格/数量/单位为临时数据，变更一律不清 ID（换单位按「单位列交互」补充档案语义更新）。

### 快速建档（二次确认弹窗）

用户在选品面板点击「新建『关键词』」时，**不再直接建档**，一律弹出「快速新增产品」二次确认窗口——所有新建档案入口的统一范式：

- **底层分开存储（核心语义）**：产品名称/品牌/规格型号/单位是**独立字段**，产品名绝不等于完整商品全名拼接串（产品名+品牌+规格）。把完整串整体当产品名 → 再次输入同名 → 又把完整串当产品名 → 在「普通品牌」下叠加出「普通品牌·通用」重复建档（例如「XXX 普通品牌 通用」变成「XXX 普通品牌 通用 普通品牌 通用」）。
- **弹窗字段分开编辑**：产品名称（必填，预填触发关键词，可修改/补全）+ 品牌（预填「普通品牌」）+ 规格型号（留空）+ 单位（留空）。
- **保存 = 缺省值二次确认**：点击「保存」→ 校验必填 → 收集「系统将自动补充」清单（规格型号未填 → 补「通用」；单位未填 → 补「件」；品牌未填 → 补「普通品牌」）→ 二次确认弹窗：**确认保存** → 建档（后端宽表组合去重幂等，见下）→ 建档结果组装选品四件套 → 选中写入当前行；**返回继续编辑** → 留在弹窗补齐字段。缺省值统一见《数据规范·缺省值注册表》。
- **宽表组合去重（幂等核心）**：产品是复杂多表结构（产品/规格/品牌/单位/规格品牌关联），去重**不在各分表分别比对**（分字段比对遇字段错位永远匹配不上 → 误判新增 → 重复建档），而是在冗余宽表上按**组合完整值**精确比对：去空格(产品名) + 去空格(规格型号) 完全一致即视为同一条，直接复用已有档案（字段错位如产品名「XX25」+ 规格空 vs 档案产品名「XX」+ 规格「25」，组合值都是「XX25」→ 命中复用）。组合候选（按优先级）：① 原始输入组合（规格原样参与，空则空）——处理字段错位；② 空规格时补「通用」的组合——处理「只录产品名」的空规格幂等。命中选择：同组合多品牌行时优先复用输入品牌对应的行，无则取第一条；单位按输入名在该规格下查找/创建。
- **相似档案匹配度决策**：精确同一（组合完整值相等）与完全无关之间是灰度地带——产品名长、输入与档案近似但不相等，系统无法自判「就是同一条还是不同产品」，**把决策权交给用户**：
  - **匹配目标 = 档案全名（产品名+规格+品牌，去空格小写）**——用户口语里的品牌词必须参与匹配；
  - **相似度** = max(语义段覆盖率, 2-gram token 覆盖率, 编辑距离, 完整包含比例)。**语义段覆盖率**为主：输入按字符类型切段（中文/字母/数字），段在档案全名**子序列命中（容错）**即算中（段长 ≥3 容忍差 1 字符，段长 ≤2 必须全部命中），命中段总长 / 输入段总长，仅当命中段数 ≥2 才启用（单段命中会候选泛滥）；**2-gram token 覆盖率**处理中文连写不分词（「伟星水管」被切为单段 → 段覆盖率被禁用）；纯编辑距离对「口语乱序 + 长短差异」不友好，仅作兜底；
  - **候选召回**：复用全局检索召回通道（全文索引 ∪ 任意位置包含**合并去重**）——口语输入前缀常不在档案名开头（输入「伟星绿色25给水管」vs 档案「ppr DN25给水管」开头是 ppr），禁止前缀匹配直接召回；全文索引对无空格中文长串是短语匹配（token 连续才命中）常 0 召回，任意位置包含才是可靠通道，两者合并保证不漏召回；候选集受控（见《数据规范·规模驱动设计》）。
  - **三段决策**：精确同一 → 静默复用（无歧义）；匹配度 **≥ 60%** → 返回候选列表（最多 3 条，含匹配度，**零副作用**——不建任何档案/单位），用户点「复用」直接选中该档案，或点「仍要新建」强制建档；**< 60%** → 视为新品静默新建。
  - **候选排序**：匹配度降序 → 命中段数降序 → 全名长度与输入接近者优先。
- **自动写行为可感知**：系统高度灵活（不设限，什么都能录），但**自动产生的写行为必须让用户感知到**，否则用户不知道底层逻辑、随手乱输会在不知不觉中累积几十条垃圾档案：
  - 后端建档结果携带 `reused` 标识：**精确命中已有档案复用 = `reused: true`**；实际新建 = `reused: false`；候选元素恒为 `reused: true`（本就存在，非新建）。
  - 保存后按 `reused` 提示：精确命中 →「已匹配到现有档案，直接使用（未新建）」；点候选「复用」→「已使用现有档案『档案全名』」；真正新建 →「新建档案成功」。告别静默复用。
- **弹窗宿主**：二次确认弹窗挂在**视图层**，禁止挂在浮动面板子树内（面板失焦关闭会卸载弹窗）；选品面板的快速新建回调为**必传**，仅上抛关键词，面板内不再有任何直接建档代码。
- **弹窗统一定位**：所有二次确认弹窗（缺省值确认/相似档案候选/新增单位确认等）统一相对**画布**水平+垂直居中，一处抽象全系统生效，禁止各弹窗各自定位（定位规则见《视觉与布局规范·画布模型》）。

### 批量补全档案

客户报单往往一整单都是手输文字（微信贴单/AI 识别订单追加的非标行），逐行补全效率低：

- **入口**：操作栏「补全档案」按钮（存在非标行时启用）。
- **交互**：弹窗列出全部非标行，每行显示当前文字 + 检索匹配（默认注入当前文字检索），可选中档案或跳过。
- **绑定语义 = 用档案数据替换该行（引用锁定）**：写入 SKU 关联四件套（`specId`/`brandId`/`productId`/`unitId`）+ `productRef` 档案全名 + 快照字段刷新 + 标记标准化；行内 `qty`/`remark` 保留（修改维度不被覆盖）；行内单价为空时自动带出档案默认售价，已录价不覆盖。
- 未匹配的行可跳过（保持非标，不阻塞）。

## 保存逻辑

### 行内编辑失焦保存

采购报价采用「编辑即保存」模式，没有「统一保存」按钮。用户修改任意单元格后失焦/回车，即触发保存：

```
用户编辑单元格 → 失焦
  ├── 行无 id（空行）→ 调用新增行
  │     └── 新行返回后追加到本地行列表
  └── 行有 id（已有行）→ 调用更新行
        ├── 合并排队中的修改（pendingPatch）
        ├── 若该行正在提交中 → 将修改放入排队队列
        └── 提交完成后 → 检查排队队列，有则自动提交下一个
```

### 提交排队机制

为防止快速连续编辑导致并发冲突，实现提交排队：正在提交中的行 ID 集合 + 排队等待的修改；行正在提交时的新修改排队，提交完成后自动处理队列中的下一个。

### 金额计算

**行金额**（前端实时计算，后端写入时重算）：

```
amount = qty × unitPrice - lineDiscount（结果 ≥ 0，保留两位小数）
```

**整单汇总**：

```
subtotal = Σ(qty × unitPrice - lineDiscount)
计税基数 = max(0, subtotal - orderDiscountAmount - roundOffAmount)

不开票（needInvoice = false）：
  taxAmount = 0
  total = 计税基数

含税（needInvoice = true 且 taxInclusive = true）：
  taxAmount = 计税基数 × taxRate / (100 + taxRate)
  total = 计税基数

不含税（needInvoice = true 且 taxInclusive = false）：
  taxAmount = 计税基数 × taxRate / 100
  total = 计税基数 + taxAmount
```

### 乐观锁机制

- **整单级别**：单据乐观锁版本号（`lock_version`），更新单据业务字段或状态时校验。
- **行级别**：行级乐观锁版本号（`lineVersion`），更新行时校验。
- 冲突时返回冲突错误，前端提示「已被其他操作修改，请刷新后重试」。

## 与单据状态机关系

- 报价阶段状态（待确认/已确认/作废）与单据全局 8 档状态机的联动见「功能概述·报价阶段状态」；单据编号格式与状态机权威定义见《单据与状态机》。
- **配货**：报价确认后（`purchase_quote_status = confirmed`）方可进入配货环节；配货基于本视图行明细进行仓库出库或外部调货。
- **成本核定**：基于本视图行明细核算内部进货成本；售价（`unitPrice`）与进价（成本行预设成本）物理隔离。
- **收款对账**：报价确认后按订单应收金额收款，收款记录与单据关联。
- **退换售后**：基于本视图行明细处理退换货，退换行强制继承原单基准数据（原数量/原单价）。
- **销售汇总**：汇总本视图的销售数据（订单金额、税额、优惠、毛利等），支持时间区间汇总。
- **定档归档**：销售定档冻结销售数据，定档后数据不可修改，用于对账和审计。
