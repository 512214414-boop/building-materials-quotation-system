# 采购报价

> 顶层依据：详见《顶层设计规范·理念4（表格唯一·交互统一）》《项目设计哲学·约束4（Excel 用户·流式录入）》《项目设计哲学·约束6（数据量级巨大·索引驱动）》。

> **职责声明**：本文档是「采购报价」（需求确认 + 报价核算合并视图）的唯一设计依据。单据/单据行表结构、单据编号、8 档状态机见《单据与状态机》；选品建档见《产品数据层》；表格/录入/悬浮定位框通用交互规则见《表格与交互规范》；权限码唯一清单见《系统管理》。

## 功能概述

「采购报价」是订单协同工作台里**同一张单的一种看法**（过程，不是一类活）。一类活见 `文档可视化/` 指导思想·销售开单。员工在此录入客户物料需求明细（产品名称、规格、数量、单位），并为每条物料行填写售价、汇总整单金额。售价直接落在单据行上。销售已定档后单据行只读，要改先反定档。

单据头：上下文栏「单据标题」与采购清单标题同一意思（写 `documents.title`，与 note 互填）。「客户信息」格匹配到人后填姓名 + 当时挑的那条联系；采购清单客户列同样显示姓名+联系，方便售后按人找单。

```
单据创建 → 采购报价（本文档范围）
  ├── 待确认（pending）：报价未完成，行可编辑；客户还看不见价
  └── 已确认（confirmed）：售价对客户可见。员工端仍可改行（除非销售已定档）
        └── 同一张单的其他看法：配货 / 交付 / 成本 / 收款 / 售后 / 汇总 / 定档
            （全局 8 档状态可来回改，见《单据与状态机》；不要把这些看法再切成一类活）
```

### 报价阶段状态

报价阶段状态（`stage_status` 三态）与单据全局状态的联动关系：

| 状态 | 枚举值 | 示例场景 | 说明 |
|------|--------|---------|------|
| 待确认 | `pending` | 单据创建、行明细录入中 | 行可编辑；单据全局状态同步为 `demand_pending` |
| 已确认 | `confirmed` | 报价定稿，售价对客户可见 | 客户可见价；员工端仍可改行（销售已定档除外）；单据全局状态同步为 `quote_confirmed` |
| 作废 | `voided` | 单据作废 | 不可编辑；不同步全局状态 |

### 核心设计原则

- **单一事实源**：售价保存在单据行（`unitPrice`/`lineDiscount`/`amount`），无独立报价行表。
- **行内点值确认才写**：单元格点开确认层，确认/回车才保存，取消不写。没有「统一保存」按钮。
- **空行即新增**：表格末尾常驻完整空行，确认层写入有效值后自动升级为真实行。
- **价格可见性**：仅报价阶段已确认时客户端才可见售价，未确认前金额字段隐藏。
- **视图级防误触锁定**：支持手动锁定/解锁编辑，锁定后所有单元格不可编辑（作废单据自动锁定）。

## 单据行录入交互

- **行内编辑即保存**：数量/备注是常驻输入，点格只聚焦、不换控件、不改列宽；失焦/回车即提交，无「统一保存」按钮。产品名/单位/单价选品：**点格进确认层**（空词也开），表格格只展示；输入+下拉挂在确认层输入框，默认展开、可收起。点空白关整层。
- **空行即新增**：表格底部空行按**当前页位置**带插入序号（翻页不与已有行撞号）；有产品名后才升级为真实行，插在该位置，不甩到表尾。只改数量/单价、没有产品名 → 不落库。
- **行操作语义**：
  - **下方插入**：在当前真实行后面插入一条**空的已落库行**（不复制产品/单价），序号 = 当前行序号 + 1，后面的行依次后移。空行没有「下方插入」。
  - **删除该行**：只删真实行，二次确认。
  - **勾选**：只勾真实行；表头勾选当前页全部真实行。
  - **操作列扩展按钮**：行上的是当前行（下方插入空行 / 删除该行）；表头同一位置的是已勾选范围（删除已勾选）或整表（整理数据）。禁止再把这些批量按钮放到工具栏。
- **键盘导航**：Enter 提交+下移 / Tab 右移 / Esc 回滚 / 方向键移动；备注列 Enter 保存、Shift+Enter 换行；业务条与税额面板输入框 Enter 或失焦保存。
- **数字列普通输入**：数量/单价列用普通输入框 + 数字键盘，禁用原生数字控件（光标跳、滚轮误改）。
- **临时数据不清 ID**：价格/数量是临时数据，变更一律不清 SKU 关联 ID（仅产品全名列文字变更才清空，见「产品列交互」）。
- **保存状态提示**：所有 API 调用统一追踪保存中/成功/失败状态。
- **视图级锁定**：锁定后所有单元格不可编辑；作废单据自动锁定、不可解锁；锁定按钮文字动态切换「锁定编辑」⇄「解锁编辑」；锁定状态持久化于 `view_locks.purchase_quote`（`view_locks` 键名统一 snake_case，视图键清单见《单据与状态机》）。
- **实时同步**：通过实时通道监听行更新、状态变更事件自动刷新数据，支持多人多设备协同编辑同一单据。
- **翻页位置化录入（v16.5）**：表格为手写单据式翻页（默认每页 13 行，可切 10/20/50/100）。在任意页、任意行的空行录入并提交时，新行**插入到你录入的那一页那一行位置**（而非一律甩到文档末尾）；每页空行携带唯一序号，互不撞车，杜绝跨页/跨行录入串位与重复新建（修复 P-014）。
- **整理数据（v16.5）**：表头扩展菜单「整理数据」——删掉产品名为空且未关联档案的行，再按当前顺序从 1 紧凑重排 `seq`（保留其余行 ID、不破坏快照），对应后端 `POST /documents/:id/lines/resequence`。
- **表头级联检索**：产品名 / 品牌 / 规格列表头是 HeaderCascadeFilter。选项来自当前单据所有行，不是全局产品库。点选=标准条件（带行上档案 ID）；失焦手输=非标。条件升到业务条旁 chip，表头仍留当前值，两边擦同步。筛只改变眼前能看见的行，不改整单合计；空行仍在表底可录入。品牌/规格列是快照只读，改货仍走产品名确认层。

## 产品列交互

产品名称/规格列是 `picker` 列，`dropdown` 触发模式——**点格进确认层**，表格格只展示。不挂小箭头。

- **产品名列宽**：与其他数据列同一套——单行、按当前页最长一行撑开（表体可横向滚动），完整可见，禁止省略号、禁止换行把行高撑乱。
- **编辑态列宽稳定**：表格格只展示，点开不换行高。清除 × 悬停才出；非标「待确认」仍在格上。展开/收起在确认层输入框的下拉上。
- **展开收起**：确认层输入框右侧下拉，默认选中就展开，再点收起。**在确认层展开就在确认层收起**，不要把箭头挂回表格。
- **非标行黄标「待确认」**：自由输入文字（非从产品库选择）→ 保存为 `productRef` 文字，同时清空 SKU 关联 ID 并标记非标；行内显示黄色提示图标「待确认：未匹配档案记录」。点击格子打开确认层 → 选中档案升级为标准行（ID 回填、快照刷新）。
- **清空 ID 唯一条件**：**仅产品全名列文字变更**才清空全部 SKU 关联 ID（`specId` 归 0、`productId`/`brandId`/`unitId` 置空）并标记非标；价格/数量/单位等临时数据变更一律不清 ID。
- **点格进确认层**：点格打开确认层（空词也开），确认层真输入同一手势出键盘。以打开时格子上的字作关键词；点空白关整层。不靠表格下拉箭头。
- **点击候选行**：面板顶栏由产品树派生（宽松 + 名称/品牌/规格/执行标准/渠道，默认名称）；同一格子同一串字，切档不改字；匹配是包含与被包含。到那一层有什么就搜什么，检索是全的，不按词禁结果。切档后入口层最左、其余层各占一列，禁止叠成一行灰字；说明默收起。默认名称视图一行一个产品名称，品牌 N 个下拉（排得下几个露几个，剩下进「还有 n」；点品牌箭头展开规格）。切到规格/执行标准/渠道时主行就是一条规格。**写入当前行只走插入按钮**。名称 / 换算率 / 面价 / 点位格子划过要看得出能点（原常驻输入那套 hover）。点开输入浮层（比选品列宽，能看全文），选品面板保持打开；里面同时有影响范围、取消、确认修改。字典格（品牌/单位/分类/售价类型/供应商）检索下拉选已有项。默认确认修改只改当前这条（例如这条规格换单位，不是把「米」在全系统改名）。单位 / 品牌 / 分类 / 售价类型 / 供应商另有「改全局」：目标名已在字典里就把所有引用并到那个档案，并列出本次会改到的数据。点位另有「改全局」：改圈组默认，已有例外的规格不动，确认层列出跟组会被改到的规格。取消即恢复原样，格子里不留半改状态。末尾空行加规格/品牌/单位/价，同样点开这层。档案改了不自动改已开的单据行；再点一次插入，这一行快照才换成当时的新内容。单价取值链：默认实际售价（面价×点位）→ 推算售价 → 行上显示的进价（兜底）→ 0。点售价/进价「插入」按钮用所选实际价。全局规则见《档案管理·选用检索》。
- **单价来源着色**：单价单元格按**来源**着色（纯前端行状态，不落库）——进价（售价未录兜底/点进价插入）→ **红色**；推算售价（基准单位价 × 换算率）→ **推算色**；真实售价（档案默认售价/点售价插入）→ 普通色；手输单价 → 来源清除普通色。统一遵循「推算/非真实数据必须颜色区分」，防止把进价/推算价当真实售价报给客户。
- **清除按钮**：与客户输入框同一套——有值且悬停/聚焦时显示纯文本 ×，不占单元格外框。
- **非激活态**：显示商品全名，空值显示占位符。

## 单位列交互

单位列与产品列同一套：**点格进确认层**，表格格只展示。

- **确认层手输（快速录入）**：在确认层输入框打单位名，点空白提交。
  - **标准行（有 `specId`）**：输入的单位名已在该规格单位列表内 → 自动绑定其单位 ID；不在列表内 → **建档前弹「新增单位」确认**（「该产品暂无单位『X』，确认新增到该产品档案？」）——确认 → 建档并绑定新单位 ID；取消 → 不建档不绑定，保留原值并提示。防止误录/乱输在不知不觉中给产品累积垃圾单位，让用户感知「输入的单位不存在，系统将新建档案」。
  - **非标行（无 `specId`）**：纯文字保存（不关联档案，无档案可挂，不涉及建档无需确认）。
- **确认层展开单位列表**：默认展开。确认层输入框的下拉可收起再展开。
  - **标准行**：同一套选品框架，检索主行换成当前行已锁定的规格（不再从产品名一级级翻）。打开的就是选品里那张单位表（单位 | 换算率 | 售价 | 进价），点插入或点售价/进价明细写入当前行。手输新单位名仍走「新增到该产品」确认。
  - **非标行 → 常见单位列表**：产品未建档时没有这棵树，展示**预设常见单位**（米/厘米/毫米/平方米/立方米/升/个/件/箱/包/卷/捆/张/套/台/公斤/千克/克/吨/支/根/条/块/片/副/对/双/次，共 28 个）：空关键词 → 显示全部直接点选；输入关键词 → 在常见单位内**本地过滤**；无匹配 → 「快速新建」纯文字。
- **展开显示全部单位**：标准行打开的是该规格全部单位（当前「米」不会把其他单位滤掉）。非标行常见单位同样先展示全部，用户改了输入才过滤。
- **单位表带出售价/进价**：与产品名列点开后的单位层同一张表，每行能看默认售价、进价，再点开切具体类型/渠道。
- **换单位自动插入对应价格**：换单位 = 换该单位行情价，按取值链自动带出（对齐产品选品）：**该单位默认售价 → 推算售价 → 进价兜底 → 0**，并按来源着色（售价普通/推算色/进价红）——换单位后单价立即对齐新单位行情，无需再手动改；无价格单位 → 0（空待录）；新建单位（无价格）→ 0。
- **换单位绝不清空产品关联 ID**：仅产品全名列文字变更才清空关联 ID。

## 单价列交互

单价列与产品名/单位同一套确认层：**点格打开确认层，在确认层敲数字或展开选品价格叶子**。

- **手输**：在确认层输入框敲，点空白提交；手输后单价来源清除（普通色）。议价就改这个数，不写回档案。
- **下拉切价（标准行）**：确认层默认展开价格叶子。名称和单位已经定了，打开的是选品单位层去掉单位列——一行「售价 | 进价」下拉，点开再展开明细（售价类型 / 进价渠道）。跟单位列同一套表头节奏，不把完整价表上下铺开。点插入切到那一档，并按来源着色。不必再从产品名一级级翻进去看价。
- **非标行 / 还没绑单位**：没有档案价可切，确认层提示先选定产品；仍可手输。

## 选品与建档

现场为什么是一格跟着嘴走、切档不改字、没货就打电话：见 `文档可视化/` 指导思想 · 销售开单。本节只写开单落行与建档。

### 选品与快照填充

从产品库选择商品时：

1. 前端组装商品全名（`productRef` = 产品名 + 品牌 + 规格型号）、**SKU 关联四件套**（`specId`/`brandId`/`productId`/`unitId`）、单位文字、规格文字、缩略图，标记标准化。
2. **选品自动带出单价**：`unitPrice` 从该 SKU 售价矩阵带出（用户点击的具体售价 > 默认售价 > 推算价 > 0）。单价是**临时数据**（议价场景可改），选品只负责带出默认值，后续可随时调整。
3. 后端按四件套反查产品档案，将 5 个独立快照字段（产品名/品牌名/分类名/规格型号/单位名）写入单据行——**快照不自动跟着档案改**（已开的行保持当时抄下来的内容）。档案在选品里改名/改价：点开输入浮层看全、确认后再写产品库；取消不写。**再插入同一行**才会把快照换成当时的新内容。改数量、改单价、只换单位，都不会按行上残留 ID 去档案里刷产品名。历史单据不会被后台按关联去刷。

### 产品数据使用-引用-修改矩阵（权威定义）

单据行消费产品库数据的完整语义，后续环节（配货/成本/收款等）沿用此矩阵：

| 产品库数据 | 订单行用法 | 引用方式 | 可否修改 | 修改的影响 |
|-----------|-----------|---------|---------|-----------|
| 产品名/规格/品牌/单位 | 展示、打印、对账 | 快照锁定（独立快照字段） | 行内可改文字，改后清空关联 ID 变非标 | 仅当前行，不影响产品档案 |
| 产品/规格/品牌/单位 ID | 统计聚合、库存扣减、成本核算维度 | ID 留存（`specId` 兜底 0=未关联） | 随选品/补全绑定、随改名清空 | 仅当前行 |
| 默认售价 | 带入单价 | 快照带入后独立 | 可改（议价/行优惠） | 仅当前行，不带回档案 |
| 分类 | 统计维度 | 快照 + ID | 不改 | — |
| 缩略图 | 展示 | URL 快照 | 不改 | — |
| 行级附加字段 | 备注/行优惠/AI 识别原始描述 | 单据行自有，档案无对应 | 可改 | 仅当前行 |

**三条铁律**（本环节闭环验收标准）：
1. **引用锁定**：下单时快照产品库文字信息，产品库后续改名/删除不影响历史单据。
2. **ID 留存**：统计/扣减/核算一律基于行内 ID 聚合，不实时关联档案主表。
3. **仅产品名断链**：只有产品全名列文字被修改才清空全部 SKU 关联 ID 变非标；价格/数量/单位为临时数据，变更一律不清 ID（换单位按「单位列交互」补充档案语义更新）。

### 快速建档（二次确认弹窗）

用户在选品面板点击「新建『关键词』」时，**不再直接建档**，一律弹出「快速新增产品」二次确认窗口——所有新建档案入口的统一范式：

- **底层分开存储（核心语义）**：产品名称/品牌/规格型号/单位是**独立字段**，产品名绝不等于完整商品全名拼接串（产品名+品牌+规格）。把完整串整体当产品名 → 再次输入同名 → 又把完整串当产品名 → 在「普通品牌」下叠加出「普通品牌·通用」重复建档（例如「XXX 普通品牌 通用」变成「XXX 普通品牌 通用 普通品牌 通用」）。
- **弹窗字段分开编辑**：产品名称（必填，预填触发关键词，可修改/补全）+ 品牌（预填「普通品牌」）+ 规格型号（留空）+ 单位（留空）。
- **保存 = 缺省值二次确认**：点击「保存」→ 校验必填 → 收集「系统将自动补充」清单（规格型号未填 → 补「通用」；单位未填 → 补「件」；品牌未填 → 补「普通品牌」）→ 二次确认弹窗：**确认保存** → 建档（后端宽表组合去重幂等，见下）→ 建档结果组装选品四件套 → 选中写入当前行；**返回继续编辑** → 留在弹窗补齐字段。缺省值统一见《数据规范·缺省值注册表》。
- **宽表组合去重（幂等核心）**：产品是复杂多表结构（产品/规格/品牌/单位/规格品牌关联），去重**不在各分表分别比对**（分字段比对遇字段错位永远匹配不上 → 误判新增 → 重复建档），而是在冗余宽表上按**组合完整值**精确比对：去空格(产品名) + 去空格(规格型号) 完全一致即视为同一条，直接复用已有档案（字段错位如产品名「XX25」+ 规格空 vs 档案产品名「XX」+ 规格「25」，组合值都是「XX25」→ 命中复用）。组合候选（按优先级）：① 原始输入组合（规格原样参与，空则空）——处理字段错位；② 空规格时补「通用」的组合——处理「只录产品名」的空规格幂等。命中选择：同组合多品牌行时优先复用输入品牌对应的行，无则取第一条；单位按输入名在该规格下查找/创建。
- **相似档案匹配度决策**：精确同一（组合完整值相等）与完全无关之间是灰度地带——产品名长、输入与档案近似但不相等，系统无法自判「就是同一条还是不同产品」，**把决策权交给用户**：
  - **匹配目标 = 档案全名（产品名+规格+品牌，去空格小写）**——用户口语里的品牌词必须参与匹配；
  - **相似度** = max(语义段覆盖率, 2-gram token 覆盖率, 编辑距离, 完整包含比例)。**语义段覆盖率**为主：输入按字符类型切段（中文/字母/数字），段在档案全名**子序列命中（容错）**即算中（段长 ≥3 容忍差 1 字符，段长 ≤2 必须全部命中），命中段总长 / 输入段总长，仅当命中段数 ≥2 才启用（单段命中会候选泛滥）；**2-gram token 覆盖率**处理中文连写不分词（「伟星水管」被切为单段 → 段覆盖率被禁用）；纯编辑距离对「口语乱序 + 长短差异」不友好，仅作兜底；
  - **候选召回**：复用全局检索召回通道（全文索引 ∪ 任意位置包含**合并去重**）——口语输入前缀常不在档案名开头（输入「伟星绿色25给水管」vs 档案「ppr DN25给水管」开头是 ppr），禁止前缀匹配直接召回；全文索引对无空格中文长串是短语匹配（token 连续才命中）常 0 召回，任意位置包含才是可靠通道，两者合并保证不漏召回；候选集受控（见《数据规范·规模驱动设计》）。
  - **三段决策**：精确同一 → 静默复用（无歧义）；匹配度 **≥ 60%** → 返回候选列表（最多 3 条，含匹配度，**零副作用**——不建任何档案/单位），用户点「复用」直接选中该档案，或点「仍要新建」强制建档；**< 60%** → 视为新品静默新建。
  - **候选排序**：匹配度降序 → 命中段数降序 → 全名长度与输入接近者优先。
- **自动写行为可感知**：系统高度灵活（不设限，什么都能录），但**自动产生的写行为必须让用户感知到**，否则用户不知道底层逻辑、随手乱输会在不知不觉中累积几十条垃圾档案：
  - 后端建档结果携带 `reused` 标识：**精确命中已有档案复用 = `reused: true`**；实际新建 = `reused: false`；候选元素恒为 `reused: true`（本就存在，非新建）。
  - 保存后按 `reused` 提示：精确命中 →「已匹配到现有档案，直接使用（未新建）」；点候选「复用」→「已使用现有档案『档案全名』」；真正新建 →「新建档案成功」。告别静默复用。
- **弹窗宿主**：二次确认弹窗挂在**视图层**，禁止挂在悬浮定位框子树内（面板失焦关闭会卸载弹窗）；选品面板的快速新建回调为**必传**，仅上抛关键词，面板内不再有任何直接建档代码。
- **弹窗统一定位**：所有二次确认弹窗（缺省值确认/相似档案候选/新增单位确认等）统一相对**画布**水平+垂直居中，一处抽象全系统生效，禁止各弹窗各自定位（定位规则见《视觉与布局规范·画布模型》）。

### 批量补全档案

客户报单往往一整单都是手输文字（微信贴单/AI 识别订单追加的非标行），逐行补全效率低：

- **入口**：操作栏「补全档案」按钮（存在非标行时启用）。
- **交互**：弹窗列出全部非标行，每行显示当前文字 + 检索匹配（默认注入当前文字检索），可选中档案或跳过。
- **绑定语义 = 用档案数据替换该行（引用锁定）**：写入 SKU 关联四件套（`specId`/`brandId`/`productId`/`unitId`）+ `productRef` 档案全名 + 快照字段刷新 + 标记标准化；行内 `qty`/`remark` 保留（修改维度不被覆盖）；行内单价为空时自动带出档案默认售价，已录价不覆盖。
- 未匹配的行可跳过（保持非标，不阻塞）。

## 保存逻辑

### 确认层写入

采购报价采用点值确认层，没有「统一保存」按钮，也没有格子失焦保存。用户点格 → 确认层改完 → 点确认（或 Enter）才触发保存；点取消 / 点空白不写：

```
用户点格 → 确认层
  ├── 取消 / 点空白 → 草稿丢掉，当前行不动
  ├── 确认 / Enter
  │     ├── 行无 id（空行）→ 调用新增行
  │     └── 行有 id → 调用更新行（带 lineVersion）
  └── 选用检索点插入 → 明确写快照（等同确认这条选用）
```

### 提交排队机制

为防止快速连续编辑导致并发冲突，实现提交排队：正在提交中的行 ID 集合 + 排队等待的修改；行正在提交时的新修改排队，提交完成后自动处理队列中的下一个。

### 金额计算

**行金额**（前端实时计算，后端写入时重算）：

```
amount = qty × unitPrice - lineDiscount（结果 ≥ 0，保留两位小数）
```

**整单汇总**：

```
subtotal = Σ(qty × unitPrice - lineDiscount)
计税基数 = max(0, subtotal - orderDiscountAmount - roundOffAmount)

不开票（needInvoice = false）：
  taxAmount = 0
  total = 计税基数

含税（needInvoice = true 且 taxInclusive = true）：
  taxAmount = 计税基数 × taxRate / (100 + taxRate)
  total = 计税基数

不含税（needInvoice = true 且 taxInclusive = false）：
  taxAmount = 计税基数 × taxRate / 100
  total = 计税基数 + taxAmount
```

### 乐观锁机制

- **整单级别**：单据乐观锁版本号（`lock_version`），更新单据业务字段或状态时校验。
- **行级别**：行级乐观锁版本号（`lineVersion`），更新行时校验。
- 冲突时返回冲突错误，前端提示「已被其他操作修改，请刷新后重试」。

## 表格列定义

统一表格列定义：

| 列标识 | 列名 | 宽度 | 对齐 | 编辑模式 | 触发方式 | 特殊说明 |
|--------|------|------|------|---------|---------|---------|
| `productRef` | 产品名称/规格 | 下限，随最长一行撑开 | left | 点值 · linePicker | 点格进确认层，选用检索挂确认层输入 | 格子只展示；插入整份重抄；手输非标走确认修改；非标「待确认」；仅本列文字变更清空 SKU 关联 ID |
| `unit` | 单位 | 下限，随最长一行撑开 | center | 点值 · linePicker | 确认层挂单位层 | 标准行：选品框架单位槽；非标行常见单位 |
| `qty` | 数量 | 下限，随最长一行撑开 | center | 点值 · lineValue | 确认层数字，确认才写 | 默认占位「0」；改数量不清 ID |
| `unitPrice` | 单价 | 下限，随最长一行撑开 | center | 点值 · linePicker | 确认层挂价格叶子 | 默认占位「0.00」；手输也走确认 |
| `amount` | 金额 | 下限，随最长一行撑开 | center | 只读 · lineRead | 不可点 | 前端计算 = qty × unitPrice - lineDiscount |
| `remark` | 备注 | 下限，随最长一行撑开 | center | 点值 · lineValue | 确认层文本，确认才写 | 默认占位「备注」 |

每行「更多」菜单（仅真实行；操作列固定首列，见《表格与交互规范》）：下方插入空行 / 删除该行（二次确认）。表头同一扩展按钮：删除已勾选（无勾选则不可用）/ 整理数据（去掉未填产品的空行 + 重排序号）。

## 与单据状态机关系

- 报价阶段状态（待确认/已确认/作废）与单据全局 8 档状态机的联动见「功能概述·报价阶段状态」；单据编号格式与状态机权威定义见《单据与状态机》。
- **配货**：报价确认后（`purchase_quote_status = confirmed`）方可进入配货环节；配货基于本视图行明细进行仓库出库或外部调货。
- **成本核定**：基于本视图行明细核算内部进货成本；售价（`unitPrice`）与进价（成本行预设成本）物理隔离。
- **收款对账**：报价确认后按订单应收金额收款，收款记录与单据关联。
- **退换售后**：落到行上之后，退换行强制继承原单基准数据（原数量/原单价）。找单入口：先勾原单当数据源，再对已卖行打名称匹配，插入复用当时名和价、数量另填。见指导思想·售后。
- **销售汇总**：汇总本视图的销售数据（订单金额、税额、优惠、毛利等），支持时间区间汇总。
- **定档归档**：销售定档冻结销售数据，定档后数据不可修改，用于对账和审计。
