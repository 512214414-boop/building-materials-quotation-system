## 一、功能概述

### 1.1 功能定位

「采购报价」是**九视图协同工作台**的第一个视图（V1），也是整个单据生命周期的起点。它承担两项核心职责：

1. **需求确认**：员工在此录入和确认客户的物料需求明细（产品名称、规格、数量、单位等）。
2. **报价核算**：员工在此为每条物料行填写售价，并汇总整单金额（含优惠、税额、应收）。

### 1.2 在业务流程中的位置

采购报价是单据生命周期（8 档状态机）的**前两个阶段**：

```
单据创建 → 采购报价（本文档范围）
  │
  ├── pending（待确认）→ 客户提交需求 / 员工录入行
  │
  └── confirmed（已确认）→ 报价已定，进入后续环节
         │
         ├── 配货（allocation）
         ├── 交付履约（delivery）
         ├── 成本核定（cost）
         ├── 收款对账（payment）
         ├── 退换售后（refund）
         └── 销售汇总（summary）
```

### 1.3 报价阶段状态

| 状态 | 枚举值 | 说明 | 对单据全局状态的影响 |
|------|--------|------|---------------------|
| 待确认 | `pending` | 报价未完成，可编辑 | 单据全局状态同步为 `demand_pending` |
| 已确认 | `confirmed` | 报价已锁定，客户可见售价 | 单据全局状态同步为 `quote_confirmed` |
| 作废 | `voided` | 单据作废，不可编辑 | 不同步全局状态 |

### 1.4 核心设计原则

- **单一事实源**：售价保存在 `document_lines` 的 `unitPrice` / `lineDiscount` / `amount` 字段，不存在独立的报价行表。
- **行内编辑即保存**：表格中每个单元格失焦即发起 API 保存，无"统一保存"按钮。
- **空行即新增**：底部空行输入内容后自动升级为真实行（调用 `addLine`）。
- **价格可见性**：仅 `purchase_quote_status === confirmed` 时，客户端才可见售价；未确认前金额字段隐藏。
- **视图级防误触锁定**：支持手动锁定/解锁编辑，锁定后所有单元格不可编辑（作废单据自动锁定）。

## 四、保存逻辑

### 4.1 行内编辑失焦保存

采购报价采用**「编辑即保存」**模式，没有"统一保存"按钮。用户修改任意单元格后失焦，即触发 API 保存。

核心流程（`commitCell` 函数）：

```
用户编辑单元格 → 失焦
  │
  ├── 行无 id（空行）→ 调用 addLine 创建新行
  │     └── 新行返回后追加到本地行列表
  │
  └── 行有 id（已有行）→ 调用 updateLine 更新行
        ├── 合并排队中的 patch（pendingPatchRef）
        ├── 若该行正在提交中 → 将 patch 放入排队队列
        └── 提交完成后 → 检查排队队列，有则自动提交下一个
```

### 4.2 提交排队机制

为防止用户快速连续编辑导致并发冲突，实现了提交排队：

- `submittingRef`：正在提交中的行ID集合
- `pendingPatchRef`：排队等待提交的修改
- 当行正在提交时，新修改会排队；提交完成后自动处理队列中的下一个修改

### 4.3 空行升级

- 表格底部始终显示空行（`emptyRowFactory` 生成），用于快速录入
- 空行 `id` 为 `undefined`，`seq` 为当前行数 + 1
- 用户编辑空行任意字段后失焦，触发 `addLine` 创建真实行
- 创建成功后新行追加到本地行列表末尾

### 4.4 金额计算

**行金额**（前端实时计算，后端写入时重算）：

```
amount = qty × unitPrice - lineDiscount（结果 ≥ 0，保留两位小数）
```

**整单汇总**（`getDocumentTotal` / `calcDocumentTotalV21`）：

```
subtotal = Σ(qty × unitPrice - lineDiscount)
计税基数 = max(0, subtotal - orderDiscountAmount - roundOffAmount)

若 needInvoice = false（不开票）：
  taxAmount = 0
  total = 计税基数

若 needInvoice = true 且 taxInclusive = true（含税）：
  taxAmount = 计税基数 × taxRate / (100 + taxRate)
  total = 计税基数

若 needInvoice = true 且 taxInclusive = false（不含税）：
  taxAmount = 计税基数 × taxRate / 100
  total = 计税基数 + taxAmount
```

### 4.5 产品档案关联与快照填充

当用户通过 ProductPicker 从产品库选择商品时：

1. 前端组装 `productRef`（产品名 + 品牌 + 规格型号）、`brandId`、`specId`、`productId`、`unitId`、`spec`、`unit`、`isStandardized=true`、`thumbnailUrl`
2. **选品自动填充单价**：`unitPrice` 从该 SKU 售价矩阵带出（用户点击的具体售价 > 默认售价 > 推算价 > 0）
   - 单价为**临时数据**（议价场景可改），选品只负责带出默认值，后续可随时调整
3. 后端 `addLine` / `updateLine` 接收到 `brandId` / `specId` / `productId` / `unitId` 后，主动查询产品档案
4. 将 5 个独立快照字段（`productName` / `brandName` / `categoryName` / `specModel` / `unitName`）写入单据行
5. 产品档案后续修改或删除不影响单据行展示

### 4.6 非标数据处理

用户在 ProductPicker 的 dropdown 模式下自由输入文字（非从产品库选择）：

- **清空 ID 的唯一触发条件 = 产品全名（产品名称/规格）变更**：
  - 用户修改产品全名列文字 → 视为断开档案引用 → 全部 SKU 关联 ID 一并清空
    （`specId` 归 0、`productId` / `brandId` / `unitId` 设为 `null`）+ `isStandardized=false`
  - **价格、数量、单位是临时数据，变更一律不清 ID**（议价/改量不破坏产品关联）
- `productRef` 直接保存用户输入的文字
- 行内显示黄色提示图标「待确认：未匹配档案记录」
- 补全路径：
  - **单行补全**：点击「待确认」图标或下拉箭头 → 打开选品面板 → 选中档案升级为标准行（ID 回填、快照刷新）
  - **批量补全**：操作栏「补全档案」按钮 → 批量弹窗（见 4.6.2）

### 4.6.1 换单位规则（补充档案语义）

切换单位（单位列）时，**产品名不变 → 在 SKU 档案下选单位，没有则新增**（对齐分类「没有就新增」范式）：

- **标准行（有 specId）**：UnitPicker 加载该 SKU 全部单位（v11.14：`resolveSpecBrand(specId+brandId)` → `getSkuOptions(specBrandId)`，含价格/换算率；解析失败退回 `listUnits by specId`）
  - 从列表选已有单位 → 写入 `unit`（文字）+ `unitId`（该档案单位 ID）+ **该单位对应价格**（见下方 v11.14 换价规则）
  - 输入新单位名 → 面板「新增到该产品」→ `createUnit({specId, unitName})` 建档 → 用**新单位 ID** 绑定
    - 新增单位自动为该 SKU 所有品牌关联建立换算率（默认 1）
    - 该 SKU 下同名单位已存在 → 后端 422 拦截，从列表选择即可
- **非标行（无 specId）**：常见单位列表 + 纯文字输入（`unitId=null`，无档案可挂）
- **换单位自动插入对应价格（v11.14，用户反馈：选标准产品后单位列换单位应插入该单位价格，逻辑闭环）**：换单位 = 换该单位行情价，按取值链自动带出（对齐产品选品）：**该单位默认售价 → 推算售价 → 进价兜底 → 0**，并按来源着色（售价普通 / 推算色 / 进价红）——用户换单位后单价立即对齐新单位行情，无需再手动改；无价格单位 → 0（空待录）。新建单位（无价格）→ 0。
- **换单位绝不清空产品关联 ID**（仅产品全名列变更才清空；v11.15 修复：换单位/改数量等不含 productId 的 updateLine 不再把 productId 吞成 null——后端三态解析补齐，杜绝「已关联行刷新后被误判非标」）

### 4.6.2 批量补全档案

客户报单往往一整单都是手输文字（微信贴单 / AI 识别订单追加的非标行），逐行补全效率低。批量补全将整单非标行一次列出、批量升级：

- **入口**：操作栏「补全档案」按钮（存在非标行时启用）
- **交互**：弹窗列出全部非标行，每行显示当前文字 + 检索匹配（默认注入当前文字检索），可选中档案或跳过
- **绑定语义** = 用档案数据替换该行（引用锁定）：
  - 写入 SKU 关联四件套（`specId`/`brandId`/`productId`/`unitId`）+ `productRef` 档案全名 + 快照字段刷新 + `isStandardized=true`
  - 行内 `qty`/`remark` 保留（修改维度不被覆盖）
  - 行内单价为空时自动带出档案默认售价；已录价不覆盖
- 未匹配的行可跳过（保持非标，不阻塞）

### 4.6.3 产品数据使用-引用-修改矩阵（权威定义）

单据行消费产品库数据的完整语义，后续环节（配货/成本/收款等）沿用此矩阵：

| 产品库数据 | 订单行用法 | 引用方式 | 可否修改 | 修改的影响 |
|-----------|-----------|---------|---------|-----------|
| 产品名 / 规格 / 品牌 / 单位 | 展示、打印、对账 | 快照锁定（5 个独立快照字段） | 行内可改文字，改后清空关联 ID 变非标 | 仅当前行，不影响产品档案 |
| 产品 / 规格 / 品牌 / 单位 ID | 统计聚合、库存扣减、成本核算维度 | ID 留存（specId 兜底 0=未关联） | 随选品/补全绑定、随改名清空 | 仅当前行 |
| 默认售价 | 带入单价 | 快照带入后独立 | 可改（议价/行优惠） | 仅当前行，不带回档案 |
| 分类 | 统计维度 | 快照 + ID | 不改 | — |
| 缩略图 | 展示 | URL 快照 | 不改 | — |
| 行级附加字段 | 备注 / 行优惠 / AI 识别原始描述 | 单据行自有，档案无对应 | 可改 | 仅当前行 |

**三条铁律**（本环节闭环验收标准）：
1. **引用锁定**：下单时快照产品库文字信息，产品库后续改名/删除不影响历史单据
2. **ID 留存**：统计/扣减/核算一律基于行内 ID 聚合，不实时关联档案主表
3. **仅产品名断链**：只有产品全名列文字被修改才清空全部 SKU 关联 ID 变非标；价格/数量/单位为临时数据，变更一律不清 ID（`unitId` 除外——换单位按 4.6.1 补充档案语义更新）

### 4.6.4 快速建档（二次确认弹窗，v11.5）

用户在选品面板点击「新建「关键词」」时，**不再直接建档**，一律弹出「快速新增产品」二次确认窗口（`QuickCreateConfirmDialog`），这是**所有新建档案入口的统一范式**：

- **底层分开存储（核心语义）**：产品名称 / 品牌 / 规格型号 / 单位是**独立字段**，产品名绝不等于「完整 productRef 拼接串」（产品名+品牌+规格）。历史上把完整串整体当产品名 → 再次输入同名 → 又把完整串当产品名 → 在「普通品牌」下叠加出「普通品牌·通用」重复建档（例如 `XXX 普通品牌 通用` 变成 `XXX 普通品牌 通用 普通品牌 通用`）。
- **弹窗字段分开编辑**：产品名称（必填，预填触发关键词，可修改/补全）+ 品牌（预填「普通品牌」）+ 规格型号（留空）+ 单位（留空）。
- **保存 = 缺省值二次确认**：点击「保存」→ 校验必填 → 收集「系统将自动补充」清单（规格型号未填 → 补「通用」；单位未填 → 补「件」；品牌未填 → 补「普通品牌」）→ `modal.confirm` 二次确认：
  - **确认保存** → `quickCreateProduct` 建档（后端**宽表组合去重幂等**，见下），建档结果组装选品四件套（`buildQuickCreateSelection`）→ 选中写入当前行；
  - **返回继续编辑** → 留在弹窗补齐字段，最灵活：有时间完整录入所有信息；没时间直接确认由系统兜底。
- **宽表组合去重（v11.6，幂等核心）**：产品是复杂多表结构（product/spec/brand/unit/spec_brand），去重**不在各分表分别比对**（产品名→product 表、规格→spec 表），而是在冗余宽表 `product_sku_search` 上按**组合完整值**精确比对：`normalize(产品名) + normalize(规格)`（去除全部空白）完全一致即视为同一条，直接复用已有档案。录入时字段可能错位（如把规格值录进产品名：产品名「XX25」+ 规格空 vs 档案产品名「XX」+ 规格「25」），分字段比对永远匹配不上 → 误判新增 → 重复建档；组合值比对则两者都是「XX25」→ 命中复用。
  - **组合候选（按优先级）**：① 原始输入组合（规格原样参与，空则空）——处理字段错位；② 空规格时补「通用」的组合——处理「只录产品名」的空规格幂等（「XX」+空 ≡「XX」+「通用」）。
  - **命中选择**：同组合多品牌行时优先复用输入品牌对应的行，无则取第一条；返回完整三级结构（product/spec/specBrand/brand/unit），单位按输入名在该 SKU 下查找/创建（v11.3 补充档案语义）。
- **相似档案匹配度决策（v11.7 决策框架 + v11.9 算法升级）**：精确同一（dedupKey 组合完全相等）与完全无关之间是**灰度地带**——产品名长、输入与档案近似但不相等，系统无法自判「就是同一条还是不同产品」，**把决策权交给用户**：
  - **匹配度算法（v11.9，用户反馈：口语输入匹配不到标准档案）**：纯编辑距离对「口语乱序 + 长短差异」极不友好（输入「ppr伟星绿色25给水管」vs 档案「ppr DN25给水管 伟星绿 en4.2」编辑距离相似度仅约 0.5，达不到候选阈值）。升级为**语义段覆盖率为主 + 2-gram token 覆盖率 + 编辑距离/完整包含兜底**，取最大值：
    - **语义段覆盖率**：输入按字符类型切段（中文/字母/数字，`segmentizeKeyword`），段在档案全名「子序列命中（容错）」即算中（段长 ≥3 容忍差 1 字符，如「伟星绿色」vs「伟星绿」；段长 ≤2 必须全部命中，防「25」被 dn32 里的 2 误命中），命中段总长 / 输入段总长；**仅当命中段数 ≥2 才启用**（单段命中会候选泛滥，如「水管」命中所有水管档案）。
    - **2-gram token 覆盖率**：中文连写不分词（「伟星水管」被切为单段 → 段覆盖率被禁用），用 2-gram token（[伟星,星水,水管]）在档案全名的命中占比兜底。
    - **匹配目标 = 档案全名（产品名+规格+品牌，去空格小写）**：用户口语里的品牌词必须参与匹配（v11.7 旧实现只拼产品名+规格，输入中的「伟星」丢失）。
    - **候选召回（v11.9）**：旧实现按输入前 2 字符前缀 LIKE——口语输入前缀常不在档案名开头（输入「伟星绿色25给水管」vs 档案「ppr DN25给水管」开头是 ppr）→ 召回直接 miss，候选永远不出现。改为复用全局检索召回通道 `recallSkuRowsByKeyword`（FULLTEXT ngram ∪ LIKE **合并去重**，`mergeLike` 模式）：FULLTEXT ngram 对无空格中文长串是短语匹配（token 连续才命中），口语乱序输入常 0 召回且会掩埋目标档案，LIKE（任意位置包含）才是可靠通道，两者合并保证不漏召回，候选集 LIMIT 500 受控。
  - **三段决策**：精确同一（dedupKey 组合 `normalize(产品名)+normalize(规格)` 相等）→ 静默复用（无歧义，`reused:true`）；匹配度 **≥ 60%** → 返回候选列表（`status: 'suggestion'`，最多 3 条，含匹配度，**零副作用**——不建任何档案/单位），弹窗内展示候选 → 用户点「复用」直接选中该档案，或点「仍要新建」（`forceNew: true`）强制建档；**< 60%** 视为新品静默新建。
  - **候选排序**：匹配度降序 → 命中段数降序 → 全名长度与输入接近者优先，取前 3。
- **用户感知（v11.8，灵活写行为必须可感知）**：系统高度灵活（不设限，什么都能录），但**自动产生的写行为必须让用户感知到**，否则用户不知道底层逻辑、随手乱输会在不知不觉中累积几十条垃圾档案：
  - 后端建档结果携带 `reused` 标识：**精确命中已有档案复用 = `reused: true`**；实际新建 = `reused: false`；候选（suggestion）元素恒为 `reused: true`（本就存在，非新建）。
  - 保存后按 `reused` 提示消息：**精确命中 → 「已匹配到现有档案，直接使用（未新建）」**；点候选「复用」→「已使用现有档案「档案全名」」；真正新建 →「新建档案成功」。彻底告别静默复用。
- **弹窗宿主**：挂在**视图层**（PurchaseQuote）/ 单元格自持（DocumentPaperView PickerCell），**禁止挂在 FloatPanel 面板子树内**（面板 focusin 外部关闭会卸载弹窗）。ProductPicker 的 `onQuickCreate` 为**必传**回调，仅上抛关键词，面板内不再有任何直接建档代码。
- **弹窗统一定位（v11.10，用户反馈：二次确认弹窗位置漂移不居中）**：所有二次确认弹窗（缺省值确认 / 相似档案候选 / 新增单位确认等）与消息提示，统一**相对视口水平+垂直居中**（`ConfigProvider modal={{centered:true}}` 全局开启，一处抽象全系统生效，禁止各弹窗各自定位）。画布可滚动可缩放，弹窗 portal 到 body 层（fixed 定位），不随画布滚动/缩放；移动端 antd centered 的基线占位方案（`::before height:100%`）在窄视口会把弹窗推到视口下方，已改为 flex 容器 + `margin:auto` 实现真正的双轴居中；弹窗保留桌面端原始宽度，窄视口下超宽时由弹窗层横向滚动查看完整内容（不裁切按钮）。

### 4.7 乐观锁机制

- **整单级别**：`documents.lock_version`，更新单据业务字段或状态时校验
- **行级别**：`document_lines.lineVersion`，更新行时校验
- 冲突时返回 409 错误，前端提示"已被其他操作修改，请刷新后重试"

### 6.1 产品名称/规格列特殊交互

- **编辑态**：dropdown 输入框（自由输入） + 右侧下拉箭头
- **文本态超长自动换行（v11.19，对齐公共组件规格「固定宽度全程锁定 + 内容超出自动换行」）**：产品列声明 `wrap` 换行模式——列宽恒 220px（colgroup 锁定，内容不参与列宽计算），超长产品名**自动换行完整可见**（不再截断省略号），行高自适应增高；短文本单行不增高，不影响密集录入。实测 36 字产品名两行展示、列宽 220→220 不变、编辑态 input 212px 铺满。
- **编辑态强稳定性（v11.18，用户反馈：进入编辑态后列宽视觉变窄、状态转换改变原本大小）**：编辑态 input **撑满单元格原本大小**——右侧图标（清空 / 下拉箭头 / 收起）一律**绝对定位悬浮**在单元格右缘，不占流式宽度；input `width:100%` 占满单元格内容区，与文本态视觉一致。单元格宽 220px 时输入框实测 212px（与文本态显示区一致），列宽状态转换前后不变。DsInput `embedded` 变体无边框、内边距 `0 4px`（对齐文本态缩进），视觉反馈由 `td.unified-table-cell-editing` 光晕统一提供。
- **展开箭头稳定性（v11.13，用户反馈：展开面板后箭头按钮消失、布局不稳定）**：下拉箭头在**展开前后保持原位置**（单元格右侧）——非激活态显示 `DownOutlined`（展开），面板打开时变 `UpOutlined`（**收起**），点击即收起面板回到非激活态。**在哪里展开就在哪里收起**，箭头不因面板开关而消失/闪现，单元格布局稳定。全局生效（产品/单位等所有 dropdown picker 列）。
- **下拉箭头**：触发 `ProductPicker` 以 `dropdownMode` 打开，支持搜索产品库
  - **v11.4 输入不丢失**：编辑态点下拉箭头 → 以**当前输入框文字**作为面板初始关键词（不先保存、不覆盖行内已保存值；选中档案后由 onCommit 整行更新），解决「有值重新输入 → 展开面板丢失当前输入值」
  - 非激活态点箭头 → 以记录显示值作为初始关键词
- **Enter 只保存不自动展开（v11.4）**：Enter 提交文字后**不再自动弹出选品面板**——第一遍录入多为简略信息（先快录后核对），输入即弹面板会打断节奏；需要检索档案时由用户主动点下拉箭头
- **选品回填**：选择产品后自动填充 `productRef`（产品名+品牌+规格）、`brandId`、`productId`、`unitId`、`spec`、`unit`、`unitPrice`（从售价矩阵取默认售价，见 4.5 选品自动填充单价）、`thumbnailUrl`
- **点击候选行 = 所见即所得（v11.11，用户反馈：行内点击只插入产品+单位，单价不带出）**：实时匹配列表每行显示「产品全名 | 单位 | 售价 | 进价」，**点击行就插入行上显示的内容**（面板内单位/价格本可切换，显示什么就插入什么）：
  - **单价取值链**：点售价「插入」按钮 → 用所选售价；点进价「插入」按钮 → 用所选进价；点击行（未选价）→ 行显示售价 → 推算售价 → **行上显示的进价（兜底）** → 0。售价未录时单价不再插入 0，而是插入行上可见的进价数字（报价参考价，用户可再调整）。
- **单价来源着色（v11.12，用户反馈：进价/推算价填入单价后无颜色区分，会误当真实售价报给客户）**：单价单元格按**来源**着色（纯前端行状态 `priceSource`，不落库）：
  - **进价**（售价未录兜底 / 点进价「插入」）→ **红色**（`--status-discount-default`），用户一眼知这是进价参考，不可直接卖，需改价；
  - **推算售价**（基准单位价 × 换算率，`derivedSalePrice`）→ **推算色**（`--text-placeholder-accent`），需人工核对；
  - **真实售价**（档案默认售价 / 点售价「插入」）→ 普通色；
  - **手输单价**（用户自己录）→ 来源清除、普通色。
  - 统一遵循「推算/非真实数据必须颜色区分」原则，防止用户完全信任系统导致报错价的生产事故。
- **插入按钮样式（v11.11）**：售价/进价/单位明细面板的「插入」小图标按钮统一 20×18 紧凑尺寸、居中于插入列（不与面板/行边框贴边重叠）、圆角用令牌 `--radius-2`（原硬编码 3，违反统一设计规范），与数据行内容高度对齐。
- **新建 = 二次确认弹窗（v11.5）**：面板「新建「关键词」」一律上抛关键词（`onQuickCreate` 必传），由视图层弹出「快速新增产品」确认窗（字段分开编辑 + 缺省值二次确认，见 4.6.4），**禁止面板内直接建档**（避免把完整 productRef 拼接串当产品名重复建档）
- **自由输入**：输入文字后失焦，直接保存为 `productRef`，同时清空 `productId`/`brandId`/`unitId`/`specId`，标记为非标数据
- **清空 ID 唯一条件**：仅本列文字变更触发 SKU 关联 ID 清空；价格/数量/单位等临时数据变更不清 ID
- **非激活态**：显示商品全名，空值显示"—"（灰色占位符）
- **清除按钮**：编辑态和非激活态均有 `CloseCircleFilled` 清除按钮（条件 `displayValue !== ''`）

### 6.2 单位列特殊交互（v11.4 dropdown 模式）

单位列与产品列视觉/交互一致：**文本自由输入 + 下拉箭头**（`pickerTrigger='dropdown'`）。

- **文本自由输入（快速录入）**：点击单位文字 → 进入编辑态直接输入，失焦/Enter 提交
  - **标准行（有 `specId`）**：输入的单位名已在该 SKU 单位列表内 → 自动绑定其单位 ID；不在列表内 → **补充档案语义**（v11.3）：**建档前弹「新增单位」确认**（v11.8：`该产品暂无单位「X」，确认新增到该产品档案？`）——确认 → `createUnit({specId, unitName})` 建档并绑定新单位 ID；取消 → 不建档不绑定，保留原值并提示。**防止误录/乱输在不知不觉中给产品累积垃圾单位**，让用户明确感知「我输入的单位不存在，系统将新建档案」。
  - **非标行（无 `specId`）**：纯文字保存（`unitId=null`，无档案可挂，不涉及建档无需确认）
- **下拉箭头**：展开 `UnitPicker` 浮动面板（见 4.6.1 换单位规则）
  - **标准行（有 `specId`）**：加载该 SKU 下全部单位（`listUnits by specId`）
    - 从列表选已有单位 → 回填 `unit` + `unitId`
    - 输入新单位名 → 面板「新增到该产品」/ 失焦 / Enter → **建档前弹「新增单位」确认**（v11.8，同上方框文案）→ 确认 → `createUnit({specId, unitName})` 建档 → 用新单位 ID 绑定；取消 → 不建档，恢复原值
    - 该 SKU 下同名单位已存在 → 直接绑定（**不再弹确认**，非建档无写行为）
    - 该 SKU 下同名单位已存在（历史数据）→ 后端 422 拦截，从列表选择即可
  - **非标行（无 `specId`）→ 常见单位列表（v11.11，用户反馈：产品未建档时全局检索单位无意义）**：产品未建档时全局匹配档案单位没有意义——输入「米」返回一堆含「米」的单位全是「已存在」，根本不是想要的。改为展示**预设常见单位**（米/厘米/毫米/平方米/立方米/升/个/件/箱/包/卷/捆/张/套/台/公斤/千克/克/吨/支/根/条/块/片/副/对/双/次，共 28 个）：
    - 空关键词 → 显示全部常见单位，一眼可见直接点选（快速录入）；
    - 输入关键词 → 在常见单位内**本地过滤**（无网络检索）；常见单位无匹配 → 「快速新建」纯文字（`unitId=null`）；
    - 冷门单位直接输入新建，无需滚动长列表。
- **展开显示全部单位（v11.13，用户反馈：多单位产品展开单位面板看不到其他单位切换）**：面板打开时初始关键词 = 当前单位值，但**初始关键词不参与过滤**（`filterActive` 仅当用户修改过输入才生效）——标准行展开展示该 SKU **全部单位**（如「米/捆/根/箱…」20 个），非标行展示全部常见单位；用户输入新关键词后才过滤。修复「当前单位『米』把 19 个其他单位全过滤掉、看不到可切换单位」的缺陷。
- **单位面板显示换算链（v11.14，用户反馈：被问「一根多长/一捆多少根」时面板里直接能看）**：非基础单位按**换算率大小逐级转换**显示（`buildConversionChain`，换算率来自 `getSkuOptions` 的 conversions，只纳入已配置换算率的单位）：
  - 单级：「1 根 = 3 米」（根 rate 3）
  - 多级：「1 捆 = 20 根 = 60 米」（相邻级 20 根 + 兜底绝对换算 60 米）
  - 基础单位显示「(基准)」；未配置换算率的单位不显示换算（换算关系未知）
- 换单位绝不清空产品关联 ID（仅产品全名列变更才清 ID）

### 6.3 行操作菜单

每行右侧有「更多」菜单（`moreMenuRenderer`），包含：

| 菜单项 | 说明 | 禁用条件 |

## 七、交互细节

### 7.1 交互范式

采购报价属于**范式 A：行内编辑 + 浮动面板辅助**。

- **行内编辑列**：数量、单价、备注 — 点击进入编辑态，失焦保存
- **Picker 列**：产品名称/规格（dropdown 模式）、单位（浮动面板模式）
- **浮动面板辅助**：税额面板（点击税额文字展开 FloatPanel，含"含税"复选框、"税点"输入框、"税额"只读显示）

### 7.2 键盘导航

- 产品名称/规格列：dropdown 输入框支持自由输入 + Enter 提交（v11.4：提交后不自动展开选品面板，需检索档案时点下拉箭头手动展开）
- 单位列：dropdown 输入框自由输入 + Enter 提交（v11.4，与产品列一致；标准行提交触发补充档案建档）
- 数量/单价列：数字输入，Enter 或 Tab 失焦保存
- 备注列：文本输入，Enter 保存（Shift+Enter 换行）
- 业务条优惠输入框：Enter 或失焦保存
- 税额面板税点输入框：Enter 或失焦保存

### 7.3 锁定/解锁

- 锁定后所有单元格不可编辑（`isRowDisabled` 返回 true）
- 锁定状态通过 `view_locks.purchaseQuote` 字段持久化
- 作废单据（`pqStatus === 'voided'`）自动锁定，不可解锁
- 锁定按钮文字动态切换："锁定编辑" ⇄ "解锁编辑"

### 7.4 识别订单

- 点击「识别订单」按钮弹出 `DsDialog`
- 用户粘贴自然语言订单文本（如聊天记录）
- 点击「识别并追加」→ 调用 `/api/staff/recognize-order`
- 后端返回识别结果（`rawDescription` + `qty` + `rawUnit`）
- 前端逐条调用 `addLine` 以非标数据模式（`isStandardized: false`）追加到单据

### 7.5 实时同步

- 通过 WebSocket 监听 `document.lines_updated`、`quote.lines_updated`、`document.status_changed` 事件
- 收到事件后自动刷新数据（`useWsAutoRefresh` hook）
- 支持多人协同：不同人员可在多个设备对同一单据进行操作

### 7.6 保存状态提示

- 通过 `useSaveStatus` 上下文管理保存状态
- 使用 `trackSave` 包装所有 API 调用，统一追踪保存中/成功/失败状态

## 八、与其他功能的关联

### 8.1 客户管理

- 单据通过 `customer_id` 关联客户
- 创建单据时可选择客户
- 业务条中可修改客户（`updateDocumentBusiness`）
- v11.0 解耦：单据保存时同步写入客户快照字段（`customerName` / `customerPhone` / `customerCompany`），客户档案删除不影响单据展示

### 8.2 产品管理

- 单据行通过 ProductPicker 从产品库选品
- 选品时自动带入：产品全名、品牌、规格型号、单位、默认售价、缩略图
- 单位列通过 UnitPicker 从产品库选择单位
- v11.0 解耦：单据行保存时写入 5 个独立快照字段（`productName` / `brandName` / `categoryName` / `specModel` / `unitName`），产品档案删除不影响单据展示
- 非标数据（手输文字）不关联产品库，行内显示"待确认"提示

### 8.3 配货管理

- 报价确认后（`purchase_quote_status === confirmed`）方可进入配货环节
- 配货视图基于采购报价的行明细进行仓库出库或外部调货

### 8.4 交付履约

- 配货完成后进入交付环节
- 交付记录与单据关联

### 8.5 成本核定

- 成本核定基于采购报价的行明细进行内部进货成本核算
- 售价（`unitPrice`）与进价（`cost_lines.preset_unit_cost`）物理隔离

### 8.6 收款对账

- 报价确认后按订单应收金额进行收款
- 收款记录与单据关联

### 8.7 退换售后

- 基于采购报价的行明细处理退换货
- 退换行强制继承原单基准数据（`original_qty` / `original_price`）

### 8.8 销售汇总

- 汇总采购报价的销售数据（订单金额、税额、优惠、毛利等）
- 支持时间区间汇总查询

### 8.9 定档归档

- 销售定档（`archiveSales`）冻结销售数据
- 定档后数据不可修改，用于对账和审计

## 九、设计原则总结

| 原则 | 实现方式 |
|------|----------|
| 单一事实源 | 售价保存在 `document_lines` 行上，无独立报价行表 |
| 编辑即保存 | 失焦即触发 API 保存，无"统一保存"按钮 |
| 空行即新增 | 底部空行编辑后自动升级为真实行 |
| 行内编辑 | 数量/单价/备注直接点击编辑 |
| Picker 辅助 | 产品名称/单位通过浮动面板选品选单位 |
| 自由输入 + 标准关联 | 产品名支持手输文字（非标）或从产品库选择（标准） |
| 价格可见性 | 仅报价确认后客户端可见售价 |
| 乐观锁 | 整单 `lock_version` + 行级 `lineVersion` 双重并发控制 |
| 提交排队 | 同行快速连续编辑自动排队，防止并发冲突 |
| WS 实时同步 | 多人协同编辑实时刷新 |
| 视图锁定 | 手动锁定/解锁，作废自动锁定，防误触 |
| 快照存储 | 单据行保存时锁定产品库信息，后续产品库变更不影响单据 |
| AI 辅助 | 自然语言订单文本识别并追加为行 |

- **v11.19（2026-08-11）产品列对齐公共组件规格：固定宽度 + 内容超出自动换行（用户反馈：测试确认产品列超长内容是否自动换行）**：产品列声明 `wrap` 换行模式——列宽恒 220px（colgroup 锁定、内容不参与列宽计算），文本态超长产品名自动换行完整可见（不再截断省略号），行高自适应；短文本单行不影响密集录入。修复点：PickerCellEditor 文本态 span 的内联样式此前强制 `nowrap + ellipsis`（覆盖了列级换行规则），wrap 列下改为 `white-space:normal + word-break:break-word`（dropdown 与 cell 两种触发模式统一）。**验证（生产版 8080 实测）**：36 字超长产品名自动两行、行高 25→55.2px、列宽 220→220 锁定、编辑态 input 212px 铺满；`tsc -b --force` 全量类型检查零错误（顺带修复被增量缓存掩盖的 `col.width` 类型错误）。

- **v11.9（2026-08-10）档案相似候选匹配升级（用户反馈：口语输入匹配不到标准档案）**：
  - **根因（用户反馈）**：用户输入「ppr伟星绿色25给水管」（口语俗语，想到什么说什么，规格值混进产品名）与标准档案「ppr DN25给水管 伟星绿 en4.2」语义高度重合，但快速建档候选**完全没有给出近似选项**。三大根因：① 候选召回按输入前 2 字符前缀 LIKE，口语输入前缀常不在档案名开头（「伟星绿色…」vs 档案开头「ppr」）→ 直接 miss；② 匹配目标只拼产品名+规格（不含品牌），输入里的「伟星」丢失；③ 编辑距离对乱序+长短差异不友好（相似度约 0.5 < 0.6）。另发现 FULLTEXT ngram 对无空格中文长串是短语匹配（token 连续才命中），口语乱序输入常 0 召回且会把目标档案掩埋。
  - **召回升级**：候选召回复用全局检索通道 `recallSkuRowsByKeyword`，新增 `mergeLike` 模式（FULLTEXT ∪ LIKE 合并去重）——LIKE（任意位置包含）保证口语乱序输入不漏召回，候选集 LIMIT 500 受控。
  - **匹配目标升级**：档案全名 = 产品名+规格+品牌（去空格小写），品牌词参与匹配。
  - **相似度算法升级**：语义段覆盖率为主（段子序列命中容错，多段命中才启用）+ 2-gram token 覆盖率（处理中文连写单段输入）+ 编辑距离/完整包含兜底，取最大值；非精确同一的极近似档案匹配度可为 1（仍走候选，精确同一由 dedupKey 判定静默复用）。
  - **验证**：API 7/7（口语输入触发候选含目标档案 / 无 ppr 口语 / 单段「伟星水管」候选 / 无关词直接新建 / 精确组合复用不受破坏）+ 浏览器 3/3（口语输入候选区出现含目标 / 复用行绑定）；v11.7 8/8+4/4、v11.6 6/6、v11.5 9/9、v11.4 9/9、v11.8 13/13、v11.3 14/14、生产冒烟 2/2 回归全部通过。
