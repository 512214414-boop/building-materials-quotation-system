# 功能文档·产品数据层

> **职责**：产品档案相关表结构、关联、保存事务、检索宽表的唯一权威（自包含）。
> 顶层依据：详见《顶层设计规范·理念4》《架构原则·数据规范》（表角色 / 强关联 vs 解耦）。
> 页面行为见《功能文档·产品管理》；开单引用见《功能文档·采购报价》。
> **表怎么组织、选用检索怎么用**以仓库根目录 `文档可视化/` 侧栏为准（概念表名，现网落点写在卡片上）。档案全局规则见《架构原则·档案管理》与侧栏「档案管理 · 全局规则」。本文写现网 Prisma 落点，不要把可视化改回这套表名。

## 业务目标

把「能卖的最小单元」表达为 **规格 × 品牌 × 单位**，让列表检索走宽表、改名全局生效、历史单据只读快照。

## 点位稳定关系

与 `文档可视化/` 同一口径。进价一套、售价一套。

| 层 | 关系 |
|---|---|
| 存 | 面价在 `sale_price` / `purchase_price`（跟单位）。点位两张：圈组默认（类型或渠道 + 品牌名 + 分类名）；规格上那一条（挂 spec_brand，不跟单位拆） |
| 读 | 实际价 = 面价 × 点位。点位：规格上那一条 → 圈组默认 → 1。实际价不存 |
| 写 | 确认修改 = 当前这一条规格（面价不动）。改全局 = 当前品牌 + 当前分类这一批（售价再锁类型，进价再锁渠道）。已经单独改过的规格不跟着变。不是整个品牌，也不是当前产品下所有分类 |
| 用 | 列表 / 选品 / 开单显示实际价。已开单据是快照 |

## 层级

```
分类 category
  └─ 产品 product（名称 + 俗称 remark；分类空则按名称确保「未分类」）
       └─ product_brand（产品挂哪些品牌）
            └─ spec（产品×品牌×系列/规格；备注=执行标准）
                 ├─ spec_unit → 全局单位
                 ├─ brand_unit_conversion（换算粒度 = 规格×品牌×单位）
                 ├─ sale_price / purchase_price（只存面价）
                 ├─ sale_spec_point / purchase_spec_point（规格上那一条）
                 └─ product_image
圈组：sale_point_rule（类型+品牌名+分类名）/ supplier_point_rule（渠道+品牌名+分类名）
宽表：product_sku_search（一行一条规格；选品名称视图再聚成产品名，品牌 N 露出）
```

**单位是全局字典，不是规格私有行。** 规格只通过 `spec_unit` 声明「本规格用哪些单位、哪个是基准、哪个默认显示」。选品里改单位名：默认是本规格换绑到另一个单位（有则复用、无则进字典再挂上）；点「改全局」才动字典——目标名不存在就改名，已有同名就把所有引用并到那个单位，不是报「已存在」。删除某规格的单位引用只删中间表，不删全局单位。删除全局单位前必须确认无 `spec_unit`、无售价/进价引用，禁止静默清空全库价格。售价/进价是配置子表：随规格品牌走 CASCADE，不随全局单位静默 CASCADE。品牌 / 分类 / 售价类型 / 供应商的改全局同一套：改名或并到已有档案。已开单据行是快照，不跟着改。

## 表结构

### category（基础档案）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | Int PK | | `3` |
| name | VARCHAR(100) | 唯一 | `管材` |
| sortOrder | Int | 默认 0 | `10` |
| status | Int | 1 启用 / 0 停用 | `1` |

空分类输入由写入层按名称确保「未分类」记录，无 `0` 魔数。

### product（基础档案）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | 应用层时间戳 ID | `20260818103500123` |
| name | VARCHAR(200) | 与 categoryId 联合唯一 | `PPR热水管` |
| categoryId | Int FK | NOT NULL → category.id | `3(管材)` |
| remark | VARCHAR(500) | 默认空 | `6分管`（俗称/别名，名称检索用） |
| status | Int | 默认 1 | `1` |

### spec（配置子表，v22 挂在产品品牌下）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | 接口仍可称 specBrandId | `9001` |
| productId | BigInt FK | CASCADE → product.id | `2026…(PPR热水管)` |
| brandId | BigInt FK | → brand.id | `12(伟星)` |
| specModel | VARCHAR(200) | 同产品同品牌下唯一 | `dn25*3.5` |
| remark | VARCHAR(500) | 默认空 | `国标 GB/T 18742.2`（这一条规格的执行标准/企标/层数，不是品牌备注） |

售价、进价、图片、换算、规格备注都挂本表。同一型号不同品牌是两行。

### spec_brand

v22 已并入 `spec`（productId+brandId+specModel）。不要再把备注写在品牌上。接口兼容字段 `specBrandId` = `spec.id`。

### brand（基础档案，name 全局唯一）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `12` |
| name | VARCHAR(100) | 唯一 | `伟星` |
| status | Int | 默认 1 | `1` |

品牌没有备注。执行标准写在 `spec.remark`。

### unit（基础档案，v16.5 全局字典）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `7` |
| unitName | VARCHAR(50) | 全局唯一 | `米` |
| status | Int | 默认 1 | `1` |

改名通过引用立即全局生效。停用后各规格不再选用该单位。

### spec_unit（配置子表，规格×全局单位）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `101` |
| specId | BigInt FK | CASCADE → spec.id | `9001(dn25*3.5)` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| isBase | Boolean | 同规格有且仅一个 true | `true`（库存核算基准） |
| isDisplay | Boolean | 同规格至多一个 true | `true`（列表默认展示；无则取基准） |

同一规格同一全局单位不重复。换算率不在此表。

### brand_unit_conversion（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `301` |
| specBrandId | BigInt FK | CASCADE → spec_brand.id | `55(dn25×伟星)` |
| unitId | BigInt FK | → unit.id | `8(根)` |
| conversionRate | Decimal(10,4) | 基准单位强制 1 | `3.0000`（1 根 = 3 米） |

### price_type（基础档案）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `1` |
| name | VARCHAR(50) | 唯一 | `零售价` |
| sortOrder / status | Int | | `0` / `1` |

### sale_price（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `401` |
| specBrandId | BigInt FK | CASCADE → spec_brand.id | `55` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| priceTypeId | BigInt FK | CASCADE → price_type.id | `1(零售价)` |
| price | Decimal(10,2) | 面价。实际售价 = 面价 × 点位（规格例外 → 组默认 → 1） | `12.50` |
| isDefault | Boolean | 同一 specBrandId+unitId 仅一个 true | `true` |
| status | Int | 默认 1 | `1` |

同一 SKU 同一价格类型不重复。

### purchase_price（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `501` |
| specBrandId | BigInt FK | CASCADE → spec_brand.id | `55` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| supplierId | BigInt | 逻辑引用供应商，无物理外键 | `9` |
| supplierName | VARCHAR(200) | 快照 | `华南管业` |
| price | Decimal(10,2) | 面价；进价 = 面价 × 点位 | `8.00` |
| isDefault | Boolean | 同一 SKU 仅一个 true | `true` |

供应商档案删除后进价行仍可展示（解耦）。点位：规格上那一条 `purchase_spec_point` → 圈组 `supplier_point_rule` → 1。售价对等：`sale_spec_point` → `sale_point_rule` → 1。实际价不存，读时算。改全局只改圈组，已经单独改过的规格不动；确认修改只写规格上那一条；单条调面价不动点位。

### sale_point_rule / sale_spec_point / purchase_spec_point

组默认按圈组：**同一品牌 + 同一分类** 这一批（售价再加售价类型，进价再加进货渠道）。用来一次调完厂家这一类货，例如伟星的 PPR 管材从 0.75 调到 0.72。不是整个品牌：伟星的阀门、电线点位本来就不一样，不会被改到。也不是「当前这一个产品下所有分类」。规格上那一条挂 spec_brand，点位不跟单位拆。没人谈点位就不建这些行。

### product_image（配置子表）

挂 `spec_brand`。含原图 / 中图 / 缩略图 URL、宽高、字节、内容哈希、是否主图。

### product_sku_search（检索宽表，非录入表）

每「规格 × 品牌」一行。冗余产品名、规格型号、分类、品牌、默认单位、默认零售价、默认进价、主图、规格备注（`remark`=spec.remark）、产品俗称（`productRemark`）、综合状态、关键词。名称层 keywords = 这一层有的字：产品名+俗称+规格型号+品牌+分类。规格备注是执行标准层的字，渠道名是供应商层的字，各自在那一层检索（到哪一层有什么就搜什么，打法是全的，不按词禁结果）。列表关键词和选品「名称」视图打 keywords；执行标准视图打 remark（FULLTEXT）；供应商视图经进价表按渠道名反查 specId。档案保存后由写入层同步，禁止业务页直接改宽表。

## 接口契约

| 能力 | 方法与路径 | 要点 |
|------|------------|------|
| 整档保存 | `POST /staff/products/save` | 入参：产品 id、specId、name、specModel、categoryId、remark（俗称）、specRemark（当前这条规格的执行标准，只写当前 specId）、units[]、brands[]（不再带品牌备注）、salePrices[]、purchasePrices[]。同步宽表 |
| 全局单位 | `GET/POST /staff/units`，`PATCH/DELETE /staff/units/:id` | 字典 CRUD；删除前检查 spec_unit 与价格引用 |
| 规格引用单位 | `GET/POST /staff/specs/:specId/units`，`DELETE .../units/:unitId` | 增删的是中间表 |
| 基准 / 显示 | `POST .../units/:unitId/base`，`POST .../units/:unitId/display` | 同规格互斥 |
| 换算 | `PATCH /staff/spec-brands/:specBrandId/units/:unitId/conversion` | 写 brand_unit_conversion；基准单位固定 1；粒度规格×品牌×单位 |
| 检索 / 选品 | `GET /staff/products/search`，`GET /staff/products/search/facets`，`GET /staff/products/sku/options`，`GET /staff/products/suggest` | 走宽表。search 带 `entryView`（宽松/名称/品牌/规格/执行标准/供应商）。默认名称。同一串字，包含与被包含。管理筛与选用检索两套，详见《档案管理》。选项来自当前结果 facets，不是全局字典 |
| 点位 | `PUT /staff/sale-spec-points`，`PUT /staff/purchase-spec-points`，`PUT /staff/sale-group-points`，`PUT /staff/purchase-group-points`，`POST /staff/point-changes/preview` | 确认修改写规格上那一条；改全局只写圈组并列出跟圈组的规格；已经单独改过的不动 |
| 快速建档 | `POST /staff/products/quick-create` | 空规格补「通用」、空单位补「件」、空品牌补「无品牌」 |

## 保存逻辑

- 分类空 → 确保「未分类」；品牌空 → 「普通品牌」；单位空 → 「件」；规格空 → 「通用」。按名称确保：库里有就挂 id，没有才建。不写种子、启动不预插。售价/进价/图片/点位用户没起头就一行不建；写了进价没选渠道 → 面价渠道；写了售价没选类型 → 零售价。
- 同名全局单位复用 id，不重复建字典行。
- 第一个挂到规格的单位自动成为基准且显示。
- 宽表同步是唯一入口：按规格刷新该 spec 行。禁止在多个服务里复制同步逻辑。实现落在 `services/product/skuSearch.ts`，其它域只调用，不各写一份 upsert。
- 单据行只存快照 + 档案 ID，不 CASCADE 到本层（见《单据与状态机》）。

## 写入层切分

`productService.ts` 只再导出。HTTP 路径与函数名不变。按域分文件，禁止再把分类/检索/存档堆回单文件。

| 模块 | 职责 |
|------|------|
| `unitDict` | 全局单位字典与规格引用 |
| `category` / `catalog` / `brand` | 分类、产品规格、品牌档案 |
| `salePrice` / `purchasePrice` / `point` / `images` | 售价、进价、点位（圈组 + 规格上那一条）、图片 |
| `skuSearch` | 宽表同步（唯一入口） |
| `search` | 检索 / SKU 选项 / suggest |
| `saveProduct` | 建档事务 |
| `shared` | 缺省常量与进价计算公式 |
