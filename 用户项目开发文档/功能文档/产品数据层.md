## 业务目标

把「能卖的最小单元」表达为 **规格 × 品牌 × 单位**，让列表检索走宽表、改名全局生效、历史单据只读快照。

## 点位稳定关系

与 `文档可视化/` 同一口径。进价一套、售价一套。

| 层 | 关系 |
|---|---|
| 存 | 面价在 `sale_price` / `purchase_price`（跟单位）。点位两张：圈组默认（类型或渠道 + 品牌名 + 分类名）；规格上那一条（挂 `spec`，不跟单位拆） |
| 读 | 实际价 = 面价 × 点位。点位：规格上那一条 → 圈组默认 → 1。实际价不存 |
| 写 | 确认修改 = 当前这一条规格（面价不动）。改全局 = 当前品牌 + 当前分类这一批（售价再锁类型，进价再锁渠道）。已经单独改过的规格不跟着变。不是整个品牌，也不是当前产品下所有分类 |
| 用 | 列表 / 选品 / 开单显示实际价。已开单据是快照 |

## 层级（v23 目标态 · 代码未实施）

```
product_name（全局字典 · 词，name 全局唯一）
  └─ product（主体 1:1 引用字典；挂俗称 remark；分类空则按名称确保「未分类」）
       ├─ product_category（产品×分类 1对N；isPrimary 主分类）
       └─ product_brand（产品挂哪些品牌）

                 ├─ brand_unit_conversion（换算粒度 = 规格×单位）
```

## 宽表字段来源登记表（产品集合体 · 唯一入口）

产品集合体 = **档案集合体**：一组表围着一个名单框（`product`）转，名单下挂子表；实体表只存 ID 引用字典，改名全局生效。登记表是唯一入口——加字段、加关系先改这里，表结构、接口、页面列、宽表同步四处跟着走。

**组织形式**：横轴 = 宽表上的一列（管理页能看到的一格）；纵轴 = 这一格的字从哪来（字段说明 / 层 / 数据表 / 字典表 / 关系表 / 宽表落点）。

| 宽表字段 → | 分类 | 产品名称 | 产品俗称 | 品牌 | 规格系列 | 规格备注 | 单位 | 售价 | 进价 |
|---|---|---|---|---|---|---|---|---|---|
| **字段说明** | 这货归到哪一类（管材/管件）。扁平无父子；一个产品可归**多个**分类，其中一个是主分类。空输入按名称确保「未分类」真实记录，不用 0 魔数 | 卖的货叫什么（`PPR热水管`）。全局只有一个这个词，改名全局生效；**跨分类不重名**——同名词就是同一个产品 | 口语叫法（`6分管`）。跟产品走，进名称检索、不进产品名 | 哪家厂/哪个牌子。全局档案，改名全局生效，停用后引用它的规格不再可用 | 型号/系列（`dn25*3.5`）。同产品同品牌下唯一；同一型号不同品牌是两行 | 这一条规格的执行标准/企标/国标/层数。**不是品牌备注**，品牌没有备注 | 按什么卖（米/根/件）。全局一套，改名所有引用它的规格立即生效 | 卖给客户的**面价**。实际售价 = 面价 × 点位（规格例外 → 圈组默认 → 1），读时算不存 | 从渠道进的**面价**。实际进价 = 面价 × 点位，同一套点位链 |
| **层** | 全局字典 + 产品挂载（关系表） | **全局字典**（词）| 档案主体字段 | 全局字典 + 产品挂载 | 挂载层（产品×品牌下） | 挂载层字段 | 全局字典 + 规格挂载 | 行级配置（挂 规格×单位） | 行级配置（挂 规格×单位×渠道） |
| **数据表**（值存在哪） | — | — （值在字典表）| `product.remark` | — | `spec.specModel` | `spec.remark` | — | `sale_price.price` | `purchase_price.price` |
| **字典表** | `category`（name 全局唯一） | `product_name`（name 全局唯一）**v23 新增** | 无 —— 是产品的一个字段，非字典（裁决 ②） | `brand`（name 全局唯一） | 无 | 无 | `unit`（unitName 全局唯一） | `price_type`（零售价/批发价/工程价） | 无 —— 渠道是供应商**档案** `supplier`，逻辑引用无物理外键 |
| **关系表 · 关系类型** | `product_category`（产品×分类，**1 对 N**；带 `isPrimary` 主分类 + `sortOrder`）**v23 新增**，不再外键直挂 | `product.productNameId` 引用字典，**1 对 1**（一个词一份产品实体） | 无 | `product_brand`（产品×品牌，**N 对 M**）+ `spec.brandId`（规格必挂品牌，**N 对一**） | 无（`spec` 靠 `productId+brandId` 挂载，是产品×品牌下的实体行） | 无 | `spec_unit`（规格×单位，**多对多**；带 `isBase`/`isDisplay`）+ `brand_unit_conversion`（换算率，粒度 规格×单位） | `sale_price`（规格 × 单位 × 价格类型，主体 **1 对 N**）；例外点位 `sale_spec_point`，圈组 `sale_point_rule` | `purchase_price`（规格 × 单位 × 供应商，主体 **1 对 N**）；点位 `purchase_spec_point` / `supplier_point_rule` |
| **宽表落点**（`product_sku_search` 列） | `categoryId` / `categoryName` = **主分类**（`isPrimary=true`）；其余所属分类名进 `keywords` | `productId` / `productName`（冗余自 `product_name.name`） | `productRemark` | `brandId` / `brandName` | `specId` / `specModel` | `remark` | `defaultUnitId` / `defaultUnitName` | `retailPrice` | `purchasePriceDefault` |

**读法**：一格里的字，要么在「数据表」自己存着，要么在「字典表」存着由 ID 引用，要么通过「关系表」挂上去。三行都空的 = 字段本身就是主体的属性，没有来源可选。宽表一行 = 一条 `spec`（产品×品牌×规格），`specId` 唯一。

**上面 9 列之外**，宽表还有这几列（同属产品集合体，管理页可见）：主图 `mainImageUrl` / `mainImageThumbUrl`（源 `product_image`，挂 `spec`）、综合状态 `status`（产品启用 ∧ 规格启用 ∧ 品牌启用）、全文检索 `keywords`（产品名+俗称+规格型号+品牌+分类拼接，不含执行标准、不含渠道名）、`updateTime`。**都不是录入列**，由写入层 `skuSearch.ts` 同步，业务页禁止直接改宽表。

### 三条裁决（2026-08-31 · v23 目标态，代码未实施）

| # | 裁决 | 落地形态 |
|---|---|---|
| ① | 产品名**升成全局字典** | 新增 `product_name`（name 全局唯一）；`product.name` 列废止，改 `product.productNameId` 引用字典。改名全局生效 |
| ② | 俗称**维持单字段** | 仍是 `product.remark`，不建子表、不进字典 |
| ③ | 分类**要关系表**，不要外键直挂 | 新增 `product_category`（产品×分类）；`product.categoryId` 列废止 |

**①③ 是联锁的，不能只做一条。** 产品名升字典后，名字全局唯一，就再也不能靠「同一分类下唯一」来区分两个同名产品——同名就是同一个产品。此时分类必须能一对多挂，否则「弯头」只能待在一个分类里。**先升字典 → 分类必须走关系表**，这就是③为什么必须一起改。

**跨分类重名怎么办（裁决①的代价与收益）**：不再允许重名。同一个词 = 一份 `product_name` = 一个产品实体，通过 `product_category` 挂多个分类；两个分类下都卖 PPR热水管，是**一个产品挂两个分类**，不是两个产品。收益：改名全局生效、检索不歧义、统计按 ID。代价：确实是两种货却同名（如 PPR弯头 / PVC弯头）必须靠名称本身区分，店员建档时同名会复用已有词而不是新建——这正是「边用边建、幂等直接建即选」的字典行为。

**`product` 与 `product_name` 是 1:1 但不合并**：字典只管「这个词」（可快建、可并档、可查引用计数、改名全局生效），产品实体承载俗称与品牌/规格子树。分层不同、可变性不同——按「分层定可变性」，不因为 1:1 就叠成一张表。

**改名全局生效的边界**：改 `product_name.name` → 引用它的产品、宽表 `productName`、检索 `keywords` 全部跟着变；已开单据行是快照，不跟着改（快照与标注分离）。

### 迁移口径（实施时照此执行，顺序不可颠倒）

1. **建 `product_name`**：从现有 `product.name` 去重抽取，每个名字一条。
2. **建 `product_category`**：原 `product.categoryId` 插一条，`isPrimary=true`。
3. **同名多 `product` 合并**：按 name 分组，组内多条 product 合成一条。
   - 各组其余的 `categoryId` → 各插一条 `product_category`（`isPrimary=false`）
   - 组内各条的 `product_brand` / `spec` → 改挂合并后的那一条 `product.id`
   - **冲突必须人工核**：合并后若出现同 `brandId` + 同 `specModel` 的 spec（且售价/进价不同），迁移脚本**只出清单不自动取舍**
   - 俗称 `remark`：取组内第一条非空值；组内多条非空且不同 → 一并进清单
4. **改 `product` 表**：删 `name` 与 `categoryId` 列，加 `productNameId` FK；唯一约束 `[categoryId, name]` → `[productNameId]`。
5. **重刷宽表**：按 spec 全量重刷。`categoryId`/`categoryName` 取 `isPrimary`，`keywords` 拼接全部所属分类名。
6. **写入层改造**：建档时产品名按 name 幂等 ensure（有就复用、无才建），与品牌/单位/分类同一套；保存事务内维护 `product_category`。

**实施前置**：迁移前 `git status` 必须干净（见《版本记录与恢复》），迁移脚本与 schema 变更分开两个提交。

### 共性与差异（看这张表要看到什么）

**共性**：

1. **凡是档案名字段，都走字典或直接/间接引用字典**：产品名、俗称、分类、品牌、单位，甚至售价/进价的维度（价格类型、供应商）也来自字典或档案。
2. **凡是型号/规格/备注类字段，都不走字典**：规格系列、规格备注是规格自身的属性，直接写在 `spec` 上。
3. **多对多关系都靠中间表**：品牌 `product_brand`、单位 `spec_unit`；一对多关系既可能是中间表（`product_category`、`product_alias`），也可能是外键直挂（`spec.brandId`、`product.categoryId`）。

**差异**：

| 维度 | 产品名称 | 产品俗称 | 分类 | 品牌 | 规格系列/备注 | 单位 | 售价/进价 |

| 关系类型（从产品看） | 1:1 引用字典 | 1:N | 1:N（图中：一个产品只能选 1 个分类） | N:M | — | N:M（规格×单位） | 配置子表 1:N |

## 表结构

### category（基础档案）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | Int PK | | `3` |
| name | VARCHAR(100) | 唯一 | `管材` |
| sortOrder | Int | 默认 0 | `10` |
| status | Int | 1 启用 / 0 停用 | `1` |

空分类输入由写入层按名称确保「未分类」记录，无 `0` 魔数。

### product_name（基础档案 · v23 新增，全局字典）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `501` |
| name | VARCHAR(200) | **全局唯一** | `PPR热水管` |
| status | Int | 1 启用 / 0 停用 | `1` |

字典只管「这个词」：边用边建、同名幂等复用、改名全局生效、被引用不能删（只能停用）。可并档：目标名不存在就改名，已存在就把所有引用并过去。

### product（基础档案 · v23 改造）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | 应用层时间戳 ID | `20260818103500123` |
| productNameId | BigInt FK | NOT NULL → product_name.id；**唯一**（一个词一份产品实体） | `501(PPR热水管)` |
| remark | VARCHAR(500) | 默认空 | `6分管`（俗称/别名，名称检索用） |
| status | Int | 默认 1 | `1` |

v23 废止 `name` 与 `categoryId` 两列（原 `[categoryId, name]` 联合唯一改为 `[productNameId]`）。产品名读 `product_name.name`；分类走 `product_category`。

### product_category（配置子表 · v23 新增，产品×分类）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `7001` |
| productId | BigInt FK | CASCADE → product.id | `2026…(PPR热水管)` |
| categoryId | Int FK | → category.id | `3(管材)` |
| isPrimary | Boolean | 同一产品**有且仅有一个** true；宽表分类列取它 | `true` |
| sortOrder | Int | 默认 0 | `0` |

同一产品同一分类不重复（`@@unique([productId, categoryId])`）。第一个挂上去的分类自动成为主分类；换主分类是改这一列的 `isPrimary`，不是删记录重挂。删除某产品的分类只删本表，不影响 `category` 字典。

### spec（配置子表，v22 挂在产品品牌下）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | 接口仍可称 specBrandId | `9001` |
| productId | BigInt FK | CASCADE → product.id | `2026…(PPR热水管)` |
| brandId | BigInt FK | → brand.id | `12(伟星)` |
| specModel | VARCHAR(200) | 同产品同品牌下唯一 | `dn25*3.5` |
| remark | VARCHAR(500) | 默认空 | `国标 GB/T 18742.2`（这一条规格的执行标准/企标/层数，不是品牌备注） |

售价、进价、图片、换算、规格备注都挂本表。同一型号不同品牌是两行。

### spec_brand

v22 已并入 `spec`（productId+brandId+specModel）。不要再把备注写在品牌上。接口兼容字段 `specBrandId` = `spec.id`。

### brand（基础档案，name 全局唯一）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `12` |
| name | VARCHAR(100) | 唯一 | `伟星` |
| status | Int | 默认 1 | `1` |

品牌没有备注。执行标准写在 `spec.remark`。

### unit（基础档案，v16.5 全局字典）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `7` |
| unitName | VARCHAR(50) | 全局唯一 | `米` |
| status | Int | 默认 1 | `1` |

改名通过引用立即全局生效。停用后各规格不再选用该单位。

### spec_unit（配置子表，规格×全局单位）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `101` |
| specId | BigInt FK | CASCADE → spec.id | `9001(dn25*3.5)` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| isBase | Boolean | 同规格有且仅一个 true | `true`（库存核算基准） |
| isDisplay | Boolean | 同规格至多一个 true | `true`（列表默认展示；无则取基准） |

同一规格同一全局单位不重复。换算率不在此表。

### brand_unit_conversion（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `301` |
| specId | BigInt FK | CASCADE → spec.id（接口兼容名 specBrandId） | `9001(dn25×伟星)` |
| unitId | BigInt FK | → unit.id | `8(根)` |
| conversionRate | Decimal(10,4) | 基准单位强制 1 | `3.0000`（1 根 = 3 米） |

### price_type（基础档案）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `1` |
| name | VARCHAR(50) | 唯一 | `零售价` |
| sortOrder / status | Int | | `0` / `1` |

### sale_price（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `401` |
| specId | BigInt FK | CASCADE → spec.id（接口兼容名 specBrandId） | `9001` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| priceTypeId | BigInt FK | CASCADE → price_type.id | `1(零售价)` |
| price | Decimal(10,2) | 面价。实际售价 = 面价 × 点位（规格例外 → 组默认 → 1） | `12.50` |
| isDefault | Boolean | 同一 specId+unitId 仅一个 true | `true` |
| status | Int | 默认 1 | `1` |

同一 SKU 同一价格类型不重复。

### purchase_price（配置子表）

| 字段 | 类型 | 约束 | 示例 |
|------|------|------|------|
| id | BigInt PK | | `501` |
| specId | BigInt FK | CASCADE → spec.id（接口兼容名 specBrandId） | `9001` |
| unitId | BigInt FK | CASCADE → unit.id | `7(米)` |
| supplierId | BigInt | 逻辑引用供应商，无物理外键 | `9` |
| supplierName | VARCHAR(200) | 快照 | `华南管业` |
| price | Decimal(10,2) | 面价；进价 = 面价 × 点位 | `8.00` |
| isDefault | Boolean | 同一 SKU 仅一个 true | `true` |

供应商档案删除后进价行仍可展示（解耦）。点位：规格上那一条 `purchase_spec_point` → 圈组 `supplier_point_rule` → 1。售价对等：`sale_spec_point` → `sale_point_rule` → 1。实际价不存，读时算。改全局只改圈组，已经单独改过的规格不动；确认修改只写规格上那一条；单条调面价不动点位。

### sale_point_rule / sale_spec_point / purchase_spec_point

组默认按圈组：**同一品牌 + 同一分类** 这一批（售价再加售价类型，进价再加进货渠道）。用来一次调完厂家这一类货，例如伟星的 PPR 管材从 0.75 调到 0.72。不是整个品牌：伟星的阀门、电线点位本来就不一样，不会被改到。也不是「当前这一个产品下所有分类」。规格上那一条挂 `spec`，点位不跟单位拆。没人谈点位就不建这些行。

### product_image（配置子表）

挂 `spec`。含原图 / 中图 / 缩略图 URL、宽高、字节、内容哈希、是否主图。

### product_sku_search（检索宽表，非录入表）

每「规格 × 品牌」一行。冗余产品名、规格型号、分类、品牌、默认单位、默认零售价、默认进价、主图、规格备注（`remark`=spec.remark）、产品俗称（`productRemark`）、综合状态、关键词。名称层 keywords = 这一层有的字：产品名+俗称+规格型号+品牌+分类。

**v23**：`productName` 冗余自 `product_name.name`（改名全局生效，重刷宽表即可）；`categoryId`/`categoryName` = **主分类**（`product_category.isPrimary=true`），该产品的**全部**所属分类名都进 `keywords`——一个产品挂三个分类，搜任一个分类名都能召回它。规格备注是执行标准层的字，渠道名是供应商层的字，各自在那一层检索（到哪一层有什么就搜什么，打法是全的，不按词禁结果）。列表关键词和选品「名称」视图打 keywords；执行标准视图打 remark（FULLTEXT）；供应商视图经进价表按渠道名反查 specId。档案保存后由写入层同步，禁止业务页直接改宽表。

## 接口契约

| 能力 | 方法与路径 | 要点 |
|------|------------|------|
| 整档保存 | `POST /staff/products/save` | 入参：产品 id、specId、name（产品名，写入层按 name 幂等 ensure `product_name`）、categories[]（v23 替代 categoryId，带 isPrimary）、specModel、remark（俗称）、specRemark（当前这条规格的执行标准，只写当前 specId）、units[]、brands[]（不再带品牌备注）、salePrices[]、purchasePrices[]。同步宽表 |
| 全局单位 | `GET/POST /staff/units`，`PATCH/DELETE /staff/units/:id` | 字典 CRUD；删除前检查 spec_unit 与价格引用 |
| 规格引用单位 | `GET/POST /staff/specs/:specId/units`，`DELETE .../units/:unitId` | 增删的是中间表 |
| 基准 / 显示 | `POST .../units/:unitId/base`，`POST .../units/:unitId/display` | 同规格互斥 |
| 换算 | `PATCH /staff/spec-brands/:specBrandId/units/:unitId/conversion` | 写 brand_unit_conversion；基准单位固定 1；粒度规格×品牌×单位 |
| 检索 / 选品 | `GET /staff/products/search`，`GET /staff/products/search/facets`，`GET /staff/products/sku/options`，`GET /staff/products/suggest` | 走宽表。search 带 `entryView`（宽松/名称/品牌/规格/执行标准/供应商）。默认名称。同一串字，包含与被包含。管理筛与选用检索两套，详见《档案管理》。选项来自当前结果 facets，不是全局字典 |
| 点位 | `PUT /staff/sale-spec-points`，`PUT /staff/purchase-spec-points`，`PUT /staff/sale-group-points`，`PUT /staff/purchase-group-points`，`POST /staff/point-changes/preview` | 确认修改写规格上那一条；改全局只写圈组并列出跟圈组的规格；已经单独改过的不动 |
| 快速建档 | `POST /staff/products/quick-create` | 空规格补「通用」、空单位补「件」、空品牌补「无品牌」 |

## 保存逻辑

- 分类空 → 确保「未分类」；品牌空 → 「普通品牌」；单位空 → 「件」；规格空 → 「通用」。按名称确保：库里有就挂 id，没有才建。不写种子、启动不预插。
- **v23 产品名按名称幂等 ensure**：库里有这个词就复用它的 `product_name.id`，没有才建——与品牌/单位/分类同一套。建档输「弯头」命中已有词 = 挂在那个产品下，不新建同名产品。售价/进价/图片/点位用户没起头就一行不建；写了进价没选渠道 → 面价渠道；写了售价没选类型 → 零售价。
- 同名全局单位复用 id，不重复建字典行。
- 第一个挂到规格的单位自动成为基准且显示。
- 宽表同步是唯一入口：按规格刷新该 spec 行。禁止在多个服务里复制同步逻辑。实现落在 `services/product/skuSearch.ts`，其它域只调用，不各写一份 upsert。
- 单据行只存快照 + 档案 ID，不 CASCADE 到本层（见《单据与状态机》）。
