## 功能概述

售后管理功能包含两条独立业务线：

### 退换售后线（refund_lines）

员工在单据详情页的「售后退款」视图中，对已产生的单据行进行退换货操作。核心设计原则：

- **强继承**：`original_qty`（原数量）和 `original_price`（原售价）强制继承自 `document_lines`，不接受前端传入，确保退换金额的准确性。
- **防御性超退**：`SUM(refund_qty WHERE line_id) ≤ document_lines.qty`，前端 + 后端双重校验，拦截超退行为。
- **系统计算金额**：`refund_amount = refund_qty × original_price`，由后端 `round2()` 计算，不接受前端传入。
- **只读展示**：列表使用 `UnifiedTable` 的 `static` 渲染模式，所有数据列只读，编辑通过 `DsDialog` 弹窗完成。
- **视图防误触锁定**：`view_locks.refund_after_sale` 独立于行级 `refund_status=closed`，前者是防误触的临时锁定（随时可解锁），后者是状态推进的永久关闭。

### 报销副单线（reimbursement_bills）

员工在单据关联场景下，为代采业务生成报销副单（如给公司财务报销用）。核心设计原则：

- **独立副单**：每条副单有独立的 `bill_no`（格式 `BX` + YYYYMMDD + 3位随机数），可包含多条明细行。
- **自由编辑**：报销副单的行数据（品名、规格、单位、数量、单价）可自由编辑，初始草稿来自单据行快照，与原始单据行解耦。
- **历史追溯**：所有副单按时间倒序保留，可查看、删除。

## 保存逻辑

### 退换行新增

```
1. 校验单据存在
2. 校验 lineId 属于 documentId
3. 超退校验：SUM(refund_qty WHERE line_id) + input.refund_qty ≤ document_lines.qty
4. 强继承：original_qty = document_lines.qty，original_price = document_lines.unitPrice
5. 系统计算：refund_amount = round2(refund_qty × unitPrice)
6. 写入 refund_lines（refund_status = pending，refund_at = now()）
7. 广播 WebSocket 事件 refund.updated → 同一单据的其他视图联动刷新
8. 审计日志记录 refund_line_add
```

### 退换行更新

```
1. 校验退换行存在
2. 若 refund_qty 未变化 → 仅更新 reason，跳过超退校验
3. 若 refund_qty 变化 → 重新超退校验（排除当前行自身）、重新计算 refund_amount
4. 广播 WebSocket 事件 refund.updated
5. 审计日志记录 refund_line_update
```

### 退换行删除

```
1. 校验退换行存在
2. 物理删除
3. 广播 WebSocket 事件 refund.updated
4. 审计日志记录 refund_line_remove
```

### 报销副单创建

```
1. 校验源单据存在
2. 生成 bill_no（格式：BX + YYYYMMDD + 3 位随机数，如 BX20260804001）
3. 逐行计算 amount = qty × unitPrice
4. 计算 subtotal = SUM(amount)，total = subtotal
5. 事务写入 reimbursement_bills + reimbursement_bill_lines
6. 记录日志
```

### 报销副单删除

```
1. 校验副单存在
2. 级联删除（reimbursement_bill_lines 随父表 CASCADE）
3. 记录日志
```

### 交互细节

#### 视图防误触锁定

- **锁定按钮**：操作栏右侧，点击直接锁定（无确认弹窗），锁定后新建/编辑/删除全部禁用。
- **解锁按钮**：锁定状态下显示，点击弹出 `Modal.confirm` 二次确认后解锁。
- **与 refund_status=closed 独立**：`closed` 是行级状态推进（已处理完毕），锁定该行不可编辑；`view_locks.refund_after_sale` 是视图级防误触（临时锁定），锁定整个视图不可操作。

#### 新建退换记录

- 商品行下拉基于 `docLines` 生成，标签格式：`产品名(规格) — 需求N / 余可退N / 单价¥N`。
- 选项自动 `disabled` 当 `remainingRefundable ≤ 0` 或 `unitPrice ≤ 0`。
- 选中商品行后，下方显示强继承基准信息条（商品/规格/单位/原需求/已退换/余可退/原售价/退换金额预览）。
- 退换金额预览实时计算：`round2(newRefundQty × selectedUnitPrice)`，红色字体。
- 前端超退校验：`newRefundQty > selectedRemaining` 时 alert 拦截。
- 添加成功后自动清空表单，刷新列表。

#### 编辑退换记录

- 首列「更多」菜单 → 编辑，打开 `DsDialog`。
- 弹窗内展示强继承基准信息网格（商品/规格+单位/原数量/原售价/已退累计/剩余可退）。
- 退换数量输入框，右侧显示「最大 N」提示。
- 退换金额预览实时计算显示。
- 原因/备注输入框，选填。
- 前端超退校验：`newQty > (editTarget.originalQty - otherRefunded)` 时拦截。
- 使用 `trackSave` 保存（行级状态点 + 全局状态栏），静默反馈。

#### 删除退换记录

- 首列「更多」菜单 → 删除，弹出 `Modal.confirm` 二次确认。
- 确认后物理删除，刷新列表。

#### 必看信息折叠区

- 展示原收款记录（来自 `docDetail.paymentRecords`），折叠/展开切换。
- 包含：收款类型标签（定金/尾款/余额）、金额、方式、时间、对账状态。
- 无收款记录时提示「退款依据缺失，请先在 V3 收款对账环节录入」。

#### WebSocket 联动

- 监听 `refund.updated`、`refund.recorded`、`payment.updated` 事件自动刷新。
- 退换行增删改后广播 `refund.updated`，其他视图联动刷新。
