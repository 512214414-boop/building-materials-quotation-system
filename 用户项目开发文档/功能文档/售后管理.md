# 售后管理

> **职责**：退换售后与报销副单两条业务线的唯一设计依据与逻辑轴心。单据主表/单据行结构与 8 档单据状态机的权威定义见《单据与状态机》，本文档只引用、不重述。
> **配套**：UI 交互总规范见 [表格与交互规范.md](../架构原则/表格与交互规范.md)。

## 功能概述

售后管理包含两条独立业务线：**退换售后线**（`refund_lines`，退换货处理）与**报销副单线**（`reimbursement_bills`，代采业务报销凭证）。两者独立运行、互不影响。

### 退换售后线

员工在单据详情页的「售后退款」视图中，对已产生的单据行进行退换货操作。核心设计原则：

- **强继承**：`original_qty`（原数量）与 `original_price`（原售价）强制继承自 `document_lines`，不接受前端传入，确保退换金额准确性；
- **防御性超退**：`SUM(refund_qty WHERE line_id) ≤ document_lines.qty`，前端 + 后端双重校验，拦截超退；
- **系统计算金额**：`refund_amount = refund_qty × original_price`，由后端 `round2()` 计算，不接受前端传入；
- **只读展示**：列表使用 `UnifiedTable` 的 `static` 渲染模式，数据列只读，编辑通过 `DsDialog` 弹窗完成；
- **视图防误触锁定**：`view_locks.refund_after_sale` 为视图级临时锁定（随时可解锁），独立于行级 `refund_status = closed` 的状态推进（永久关闭）。

### 报销副单线

员工在单据关联场景下，为代采业务生成报销副单（如给公司财务报销用）。核心设计原则：

- **独立副单**：每条副单有独立编号，可包含多条明细行；
- **自由编辑**：副单行数据（品名、规格、单位、数量、单价）可自由编辑，初始草稿来自单据行快照，与原始单据行解耦；
- **历史追溯**：所有副单按时间倒序保留，可查看、删除；
- **权限现状**：报销副单权限码复用 `purchase_quote`（购销报价权限）。

## 退换规则

退换售后线的业务规则（字段定义见「表结构」）：

- **强制继承基准**：`original_qty` = `document_lines.qty`，`original_price` = `document_lines.unitPrice`，创建时由后端从单据行读取写入，永不可改；
- **退换类型**：`refund_type` 二选一——`refund`（退款）/ `exchange`（换货）；
- **超退校验**：`SUM(refund_qty WHERE line_id) + 本次退换数量 ≤ document_lines.qty`，前端弹窗拦截 + 后端服务端校验双重保证；
- **金额系统计算**：`refund_amount = round2(refund_qty × original_price)`，后端计算，前端仅预览展示；
- **状态推进**：`refund_status` 二态——`pending`（待处理）/ `closed`（已关闭）；`closed` 为行级永久关闭，该行不可再编辑；
- **定档联动**：退换发生时同时写入 `archived_refunds`（定档退换记录，供月度统计归月），定档后不可修改；
- **销售汇总扣减**：销售汇总的退货扣减 = `Σ refund_lines.refund_amount` 且 `refund_type = refund`（见「与销售汇总关系」）。

## 报销副单

报销副单线的业务规则（字段定义见「表结构」）：

- **挂靠单据**：每条副单必须挂靠一张源单据（`source_document_id → documents.id`），单据删除时副单级联删除；
- **编号**：`bill_no` 唯一，编号格式统一 `YY-MM-DD-序号`（与单据编号同规则，见《单据与状态机》），本地不另立格式；
- **自由行编辑**：行数据（`product_ref`/`spec`/`unit`/`qty`/`unit_price`）自由编辑，初始草稿来自单据行快照（`document_lines` 的 `productRef`/`spec`/`unit`），与原始单据行解耦；
- **金额计算**：行 `amount = qty × unit_price`；单 `subtotal_amount = Σ amount`，`total_amount = subtotal`；
- **删除**：级联删除明细行（`reimbursement_bill_lines` 随父表 CASCADE）。

## 保存逻辑

### 退换行新增

```
1. 校验单据存在；
2. 校验 lineId 属于 documentId；
3. 超退校验：SUM(refund_qty WHERE line_id) + input.refund_qty ≤ document_lines.qty；
4. 强继承：original_qty = document_lines.qty，original_price = document_lines.unitPrice（不接受前端传入）；
5. 系统计算：refund_amount = round2(refund_qty × unitPrice)；
6. 写入 refund_lines（refund_status = pending，refund_at = now()）；
7. 广播 WebSocket 事件 refund.updated → 同一单据的其他视图联动刷新；
8. 审计日志记录 refund_line_add。
```

### 退换行更新

```
1. 校验退换行存在；
2. 若 refund_qty 未变化 → 仅更新 reason，跳过超退校验；
3. 若 refund_qty 变化 → 重新超退校验（排除当前行自身）、重新计算 refund_amount；
4. 广播 WebSocket 事件 refund.updated；
5. 审计日志记录 refund_line_update。
```

### 退换行删除

```
1. 校验退换行存在；
2. 物理删除；
3. 广播 WebSocket 事件 refund.updated；
4. 审计日志记录 refund_line_remove。
```

### 定档退换记录

```
1. 校验单据行存在；
2. 事务内同时写入 refund_lines（待处理）与 archived_refunds（定档归月，document_no 快照编号）；
3. 广播 WebSocket 事件 refund.recorded；
4. 审计日志记录。
```

### 报销副单创建

```
1. 校验源单据存在；
2. 生成 bill_no（编号格式 YY-MM-DD-序号，与单据编号同规则）；
3. 逐行计算 amount = qty × unitPrice；
4. 计算 subtotal = SUM(amount)，total = subtotal；
5. 事务写入 reimbursement_bills + reimbursement_bill_lines；
6. 记录日志。
```

### 报销副单删除

```
1. 校验副单存在；
2. 级联删除（reimbursement_bill_lines 随父表 CASCADE）；
3. 记录日志。
```

### 交互细节

**视图防误触锁定**：

- 锁定按钮：操作栏右侧，点击直接锁定（无确认弹窗），锁定后新建/编辑/删除全部禁用；
- 解锁按钮：锁定状态下显示，点击弹出 `Modal.confirm` 二次确认后解锁；
- 与行级 `refund_status=closed` 独立：`closed` 是行级状态推进（处理完毕、该行锁定）；`view_locks.refund_after_sale` 是视图级防误触（临时锁定，整个视图不可操作）。`view_locks` 字段结构与 snake_case 键名规则见《单据与状态机》，本文档不本地定义。

**新建退换记录**：

- 商品行下拉基于 `docLines` 生成，标签格式：`产品名(规格) — 需求N / 余可退N / 单价¥N`；
- 选项自动 `disabled` 当 `remainingRefundable ≤ 0` 或 `unitPrice ≤ 0`；
- 选中商品行后显示强继承基准信息条（商品/规格/单位/原需求/已退换/余可退/原售价/退换金额预览）；
- 退换金额预览实时计算：`round2(newRefundQty × selectedUnitPrice)`，红色字体；
- 前端超退校验：`newRefundQty > selectedRemaining` 时 alert 拦截；
- 添加成功后自动清空表单，刷新列表。

**编辑退换记录**：

- 首列「更多」菜单 → 编辑，打开 `DsDialog`；
- 弹窗内展示强继承基准信息网格（商品/规格+单位/原数量/原售价/已退累计/剩余可退）；
- 退换数量输入框，右侧显示「最大 N」提示；
- 退换金额预览实时计算显示；
- 原因/备注输入框，选填；
- 前端超退校验：`newQty > (editTarget.originalQty - otherRefunded)` 时拦截；
- 使用 `trackSave` 保存（行级状态点 + 全局状态栏），静默反馈。

**删除退换记录**：

- 首列「更多」菜单 → 删除，弹出 `Modal.confirm` 二次确认；
- 确认后物理删除，刷新列表。

**必看信息折叠区**：

- 展示原收款记录（来自 `docDetail.paymentRecords`），折叠/展开切换；
- 包含：收款类型标签（定金/尾款/余额）、金额、方式、时间、对账状态；
- 无收款记录时提示「退款依据缺失，请先在收款对账环节录入」。

**WebSocket 联动**：

- 监听 `refund.updated`、`refund.recorded`、`payment.updated` 事件自动刷新；
- 退换行增删改后广播 `refund.updated`，其他视图联动刷新。

### 报销副单面板（ReimbursementBillPanel）

组件路径：`frontend/src/shared/components/ReimbursementBillPanel.tsx`。该组件为共享浮动面板，含三种状态：

1. **编辑状态**：草稿表格（品名/规格/单位/数量/报销单价/金额），可自由编辑、删除行、重置为当前单据行；
2. **历史列表状态**：历史副单列表（副单号/时间/创建者/金额/项数），点击进入详情；
3. **详情状态**：查看单条副单的完整明细（品名/单位/数量/单价/金额/合计），可删除。

## 与销售汇总关系

| 关联功能 | 关联方式 | 说明 |
|----------|----------|------|
| 采购报价 | 退换行强继承 `document_lines.unitPrice`（来自报价阶段确认的售价） | 退换金额基于已确认的售价计算 |
| 收款对账 | 退换视图展示原收款记录作为退款依据 | 无收款记录时提示先录入收款 |
| 定档归档 | 退换发生时同时写 `archived_refunds`，月度统计归月 | 定档退换接口由归档控制器处理 |
| 销售汇总 | 退换数据影响销售汇总的净利润：**退货扣减 = Σ `refund_lines.refund_amount` 且 `refund_type=refund`**（实时标注层口径，与销售汇总服务的 `refundDeduction` 一致）；定档归档同步写 `archived_refunds` 供月度统计归月 | 已定稿 |
| 产品管理 | 退换行关联 `document_lines` 的产品快照字段（productRef/spec/unit 等） | 解耦设计，产品删除不影响退换行展示 |
| 权限管理 | 视图权限码 `after_sales`（ro=只读，rw=读写） | 报销副单权限码 `purchase_quote`（复用购销报价权限） |
| 操作审计 | 退换行增删改均记录审计日志（`refund_line_add/update/remove`） | 审计日志页面可查询 |
