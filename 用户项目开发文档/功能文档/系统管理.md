> **职责**：角色权限、用户、授权码、访问申请、审计日志的唯一设计依据；权限模型与角色职责划分见《权限与职责规范》，全局 UI 与交互范式见《表格与交互规范》。

## 权限码清单（唯一权威）

系统内导航叶子权限码共 **17 个**，按业务模块组织为导航树。每个角色对每个叶子设置三档权限：`none`（不可见）/ `ro`（只读）/ `rw`（可读可写）。权限码清单以本节为唯一权威，任何页面注册、路由鉴权、角色授权均以此为准。

| 权限码 | 所属模块 | 中文名称 |
|--------|---------|---------|
| purchase_quote | 订单中心 | 采购报价 |
| payment_recon | 订单中心 | 收款对账 |
| allocation | 订单中心 | 统一配货 |
| delivery_fulfill | 订单中心 | 订单交付 |
| cost_verify | 订单中心 | 成本标注 |
| after_sales | 订单中心 | 售后退款 |
| sales_summary | 订单中心 | 销售汇总 |
| archive | 订单中心 | 定档归档 |
| product_manage | 基础数据 | 产品管理 |
| customer_manage | 基础数据 | 客户档案 |
| supplier_manage | 基础数据 | 供应商档案 |
| inventory | 库存管理 | 库存台账（含欠库/待入库） |
| auth_code_manage | 系统管理 | 授权码管理 |
| access_request_manage | 系统管理 | 访问申请审核 |
| user_manage | 系统管理 | 用户管理 |
| audit_log_manage | 系统管理 | 审计日志 |
| role_manage | 系统管理 | 角色权限 |

**权限级别**：`none`（不可见）→ `ro`（只读）→ `rw`（可读可写）。一人多角色权限取并集：`rw > ro > none`。

## 角色与权限

### roles 角色表（职责：角色档案，承载视图权限矩阵）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | Int PK AUTO_INCREMENT | 1 | 主键 |
| code | varchar(30) UNIQUE | sales | 角色编码，小写字母开头，仅含小写字母/数字/下划线 |
| name | varchar(50) | 报价员 | 角色显示名称 |
| description | varchar(200)? | 负责采购报价与成本核定 | 角色说明 |
| is_system | Boolean DEFAULT false | false | 是否系统预置角色（预置角色不可删除，可改权限） |
| view_permissions | JSON? | {"purchase_quote":"rw","payment_recon":"ro"} | 视图权限矩阵，格式 `{ "权限码": "none/ro/rw" }` |
| created_at | DateTime DEFAULT now() | 2026-08-01 10:00:00 | 创建时间 |

**表映射**：`@@map("roles")`

### user_roles 用户-角色关联表（职责：多对多绑定，一人多角色）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | BigInt PK AUTO_INCREMENT | 1 | 主键 |
| user_id | BigInt FK | 7(张三) →users.id | 用户ID，级联删除 |
| role_id | Int FK | 2(sales) →roles.id | 角色ID，级联删除 |
| created_at | DateTime DEFAULT now() | | 创建时间 |

**约束**：`@@unique([user_id, role_id])`；`@@index([user_id])`、`@@index([role_id])`
**表映射**：`@@map("user_roles")`

### 系统预置角色

| 角色编码 | 显示名称 | 业务权限简述 |
|----------|---------|-------------|
| sales | 报价员 | 采购报价(rw)、成本核定(rw)、售后(rw)、客户档案(ro) |
| allocator | 配货员 | 采购报价(ro)、统一配货(rw)、库存台账(rw)、客户档案(ro) |
| cashier | 收银 | 采购报价(ro)、收款对账(rw)、客户档案(ro) |
| delivery | 交付员 | 采购报价(ro)、配货(ro)、订单交付(rw)、客户档案(ro) |
| manager | 店长 | 全部业务(rw)、全部基础数据(rw)、系统管理(ro) |
| admin | 管理员 | 业务全(ro)、基础数据(rw)、系统管理全(rw) |

### 超级管理员

`admin` 账号为硬编码超级管理员，永远拥有全部 17 个权限码的 `rw` 权限，不依赖数据库 `roles.view_permissions` 配置，避免 seed 脏数据导致权限丢失。超级管理员账号列表硬编码在 `backend/src/types/index.ts` 的 `SUPERADMIN_USERNAMES` 中。

### 接口

| 方法 | 路由 | 权限 | 说明 |

## 授权码管理

### authorization_codes 授权码表（职责：客户准入凭证，手机号+授权码登录）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | BigInt PK AUTO_INCREMENT | 1 | 主键 |
| code | varchar(10) UNIQUE | 123456 | 6 位数字授权码 |
| phone | varchar(20)? | 13800138000 | 绑定手机号（可为空，表示未绑定） |
| status | varchar(20) DEFAULT active | active | active 活跃 / used 已使用 / revoked 已作废 |
| expiresAt | DateTime | 2026-08-14 10:00:00 | 过期时间 |
| createdBy | BigInt | 1 | 创建者用户ID（无物理外键） |
| creatorName | varchar(50)? | 张三 | 创建者名称快照（来自 users.real_name） |
| source | varchar(20) DEFAULT manual | manual | manual 手动生成 / access_request 准入申请审批通过 |
| activatedAt | DateTime? | | 激活时间（客户首次使用时间） |
| createdAt | DateTime DEFAULT now() | | 创建时间 |

**索引**：`@@index([phone])`、`@@index([status])`
**表映射**：`@@map("authorization_codes")`

### 业务规则

1. **授权码生成**：6 位随机数字，单次可生成 1-50 个，默认有效 72 小时（可配置，最长 720 小时）。
2. **授权码绑定**：可为空（未绑定手机号），绑定时客户必须使用绑定手机号登录。
3. **授权码验证**：客户登录时验证授权码有效性（存在 + 未过期 + 未使用/未作废 + 手机号匹配）。
4. **授权码使用**：客户首次验证通过后，状态变为 `used`，记录 `activatedAt`，自动创建客户档案（如不存在）。
5. **授权码作废**：仅 `active` 状态可作废。

### 接口

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/auth-codes` | auth_code_manage:rw | 授权码列表（分页，支持 status/phone/code 筛选） |
| POST | `/api/staff/auth-codes` | auth_code_manage:rw | 批量生成授权码 |
| POST | `/api/staff/auth-codes/:id/revoke` | auth_code_manage:rw | 作废授权码 |
| GET | `/api/staff/auth-codes/stats` | auth_code_manage:rw | 授权码统计（总数/活跃/已使用/已作废/已过期） |

**生成授权码请求体**：

```json
{
  "count": 5,
  "phone": "13800138000",
  "expiresHours": 72
}
```

**生成授权码返回**：

```json
{
  "codes": ["123456", "234567", "345678", "456789", "567890"]
}
```

### 前端交互

页面文件：`frontend/src/apps/staff/pages/AuthCodes.tsx`

**布局**：标准 ViewFrame 结构。

**顶部统计卡片**：五列网格展示总数、活跃、已使用、已作废、已过期数量。

**筛选栏**：授权码搜索、绑定手机号搜索、状态筛选（全部/活跃/已使用/已作废/已过期）。

**表格列**：授权码、绑定手机、状态（标签）、创建时间、过期时间。

## 访问申请

### access_requests 准入申请表（职责：客户准入申请与审批留痕）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | BigInt PK AUTO_INCREMENT | 1 | 主键 |
| phone | varchar(20) | 13800138000 | 申请手机号 |
| status | varchar(20) DEFAULT pending | pending | pending 待审核 / approved 已通过 / rejected 已拒绝 |
| reviewedBy | BigInt? | 1 | 审核人用户ID（无物理外键） |
| reviewerName | varchar(50)? | 李四 | 审核人名称快照（来自 users.real_name） |
| reviewedAt | DateTime? | | 审核时间 |
| rejectReason | varchar(500)? | 非目标客户 | 拒绝原因 |
| issuedAuthCode | varchar(10)? | 654321 | 审批通过时下发的授权码 |
| issuedAuthCodeExpiresAt | DateTime? | | 下发授权码的过期时间 |
| createdAt | DateTime DEFAULT now() | | 创建时间 |

**索引**：`@@index([phone])`、`@@index([status])`
**表映射**：`@@map("access_requests")`

### 审批规则

- 同一手机号最多一个 `pending` 状态的申请；
- **通过**：自动创建客户档案（如不存在），自动生成绑定该手机号的授权码，并将授权码信息写回申请记录（`issuedAuthCode` / `issuedAuthCodeExpiresAt`）；
- **拒绝**：必须填写拒绝原因（`rejectReason`）。

### 接口

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/access-requests` | access_request_manage:ro | 准入申请列表（分页，支持 status/phone 筛选） |
| POST | `/api/staff/access-requests/:id/review` | access_request_manage:rw | 审批准入申请（通过/拒绝） |

**审批请求体**：

```json
{
  "status": "approved"
}
```

或

```json
{
  "status": "rejected",
  "rejectReason": "非目标客户"
}
```

### 前端交互

页面文件：`frontend/src/apps/staff/pages/AccessRequests.tsx`

**布局**：标准 ViewFrame 结构。

**筛选栏**：手机号搜索、状态筛选（全部/待审核/已通过/已拒绝）。

**表格列**：手机号、状态（标签）、申请时间、审核人、审核时间、授权码（可点击复制）、拒绝原因。

**操作菜单**：
- 待审核：通过（二次确认 → 展示授权码弹窗）、拒绝（弹出拒绝原因弹窗）
- 已通过：查看授权码

**通过后弹窗**：展示手机号 + 授权码 + 有效期，有复制授权码和「我已告知客户」按钮。

**拒绝弹窗**：显示申请手机号，填写拒绝原因（必填）。

### 留痕规则

审计遵循「留痕优于审批」原则，通过 Express 中间件 `auditMiddleware`（`backend/src/middleware/auditLogger.ts`）自动记录。中间件在 `req` 上挂载 `req.audit(action, resourceType, resourceId?, detail?)` 方法，控制器在关键操作后调用。

**名称快照规则**：审计日志表不建立指向 `users` / `customers` 的物理外键，而是存储 `userName` / `customerName` 快照字段（写日志时取自档案实时值并锁定）。**员工/客户档案删除后，审计日志仍可正常展示**，历史追溯不受档案生命周期影响。

## 通用设计原则

### 权限鉴权流程

```
前端导航注册表（menu.config.ts）声明每个页面所需的权限码
    ↓
后端路由中间件（requireViewPermission / requireAnyViewPermission）校验
    ↓
JWT 中携带 viewPermissions（登录时从 DB 动态计算并集）
    ↓
每次 /me 请求从 DB 重算权限（角色权限变更即时生效，无需等 JWT 过期）
```

### 一人多角色权限合并

用户拥有多个角色时，权限取并集：`rw > ro > none`。超级管理员 `admin` 账号硬编码全权限 `rw`，不依赖数据库配置。

### 无权限提示

当用户访问无权限页面时，前端显示 `NoPermission` 页面（`frontend/src/apps/staff/pages/NoPermission.tsx`），使用业务话术提示（不暴露技术词），引导返回采购清单。

### 解耦原则

系统管理模块中涉及用户/客户关联的表（`audit_logs`、`authorization_codes`、`access_requests`）均不建立物理外键约束：
- 保留 `user_id` / `customer_id` / `createdBy` / `reviewedBy` 等 BigInt 字段用于聚合统计
- 新增 `userName` / `customerName` / `creatorName` / `reviewerName` 等快照字段用于展示
- 员工/客户档案删除后，审计日志、授权码、准入申请记录仍可正常展示
