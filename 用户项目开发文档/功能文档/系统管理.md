## 一、角色权限管理

### 1.1 功能概述

角色权限管理实现基于 RBAC（基于角色的访问控制）的导航叶子权限系统。将系统内的 15 个视图叶子按业务模块组织为导航树，每个角色可对每个叶子设置三档权限：无（none）、只读（ro）、读写（rw）。一人可拥有多个角色，权限取并集（rw > ro > none）。

### 1.2 表结构

#### roles 角色表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | Int | PK, AUTO_INCREMENT | 主键 |
| code | varchar(30) | UNIQUE, NOT NULL | 角色编码，小写字母开头，仅含小写字母/数字/下划线 |
| name | varchar(50) | NOT NULL | 角色显示名称 |
| description | varchar(200) | | 角色说明 |
| is_system | Boolean | DEFAULT false | 是否系统预置角色（预置角色不可删除，可改权限） |
| view_permissions | JSON | | 视图权限矩阵，格式 `{ "purchase_quote": "rw", "payment_recon": "rw", ... }`，三档 none/ro/rw |
| created_at | DateTime | DEFAULT now() | 创建时间 |

**表映射**：`@@map("roles")`

#### user_roles 用户-角色关联表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| user_id | BigInt | FK → users.id, CASCADE | 用户ID |
| role_id | Int | FK → roles.id, CASCADE | 角色ID |
| created_at | DateTime | DEFAULT now() | 创建时间 |

**约束**：`@@unique([user_id, role_id])`
**表映射**：`@@map("user_roles")`

### 1.3 系统预置角色

| 角色编码 | 显示名称 | 业务权限简述 |
|----------|---------|-------------|
| sales | 报价员 | 采购报价(rw)、成本核定(rw)、售后(rw)、客户档案(ro) |
| allocator | 配货员 | 采购报价(ro)、统一配货(rw)、客户档案(ro) |
| cashier | 收银 | 采购报价(ro)、收款对账(rw)、客户档案(ro) |
| delivery | 交付员 | 采购报价(ro)、配货(ro)、订单交付(rw)、客户档案(ro) |
| manager | 店长 | 全部业务(rw)、全部基础数据(rw)、系统管理(ro) |
| admin | 管理员 | 业务全(ro)、基础数据(rw)、系统管理全(rw) |

### 1.4 权限码定义（15 个导航叶子）

| 权限码 | 所属模块 | 中文名称 |
|--------|---------|---------|
| purchase_quote | 订单中心 | 采购报价 |
| payment_recon | 订单中心 | 收款对账 |
| allocation | 订单中心 | 统一配货 |
| delivery_fulfill | 订单中心 | 订单交付 |
| cost_verify | 订单中心 | 成本标注 |
| after_sales | 订单中心 | 售后退款 |
| sales_summary | 订单中心 | 销售汇总 |
| archive | 订单中心 | 定档归档 |
| product_manage | 基础数据 | 产品管理 |
| customer_manage | 基础数据 | 客户档案 |
| auth_code_manage | 系统管理 | 授权码管理 |
| access_request_manage | 系统管理 | 访问申请审核 |
| user_manage | 系统管理 | 用户管理 |
| audit_log_manage | 系统管理 | 审计日志 |
| role_manage | 系统管理 | 角色权限 |

**权限级别**：`none`（不可见）→ `ro`（只读）→ `rw`（可读可写）

### 1.5 超级管理员

`admin` 账号为硬编码超级管理员，永远拥有全部 15 个视图的 `rw` 权限，不依赖数据库 `roles.view_permissions` 配置，避免 seed 脏数据导致权限丢失。超级管理员账号列表硬编码在 `backend/src/types/index.ts` 的 `SUPERADMIN_USERNAMES` 中。

### 1.6 接口列表

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/roles` | role_manage:ro 或 user_manage:ro | 获取全部角色列表 |
| POST | `/api/staff/roles` | role_manage:rw | 新建自定义角色 |
| PATCH | `/api/staff/roles/:code` | role_manage:rw | 更新角色名称/说明 |
| DELETE | `/api/staff/roles/:code` | role_manage:rw | 删除自定义角色（系统角色不可删，有用户绑定时不可删） |
| PUT | `/api/staff/roles/:code/permissions` | role_manage:rw | 更新角色导航叶子权限图 |

**新建角色请求体**：
```json
{
  "code": "warehouse_lead",
  "name": "仓库主管",
  "description": "负责仓库出库与调货管理",
  "viewPermissions": {
    "allocation": "rw",
    "delivery_fulfill": "ro",
    "purchase_quote": "ro"
  }
}
```

**更新权限请求体**：
```json
{
  "viewPermissions": {
    "purchase_quote": "rw",
    "payment_recon": "none",
    "allocation": "rw",
    ...
  }
}
```

### 1.7 前端页面结构

页面文件：`frontend/src/apps/staff/pages/RolePermissions.tsx`

**布局**：左右分栏结构。
- **左侧角色列表**（宽 220px）：显示全部角色，标注系统预置标签，点击切换选中角色，底部有「新建」按钮。
- **右侧权限树**（弹性宽度）：显示导航权限树（三级结构：模块 → 子功能 → 叶子），每个叶子节点右侧有 Segmented 控件切换无/只读/读写；父节点提供快捷按钮一键设置本枝全部叶子为同一级别。

**工具栏**：全部展开/全部折叠按钮 + 保存权限按钮。

**弹窗**：
- 新建/编辑角色弹窗：角色编码（仅新建时填写，小写字母开头）、显示名称、说明。
- 删除确认：自定义角色且无用户绑定时可删除。

## 二、用户管理

### 2.1 功能概述

用户管理提供员工账号的完整生命周期管理：创建、编辑、角色分配、状态启用/停用、密码重置。列表支持关键词搜索（用户名/真实姓名/手机号）、状态筛选、分页。

### 2.2 表结构

#### users 用户表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| user_code | varchar(30) | UNIQUE, NOT NULL | 员工编码（系统自动生成，不可变） |
| username | varchar(50) | UNIQUE, NOT NULL | 登录用户名 |
| password_hash | varchar(255) | NOT NULL | bcrypt 加密密码哈希 |
| real_name | varchar(50) | NOT NULL | 真实姓名 |
| phone | varchar(20) | | 手机号 |
| status | enum(active, disabled) | DEFAULT active | 账号状态：启用/已停用 |
| last_login_at | DateTime | | 最后登录时间 |
| created_at | DateTime | DEFAULT now() | 创建时间 |
| updated_at | DateTime | @updatedAt | 更新时间 |

**表映射**：`@@map("users")`

### 2.3 接口列表

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/users` | user_manage:rw | 用户列表（分页，支持 keyword/status 筛选） |
| POST | `/api/staff/users` | user_manage:rw | 创建用户 |
| PATCH | `/api/staff/users/:id` | user_manage:rw | 更新用户信息（姓名/手机/角色/状态） |
| POST | `/api/staff/users/:id/reset-password` | user_manage:rw | 重置密码 |

**创建用户请求体**：
```json
{
  "username": "zhangsan",
  "password": "123456",
  "realName": "张三",
  "phone": "13800138000",
  "roleCodes": ["sales", "cashier"]
}
```

**更新用户请求体**：
```json
{
  "realName": "张三",
  "phone": "13900139000",
  "status": "active",
  "roleCodes": ["sales"]
}
```

**重置密码请求体**：
```json
{
  "password": "newpassword123"
}
```

**列表查询参数**：
- `keyword`：关键词搜索（匹配用户名/真实姓名/手机号）
- `status`：状态筛选（active / disabled）
- `page` / `pageSize`：分页参数

**返回列表项结构**：
```json
{
  "id": "123",
  "userCode": "E20260804001",
  "username": "zhangsan",
  "realName": "张三",
  "phone": "13800138000",
  "status": "active",
  "roles": ["sales", "cashier"],
  "createdAt": "2026-08-04T00:00:00.000Z"
}
```

### 2.4 前端页面结构

页面文件：`frontend/src/apps/staff/pages/AdminUsers.tsx`

**布局**：标准 ViewFrame 结构（ActionBar + BizStrip + UnifiedTable）。

**筛选栏**：
- 关键词搜索输入框（支持用户名/真实姓名/手机号搜索，300ms 防抖）
- 状态筛选下拉（全部/启用/已停用）
- 查询/重置按钮

**表格列**：工号、用户名、真实姓名、手机号、角色（彩色标签）、状态（标签）、创建时间。

**操作菜单**（每行更多按钮）：
- 编辑：弹出编辑弹窗（不可修改用户名和密码，可修改姓名/手机/角色/状态）
- 重置密码：弹出重置密码弹窗（新密码 + 确认密码）
- 停用/启用：二次确认弹窗

**弹窗**：
- 新增用户弹窗：用户名、密码、真实姓名、手机号、角色多选
- 编辑用户弹窗：真实姓名、手机号、角色多选（用户名和密码不可修改）
- 重置密码弹窗：新密码 + 确认密码，显示被重置用户信息

## 三、授权码管理

### 3.1 功能概述

授权码管理包含两个子模块：**授权码管理**（生成/作废/统计）和**访问申请审核**（审批客户准入申请）。授权码是客户访问系统的凭证，客户使用「手机号 + 授权码」在准入页登录。

### 3.2 表结构

#### authorization_codes 授权码表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| code | varchar(10) | UNIQUE, NOT NULL | 6 位数字授权码 |
| phone | varchar(20) | | 绑定手机号（可为空，表示未绑定） |
| status | varchar(20) | DEFAULT 'active' | 状态：active（活跃）/ used（已使用）/ revoked（已作废） |
| expiresAt | DateTime | NOT NULL | 过期时间 |
| createdBy | BigInt | NOT NULL | 创建者用户ID（v11.0 解耦：无物理外键约束） |
| creatorName | varchar(50) | | 创建者名称快照（v11.0 解耦新增） |
| source | varchar(20) | DEFAULT 'manual' | 来源：manual（手动生成）/ access_request（准入申请审批通过） |
| activatedAt | DateTime | | 激活时间（客户首次使用时间） |
| createdAt | DateTime | DEFAULT now() | 创建时间 |

**表映射**：`@@map("authorization_codes")`
**索引**：`@@index([phone])`、`@@index([status])`

#### access_requests 准入申请表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| phone | varchar(20) | NOT NULL | 申请手机号 |
| status | varchar(20) | DEFAULT 'pending' | 状态：pending（待审核）/ approved（已通过）/ rejected（已拒绝） |
| reviewedBy | BigInt | | 审核人用户ID（v11.0 解耦：无物理外键约束） |
| reviewerName | varchar(50) | | 审核人名称快照（v11.0 解耦新增） |
| reviewedAt | DateTime | | 审核时间 |
| rejectReason | varchar(500) | | 拒绝原因 |
| issuedAuthCode | varchar(10) | | 审批通过时下发的授权码 |
| issuedAuthCodeExpiresAt | DateTime | | 下发授权码的过期时间 |
| createdAt | DateTime | DEFAULT now() | 创建时间 |

**表映射**：`@@map("access_requests")`
**索引**：`@@index([phone])`、`@@index([status])`

### 3.3 业务规则

1. **授权码生成**：6 位随机数字，单次可生成 1-50 个，默认有效 72 小时（可配置，最长 720 小时）。
2. **授权码绑定**：可为空（未绑定手机号），绑定时客户必须使用绑定手机号登录。
3. **授权码验证**：客户登录时验证授权码有效性（存在 + 未过期 + 未使用/未作废 + 手机号匹配）。
4. **授权码使用**：客户首次验证通过后，状态变为 `used`，记录 `activatedAt`，自动创建客户档案（如不存在）。
5. **授权码作废**：仅 `active` 状态可作废。
6. **准入申请**：客户提交手机号申请，同一手机号最多一个 `pending` 状态的申请。
7. **准入申请审批**：
   - 通过：自动创建客户档案（如不存在），自动生成绑定手机号的授权码，在申请记录上记录授权码信息。
   - 拒绝：需填写拒绝原因。

### 3.4 授权码管理接口

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/auth-codes` | auth_code_manage:rw | 授权码列表（分页，支持 status/phone/code 筛选） |
| POST | `/api/staff/auth-codes` | auth_code_manage:rw | 批量生成授权码 |
| POST | `/api/staff/auth-codes/:id/revoke` | auth_code_manage:rw | 作废授权码 |
| GET | `/api/staff/auth-codes/stats` | auth_code_manage:rw | 授权码统计（总数/活跃/已使用/已作废/已过期） |

**生成授权码请求体**：
```json
{
  "count": 5,
  "phone": "13800138000",
  "expiresHours": 72
}
```

**生成授权码返回**：
```json
{
  "codes": ["123456", "234567", "345678", "456789", "567890"]
}
```

### 3.5 准入申请管理接口

| 方法 | 路由 | 权限 | 说明 |
|------|------|------|------|
| GET | `/api/staff/access-requests` | access_request_manage:ro | 准入申请列表（分页，支持 status/phone 筛选） |
| POST | `/api/staff/access-requests/:id/review` | access_request_manage:rw | 审批准入申请（通过/拒绝） |

**审批请求体**：
```json
{
  "status": "approved"
}
```
或
```json
{
  "status": "rejected",
  "rejectReason": "非目标客户"
}
```

### 3.6 前端页面结构

#### 授权码管理页

页面文件：`frontend/src/apps/staff/pages/AuthCodes.tsx`

**布局**：标准 ViewFrame 结构。

**顶部统计卡片**：五列网格展示总数、活跃、已使用、已作废、已过期数量。

**筛选栏**：授权码搜索、绑定手机号搜索、状态筛选（全部/活跃/已使用/已作废/已过期）。

**表格列**：授权码、绑定手机、状态（标签）、创建时间、过期时间。

**操作菜单**：活跃/已过期状态的授权码可作废。

**生成弹窗**：
- 表单：生成数量（1-50）、绑定手机（可选）、有效时长（默认 72 小时）
- 生成后展示结果：授权码列表 + 复制全部按钮 + 再生成一批按钮

#### 访问申请审核页

页面文件：`frontend/src/apps/staff/pages/AccessRequests.tsx`

**布局**：标准 ViewFrame 结构。

**筛选栏**：手机号搜索、状态筛选（全部/待审核/已通过/已拒绝）。

**表格列**：手机号、状态（标签）、申请时间、审核人、审核时间、授权码（可点击复制）、拒绝原因。

**操作菜单**：
- 待审核：通过（二次确认 → 展示授权码弹窗）、拒绝（弹出拒绝原因弹窗）
- 已通过：查看授权码

**通过后弹窗**：展示手机号 + 授权码 + 有效期，有复制授权码和"我已告知客户"按钮。

**拒绝弹窗**：显示申请手机号，填写拒绝原因（必填）。

## 四、审计日志

### 4.1 功能概述

审计日志记录系统内所有关键操作，遵循"留痕优于审批"原则。记录谁、何时、对什么资源、做了什么操作。同时提供字段变更日志，记录数据表字段级的前后值变化。

### 4.2 表结构

#### audit_logs 审计日志表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| user_id | BigInt | | 操作人用户ID（v11.0 解耦：无物理外键约束） |
| userName | varchar(50) | | 操作人名称快照（v11.0 解耦新增） |
| customer_id | BigInt | | 关联客户ID（v11.0 解耦：无物理外键约束） |
| customerName | varchar(100) | | 客户名称快照（v11.0 解耦新增） |
| action | varchar(50) | NOT NULL | 操作类型，格式 `<resource>_<verb>`，如 `user_create`、`document_status_change` |
| resource_type | varchar(50) | NOT NULL | 资源类型，如 `users`、`documents`、`authorization_codes` |
| resource_id | BigInt | | 资源ID |
| detail | JSON | | 操作详情（JSON 格式，存储变更上下文） |
| ip_address | varchar(45) | | 操作者IP地址 |
| created_at | DateTime | DEFAULT now() | 创建时间 |

**表映射**：`@@map("audit_logs")`
**索引**：`@@index([user_id])`、`@@index([customer_id])`、`@@index([resource_type, resource_id])`

#### field_change_logs 字段变更日志表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| table_name | varchar(50) | NOT NULL | 表名 |
| record_id | BigInt | NOT NULL | 记录ID |
| field_name | varchar(100) | NOT NULL | 字段名 |
| old_value | Text | | 变更前值 |
| new_value | Text | | 变更后值 |
| changed_by | BigInt | | 修改人用户ID（v11.0 解耦：无物理外键约束） |
| changedByName | varchar(50) | | 修改人名称快照（v11.0 解耦新增） |
| changed_at | DateTime | DEFAULT now() | 变更时间 |

**表映射**：`@@map("field_change_logs")`
**索引**：`@@index([table_name, record_id])`、`@@index([changed_by])`

### 4.3 审计日志中间件

审计日志通过 Express 中间件 `auditMiddleware`（`backend/src/middleware/auditLogger.ts`）自动记录。中间件在 `req` 上挂载 `req.audit(action, resourceType, resourceId?, detail?)` 方法，控制器在关键操作后调用。

**v11.0 解耦**：审计日志表不再通过 `@relation` 物理外键关联 `users` 和 `customers` 表，而是存储 `userName` / `customerName` 快照字段。员工/客户档案删除后，审计日志仍可正常展示。

## 五、通用设计原则

### 5.1 权限鉴权流程

```
前端导航注册表（menu.config.ts）声明每个页面所需的权限码
    ↓
后端路由中间件（requireViewPermission / requireAnyViewPermission）校验
    ↓
JWT 中携带 viewPermissions（登录时从 DB 动态计算并集）
    ↓
每次 /me 请求从 DB 重算权限（角色权限变更即时生效，无需等 JWT 过期）
```

### 5.2 一人多角色权限合并

用户拥有多个角色时，权限取并集：`rw > ro > none`。超级管理员 `admin` 账号硬编码全权限 `rw`，不依赖数据库配置。

### 5.3 无权限提示

当用户访问无权限页面时，前端显示 `NoPermission` 页面（`frontend/src/apps/staff/pages/NoPermission.tsx`），使用业务话术提示（不暴露技术词），引导返回采购清单。

### 5.4 v11.0 解耦原则

系统管理模块中涉及用户/客户关联的表（`audit_logs`、`authorization_codes`、`access_requests`）均已解除物理外键约束：
- 保留 `user_id` / `customer_id` / `createdBy` / `reviewedBy` 等 BigInt 字段用于聚合统计
- 新增 `userName` / `customerName` / `creatorName` / `reviewerName` 等快照字段用于展示
- 员工/客户档案删除后，审计日志、授权码、准入申请记录仍可正常展示
