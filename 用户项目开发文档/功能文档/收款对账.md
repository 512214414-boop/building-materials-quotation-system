# 收款对账系统设计文档

> **职责**：收款记录与对账的唯一设计依据；单据状态机（8 档状态与流转规则）见《单据与状态机》，视图级防误触锁定见《表格与交互规范》。

---

## 功能概述

### 业务定位

收款对账是单据体系中的**标注层视图**，负责记录单据的收款明细、核销确认，并自动推进单据主状态。收款对账处于 8 档状态机中 `quote_confirmed`（报价已确认）之后，核销完成后自动推进到 `payment_settled`（款项已结清）。

### 在业务流程中的位置

```
需求待确认(demand_pending) → 报价已确认(quote_confirmed) → 款项已结清(payment_settled)
                                    ↑                               ↑
                                    └── 收款对账视图工作区间 ────────┘
```

- **工作区间**：单据主状态为 `demand_pending` 或 `quote_confirmed` 时，收款对账视图可操作。
- **自动推进**：全部收款记录均已核销（`reconcile_status = 'reconciled'`）且已核销金额合计 ≥ 单据价税合计（`total_amount`）时，系统自动推进单据主状态为 `payment_settled`（推进实现见《单据与状态机》）。
- **设计原则**：`payment_records` 是单据的标注表，不修改 `document_lines`。收款记录仅记录金额、类型、方式、日期，不与单据行一一对应。

### 三层收款类型

| 类型 | 枚举值 | 说明 | 标签颜色 |
|------|--------|------|----------|
| 定金 | `deposit` | 确认订单时收取的定金 | 品牌色(brand) |
| 尾款 | `final` | 交付前或交付时收取的尾款 | 警示色(warning) |
| 余款 | `balance` | 赊账余款，后续补收 | 默认色(default) |

### 对账状态

| 状态 | 枚举值 | 说明 | 标签颜色 |
|------|--------|------|----------|
| 待对账 | `pending` | 收款记录已录入，尚未核销 | 默认色(default) |
| 已核销 | `reconciled` | 已与银行/支付平台对账确认 | 成功色(success) |

## 收款记录

### payment_records 收款记录表（职责：单据级收款标注，核销推进单据状态）

`payment_records` 是单据的标注表，通过 `document_id` 外键关联 `documents`，级联删除（CASCADE）。

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|-----------|--------|------|
| id | BigInt PK AUTO_INCREMENT | 1 | 主键 |
| document_id | BigInt FK | 100(26-08-11-001) →documents.id | 所属单据，级联删除 |
| payment_type | enum(payment_type) | deposit | 收款类型：deposit 定金 / final 尾款 / balance 余款 |
| method | varchar(50) | 微信 | 收款方式：现金 / 微信 / 支付宝 / 银行转账 |
| amount | Decimal(14,2) | 5000.00 | 收款金额 |
| paid_at | DateTime | 2026-08-01 10:00:00 | 收款日期时间 |
| invoice_info | JSON? | {} | 发票信息（JSON 对象，可选） |
| reconcile_status | enum(reconcile_status) DEFAULT pending | pending | 对账状态：pending 待对账 / reconciled 已核销 |
| created_by | BigInt? | 7 | 创建者用户ID（无物理外键） |
| creatorName | varchar(50)? | 张三 | 创建者名称快照（来自 users.real_name） |
| created_at | DateTime DEFAULT now() | | 创建时间 |
| updated_at | DateTime @updatedAt | | 更新时间 |

**索引**：`@@index([document_id])`（按单据查询）、`@@index([reconcile_status])`（按对账状态筛选）、`@@index([paid_at])`（按收款日期排序）
**表映射**：`@@map("payment_records")`

### 与单据的关系

```
documents (1) ──── (N) payment_records
```

- `payment_records.document_id` 外键关联 `documents.id`，`onDelete: Cascade`；删除单据时，其下所有收款记录自动级联删除；
- 收款记录不关联 `document_lines`，是单据级别的标注；
- `created_by` 不建立指向 `users` 的物理外键，`creatorName` 快照保证员工档案删除后收款记录仍可正常展示创建者姓名。

### 枚举定义

```prisma
enum payment_type {
  deposit   // 定金
  final     // 尾款
  balance   // 余款
}

enum reconcile_status {
  pending     // 待对账
  reconciled  // 已核销
}
```

## 对账口径

### 收款汇总统计

`GET /api/staff/documents/:id/payments/summary` 返回 `PaymentSummary`，口径如下：

| 字段 | 说明 |
|------|------|
| payableAmount | 应收总额：优先取 `documents.total_amount`，若为 0 则从 `document_lines.amount` 汇总 |
| receivedAmount | 已收总额：所有收款记录金额合计 |
| reconciledAmount | 已核销金额：`reconcile_status = 'reconciled'` 的收款金额合计 |
| unreconciledAmount | 待核销金额：`receivedAmount - reconciledAmount` |
| outstandingAmount | 未收金额：`payableAmount - receivedAmount` |
| byType.deposit | 定金合计 |
| byType.final | 尾款合计 |
| byType.balance | 余款合计 |

```json
{
  "payableAmount": 10000.00,
  "receivedAmount": 8000.00,
  "reconciledAmount": 5000.00,
  "unreconciledAmount": 3000.00,
  "outstandingAmount": 2000.00,
  "byType": {
    "deposit": 3000.00,
    "final": 4000.00,
    "balance": 1000.00
  }
}
```

## 状态流转

- **8 档状态机的完整定义**（状态键/中文名/顺序、任意双向可逆流转规则、自动推进与手动切换、与报价阶段状态解耦）见《单据与状态机》，本文档不重复定义；
- 收款对账仅定义本环节的**推进条件**：
  1. 单据主状态为 `demand_pending` 或 `quote_confirmed`；
  2. 所有已核销收款金额合计 > 0；
  3. 若单据 `total_amount > 0`，已核销金额 ≥ `total_amount`（允许 0.01 精度误差）；
  4. 满足条件后自动推进单据主状态至 `payment_settled`（推进实现见《单据与状态机》）。
- 状态变更副作用（WebSocket 广播 `document.status_changed` + 审计日志）遵循《单据与状态机》全局规则。

### 页面结构说明

- **操作栏**（`ViewFrame.actionBar`）：左侧显示收款记录笔数 + 状态提示（锁定/未锁定），右侧显示锁定/解锁按钮。
- **业务条**（`ViewFrame.bizStrip`）：

### 快录行新增流程

```
用户输入收款类型 → 输入金额 → 选择收款方式 → 选择收款日期 → 点击「添加」或按回车
    ↓
前端校验金额为正数
    ↓
调用 addPayment 接口
    ↓
后端创建 payment_records 记录（reconcile_status = 'pending'）
    ↓
WebSocket 广播 payment.updated
    ↓
前端追加新记录到列表 → 重置快录行金额 → 刷新汇总
```

### 行内编辑流程

```
用户修改收款方式（DsSelect）或收款日期（DatePicker）
    ↓
失焦/关闭面板时触发 commitEditLine
    ↓
比对 editBuffer 与原始值，无变化则跳过
    ↓
调用 updatePayment 接口
    ↓
后端更新对应字段 → WebSocket 广播 payment.updated
    ↓
前端更新行数据 → 回写 editBuffer
```

### 核销流程

```
用户点击行尾「更多」菜单 → 选择「核销」或「撤销核销」
    ↓
调用 reconcilePayment(record.id, nextStatus)
    ↓
后端事务内：更新 reconcile_status → 尝试自动推进单据状态（推进条件见「状态流转」）
    ↓
WebSocket 广播 payment.updated + document.status_changed（如有）
    ↓
前端更新行数据 → 刷新汇总
```

### 视图锁定机制

- 锁定状态存储在 `documents.view_locks` JSON 字段中，锁键名为 snake_case（`payment_reconcile`），范式定义见《表格与交互规范》；
- 锁定：一次点击即锁定（无需确认），提示「已锁定，防止误触」；
- 解锁：弹出二次确认弹窗「解锁后所有收款记录将恢复可编辑状态，确定要解锁吗？」，确认后解锁；
- 锁定后：快录行隐藏，收款方式、收款日期变为只读文本，核销/撤销核销/删除菜单项禁用；锁定不影响收款记录的查看和汇总统计。

### 编辑缓冲机制

- 行内编辑使用 `editBuffer`（`Record<string, EditBuffer>`）管理各行的编辑状态；
- 修改收款方式/日期时先更新 `editBuffer`，失焦/关闭面板时比对原始值，无变化则跳过提交；
- 提交失败时回滚 `editBuffer` 到原始值；
- 使用 `submittingRef`（`Set<string>`）防止同一行重复提交。

### 新增收款记录

`POST /api/staff/documents/:id/payments`

**请求体**（`paymentCreateSchema` 校验）：

```json
{
  "paymentType": "deposit",
  "method": "微信",
  "amount": 5000.00,
  "paidAt": "2026-08-01T10:00:00.000Z",
  "invoiceInfo": {}
}
```

| 字段 | 必填 | 校验规则 |
|------|------|----------|
| paymentType | 是 | `deposit` / `final` / `balance` |
| method | 是 | 字符串，1-50 字符 |
| amount | 是 | 正数 |
| paidAt | 否 | ISO 8601 datetime 字符串，默认当前时间 |
| invoiceInfo | 否 | 任意 JSON 对象 |

**返回**：`PaymentView`，HTTP 201。

**后端逻辑**：
- 校验单据存在；
- 创建 `payment_records` 记录，`reconcile_status` 默认为 `pending`；
- 通过 WebSocket 广播 `payment.updated` 事件；
- 记录审计日志（action: `payment_add`）。

### 更新收款记录

`PATCH /api/staff/payments/:id`

**请求体**（`paymentUpdateSchema` 校验，所有字段可选）：

```json
{
  "method": "银行转账",
  "paidAt": "2026-08-01T14:00:00.000Z",
  "reconcileStatus": "pending"
}
```

**后端逻辑**：
- 校验收款记录存在；
- 仅更新传入的非 `undefined` 字段；
- 通过 WebSocket 广播 `payment.updated` 事件；
- 记录审计日志（action: `payment_update`）。

### 核销/取消核销

`POST /api/staff/payments/:id/reconcile`

**请求体**：

```json
{
  "status": "reconciled"
}
```

`status` 取值：`pending`（待对账）或 `reconciled`（已核销）。

**后端逻辑**（事务包裹）：
1. 校验收款记录存在，且当前状态与目标状态不同（相同则报 42206）；
2. 在事务内：
   - 更新 `payment_records.reconcile_status` 为目标状态；
   - 若目标状态为 `reconciled`，按「状态流转」推进条件尝试自动推进单据状态；
3. 事务提交后：
   - 广播 `payment.updated` 事件；
   - 若单据状态推进成功，广播 `document.status_changed` 事件；
4. 记录审计日志（action: `payment_reconcile`）。

### 删除收款记录

`DELETE /api/staff/payments/:id`

**后端逻辑**：
- 校验收款记录存在；
- 物理删除；
- 通过 WebSocket 广播 `payment.updated` 事件；
- 记录审计日志（action: `payment_remove`）。

### 锁定/解锁视图

`POST /api/staff/documents/:id/payments/lock`
`POST /api/staff/documents/:id/payments/unlock`

**后端逻辑**：
- 在 `documents.view_locks` JSON 字段中设置/清除 `payment_reconcile` 键（snake_case 锁键名，范式见《表格与交互规范》）；
- 锁定后前端禁止编辑收款方式、收款日期、核销操作、删除操作；
- 锁定不影响收款记录的查看和汇总统计。

## 与归档关系

### 正式区定档

- 销售定档（`archived_orders`）中包含 `paid_amount` 字段，定档时快照当前已收金额；
- 收款记录的创建/修改/删除不影响已定档的销售记录。

### 审计日志

所有收款操作均记录审计日志，`resource_type = 'payment_records'`：

| 操作 | action |
|------|--------|
| 新增收款 | `payment_add` |
| 更新收款 | `payment_update` |
| 核销/取消核销 | `payment_reconcile` |
| 删除收款 | `payment_remove` |

### 与其他功能的关系

- 收款对账独立于配货（`allocation_lines`）、交付（`delivery_records`）、成本（`cost_lines`）等标注层，收款记录不关联单据行，与配货行、成本行无直接关系；
- 收款对账、配货、交付、成本等视图共享同一单据的 WebSocket 刷新通道，任一视图变更可联动刷新其他视图；
- 采购报价确认后（`purchase_quote_status = 'confirmed'`），单据进入 `quote_confirmed` 状态，收款对账视图进入可操作区间；核销金额比对目标是采购报价确认后的价税合计（`total_amount`）。
