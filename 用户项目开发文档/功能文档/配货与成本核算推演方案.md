# 配货与成本

> 顶层依据：详见《顶层设计规范·理念4（表格唯一·交互统一）》《项目设计哲学·约束6（数据量级巨大·宽表承载·索引驱动）》《项目设计哲学·原则2（分层隔离·快照解耦）》。

> **职责**：配货履约（内部出库+外部调货、欠库、成本三段）及因此产生的供应商应付触发。一类活切法见 `文档可视化/` 指导思想：配货是给客户那张单凑货；点进仓、待入、按仓看库存是「进货管货」，不要写成配货的附录。库存/待入库/独立采购的表结构因交叉引用仍写在本文。
> **引用文档**：单据/单据行与 8 档状态机见《单据与状态机》；供应商档案见《供应商管理》；采购报价录入见《采购报价》。

---

## 功能概述

配货与成本是单据生命周期中**配货履约**的核心承载。进货管货（点进仓、待入、库存台账）是另一类活，菜单在「进货管货」。

1. **配货**：同一订单单品可拆分多个来源（内部仓库出库 + 外部供应商调货），来源通过统一检索交互选择；不够当场记下欠库。
2. **成本与应付**：成本三段分层落账（内部出库 / 外部刚需 / 外部超额）。仓出按当时均价；外面刚好够这笔的算进订单成本；外面多调的不算这笔订单成本，货进库存（进货那一摊去点进仓）。外部货品计入供应商应付。
3. **碰到进货时**：超额调货自动生成待入库单，不阻塞配货主线；确认入库是进货管货的动作。

单据状态流转（配货确认、待入库确认对单据状态的推进）以《单据与状态机》为权威，本文档仅定义配货环节自身的数据结构与业务规则。

## 来源拆分：内部仓库 vs 外部供应商

### 内部来源：本店自有库房

- 自有库房**支持多仓库、多库区点位**：A 库房、B 门店仓、样品仓等**均归类为内部来源**。
- 内部来源出库：**扣自身现有库存**；成本取自**本仓入库采购单价**（加权平均进价）。
- 底层架构：内部仓库为**独立档案实体**（`warehouse`），与外部供应商永久拆分。

### 外部来源：合作供应商

- 外部来源 = **合作供应商档案**（`supplier`），**不含自有仓库**。
- 订单配货向外调货属于**即时外协调货**：
  - **常规等额直送客户**（调货量 = 订单需求量）；
  - **超额拿货**自动生成简易采购入库。
- 底层架构：外部供应商沿用既有 `supplier` 档案，与内部仓库**永久拆分**。

### 统一检索交互

- **不拆分「内部/外部单选按钮」**：配货来源为**单列关键词检索输入框**，下拉自动**分组展示**（上方内部仓库列表、下方外部供应商列表），视觉清晰区分两类来源。
- **同步支持来源快速新建**（新建仓库 / 新建供应商二选一），提升开单效率，全程不用切换页面。

## 配货基础逻辑

### 同单单品可多来源拆分凑量

同一订单单品允许来自多个来源（内部仓库 + 外部供应商），**单品分行填写，各自标记来源、出库/调货数量**。

举例：订单需 PPR DN25 弯头 50 个

| 来源 | 类型 | 数量 |
|------|------|------|
| 自有一号仓库 | 内部 | 出库 30 个 |
| 甲供应商 | 外部 | 直发 20 个 |

### 等额外部调货标准规则（调货量 = 订单需求量）

外部供应商等额货物直接直发客户：

1. **不进入本店库存**：不扣自有仓、不新增库存；
2. **成本直接绑定**该供应商本次拿货进价，计入本单订单成本；
3. **账目归属**：计入该供应商应付账款，后续统一结算，**无需走独立采购单**。

## 超额调货

### 判定规则

订单消耗 = 订单必填数量；多出部分 = 超额入库数量。

```
订单需求 Q = document_lines.qty
超额数量 E = Σ外部调货数量 + Σ内部出库数量 - Q     （E > 0 时存在超额）
```

### 归属主体

超额部分全部归属**本次该单品最后选定的外部供应商**。同一单品多外部商家分批调货时，**多出货品固定记入最后一家供应商台账**。

> 「最后选定」判定 = 该单品下 `source_type='external'` 的配货行中，**创建/配货时间（alloc_at）最晚**的一条所对应的供应商。内部出库不参与超额归属。

### 入库仓位

超额部分统一**默认入库至本店主自有库房**，允许手动修改目标内部仓库点位。

> 「主自有库房」= `warehouse` 档案中 `isMain=true` 的仓库；无主仓标记时取排序第一的启用仓库。超额入库目标仓库允许在待入库单据上手动改为任意内部仓库。

### 两步流程（不阻塞配货主线）

- **第一步（主线不卡顿）**：订单直接确认、出库、完结客户单据，正常做客户应收、订单成本核算（**仅计算订单刚需数量**）。
- **第二步（进货管货去点进仓）**：系统自动生成**待入库单据**（`inbound_tasks` / `inbound_lines`），标注来源供应商、超额数量、对应进价；工作人员后续在进货管货里**确认入库**，货品纳入自有库存，同步增加该供应商应付欠款。多调的不算这笔客户单成本。

### 边界区分

- **订单内超额调货**：配货页面直接生成待入库，**不用跳转独立采购模块**；
- **订单以外常规大批量囤货**：走进货管货「采购入库」页（权限叶子 `inventory`），**不是**工作台新视图。选品复用 ProductPicker。确认即落账：加库存（`inventory_ledger.biz_type=purchase`）+ 供应商应付 `purchase` + 冲欠库。
- **期初盘点**：库存台账「期初入库」条，尚无库存行时按 SKU × 仓写入数量和成本，流水 `biz_type=adjust`。已有台账请用盘点改数量/成本。
- **两条流程互不冲突**，长期并存，不可合并、不可删除其一。不可拿强制绑定客户单的 `inbound_tasks` 硬套独立采购。

## 欠库兜底

门店边接单、边补货是常态，**不强制库存充足才可开单**。

### 正常扣减

内部仓库勾选出库，若当前库存 ≥ 填写数量：**正常扣减仓库库存**。

### 库存不足双处置

若库存 < 填写出库数量：

1. **已有的库存全额扣除**；
2. **缺口自动挂欠库**（`backorders`，幂等 upsert），弹窗告知「已自动挂欠库」，可改走外部调货补齐。不阻拦当下订单。
3. 补货入库（待入库确认或独立采购入库）后按仓 + SKU 先进先出冲抵。

### 欠库台账

欠库台账**单独汇总，可批量导出**，作为采购补货清单，适配建材日常经营节奏。

**冲抵规则**：待入库/采购入库时，按入库仓库 + SKU 维度**先进先出**冲抵 `pending` 欠库，冲抵数量 = min(入库数量, 欠库剩余)；欠库清零转 `fulfilled` 并写入 `fulfilled_at`。

## 库存与流水（加权平均进价）

### 库存台账

- 库存台账按**仓库 × SKU**（规格 × 品牌 × 单位）唯一存在一条记录（`inventory`），维护当前数量与加权平均进价。
- 库存为纯业务台账（无物理外键，SKU 仅存 ID，全名冗余在快照；详见《数据规范·解耦三原则》）。

### 加权平均进价算法（SSOT）

```
新加权平均进价 = (旧库存量 × 旧加权平均进价 + 本次入库量 × 本次入库采购单价) / (旧库存量 + 本次入库量)
结果保留两位小数（round2）；旧库存量为 0 时直接取本次入库采购单价。
```

- **入库**：按本次入库采购单价重算该仓库该 SKU 的加权平均进价，写 `inventory_ledger.in` 流水（`balance_avg_cost` 记录变动后均价）。
- **出库**：单价 = 出库时该仓库当前加权平均进价（快照写入 `allocation_lines.unit_cost` 与 `inventory_ledger.out.unit_cost`），**出库不改变加权平均进价**。
- 算法单一实现：后端 `engines/pricing-engine.ts` 的 `calcWeightedAvgCost`，前端不重写。

## 成本分层

### 三段分层

| 分层段 | cost_segment | 数量口径 | 单价口径 | 是否计订单成本 | 是否动库存 | 是否增供应商应付 |
|--------|-------------|---------|---------|--------------|-----------|----------------|
| 内部出库 | internal | Σ内部出库量 | 当前仓库加权平均进价 | ✅ | 扣减 | — |
| 外部刚需 | external_agreed | min(Σ外部调货量, 订单剩余需求) | 该供应商本次约定进价 | ✅ | 不动 | ✅ |
| 外部超额 | external_excess | Σ外部调货量 − 外部刚需量 | 该供应商本次约定进价 | ❌（入库时计入库存成本） | 后置入库增加 | ✅ |

> 订单剩余需求 = max(Q − Σ内部出库量, 0)。成本分层在配货确认时按上述口径落账（`cost_lines`），后置入库时仅把「外部超额」段从待入库转入库存。

### 分层单价锁定

- 分层单价由系统按口径写入并**锁定**（internal=加权平均进价；external_agreed / external_excess=约定进价），成本核定仅可调整 `actual_cost` / `freight` / `remark`；
- 同一行内唯一约束为 `(line_id, cost_segment, source_id)`——同一行外部来源可同时存在 `external_agreed` 与 `external_excess` 两段。

## 供应商应付

### 三类账目

外部调货成本账目统一计入 `supplier_payable_lines`，按来源分三类：

| biz_type | 来源 | 产生时机 |
|----------|------|---------|
| allocation_external | 等额直发 | 配货确认时，外部刚需段落应付 |
| inbound_task | 超额入库 | 待入库一键确认时，超额段落应付 |
| purchase | 独立采购 | 独立采购模块入库时 |

### 结算规则

- 供应商对账视图按供应商汇总 `pending` 应付，支持按单据/日期范围结算打款；
- 结算后置 `settled` + `settled_at`；
- 与客户应收（`payment_records` 收款对账）物理分表，互不干扰。

## 数据模型

> 设计原则：业务台账 → 基础档案**无物理外键、保留 ID + 名称快照**（详见《数据规范·解耦三原则》）；库存/欠库/待入库为业务台账，随业务生命周期留痕。SKU 维度统一为**规格 × 品牌 × 单位**（spec_id / brand_id / unit_id），产品全名冗余在快照字段。

### 表间关系总图

```
基础档案（永久拆分）：
  warehouse（内部仓库，含 zones 库区点位）     supplier（外部供应商，见《供应商管理》）
          │                                        │
业务台账（无物理外键 + 快照）：
  inventory（库存台账）──inventory_ledger（流水，加权平均依据）
  backorders（欠库台账）──待入库/采购入库自动冲抵
  inbound_tasks / inbound_lines（超额后置入库）
  allocation_lines（配货行，source_id 双态：内→warehouse / 外→supplier）
  cost_lines（成本分层：internal / external_agreed / external_excess）
  supplier_payable_lines（供应商应付：等额直发 / 超额入库 / 独立采购）

追溯闭环：
  documents ← document_lines ← allocation_lines → inbound_lines → inventory_ledger
                              ↓
                        cost_lines / supplier_payable_lines
```

### 追溯归档

- **订单单品永久留存**：每一笔订单单品永久留存来源类型（内/外）、对应仓库/供应商（含名称快照）、取用数量（出库/调货量）、超额入库数量、单品成本。
- **三方互查闭环**：订单详情、供应商对账、仓库库存台账**三方数据互相关联**，任意一端均可**反向追溯**本次货品去向、来源——`allocation_lines` 为三方关联的锚点（`line_id` ↔ 单据行，`source_id` ↔ 仓库/供应商，`over_qty` ↔ 待入库/库存流水），库存流水号（`ledger_no`）与待入库单号（`inbound_no`）双向可查。
- **归档**：单据定档时 `allocation_lines` / `cost_lines` / 待入库关联随快照留存；档案（仓库/供应商/产品）删除不影响历史追溯（遵循《数据规范·解耦三原则》）。

## 保存事务

### 配货确认主流程（不阻塞主线）

```
用户录入配货来源 + 数量（单列检索、分组下拉、可快速新建）
        │
        ▼
配货确认（主线即时完成，不等待后置环节）
  ├─ 内部来源出库量 → 校验仓库库存：
  │     ├─ 库存 ≥ 出库量：扣减库存（写 inventory_ledger.out，单价 = 加权平均进价）
  │     └─ 库存 < 出库量：全额扣减已有库存，缺口弹窗双处置：
  │          ① 新增外部供应商来源补齐（转入外部调货流程）
  │          ② 挂欠库标记（写 backorders.pending）
  ├─ 外部来源调货量 → 拆分刚需/超额：
  │     ├─ 刚需量 = min(调货量, 订单剩余需求)：
  │     │    成本 = 约定进价 → 写 cost_lines(external_agreed) + supplier_payable_lines
  │     └─ 超额量 = 调货量 - 刚需量：
  │          生成待入库（inbound_tasks + inbound_lines，来源 = 最后选定外部供应商，
  │          目标仓 = 主自有库房，可改）→ 写 cost_lines(external_excess, over_qty)
  └─ 订单成本核算：仅计算订单刚需数量（internal + external_agreed）
```

### 后置入库流程（工作人员空闲时一键完成）

```
待入库列表（status=pending）
        │
        ▼ 一键确认入库（POST /inbound-tasks/:id/confirm，事务）
  ├─ 库存增加：inventory.qty += 超额量；
  │    加权平均进价重算 = (旧qty×旧均价 + 超额量×约定进价) / (旧qty+超额量)
  │    → 写 inventory_ledger.in（biz_type=inbound_task，biz_no=inbound_no）
  ├─ 供应商应付：supplier_payable_lines 新增（biz_type=inbound_task）
  ├─ 欠库冲抵：按 仓库+SKU 先进先出冲抵 backorders.pending → fulfilled
  └─ 待入库状态：task/lines → done，cost_lines(external_excess) 回填 inbound_line_id
```

### 欠库冲抵流程

- 触发点：待入库确认入库、独立采购入库（biz_type=inbound_task / purchase）。
- 冲抵口径：入库数量先冲抵该仓库该 SKU 的 `pending` 欠库（先进先出），剩余入库量进入库存。
- 结果：欠库台账 `fulfilled` + `fulfilled_at`；欠库导出清单仅含 `pending`。

### 超额归属算法

```
外部调货行按 alloc_at 升序排列；超额量 E 归属最后一条外部调货行对应供应商
（「最后选定」= 该单品外部配货行中 alloc_at 最晚者，若同一供应商多行则合并归属该供应商）。
```

- 归属供应商名称快照写入 `inbound_tasks.supplierName`。
- 内部出库不参与超额归属；超额量 E = Σ配货量 − 订单需求 Q（E ≤ 0 无超额）。
