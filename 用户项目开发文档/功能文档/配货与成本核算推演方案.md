## 一、顶层核心定义（固定概念，全程统一口径）

### 1.1 内部来源：本店自有库房

- 自有库房**支持多仓库、多库区点位**：A 库房、B 门店仓、样品仓等**均归类为内部来源**。
- 内部来源出库：**扣自身现有库存**；成本取自**本仓入库采购单价**（加权平均进价）。
- 底层架构：内部仓库为**独立档案实体**（warehouse），与外部供应商永久拆分。

### 1.2 外部来源：合作供应商

- 外部来源 = **合作供应商档案**，**不含自有仓库**。
- 订单配货向外调货属于**即时外协调货**：
  - **常规等额直送客户**（调货量 = 订单需求量，见第二章）；
  - **超额拿货**自动生成简易采购入库（见第三章）。
- 底层架构：外部供应商沿用既有 `supplier` 档案，与内部仓库**永久拆分**。

### 1.3 配货统一交互规则

- **不拆分「内部/外部单选按钮」**：配货来源为**单列关键词检索输入框**，下拉自动**分组展示**（上方内部仓库列表、下方外部供应商列表），视觉清晰区分两类来源。
- **同步支持来源快速新建**（新建仓库 / 新建供应商二选一），提升开单效率，全程不用切换页面。

## 二、配货基础业务逻辑（等额调货常规场景）

### 2.1 同一订单单品可多来源拆分凑量

**固定规则**：同一订单单品允许来自多个来源（内部仓库 + 外部供应商），**单品分行填写，各自标记来源、出库/调货数量**。

举例：订单需 PPR DN25 弯头 50 个

| 来源 | 类型 | 数量 |
|------|------|------|
| 自有一号仓库 | 内部 | 出库 30 个 |
| 甲供应商 | 外部 | 直发 20 个 |

### 2.2 等额外部调货标准规则（调货量 = 订单需求量）

**固定规则**：外部供应商等额货物直接直发客户：

1. **不进入本店库存**：不扣自有仓、不新增库存；
2. **成本直接绑定**该供应商本次拿货进价，计入本单订单成本；
3. **账目归属**：计入该供应商应付账款，后续统一结算，**无需走独立采购单**。

## 三、超额调货核心规则（调货数量 ＞ 订单需求，门店多拿备货/样品）

### 3.1 判定规则

**固定规则**：订单消耗 = 订单必填数量；多出部分 = 超额入库数量。

```
订单需求 Q = document_lines.qty
超额数量 E = Σ外部调货数量 + Σ内部出库数量 - Q     （E > 0 时存在超额）
```

### 3.2 归属主体

**固定规则**：超额部分全部归属**本次该单品最后选定的外部供应商**。同一单品多外部商家分批调货时，**多出货品固定记入最后一家供应商台账**。

> 逻辑演绎补全：「最后选定」判定 = 该单品下 `source_type='external'` 的配货行中，**创建/配货时间最晚**的一条所对应的供应商。内部出库不参与超额归属。

### 3.3 入库仓位

**固定规则**：超额部分统一**默认入库至本店主自有库房**，允许手动修改目标内部仓库点位。

> 逻辑演绎补全：「主自有库房」= warehouse 档案中 `isMain=true` 的仓库；无主仓标记时取排序第一的启用仓库。超额入库目标仓库允许在待入库单据上手动改为任意内部仓库。

### 3.4 流程处理（不阻塞配货开单主线，拆分两步）

**固定规则**：

- **第一步（主线不卡顿）**：订单直接确认、出库、完结客户单据，正常做客户应收、订单成本核算（**仅计算订单刚需数量**）。
- **第二步（后置附属环节）**：系统自动生成**待入库单据**，标注来源供应商、超额数量、对应进价；工作人员后续空闲时**一键确认入库**，货品纳入自有库存，同步增加该供应商应付欠款。

### 3.5 边界区分

**固定规则**：

- **订单内超额调货**：配货页面直接生成待入库，**不用跳转独立采购模块**；
- **订单以外常规大批量囤货**：依旧走独立采购管理模块；
- **两条流程互不冲突**，兼顾直观性与规范性。

## 四、自有仓库库存不足兜底逻辑（边用边补适配模式）

**固定规则**：门店边接单、边补货是常态，**不强制库存充足才可开单**。

### 4.1 正常扣减

内部仓库勾选出库，若当前库存 ≥ 填写数量：**正常扣减仓库库存**。

### 4.2 库存不足双处置

若库存 < 填写出库数量：

1. **已有的库存全额扣除**；
2. **缺口数量自动弹窗提示**，支持两种快速处置：
   - ① **直接新增外部供应商来源，补齐缺口**（转外部等额/超额调货）；
   - ② **临时挂欠库标记**，后续补货入库后自动冲抵欠库，**不阻拦当下订单开单**。

### 4.3 欠库台账

欠库台账**单独汇总，可批量导出**，作为采购补货清单，适配建材日常经营节奏。

## 五、成本核算分层规则（适配内/外来源，账单精准可追溯）

### 5.1 内部仓库出库部分

**固定规则**：成本 = 该货品**当前仓库加权平均进价**；库存同步扣减。

### 5.2 外部等额直发部分

**固定规则**：成本 = **本次和该供应商约定的单品进价**，不计入本店库存，只计入订单成本、供应商应付款。

### 5.3 外部超额入库部分

**固定规则**：

- ① **订单刚需部分**：进价计入订单成本；
- ② **超额入库部分**：进价录入库存成本（入库时），同步增加供应商应付，**不计入当前订单成本**，下次本店售卖该库存时再核算利润。

### 5.4 分层汇总口径（逻辑演绎补全）

| 成本来源段 | 数量口径 | 单价口径 | 是否计订单成本 | 是否动库存 | 是否增供应商应付 |
|-----------|---------|---------|--------------|-----------|----------------|
| 内部出库 | Σ内部出库量 | 当前仓库加权平均进价 | ✅ | 扣减 | — |
| 外部刚需 | min(Σ外部调货量, 订单剩余需求) | 该供应商本次约定进价 | ✅ | 不动 | ✅ |
| 外部超额 | Σ外部调货量 − 外部刚需量 | 该供应商本次约定进价 | ❌（入库时计入库存成本） | 后置入库增加 | ✅ |

> 订单剩余需求 = max(Q − Σ内部出库量, 0)。成本分层在配货确认时按上述口径落账，后置入库时仅把「外部超额」段从待入库转入库存。

## 六、检索UI交互定型（统一组件，和产品检索规则全域复用）

### 6.1 检索打分复用

**固定规则**：配货来源输入框**共用全局检索打分逻辑**：完全匹配 ＞ 前缀 ＞ 词组包含 ＞ 零散关键词。

> 逻辑演绎补全：复用双端 SSOT `search-scoring.ts`（`scoreSkuByCustomWeights` 三层打分），**禁止为配货来源另立匹配规则**；仓库/供应商检索字段为 `name`（可含 code/别名同源），打分规则与产品检索完全一致。

### 6.2 下拉分组展示

**固定规则**：下拉列表**分组展示**——上方「内部仓库列表」、下方「外部供应商列表」，视觉清晰区分两类来源。

### 6.3 快速新建档案

**固定规则**：检索无对应仓库/供应商时，**弹窗一键快速新建档案**（仓库/供应商二选一），新建完成自动回填选中，全程不用切换页面。

## 七、追溯归档规则（满足后期对账复盘）

### 7.1 订单单品永久留存

**固定规则**：每一笔订单单品**永久留存**：

- 来源类型（内/外）；
- 对应仓库/供应商（含名称快照）；
- 取用数量（出库/调货量）；
- 超额入库数量；
- 单品成本。

### 7.2 三方互查闭环

**固定规则**：订单详情、供应商对账、仓库库存台账**三方数据互相关联**，任意一端均可**反向追溯**本次货品去向、来源。

> 逻辑演绎补全：allocation_lines 为三方关联的锚点（line_id ↔ document，source_id ↔ 仓库/供应商，over_qty ↔ 待入库/库存流水），库存流水号（ledger_no）与待入库单号（inbound_no）双向可查。

## 九、数据模型（逻辑演绎补全）

> 设计原则：对齐 v11.0 全域解耦——业务交易表 → 基础档案表**无物理外键**，保留 ID 字段 + 索引 + 名称快照；库存/欠库/待入库为业务台账，随业务生命周期留痕。所有 ID 用应用层时间戳生成（同产品ID 规则）或 autoincrement 兜底。

### 9.1 warehouse 仓库档案表（内部来源，基础档案）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| name | varchar(200) | NOT NULL | 仓库名称（A库房 / B门店仓 / 样品仓） |
| code | varchar(50) | UNIQUE | 仓库编码（可选，检索辅助） |
| zones | Json | | 多库区点位 `[{ "name": "A区", "sortOrder": 1 }]`（库区点位归类内部，不拆表） |
| address | varchar(500) | | 地址 |
| manager | varchar(50) | | 负责人 |
| isMain | Boolean | DEFAULT false | 是否主自有库房（超额默认入仓；同店有且仅有一个 true） |
| sortOrder | Int | DEFAULT 0 | 排序（下拉内部列表顺序） |

### 9.4 backorders 欠库台账表（业务台账）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| document_id | BigInt | NOT NULL | 欠库来源订单（无物理外键） |
| line_id | BigInt | NOT NULL | 欠库来源单据行 |
| warehouse_id | BigInt | NOT NULL | 欠库仓库 |
| brand_id / unit_id | BigInt | NOT NULL | SKU 维度 |
| qty | Decimal(14,3) | NOT NULL | 欠库数量（缺口） |
| status | enum('pending','fulfilled','cancelled') | DEFAULT 'pending' | 待补 / 已补 / 已取消 |
| fulfilled_at | DateTime | | 冲抵时间 |
| fulfilled_by | BigInt | | 冲抵操作人 ID |
| fulfilledName | varchar(50) | | 冲抵操作人名称快照 |
| note | varchar(500) | | 备注 |
| created_at / updated_at | DateTime | | 创建/更新时间 |

**约束**：`@@index([status])`、`@@index([document_id])`、`@@index([warehouse_id, brand_id, unit_id])`。

> 冲抵规则（逻辑演绎）：待入库/采购入库时，按入库仓库 + SKU 维度**先进先出**冲抵 `pending` 欠库，冲抵数量 = min(入库数量, 欠库剩余)；欠库清零转 `fulfilled` 并写入 `fulfilled_at`。欠库台账可批量导出为采购补货清单。

### 9.5 inbound_tasks / inbound_lines 待入库表（业务台账，超额后置环节）

**inbound_tasks（待入库单主表）**：

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| inbound_no | varchar(50) | UNIQUE | 待入库单号（如 `IB20260808xxxx`） |

| supplier_id | BigInt | NOT NULL | 超额归属供应商（最后选定外部供应商） |

| target_warehouse_id | BigInt | NOT NULL | 目标入库仓库（默认主自有库房，可改） |
| total_qty | Decimal(14,3) | NOT NULL | 超额入库总数量 |
| total_amount | Decimal(14,2) | NOT NULL | 超额入库总金额（Σ 数量 × 约定进价） |
| status | enum('pending','done','cancelled') | DEFAULT 'pending' | 待确认 / 已入库 / 已取消 |
| confirmed_at | DateTime | | 入库确认时间 |
| confirmed_by | BigInt | | 确认人 ID |
| confirmedName | varchar(50) | | 确认人名称快照 |
| note | varchar(500) | | 备注 |

**inbound_lines（待入库行表）**：

### 9.9 表间关系总图

```
基础档案（永久拆分）：
  warehouse（内部仓库，含 zones 库区点位）     supplier（外部供应商）
          │                                        │
业务台账（v11.0 解耦：无物理外键 + 快照）：
  inventory（库存台账）──inventory_ledger（流水，加权平均依据）
  backorders（欠库台账）──待入库/采购入库自动冲抵

  cost_lines（成本分层：internal / external_agreed / external_excess）
  supplier_payable_lines（供应商应付：等额直发 / 超额入库 / 独立采购）

追溯闭环：
  documents ← document_lines ← allocation_lines → inbound_lines → inventory_ledger
                              ↓
                        cost_lines / supplier_payable_lines
```

## 十一、保存逻辑与流程闭环（逻辑演绎补全）

### 11.1 配货确认主流程（不阻塞主线）

```
用户录入配货来源 + 数量（单列检索、分组下拉、可快速新建）
        │
        ▼
配货确认（主线即时完成，不等待后置环节）
  ├─ 内部来源出库量 → 校验仓库库存：
  │     ├─ 库存 ≥ 出库量：扣减库存（写 inventory_ledger.out，单价 = 加权平均进价）
  │     └─ 库存 < 出库量：全额扣减已有库存，缺口弹窗双处置：
  │          ① 新增外部供应商来源补齐（转入外部调货流程）
  │          ② 挂欠库标记（写 backorders.pending）
  ├─ 外部来源调货量 → 拆分刚需/超额：
  │     ├─ 刚需量 = min(调货量, 订单剩余需求)：
  │     │    成本 = 约定进价 → 写 cost_lines(external_agreed) + supplier_payable
  │     └─ 超额量 = 调货量 - 刚需量：
  │          生成待入库（inbound_tasks + inbound_lines，来源 = 最后选定外部供应商，
  │          目标仓 = 主自有库房，可改）→ 写 cost_lines(external_excess, over_qty)
  └─ 订单成本核算：仅计算订单刚需数量（internal + external_agreed）
```

### 11.2 后置入库流程（工作人员空闲时一键完成）

```
待入库列表（status=pending）
        │
        ▼ 一键确认入库（POST /inbound-tasks/:id/confirm，事务）
  ├─ 库存增加：inventory.qty += 超额量；
  │    加权平均进价重算 = (旧qty×旧均价 + 超额量×约定进价) / (旧qty+超额量)
  │    → 写 inventory_ledger.in（biz_type=inbound_task，biz_no=inbound_no）
  ├─ 供应商应付：supplier_payable_lines 新增（biz_type=inbound_task）
  ├─ 欠库冲抵：按 仓库+SKU 先进先出冲抵 backorders.pending → fulfilled
  └─ 待入库状态：task/lines → done，cost_lines(external_excess) 回填 inbound_line_id
```

### 11.3 欠库冲抵流程

- 触发点：待入库确认入库、独立采购入库（biz_type=inbound_task/purchase）。
- 冲抵口径：入库数量先冲抵该仓库该 SKU 的 `pending` 欠库（先进先出），剩余入库量进入库存。
- 结果：欠库台账 `fulfilled` + `fulfilled_at`；欠库导出清单仅含 `pending`。

### 11.4 加权平均进价算法（SSOT）

```
新加权平均进价 = (旧库存量 × 旧加权平均进价 + 本次入库量 × 本次入库采购单价) / (旧库存量 + 本次入库量)
结果保留两位小数（round2）；旧库存量为 0 时直接取本次入库采购单价。
```

- 内部出库：单价 = 出库时该仓库当前加权平均进价（快照写入 allocation_lines.unit_cost + inventory_ledger.out.unit_cost），**出库不改变加权平均进价**。
- 算法单一实现：后端 `engines/pricing-engine.ts` 扩展 `calcWeightedAvgCost`，前端不重写。

### 11.5 超额归属算法

```
外部调货行按 alloc_at 升序排列；超额量 E 归属最后一条外部调货行对应供应商
（「最后选定」= 该单品外部配货行中 alloc_at 最晚者，若同一供应商多行则合并归属该供应商）。
```

- 归属供应商名称快照写入 inbound_tasks.supplierName。
- 内部出库不参与超额归属；超额量 E = Σ配货量 - 订单需求 Q（E ≤ 0 无超额）。

## 十三、演进路线（与现有实现的映射）

| 能力 | 现有实现（基线） | 本方案目标 | 落地方式 |
|------|----------------|-----------|---------|
| 内部仓库 | 无独立档案（supplier 表无 type，配货来源仅 supplier） | 独立 warehouse 表 + zones 库区点位 | 新增表 + 档案管理 |
| 来源类型 | `allocation_lines.source_type = warehouse/external` | 枚举统一为 `internal/external`（内部 → warehouse.id） | 迁移映射 |
| 库存 | 无 | inventory + inventory_ledger（加权平均） | 新增表 + 出/入库扣增 |
| 外部等额 | 直接记录配货（unit_cost 手工） | 不进库存 + 约定进价落订单成本 + 供应商应付 | 扩展 upsert 逻辑 |
| 超额调货 | 超拿仅数量记录（无库存/待入库） | 自动生成待入库 + 后置一键入库 | 新增 inbound 表 + 流程 |
| 库存不足 | 无库存概念，无校验 | 全额扣减 + 缺口双处置（外部补齐/挂欠库） | 新增欠库表 + 弹窗交互 |
| 成本核算 | 三源汇集（仓库/供应商/运费），预设成本=最低有效进价 | 分层：内部加权平均 / 外部刚需约定进价 / 外部超额（入库时计库存） | cost_lines 扩展分层字段 |
| 供应商应付 | 无 | supplier_payable_lines（等额/超额/采购三源） | 新增表 + 对账结算 |
| 来源检索 | AllocationSourcePicker（本地过滤，仅供应商可新建） | 全局打分检索 + 分组下拉 + 仓库/供应商快速新建 | 复用 search-scoring SSOT |

**落地顺序建议（单焦点串行）**：
1. 仓库档案 + 库存台账（warehouse / inventory / inventory_ledger）
2. 配货来源统一检索 + 快速新建（替换 AllocationSourcePicker）
3. 配货行扩展（内部出库扣库存 / 外部等额落应付）
4. 超额调货 → 待入库 → 一键入库（含欠库冲抵）
5. 库存不足兜底（欠库台账 + 弹窗双处置 + 导出）
6. 成本分层（cost_lines 扩展）
7. 供应商应付对账结算
