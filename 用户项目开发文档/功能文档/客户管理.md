## 功能概述

客户管理是建材报价系统的基础数据管理模块，负责维护客户档案信息。核心能力包括：

- **客户档案 CRUD**：支持列表页行内编辑（手机号、姓名、微信、公司、类型、折扣率、开票信息、状态、备注），无需弹窗；
- **快速新建客户**：手机号+姓名至少填一个即可建档，其余字段后续行内编辑补全；
- **关键词检索**：支持手机号、姓名、公司、微信多字段模糊匹配；
- **地址下钻管理**：点击客户姓名或地址数进入该客户的地址子表（二层 DrillState），地址同样支持行内编辑；
- **客户停用/启用**：停用后不再出现在新建单据的客户检索中，但已存在单据不受影响；
- **客户物理删除**：允许被引用的客户物理删除（单据通过快照字段独立存在），删除前展示引用计数；
- **客户选择器**：新建单据时通过 `CustomerPicker` 组件进行匹配检索 + 快速新建，实现无断点操作。

客户档案数据相对独立、字段简单，直接在列表页行内编辑（**Excel 式即时保存：输入当场生效，无保存按钮**）；地址管理作为客户的下钻子表，采用「主表 → 地址子表」DrillState 层级切换模式。

## 表结构

### customers 客户主表（职责：客户档案主表，被单据与审计日志快照引用）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|----------|--------|------|
| id | BigInt PK | 1 | 主键 |
| customer_code | VarChar(30) NOT NULL @@unique | C1001 | 客户编码，系统自动生成，不可变（检索辅助） |
| phone | VarChar(20)? @@unique | 13800000001 | 手机号：**可空 + 有值唯一**（NULL 多值不冲突，有值不可重复） |
| name | VarChar(100)? | 张三 | 客户姓名 |
| wechat | VarChar(100)? | wx_zhangsan | 微信号 |
| company | VarChar(200)? | X建材公司 | 公司名称 |
| note | Text? | 长期客户 | 备注 |
| status | enum customer_status DEFAULT active | active | 状态：active=正常，disabled=已禁用 |
| customer_type | enum customer_type DEFAULT personal | personal | 类型：personal=个人业主，company=公司（仅标识，不参与业务决策） |
| discount_rate | Decimal(5,2) DEFAULT 100 | 100 | 折扣率（0-100，100=不打折） |
| invoice_info | Json DEFAULT '{}' | 见下 | 开票信息（6 子字段） |
| created_at / updated_at | DateTime | — | 创建 / 更新时间 |

**关联**：
- `customer_sessions`：1:N，CASCADE 删除（客户删除时会话失效）；
- `customer_addresses`：1:N，CASCADE 删除（客户删除时地址清理）；
- `documents` / `audit_logs`：解耦（无物理外键），仅保留 `customer_id` 字段 + 索引 + 名称快照（见「与单据及审计的关系」）。

**枚举**：

| 枚举 | 值 | 说明 |
|------|------|------|
| customer_status | active, disabled | 客户状态 |
| customer_type | personal, company | 客户类型（标识性，不参与业务决策） |

### customer_addresses 客户地址表（职责：客户地址下钻子表，跟随客户生命周期级联）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|----------|--------|------|
| id | BigInt PK | 1 | 主键 |
| customerId | BigInt FK CASCADE | 1(张三) →customers.id | 所属客户 |
| label | VarChar(50)? | 家 | 地址标签（如「家」「公司」「工地」） |
| contact | VarChar(100) NOT NULL | 张三 | 联系人姓名 |
| phone | VarChar(20) NOT NULL | 13800000001 | 联系人电话 |
| province | VarChar(50)? | 广东省 | 省 |
| city | VarChar(50)? | 广州市 | 市 |
| district | VarChar(50)? | 天河区 | 区/县 |
| detail | VarChar(500) NOT NULL | 天河路 100 号 | 详细地址 |
| isDefault | Boolean DEFAULT false | true | 是否默认地址（同一客户至多一条） |
| createdAt / updatedAt | DateTime | — | 创建 / 更新时间 |

**索引**：`@@index([customerId])`

### invoice_info 开票信息 JSON 结构

6 子字段：税号、发票抬头、开户行、银行账号、开票地址、开票电话。

```json
{
  "taxNumber": "91330100MA27XXXXXX",
  "invoiceTitle": "X建材有限公司",
  "bankName": "中国工商银行广州分行",
  "bankAccount": "3602 0000 0000 0000 000",
  "address": "广州市天河区天河路100号",
  "phone": "020-88888888"
}
```

保存时自动清理空值（trim 后为空的不写入 JSON）。

## 保存逻辑（行内即时保存）

客户档案采用 **Excel 式行内即时保存**：单元格输入后当场生效，无需额外点击保存按钮；输入有效数据后按 Enter 或失焦自动提交。

### 客户列表加载

```
GET /api/staff/customers?keyword=xxx&status=active&page=1&pageSize=20
  → customerService.listCustomers()
    → 构建 WHERE 条件：
      - keyword 非空 → OR 匹配 phone/name/company/wechat（contains）
      - status 非空 → 精确匹配 status
    → Promise.all([count, findMany])
      → findMany 按 created_at DESC 排序，include _count.customer_addresses
    → paginate(list, total, page, pageSize)
```

### 快速新建客户

```
POST /api/staff/customers/quick-add { phone?, name?, wechat?, company?, note?, customerType?, discountRate?, invoiceInfo? }
  → customerQuickAddSchema 校验：
    - phone 与 name 至少填一个
    - phone 有值时 max 20 字符
    - name 有值时 max 100 字符
    - customerType ∈ ['personal','company']
    - discountRate ∈ [0, 100]
  → customerService.quickAddCustomer()：
    - phone 有值 → 查 unique 冲突：
      - 已存在且原 name 为空 → 补全姓名后返回既有记录
      - 已存在且原 name 不为空 → 直接返回既有记录
    - 无冲突 → 生成 customer_code（系统自动编码）→ 创建记录
      - status 默认 'active'
      - customer_type 默认 'personal'
      - discount_rate 默认 100
      - invoice_info 默认 {}
  → 审计日志：customer_quick_add
```

### 更新客户档案（行内即时保存）

```
PATCH /api/staff/customers/:id { phone?, name?, wechat?, company?, note?, customerType?, discountRate?, invoiceInfo?, status? }
  → customerUpdateSchema 校验
  → customerService.updateCustomer()：
    - 查 existing 记录（不存在 → 404）
    - camelCase 入参 → snake_case 列名映射（name/wechat/company/note/status/customerType→customer_type/discountRate→discount_rate/invoiceInfo→invoice_info）
    - phone 变更处理：
      - 空字符串 → 清空为 null
      - 有值且与现有不同 → 查 unique 冲突：
        - 冲突 → 抛错 "该手机号已属于客户「XXX」，请直接搜索该客户关联，或修改为其他号码"
      - 无冲突 → 写入 update.phone
    - customer_code 不可变，不在可更新列表中
    - 执行 prisma.customers.update({ where: { id }, data: update })
  → 审计日志：customer_update
```

### 设置客户状态

```
POST /api/staff/customers/:id/status { status: 'active' | 'disabled' }
  → 校验 status 枚举值
  → customerService.setCustomerStatus()：
    - 查 existing（不存在 → 404）
    - 直接更新 status 字段
  → 审计日志：customer_status_change
```

### 查询客户引用计数

```
GET /api/staff/customers/:id/ref-counts
  → customerService.getCustomerRefCounts()：
    - 查 existing（不存在 → 404）
    - Promise.all([
        documents.count({ where: { customer_id: id } }),
        audit_logs.count({ where: { customer_id: id } }),
      ])
    - 返回 { customerId, documentCount, auditLogCount, totalRefs }
```

### 删除客户（物理删除）

```
DELETE /api/staff/customers/:id
  → customerService.deleteCustomer()：
    - 查 existing（不存在 → 404）
    - 收集引用计数（documentCount + auditLogCount）
    - 清理：customer_addresses.deleteMany({ where: { customerId: id } })
    - customer_sessions 通过 CASCADE 自动清理
    - authorization_codes 保留（授权码历史记录有 creatorName 快照）
    - 执行 customers.delete({ where: { id } })
    - 返回 { customerId, customerName, customerPhone, deletedRefCounts }
  → 审计日志：customer_delete（含 deletedRefCounts）
```

### 地址管理

**新增地址**：

```
POST /api/staff/customers/:id/addresses { contact, phone, detail, label?, province?, city?, district?, isDefault? }
  → contact/phone/detail 必填
  → isDefault=true → 先清除该客户其他地址的 isDefault
  → 创建地址记录
```

**更新地址**：

```
PATCH /api/staff/customers/:customerId/addresses/:id { ... }
  → 部分字段更新
  → isDefault=true → 先清除该客户其他地址的 isDefault
  → 执行更新
```

**删除地址**：

```
DELETE /api/staff/customers/:customerId/addresses/:id
  → 查地址存在性（不存在 → 404）
  → 物理删除
```

### DrillState 层级切换

```typescript
type CustomerDrillState =
  | { level: 1 }                                  // 层级1：客户主表
  | { level: 2; parent: CustomerView };           // 层级2：地址子表（携带父客户信息）
```

- 层级1 → 层级2：点击客户姓名列或地址数列，`setDrill({ level: 2, parent: record })`；
- 层级2 → 层级1：点击返回按钮，`setDrill({ level: 1 })`，同时刷新主表（地址数可能变化）；
- 整页重渲染，非抽屉、非弹窗。

### 删除确认流程

```
用户点击删除 → 
  1. 调用 getCustomerRefCounts(id) 获取引用计数
  2. 组装确认内容：
     - 被单据引用 N 项 → 显示 "单据 N 项"
     - 被审计日志引用 N 项 → 显示 "审计日志 N 项"
     - 未被引用 → 显示 "该客户未被任何业务记录引用，可安全删除"
  3. Modal.confirm 弹窗（okText: "物理删除", okType: "danger"）
     - 引用计数获取失败 → 降级确认（提示无法获取引用计数，仍可继续）
  4. 确认 → deleteCustomer(id) → 刷新列表
```

### 新增客户 Modal

- 手机号输入框 + 姓名输入框（两个至少填一个）
- 底部提示：「手机号与姓名至少填一个。建档后可在列表中行内编辑补全其他信息。」
- 确认按钮：`okText="建档"`

## 与单据及审计的关系

### 单据引用客户快照

新建单据时通过 `CustomerPicker` 选择客户后，单据主表 `documents` 存储：

| 字段 | 来源 | 说明 |
|------|------|------|
| `customer_id` | customers.id | 客户 ID（BigInt，用于聚合统计） |
| `customerName` | customers.name | 客户名称快照（下单时锁定） |
| `customerPhone` | customers.phone | 客户电话快照 |
| `customerCompany` | customers.company | 客户公司快照 |

解耦后，客户档案删除不影响单据展示、打印、统计。单据详情页完全依赖快照字段展示客户信息。单据编号（`YY-MM-DD-序号`）与 8 档状态机见《单据与状态机》。

### 审计日志引用客户

`audit_logs` 表记录客户相关操作时存储：

| 字段 | 来源 | 说明 |
|------|------|------|
| `customer_id` | customers.id | 客户 ID（BigInt，用于聚合统计） |
| `customerName` | customers.name | 客户名称快照 |

解耦后，客户档案删除不影响审计日志展示。

### 客户选择器（CustomerPicker）

`CustomerPicker` 组件用于新建单据时选择客户，交互流程：

```
输入关键词（手机号/姓名/公司/微信）→ 
  250ms 防抖 → searchCustomers API（仅返回 status=active 的客户）→ 
  浮动面板展示：
    - 第一行：快速新建客户（绿色高亮）
    - 已匹配客户列表（姓名 + 手机号 + 公司）
  →
    选择已有客户 → 回填 id/phone/name/company/wechat
    或
    点击快速新建 → 弹出快速新建面板（手机号/姓名/公司/类型）→ 建档后回填
```

智能解析：输入内容自动识别手机号（`1[3-9]\d{9}`）和姓名，快速新建时预填。
