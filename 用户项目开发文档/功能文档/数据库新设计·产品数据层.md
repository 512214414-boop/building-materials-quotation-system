## 第二部分 产品案例（完整实现）

> 本部分以产品管理为完整案例，演示通用理念如何落地。**新增功能/表时照此结构输出**：用户故事 → 数据模型总览 → 表结构详解 → 保存逻辑 → 接口契约 → 前端数据交互。

### 用户故事（业务 → 数据的映射）

**故事 1：销售现场极速建档**

打开建档弹窗 → 输入产品名「PPR热水管」→ 输入规格型号「25」→ 添加单位「米」→ 确认。

数据落地：`product` 新增 → `spec` 新增（规格型号「25」）→ `brand` 自动新增「普通品牌」→ `spec_brand` 新增（规格×品牌关联）→ `unit` 新增「米」（isBase+isDisplay）→ `brand_unit_conversion` 新增（×1）→ `product_sku_search` 自动同步。

**故事 2：完善品牌与价格**

编辑产品 → 添加品牌「伟星」→ 为伟星设置「根」的换算系数 4.0000 → 填写售价/进价 → 上传图片。

数据落地：`spec_brand` 新增（规格×伟星）→ `brand_unit_conversion` 新增（伟星+米=1、伟星+根=4）→ `sale_price`/`purchase_price` 新增（挂 specBrandId）→ `product_image` 新增（挂 specBrandId）。

**故事 3：品牌改名全局生效**

档案层把「伟星」改名为「伟星管业」→ 所有引用它的规格、SKU、价格、列表展示自动变为新名（ID 不变），历史单据快照保持原名不变。

**故事 4：产品物理删除不影响历史单据**

产品被 5 张采购单、3 张销售单引用 → 二次确认后物理删除 → 单据快照字段、金额、统计完全不变；通过单据跳转产品档案时显示「该产品档案已移除」。

**故事 5：统计按 ID 聚合**

同一条产品改名两次、被三张单据引用 → 出入库/销量/成本统计按单据内留存的 specId/productId 聚合 → 三张单据归为同一条产品。

### 数据模型总览（v14.0 层级）

```
category（分类，扁平）
   │ 1:N
product（只存产品名：name + categoryId + 状态）
   │ 1:N
spec（规格变体：specModel）
   ├── 1:N ── spec_brand（规格×品牌关联：承载规格内品牌备注/排序/状态）
   │              └── 1:N ── brand（全局独立档案，name 全局唯一）
   └── 1:N ── unit（单位，挂规格；单位名规格内共享，不按品牌独立）
                  │
      SKU = 规格变体 × 品牌 × 单位（spec_brand + unit）
                  │
   sale_price（售价：specBrandId+unitId+priceTypeId）
   purchase_price（进价：specBrandId+unitId+supplierId）
   product_image（图片：specBrandId）
   brand_unit_conversion（换算率：specBrandId+unitId，按规格×品牌独立）
   │
product_sku_search（宽表：每「规格×品牌」一行，冗余展示 + 检索）
```

**核心关系一句话**：产品只存名字，规格型号拆到 spec；每个规格有自己的品牌（spec_brand）和共享的单位名列表（unit）；只有换算率按「规格×品牌」独立（brand_unit_conversion）；SKU = 规格×品牌×单位。

### 表结构详解（唯一权威，Prisma 字段 camelCase，物理列名与字段名一致）

#### category 分类表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | Int | PK | 主键 |
| name | String(100) | NOT NULL | 分类名称 |
| sortOrder | Int | DEFAULT 0 | 排序号 |
| status | Int | DEFAULT 1 | 状态 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

扁平结构，无父子层级；删除时产品数 > 0 禁止。

#### supplier 供应商表（purchase_price 引用方）

> 供应商档案的完整表结构、字段、接口契约与保存逻辑见 [供应商管理.md](./供应商管理.md)，本文档**不再重复定义**（引用代替复制，单一信息源）。
> 本层只消费两个事实：`purchase_price.supplierId` 引用 `supplier.id`（唯一约束 + 按名称复用/合并）；进价录入时供应商可先留空，后端按名称唯一补默认「面价渠道」。

#### product 产品表（只存产品名）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键（应用层时间戳生成，格式见「产品ID 生成规则」） |
| name | String(200) | NOT NULL | 产品名称 |
| categoryId | Int | DEFAULT 0, FK → category.id | 分类ID（0=未分类） |
| remark | String(500) | DEFAULT '' | 备注（别名、俗称） |
| status | Int | DEFAULT 1 | 状态 1启用 0停用 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**约束**：`@@unique([categoryId, name])`
**v11.0 解耦**：`id` 应用层时间戳生成（`generateProductId()`，epochMs × 1_000_000 + 随机6位，19 位 BigInt，全局永久唯一，删除后不复用）；与 `document_lines` 无物理外键。

#### spec 规格变体表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| productId | BigInt | NOT NULL, FK → product.id, CASCADE | 所属产品 |
| specModel | String(200) | NOT NULL | 规格型号（dn25 / 25三层） |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**约束**：`@@unique([productId, specModel])`
**规则**：一个产品可有多个规格变体；品牌与单位均挂在规格下。

#### brand 品牌表（全局独立档案）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| name | String(100) | NOT NULL, UNIQUE | 品牌名称（全局唯一） |
| status | Int | DEFAULT 1 | 状态 1启用 0停用 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**规则**：不从属任何产品/规格，通过 `spec_brand` 关联到规格；改名全局生效；备注/排序在 spec_brand。

#### spec_brand 规格×品牌关联表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specId | BigInt | NOT NULL, FK → spec.id, CASCADE | 所属规格变体 |
| brandId | BigInt | NOT NULL, FK → brand.id, CASCADE | 全局品牌 ID |
| remark | String(500) | NOT NULL DEFAULT '' | 该规格下该品牌备注（执行标准/层数） |
| sortOrder | Int | NOT NULL DEFAULT 0 | 该规格下该品牌排序 |
| status | Int | NOT NULL DEFAULT 1 | 该规格下该品牌状态 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**约束**：`@@unique([specId, brandId])`
**规则**：SKU 最小定价单元 = 规格×品牌×单位；价格/图片/换算/宽表均挂本表维度（specBrandId）。

#### unit 单位表（挂规格）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specId | BigInt | NOT NULL, FK → spec.id, CASCADE | 所属规格变体 |
| unitName | String(50) | NOT NULL | 单位名称 |
| isBase | Boolean | NOT NULL DEFAULT false | 是否基础单位（同规格唯一） |
| isDisplay | Boolean | NOT NULL DEFAULT false | 是否默认显示单位（同规格唯一） |
| status | Int | DEFAULT 1 | 状态 |
| createdAt | DateTime | | 创建时间 |

**约束**：`@@unique([specId, unitName])`
**规则**：单位**不按品牌独立**——同一规格所有品牌共享同一套单位名列表。

#### brand_unit_conversion 品牌单位换算表（按规格×品牌独立）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specBrandId | BigInt | NOT NULL, FK → spec_brand.id, CASCADE | 规格×品牌关联ID |
| unitId | BigInt | NOT NULL, FK → unit.id, CASCADE | 单位ID |
| conversionRate | Decimal(10,4) | NOT NULL DEFAULT 1.0000 | 1 个该单位 = 多少基础单位 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**约束**：`@@unique([specBrandId, unitId])`

**规则**：
- 基础单位对应换算率强制 1.0000
- 闭环不变量：每个规格×品牌 × 其基准单位必有换算记录（×1）；保存时后端显式重建基准记录
- 「有就有，没有就没有」：品牌未配置换算率的单位不创建记录，列表据此隐藏
- 切换基准单位时全部换算率按新基准归一化
- 库存换算取当前规格×品牌 + 当前单位的 conversionRate

#### price_type 价格类型字典表（全局共享）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| name | String(50) | NOT NULL, UNIQUE | 价格类型名（零售价/批发价/工程价） |
| sortOrder | Int | DEFAULT 0 | 排序 |
| status | Int | DEFAULT 1 | 状态 |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

服务启动幂等预置三种默认类型。

#### sale_price 产品售价表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specBrandId | BigInt | NOT NULL, FK → spec_brand.id, CASCADE | 规格×品牌关联ID |
| unitId | BigInt | NOT NULL, FK → unit.id, CASCADE | 单位ID |
| priceTypeId | BigInt | NOT NULL, FK → price_type.id | 价格类型ID |
| price | Decimal(10,2) | NOT NULL | 售价 |
| isDefault | Boolean | NOT NULL DEFAULT false | 是否默认展示售价（同 SKU 唯一） |
| status | Int | DEFAULT 1 | 状态 |

**约束**：`@@unique([specBrandId, unitId, priceTypeId])`

#### purchase_price 产品进价表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specBrandId | BigInt | NOT NULL, FK → spec_brand.id, CASCADE | 规格×品牌关联ID |
| unitId | BigInt | NOT NULL, FK → unit.id, CASCADE | 单位ID |
| supplierId | BigInt | NOT NULL（业务可空，后端补全） | 供应商ID（v13.0 起业务允许先留空，后端补「面价渠道」） |
| supplierName | String(200)? | | 供应商名称快照（解耦冗余，写入时主动填充） |
| price | Decimal(10,2) | NOT NULL | **面价**（用户录入值；进价 = 面价 × 点位） |
| isDefault | Boolean | NOT NULL DEFAULT false | 是否默认展示进价 |
| status | Int | DEFAULT 1 | 状态 |

**约束**：`@@unique([specBrandId, unitId, supplierId])`

**定价语义**：`price` 存面价；进价 = 面价 × 点位（点位来自 `supplier_point_rule`，无规则默认 1）；点位变化永不重算面价，进价实时派生；成本/宽表/前端展示统一按「面价 × 点位」计算。

#### supplier_point_rule 供应商点位规则表

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| supplierId | BigInt | NOT NULL | 供应商ID（无物理外键） |
| supplierName | String(200)? | | 供应商名称快照 |
| brandName | String(100) | NOT NULL | 品牌名（粒度由人控制） |
| categoryName | String(100) | NOT NULL | 分类名（粒度由人控制） |
| point | Decimal(10,4) | NOT NULL | 点位（进价 = 面价 × 点位） |
| createdAt / updatedAt | DateTime | | 创建 / 更新时间 |

**约束**：`@@unique([supplierId, brandName, categoryName])`

#### product_image 产品图片表（挂规格×品牌）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| specBrandId | BigInt | NOT NULL, FK → spec_brand.id, CASCADE | 规格×品牌关联ID |
| imageUrl | String(500) | NOT NULL | 原图 URL（`{hash}_orig.webp`） |
| mediumUrl | String(500) | NOT NULL DEFAULT '' | 中图 URL（600x600，编辑弹窗用） |
| thumbnailUrl | String(500) | NOT NULL DEFAULT '' | 缩略图 URL（200x200，列表卡片用） |
| width / height / size | Int | NOT NULL DEFAULT 0 | 原图元数据 |
| hash | String(64) | NOT NULL DEFAULT '' | SHA-256 内容寻址（同 hash 物理文件仅一份） |
| sortOrder | Int | DEFAULT 0 | 排序 |
| isMain | Int | DEFAULT 0 | 是否主图（同规格×品牌唯一） |
| createdAt | DateTime | | 创建时间 |

**索引**：`@@index([specBrandId])` + `@@index([hash])`

**存储规范**：本地磁盘多版本 WebP（原图 1280 / 中图 600 / 缩略图 200）+ 内容寻址去重；物理文件引用计数感知清理（同 hash 仍被任一 product_image 引用时禁止删文件）；主图互斥由前端保证 + 后端 saveProduct 兜底。

#### product_sku_search 检索宽表（每「规格×品牌」一行）

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | BigInt | PK | 主键 |
| productId | BigInt | NOT NULL | 产品 ID |
| productName | String(200) | NOT NULL | 产品名称 |
| specId | BigInt | NOT NULL | 规格变体 ID |
| specModel | String(200) | NOT NULL | 规格型号 |
| categoryId / categoryName | BigInt / String(100) | | 分类冗余 |
| brandId / brandName | BigInt / String(100) | | 品牌冗余 |
| specBrandId | BigInt | NOT NULL, UNIQUE | 规格×品牌关联 ID（行主维度） |
| defaultUnitId / defaultUnitName | BigInt? / String(50)? | | 默认显示单位 |
| retailPrice | Decimal(10,2)? | | 默认单位默认售价 |
| purchasePriceDefault | Decimal(10,2)? | | 默认单位默认进价（= 面价 × 点位） |
| mainImageUrl / mainImageThumbUrl | String(500)? | | 主图（原图 / 缩略图） |
| remark | String(500) | DEFAULT '' | 规格×品牌备注冗余 |
| status | Int | DEFAULT 1 | 综合状态 = SPU启用 且 规格×品牌启用 |
| updateTime | DateTime | | 更新时间 |
| keywords | String(768) | | 全文检索字段 |

**索引**：`@@unique([specBrandId])` / `@@index([specId])` / FULLTEXT ngram（keywords）/ 复合索引（status+updateTime / categoryId+status+updateTime）

**keywords 生成**：`(productName + specModel + brandName + remark + categoryName)` 转小写拼接。
**默认单位取值**：`isDisplay=true` 的单位，无则取 `isBase=true`。
**宽表同步**：saveProduct 事务提交 / 品牌增删改 / 分类改名 / 单位 isBase/isDisplay 变更 / 售价进价增删改 / 主图变更 / 批量改价 / 停用启用 / 删除 → 重建对应宽表行。

### 产品ID 生成规则

- 格式：`epochMs × 1_000_000 + RND(6位)`（Snowflake 简化版，单进程最优）
- 2026 年约 `1.79×10^18` < BIGINT 上限 `9.22×10^18`（安全到约 2262 年）
- 全局永久唯一，删除后不复用；单毫秒冲突概率 1/1,000,000；主键约束兜底
- `schema` 保留 `@default(autoincrement())` 仅作 DB 兜底（子表 @relation 外键引用依赖 autoincrement 属性），应用层 `createProduct/saveProduct/quickCreateProduct` 显式覆盖

### 保存逻辑（saveProduct 事务）

```
1. 前置校验：单位 ≥1；有且仅有一个基础单位；分类有效性
2. 编辑模式：查询"被删除的品牌/单位"差集 → 手动清理宽表孤儿行 → 级联删除
3. product 建/改（应用层 generateProductId；新建/编辑均做 (categoryId,name) 唯一性预检 → 422 友好提示）
4. spec 建/改（规格变体：specId 传入则更新，否则新建；productId+specModel 唯一）
5. spec_brand 建/改（品牌按名称唯一复用/新建；含规格内品牌 remark）
6. unit 建/改（有且仅有一个 isBase、有且仅有一个 isDisplay）
7. brand_unit_conversion（删除旧换算 → 显式重建基准 ×1 → 按载荷重建非基准有效换算）
8. 售价/进价"先删后建"（客户端去重；isDefault 互斥；进价填充 supplierName 快照）
9. 事务提交 → 重建该产品全部宽表行
10. 图片文件差集清理（旧 URL − 本次仍引用 URL，且整库 0 引用才删物理文件）
```

前端校验：产品名称非空；至少一个单位 + 一个基准单位；已存在品牌名称为空时阻止保存；全品牌为空自动补「普通品牌」。

### 接口契约

> 员工端前缀 `/api/staff/...`（鉴权 + `product_manage` 视图权限）；公开端 `/api/...`（客户/未登录，自动剥离进价）。

| 接口 | 方法 | 用途 |
|------|------|------|
| `/products/search` | GET | 产品检索（keyword/categoryId/status/page/size），首条 creation_prompt |
| `/products/sku/options?specBrandId=` | GET | 该规格×品牌全部单位 + 售价/进价明细 + 换算率（公开端剥离进价） |
| `/products/suggest?field=&keyword=&productId=` | GET | 输入框快捷检索（product/specModel/brand/unit/category/priceType/supplier/remark） |
| `/products/save` | POST | 产品建档/编辑事务（唯一写入口） |
| `/products/quick-create` | POST | 快速建档（产品名+规格+单位，幂等） |
| `/products/:id?specId=` | GET | 产品详情（当前规格扁平化：品牌/单位/换算/价格/图片全量 + specs 列表） |
| `/products/:id/sibling-specs` | GET | 同产品名不同规格列表（规格快切） |
| `/products/:id/deactivate` / `/activate` | POST | 停用/启用（同步宽表综合状态） |
| `/products/:id/doc-refs` | GET | 单据引用计数（删除二次确认提示） |
| `/products` | DELETE | 物理删除整个产品（二次确认 + 引用计数） |
| `/purchase-prices/point-rule` | GET | 点位规则查询（旧点位自动带出） |
| `/purchase-prices/batch-preview` / `batch-adjust` | POST | 批量改价预览/确认（只更新点位规则） |
| `/product-images/library` | GET | 图片库（按 hash 去重 + 引用数） |
| `/product-images/upload` | POST | 上传图片（sharp 三版本 + hash） |
| `/product-images` | POST/PATCH/DELETE | 图片建档/设主图/删除（引用计数清理） |
| `/categories` | GET/POST/PATCH/DELETE | 分类管理（删除有产品引用时禁止） |
| `/brands` | GET/POST/PATCH/DELETE | 品牌全局档案管理（name 唯一；改名/停启用同步全部引用宽表） |
| `/brands/quick-add` | POST | 品牌快捷新建（仅 name，同名幂等复用；规格编辑弹窗「新建品牌」入口） |
| `/suppliers` | GET/POST/PATCH/DELETE | 供应商管理（独立档案 + 引用计数） |

**搜索返回行**（SKU 行）：`id / productId / productName / specId / specModel / specBrandId / categoryId / categoryName / brandId / brandName / remark / defaultUnitId / defaultUnitName / retailPrice / purchasePriceDefault / mainImageUrl / mainImageThumbUrl / status / updateTime`。

**SKU 选项返回**（每单位一项）：`unitId / unitName / isBase / isDisplay / conversions[] / salePrices[]（priceTypeId/priceTypeName/price/isDefault）/ defaultSalePrice / purchasePrices[]（supplierId/supplierName/price(面价)/point/effectivePrice/isDefault）/ defaultPurchasePrice / derivedSalePrice / derivedPurchasePrice`。

**派生价格（v1.5.6.3）**：`derivedSalePrice/derivedPurchasePrice` 由后端 `getSkuOptions` 统一计算（**不写库**）= 基准单位已录默认价 × 目标单位换算率，round2；仅当该单位未录默认价且基准单位已录时填充；消费端回退链：① 当前单位已录默认价 → ② 推算价 → ③ 宽表默认单位参考价；前端行内兜底与后端同口径（`calcDerivedUnitPrice` 纯函数，双端 SSOT）。

**批量改价（v12.0）**：进价 = 面价 × 点位；批量改价 = **只更新点位规则**（`supplier_point_rule`），面价永不重算，进价自动派生；定位同类 = `purchase_price JOIN spec_brand ON specBrandId`（品牌名匹配）+ `spec → product JOIN category`（分类名匹配）+ `supplierId` 过滤。

### 前端数据交互

- 列表：直接读宽表（一次查询，无需逐行二次请求）；单位/售价/进价下拉各行独立互不影响
- 单位列下拉：当前规格×品牌下所有单位及换算系数，支持新增/删除/设基准
- 售价/进价列下拉：当前单位下所有价格类型/供应商进价，支持设置默认
- 编辑弹窗：分类 | 产品名称 | 规格型号（主体区）+ 品牌切换区 + 单位区（当前品牌换算率）+ 售价/进价矩阵 + 图片区；`initialBrandId` 预选
- 保存走 `/products/save` 单一写入口
