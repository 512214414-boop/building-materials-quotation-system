>
> **设计动机**：供应商是跨功能的引用数据源——既被产品进价表（purchase_price）引用，又被单据体系的配货（allocation_lines）和成本核定（cost_lines）引用。后续还需关联出入库、采购统计，且供应商信息可能变更，必须独立维护。v11.0 解耦后，供应商档案删除不影响历史业务记录展示与统计。

## 设计哲学

供应商管理采用**最简档案模型**，与客户管理、产品管理同属基础数据层。供应商作为纯引用数据源，不产生自有的业务数据，仅提供档案信息供其他功能引用。管理界面采用最简表格行内编辑，无下钻子表、无编辑弹窗，所有字段直接在表格中维护。

**推导原则**：

- **最简字段集**：供应商名称 + 联系人 + 经营范围 + 地址 + 备注 + 状态，够用不冗余；
- **联系人 JSON 数组**：一个供应商可能有多个联系人，每条联系人含姓名、联系方式类型、联系方式值，灵活扩展；
- **快速新增**：仅需名称即可建档（`quickAddSupplier`），后续信息可在表格中就地补充；
- **停用/启用**：停用后不可作为新配货来源，但历史业务记录不受影响；
- **物理删除允许**：解耦后业务记录通过快照字段独立存在，供应商档案删除后仅丢失查阅入口。

## 功能概述

供应商管理用于维护所有上游供货渠道的档案信息。供应商档案是跨功能的引用数据源，被以下功能引用：

| 引用功能 | 引用表 | 引用字段 | 用途 |
|---------|--------|---------|------|
| 产品进价管理 | `purchase_price` | `supplierId` + `supplierName`(快照) | 标记进价对应的供应商 |
| 配货（外部调货） | `allocation_lines` | `source_id` + `sourceName`(快照) | 标记外部调货来源供应商 |
| 成本核定 | `cost_lines` | `source_id` + `sourceName`(快照) | 标记成本来源供应商（source_type=supplier） |

供应商档案与产品管理中的进价面板通过 `supplierId` 关联，供应商独立建档后，产品进价管理中通过带检索和快速新建的面板引用供应商。

## 表结构

### supplier 供应商档案表

> 数据库表名：`supplier`（Prisma 模型名 `supplier`，v9.0 重构，原 `suppliers` 表已废弃）

| 字段名 | 数据库类型 | 约束 | 说明 |
|--------|-----------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| name | varchar(200) | NOT NULL, **UNIQUE（v13.2）** | 供应商名称，唯一索引保证按名称复用/合并（杜绝重复建档） |
| contacts | JSON | 可空 | 联系信息数组，格式 `[{"name":"联系人","method":"微信/电话/邮箱","value":"具体值"}]` |
| businessScope | varchar(500) | 可空 | 经营业务范围 |
| address | varchar(500) | 可空 | 地址 |
| remark | Text | 可空 | 备注 |
| status | Int | DEFAULT 1 | 状态：1=启用，0=停用 |
| createdAt | DateTime | | 创建时间 |
| updatedAt | DateTime | | 更新时间 |

**索引**：`@@unique([name])`（v13.2 新增）+ `@@index([status])`

**v13.2 名称唯一约束**：
- `name` 建立数据库唯一索引，为「按名称唯一复用/合并」提供数据库级保证；
- 唯一索引迁移前需先检查存量数据重名（本项目现有数据无重名，已通过迁移文件落库）。

### contact_method 联系方式方式字典表（v1.7.1.5 新增）

> 数据库表名：`contact_method`（Prisma 模型名 `contact_method`，对齐 `price_type` 全局字典范式）

| 字段名 | 数据库类型 | 约束 | 说明 |
|--------|-----------|------|------|
| id | BigInt | PK, AUTO_INCREMENT | 主键 |
| name | varchar(50) | NOT NULL, UNIQUE | 方式名称（微信/电话/座机/邮箱/QQ…） |
| sortOrder | Int | DEFAULT 0 | 排序 |
| status | Int | DEFAULT 1 | 状态：1=启用，0=禁用 |
| createdAt | DateTime | | 创建时间 |
| updatedAt | DateTime | | 更新时间 |

**说明**：
- 全局共享一套方式字典，供应商联系信息 `contacts[].method` 使用本字典的值；
- 可自由维护（自由输入新增 + 已有值点选），不靠代码级改动加值；
- 已使用的方式作为字符串保留在 `contacts` JSON 中，删除字典项不影响历史数据。

**v11.0 解耦说明**：
- 移除所有业务交易表的反向关联（`purchase_price` / `allocation_lines` / `cost_lines` 的 `@relation` 物理外键）；
- 业务记录通过 `supplierId` / `source_id` BigInt 字段留存 ID，通过 `supplierName` / `sourceName` 快照字段留存名称；
- 供应商档案物理删除后，业务记录仍可正常展示和统计，仅丢失档案查阅入口。

### 3. 创建供应商 `POST /staff/suppliers`

**请求体**：

```json
{
  "name": "供应商A",
  "contacts": [
    { "name": "张三", "method": "电话", "value": "13800000001" }
  ],
  "businessScope": "PPR管材管件",
  "address": "广东省佛山市",
  "remark": "长期合作"
}
```

**参数校验（v13.2 名称可空）**：
- `name`：**可选（v13.2）**，1-200 字符；**为空时后端补系统默认「面价渠道」**（业务必填宽松，见 [数据规范·按名称唯一复用](../架构原则/数据规范.md#按名称唯一复用)）
- `contacts`：可选，数组，每项含 name/method/value 三个字符串字段
- `businessScope`：可选，最大 500 字符
- `address`：可选，最大 500 字符
- `remark`：可选，任意文本

**行为（v13.2 按名称唯一复用/合并）**：
1. 名称有值 → 按名称查 supplier 表：
   - 命中已存在 → **复用该记录**，本次携带的档案字段（contacts/businessScope/address/remark）**仅覆盖本次提供的字段**，未提供不清空；`status` 不覆盖；
   - 未命中 → 连同档案字段新建，`status=1`（启用）；
2. 名称为空 → 补「面价渠道」默认值后走上述复用/新建流程；
3. 并发同名创建触发唯一约束（P2002）→ 回查复用，竞态兜底；
4. 写入审计日志（`supplier_create`）。
5. 返回完整供应商对象（无论复用或新建，返回 id 均为最终命中的记录）。

> 前端弹窗仍可业务性校验名称（渐进式录入提示），但**不再强制必填**：仅当整表单全空时拦截（无任何信息可保存），其余情况均可提交由后端补全。

### 4. 快速新增 `POST /staff/suppliers/quick-add`

**请求体**：

```json
{
  "name": "供应商B"
}
```

**参数校验**：`name` 必填，1-200 字符。

**行为**：
- 同名幂等：若已存在同名供应商，直接返回已有记录；
- 否则创建新记录，自动设置 `status=1`、`remark='待完善'`；
- **并发同名创建触发唯一约束（P2002）→ 回查复用，竞态兜底（v13.2）**；
- 写入审计日志（`supplier_quick_add`）。

**使用场景**：产品进价管理面板中快速新建供应商、订单协同工作台配货视图快速补录供应商。

### 5. 更新供应商 `PATCH /staff/suppliers/:id`

**路径参数**：`id` - 供应商 ID

**请求体**（所有字段可选）：

```json
{
  "name": "供应商A（新名）",
  "contacts": [
    { "name": "张三", "method": "电话", "value": "13800000002" }
  ],
  "businessScope": "PPR管材管件、PVC管材",
  "address": "广东省佛山市顺德区",
  "remark": "长期合作，月结",
  "status": 1
}
```

**校验**：
- `status`：可选，必须为 0 或 1
- 其他字段校验同创建接口（`name` 可选）

**行为**：部分更新（`partial`），仅更新传入的字段，写入审计日志（`supplier_update`）。
**v13.2 改名冲突**：显式将 `name` 改为已存在的名称时，触发唯一约束（P2002）→ 友好报错「供应商名称「XXX」已存在」，不走系统合并（显式编辑属真实冲突）。

### 6. 设置状态 `POST /staff/suppliers/:id/status`

**路径参数**：`id` - 供应商 ID

**请求体**：

```json
{
  "status": 0
}
```

**校验**：`status` 必填，必须为 0（停用）或 1（启用）。

**行为**：
- 停用（status=0）：该供应商不可作为新配货来源（`allocationService` 校验 `status=1`），已存在的业务记录不受影响；
- 启用（status=1）：重新进入检索结果，可正常引用。

### 7. 查询引用计数 `GET /staff/suppliers/:id/ref-counts`

**路径参数**：`id` - 供应商 ID

**返回结构**：

```json
{
  "supplierId": "1",
  "purchasePriceCount": 15,
  "allocationCount": 8,
  "costCount": 5,
  "totalRefs": 28
}
```

**说明**：
- `purchasePriceCount`：该供应商的进价记录数（`purchase_price` 表）
- `allocationCount`：该供应商的配货行数（`allocation_lines` 表，`source_id` 匹配）
- `costCount`：该供应商的成本核定行数（`cost_lines` 表，`source_id` 匹配）
- `totalRefs`：三项合计

**使用场景**：前端删除按钮点击后，先调用此接口获取引用计数，在二次确认弹窗中显示影响范围。

### 8. 删除供应商 `DELETE /staff/suppliers/:id`

**路径参数**：`id` - 供应商 ID

**返回结构**：

```json
{
  "supplierId": "1",
  "supplierName": "供应商A",
  "deletedRefCounts": {
    "purchasePriceCount": 15,
    "allocationCount": 8,
    "costCount": 5,
    "totalRefs": 28
  }
}
```

**行为**：
- 物理删除（允许被引用）；
- 删除前收集引用计数，返回给前端展示审计信息；
- 解耦后业务记录通过 `supplierName` / `sourceName` 快照字段独立存在，档案删除不影响业务展示；
- 写入审计日志（`supplier_delete`）。

**权限**：`supplier_manage` rw

**行为**：删除字典项，写入审计日志（`contact_method_delete`）。已使用的方式作为字符串保留在 `supplier.contacts` JSON 中，不受影响。

### 13. 方式输入框检索 `GET /staff/products/suggest?field=contactMethod`

**权限**：`supplier_manage` ro（走 suggest 统一接口）

**说明**：联系信息「方式」列通过 `DictFieldInput`（输入框检索 + 快速新建 + ▾ 字典管理面板）承载，检索从 `contact_method` 字典表匹配，快速新建走 `createContactMethod` 标准接口——同一字典配置参数注入差异，禁止各功能各自接线字典 API。

## 保存逻辑

### 创建流程

```
1. 前端校验：整表单非全空即可（名称可空，v13.2 业务必填宽松）
2. 调用 POST /staff/suppliers
3. 后端校验：name 可选 1-200 字符（空 → 补默认「面价渠道」），contacts 数组格式校验，
   businessScope/address 最大 500 字符
4. 按名称唯一复用/合并（业务补全层 businessDefaults）：
   - 名称空 → 补「面价渠道」；名称有值 → 直接查
   - 命中已存在 → 复用该记录 + 仅覆盖本次提供的档案字段（未提供不清空）
   - 未命中 → 连同档案字段新建（status=1）
   - 并发同名（P2002）→ 回查复用
5. 写入审计日志（supplier_create）
6. 返回完整供应商对象
```

### 快速新增流程

```
1. 前端校验：name 不能为空，1-200 字符
2. 调用 POST /staff/suppliers/quick-add
3. 后端查询同名供应商
   - 存在 → 直接返回已有记录（幂等）
   - 不存在 → 创建新记录（status=1, remark='待完善'）
   - 并发同名创建（P2002）→ 回查复用，竞态兜底
4. 写入审计日志（supplier_quick_add）
5. 返回供应商对象
```

### 编辑流程

```
1. 前端：表格行内编辑，修改任意字段后失焦即保存
2. 调用 PATCH /staff/suppliers/:id
3. 后端校验：status 若传入必须为 0 或 1
4. 部分更新（仅更新传入的字段）
5. 改名撞已存在名称 → 唯一约束（P2002）→ 报错「供应商名称「XXX」已存在」（v13.2）
6. 写入审计日志（supplier_update）
7. 返回更新后的供应商对象
```

### 停用/启用流程

```
1. 前端点击操作列「停用/启用」按钮
2. 停用：一次确认弹窗 → 调用 POST /staff/suppliers/:id/status { status: 0 }
3. 启用：无需确认 → 调用 POST /staff/suppliers/:id/status { status: 1 }
4. 后端校验 status 必须为 0 或 1
5. 更新 supplier.status
6. 返回更新后的供应商对象
```

### 删除流程

```
1. 前端点击操作列「删除」按钮
2. 调用 GET /staff/suppliers/:id/ref-counts 获取引用计数
3. 弹出二次确认弹窗：
   - 第一次：「确认删除供应商「XXX」？该操作将物理删除档案数据。」
   - 若 totalRefs > 0，追加提示：「该供应商已被 N 条业务记录引用（进价X条、配货X条、成本X条），删除后历史业务记录不受影响，但供应商档案将无法查阅。」
   - 第二次：「再次确认删除？此操作不可撤销。」
4. 两次确认后调用 DELETE /staff/suppliers/:id
5. 后端物理删除 supplier 记录
6. 写入审计日志（supplier_delete）
7. 返回删除结果（含引用计数，用于前端审计展示）
8. 前端从列表中移除该行
```

- **联系信息列（多记录字段矩阵面板）**：一列显示一条完整记录（默认联系人）+ ▾ 展开**矩阵面板**（表头行 + 数据行含默认星标/删除 + 末尾常驻空行直接输入自动追加），对齐售价/进价面板结构；
- **无分页跳转**：使用标准分页器，支持调整每页条数。

### 联系信息默认联系人规则（多记录字段统一模型）

- 每条联系人可有 `isDefault` 标记（至多一条）；

- **默认值写入数据表（后端规范化）**：无论用户是否指定，保存时后端将默认标记写入数据表——数据表永远有明确默认联系人，点开面板默认已选中，不会出现"无默认"状态；

## 交互细节

### 范式归属

供应商管理属于 **范式 A（主表行内编辑 + 名称字段触发集合弹窗）**（v1.7.1.3 起）：

- 单文本字段（主营业务/地址/备注）**单元格点击直接编辑、失焦即存**——基础数据管理页看到即能点、点即编辑，禁止只读+弹窗双轨；
- **名称字段（主标识）点击 → 触发集合弹窗**（编辑弹窗 = 完整编辑面板）——通用稳定规则，每个表一致；
- 无下钻子表（无范式 C）；
- 联系信息是多记录字段（JSON 数组），单元格显示默认联系人完整记录 + ▾ 展开**矩阵面板**（对齐售价/进价面板）；
- 符合表格设计中心思想：操作列首列 fixed:left、行内直接编辑、名称字段主标识（详见 [表格与交互规范](../架构原则/表格与交互规范.md)）。

### 行内编辑交互

- 主营业务/地址/备注：点击单元格 → 显示输入框，失焦 / Enter / Tab 即保存（改即生效），Esc 放弃；
- 保存失败显示错误提示并回滚（重新拉取列表）。

### 名称字段（主标识）交互

- 供应商名称列以品牌色下划线链接显示，点击 → 打开编辑弹窗（集合弹窗，含全部字段）；
- 引用/检索默认匹配名称字段（可组合匹配：名称/主营业务/备注）。

### 联系信息列交互（多记录字段矩阵面板）

联系信息列遵循「一列一条完整记录 + 下拉箭头展开全部 + 矩阵面板」习惯（对齐售价/进价面板，详见 [表格与交互规范·AI 工程范式](../架构原则/表格与交互规范.md#第三步多记录字段对齐矩阵面板)）：

```
单元格（可编辑）：[王小二·微信·gshhbdnd ▾]   ← 显示的就是默认联系人（无额外图标）
点击 ▾ 展开矩阵面板：
┌─ 默认 │ 联系人 │ 方式 │ 联系方式 │ 操作 ─────────┐
│  ★   │ 王小二  │微信│ gshhbdnd        │ ×    │  ← 数据行：全部可直接编辑，★ = 已选中默认
│      │ 李大翠  │电话│ 15364768585     │ ×    │  ← 行级操作：默认星标 / 删除
│      │         │    │ 输入后自动追加   │      │  ← 末尾常驻空行：直接输入自动追加
│              [+ 添加联系人]                    │
└──────────────────────────────────────────────┘
```

- 一列只显示**一条完整记录**（默认联系人），禁止多条拼接、禁止省略号摘要；
- 必带下拉箭头（语义 = 还有更多记录可展开）；
- **矩阵面板结构**：表头行 + 数据行（默认星标 + 联系人 + 方式 + 值 + 删除，每行全部可直接编辑）+ **末尾常驻空行**（输入有效值自动追加新行，Enter/失焦；无效输入清空空行保留）+ 常驻新增按钮——完全不阻塞，想输多少输多少；
- 默认标记：星标指定默认（isDefault，至多一条）；用户未指定 → 全局规则取第一条；
- 面板关闭时统一保存（dirty 落库），无需额外确认按钮。

## 与其他功能的关联

### 1. 产品进价管理（purchase_price）

供应商是产品进价的要素之一（v14.0：规格×品牌 + 单位 + 供应商 = 唯一进价记录）。

**关联方式**：
- `purchase_price.specBrandId`（v14.0：规格×品牌关联 ID）存储进价所属 SKU 维度；
- `purchase_price.supplierId` 存储供应商 ID（BigInt），用于聚合统计；
- `purchase_price.supplierName` 存储供应商名称快照（varchar(200)），用于展示。

**影响**：
- 供应商删除后，`purchase_price` 记录的 `supplierName` 快照字段仍保留供应商名称，进价列表正常展示；
- 进价统计基于 `supplierId` 字段聚合，供应商删除后仍可统计历史进价数据；
- 产品进价管理面板中，供应商选择器通过 `quickAddSupplier` 快速新增供应商。

**详情参见**：[产品管理.md](./产品管理.md) 中「售价 / 进价明细面板」章节与 [数据库新设计·产品数据层.md](./数据库新设计·产品数据层.md)。

### 2. 配货来源引用（allocation_lines）

配货视图中的外部调货（source_type=external）引用供应商作为配货来源。

**关联方式**：
- `allocation_lines.source_id` 存储供应商 ID（BigInt），用于统计；
- `allocation_lines.sourceName` 存储供应商名称快照（varchar(200)），用于展示。

**影响**：
- 供应商停用（status=0）后，`allocationService` 校验 `status=1`，不可作为新配货来源；
- 已存在的配货记录不受影响（使用快照字段展示）；
- 供应商删除后，配货记录的 `sourceName` 快照字段仍保留供应商名称，配货视图正常展示。

### 3. 成本核定引用（cost_lines）

成本核定视图中，成本来源为供应商（channel_type=supplier）时引用供应商档案。

**关联方式**：
- `cost_lines.source_id` 存储供应商 ID（BigInt），用于统计；
- `cost_lines.sourceName` 存储供应商名称快照（varchar(200)），用于展示。

**影响**：
- 供应商删除后，成本核定记录的 `sourceName` 快照字段仍保留供应商名称，成本核定视图正常展示；
- 成本统计基于 `source_id` 字段聚合，供应商删除后仍可统计历史成本数据。

### 4. 输入框快捷辅助录入（SuggestInput）

供应商名称字段通过 `SuggestInput` 组件实现边输入边检索 + 快速新建。

**规则归属**（通用判定规则见 [表格与交互规范·输入辅助](../架构原则/表格与交互规范.md)）：
- ① 关联字段（值来自关联表 `supplier`）→ ✅
- ② 独立建档（`supplier` 表独立存在）→ ✅
- ③ 单字段建档（仅需 name）→ ✅
- → 启用快速新建（`quickAddSupplier`）

**检索接口**：`GET /api/staff/products/suggest?field=supplier&keyword=xxx`

**返回结构**：
```json
{
  "options": [
    { "type": "create", "label": "新建「供应商A」", "value": "供应商A" },
    { "type": "existing", "label": "供应商A（已存在）", "value": "供应商A", "id": "1" }
  ]
}
```
