## 功能概述

供应商管理维护所有上游供货渠道的档案信息。供应商是跨功能的引用数据源，被以下功能引用：

| 引用功能 | 引用表 | 引用字段 | 用途 |
|---------|--------|---------|------|
| 产品进价管理 | `purchase_price` | `supplierId` + `supplierName`(快照) | 标记进价对应的供应商 |
| 配货（外部调货） | `allocation_lines` | `source_id` + `sourceName`(快照) | 标记外部调货来源供应商 |
| 成本核定 | `cost_lines` | `source_id` + `sourceName`(快照) | 标记成本来源供应商（source_type=supplier） |

设计原则：

- **最简字段集**：供应商名称 + 联系人 + 经营范围 + 地址 + 备注 + 状态，够用不冗余；
- **联系人 JSON 数组**：一个供应商可能有多个联系人，每条联系人含姓名、联系方式类型、联系方式值，灵活扩展；
- **快速新增**：仅需名称即可建档（`quickAddSupplier`），后续信息可在表格中就地补充；
- **停用/启用**：停用后不可作为新配货来源，但历史业务记录不受影响；
- **物理删除允许**：解耦后业务记录通过快照字段独立存在，供应商档案删除后仅丢失查阅入口。

供应商独立建档后，产品进价管理中通过带检索和快速新建的面板引用供应商（交互见《产品管理》）。**选用检索**（进货入库等取一家供应商）：顶栏由供应商树派生（见《档案管理·选用检索》）。点行回填一家。开单选品顶栏「渠道」档问的是这货谁可能供：已进价 ∪ 经营范围，好打电话；不是把供应商档案名当产品名搜。其余启用供应商不要灌进选品（那是进价面板「查看可能渠道」的第三档）。现场意图见 `文档可视化/` 指导思想 · 销售开单 / 供应商管理 · 出发点。

## 表结构

### supplier 供应商档案表（职责：上游供货渠道档案，被进价/配货/成本跨功能引用）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|----------|--------|------|
| id | BigInt PK | 1 | 主键 |
| name | VarChar(200) NOT NULL **@@unique** | 伟星管道 | 供应商名称，**全局唯一**（为「按名称唯一复用/合并」提供数据库保证，杜绝重复建档） |
| contacts | Json? | `[{"name":"张三","method":"电话","value":"13800000001"}]` | 联系信息数组（结构见下） |
| businessScope | VarChar(500)? | PPR管材管件 | 经营业务范围 |
| address | VarChar(500)? | 广东省佛山市 | 地址 |
| remark | Text? | 长期合作，月结 | 备注 |
| status | Int DEFAULT 1 | 1 | 状态：1=启用，0=停用 |
| createdAt / updatedAt | DateTime | — | 创建 / 更新时间 |

**索引**：`@@unique([name])`、`@@index([status])`

**关联**：无物理外键，全域解耦规范详见《数据规范·解耦三原则》；业务表 `purchase_price`/`allocation_lines`/`cost_lines` 仅留 `supplierId`/`source_id` BigInt + 索引 + 名称快照，删除后业务记录仍可展示与统计。

### contact_method 联系方式字典表（职责：供应商联系方式方式值的全局共享字典，对齐 price_type 全局字典范式）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|----------|--------|------|
| id | BigInt PK | 1 | 主键 |
| name | VarChar(50) NOT NULL @@unique | 微信 | 方式名称（微信/电话/邮箱/QQ…），全局唯一 |
| sortOrder | Int DEFAULT 0 | 0 | 排序 |
| status | Int DEFAULT 1 | 1 | 状态：1=启用，0=禁用 |
| createdAt / updatedAt | DateTime | — | 创建 / 更新时间 |

**说明**：
- 全局共享一套方式字典，供应商联系信息 `contacts[].method` 使用本字典的值；
- 方式值自由维护（输入新增 + 点选），由字典承载、不靠代码改动加值（详见《表格与交互规范·枚举字段》）；
- 已使用的方式作为字符串保留在 `contacts` JSON 中，删除字典项不影响历史数据。

### supplier_point_rule 供应商点位规则表（职责：记录「供应商 + 品牌名 + 分类名 → 点位」，批量改价只更新本表）

| 字段 | 类型/约束 | 示例值 | 说明 |
|------|----------|--------|------|
| id | BigInt PK | 1 | 主键 |
| supplierId | BigInt 逻辑关联 | 1(伟星管道) →supplier.id | 供应商 ID（解耦：无物理外键，仅逻辑关联 + 索引） |
| supplierName | VarChar(200)? | 伟星管道 | 供应商名称快照（来自 supplier.name） |
| brandName | VarChar(100) | 伟星 | 品牌名（粒度由人控制：同品牌不同系列点位不同则名录细，如「伟星瓷芯」） |
| categoryName | VarChar(100) | 给水管 | 分类名（粒度由人控制：管材/管件点位不同则名录细） |
| point | Decimal(10,4) | 0.5800 | 点位（如 0.58 = 面价×58%） |
| createdAt / updatedAt | DateTime | — | 创建 / 更新时间 |

**索引**：`@@unique([supplierId, brandName, categoryName])`（同一 供应商+品牌名+分类名 只有一条点位规则）、`@@index([supplierId])`、`@@index([brandName])`

### contacts 字段 JSON 结构

```json
[
  {
    "name": "张三",
    "method": "电话",
    "value": "13800000001"
  },
  {
    "name": "李四",
    "method": "微信",
    "value": "lisi_wx"
  }

```

前端类型定义（`SupplierContact`）：

```typescript
export interface SupplierContact {
  name: string;      // 联系人姓名
  method: string;    // 联系方式类型（微信/电话/邮箱/...）

}
```

## 点位规则

- **定价语义**：`purchase_price.price` 存**面价**（用户录入值，点位变化永不重算）；**进价 = 面价 × 点位**（点位：规格上那一条 → 圈组 `supplier_point_rule` → 1）；面价录入入口在进价明细面板（见《产品管理》）。
- **改全局只更新圈组点位**：按「供应商 + 品牌名 + 分类名」这一批，只更新 `supplier_point_rule`，面价不重算，已经单独改过的规格不跟着变，进价随新点位自动派生。
- **调整成功后自动写入/更新该圈组**：下次旧点位自动带出，只需输新点位。
- 前端/后端有效进价计算统一走 `calcEffectivePrice`（单一实现 SSOT，见《产品数据层》）。

### 创建供应商 POST /staff/suppliers

**请求体**：

```json
{
  "name": "供应商A",
  "contacts": [
    { "name": "张三", "method": "电话", "value": "13800000001" }
  ],
  "businessScope": "PPR管材管件",
  "address": "广东省佛山市",
  "remark": "长期合作"
}
```

**参数校验**：
- `name`：**可选**，1-200 字符；为空时后端补系统默认「面价渠道」（业务必填宽松，机制见 [数据规范·按名称唯一复用](../架构原则/数据规范.md)）
- `contacts`：可选，数组，每项含 name/method/value 三个字符串字段
- `businessScope`：可选，最大 500 字符
- `address`：可选，最大 500 字符
- `remark`：可选，任意文本

**行为（按名称唯一复用/合并）**：
1. 名称有值 → 按名称查 supplier 表：
   - 命中已存在 → **复用该记录**，本次携带的档案字段（contacts/businessScope/address/remark）**仅覆盖本次提供的字段**，未提供不清空；`status` 不覆盖；
   - 未命中 → 连同档案字段新建，`status=1`（启用）；
2. 名称为空 → 补「面价渠道」默认值后走上述复用/新建流程；
3. 并发同名创建触发唯一约束（P2002）→ 回查复用，竞态兜底；
4. 写入审计日志（`supplier_create`）；
5. 返回完整供应商对象（无论复用或新建，返回 id 均为最终命中的记录）。

> 前端弹窗仍可业务性校验名称（渐进式录入提示），但**不再强制必填**：仅当整表单全空时拦截（无任何信息可保存），其余情况均可提交由后端补全。

### 快速新增 POST /staff/suppliers/quick-add

**请求体**：

```json
{
  "name": "供应商B"
}
```

**参数校验**：`name` 必填，1-200 字符。

**行为**：
- 同名幂等：若已存在同名供应商，直接返回已有记录；
- 否则创建新记录，自动设置 `status=1`、`remark='待完善'`；
- 并发同名创建触发唯一约束（P2002）→ 回查复用，竞态兜底；
- 写入审计日志（`supplier_quick_add`）。

**使用场景**：产品进价管理面板中快速新建供应商、订单协同工作台配货视图快速补录供应商。

### 更新供应商 PATCH /staff/suppliers/:id

**路径参数**：`id` - 供应商 ID

**请求体**（所有字段可选）：

```json
{
  "name": "供应商A（新名）",
  "contacts": [
    { "name": "张三", "method": "电话", "value": "13800000002" }
  ],
  "businessScope": "PPR管材管件、PVC管材",
  "address": "广东省佛山市顺德区",
  "remark": "长期合作，月结",
  "status": 1
}
```

**校验**：
- `status`：可选，必须为 0 或 1
- 其他字段校验同创建接口（`name` 可选）

**行为**：部分更新（`partial`），仅更新传入的字段，写入审计日志（`supplier_update`）。
**改名冲突**：显式将 `name` 改为已存在的名称时，触发唯一约束（P2002）→ 友好报错「供应商名称「XXX」已存在」，不走系统合并（显式编辑属真实冲突）。

### 设置状态 POST /staff/suppliers/:id/status

**路径参数**：`id` - 供应商 ID

**请求体**：

```json
{
  "status": 0
}
```

**校验**：`status` 必填，必须为 0（停用）或 1（启用）。

**行为**：
- 停用（status=0）：该供应商不可作为新配货来源（`allocationService` 校验 `status=1`），已存在的业务记录不受影响；
- 启用（status=1）：重新进入检索结果，可正常引用。

### 查询引用计数 GET /staff/suppliers/:id/ref-counts

**路径参数**：`id` - 供应商 ID

**返回结构**：

```json
{
  "supplierId": "1",
  "purchasePriceCount": 15,
  "allocationCount": 8,
  "costCount": 5,
  "totalRefs": 28
}
```

**说明**：
- `purchasePriceCount`：该供应商的进价记录数（`purchase_price` 表）
- `allocationCount`：该供应商的配货行数（`allocation_lines` 表，`source_id` 匹配）
- `costCount`：该供应商的成本核定行数（`cost_lines` 表，`source_id` 匹配）
- `totalRefs`：三项合计

**使用场景**：前端删除按钮点击后，先调用此接口获取引用计数，在二次确认弹窗中显示影响范围。

### 删除供应商 DELETE /staff/suppliers/:id

**路径参数**：`id` - 供应商 ID

**返回结构**：

```json
{
  "supplierId": "1",
  "supplierName": "供应商A",
  "deletedRefCounts": {
    "purchasePriceCount": 15,
    "allocationCount": 8,
    "costCount": 5,
    "totalRefs": 28
  }
}
```

**行为**：
- 物理删除（允许被引用）；
- 删除前收集引用计数，返回给前端展示审计信息；
- 档案删除不影响业务展示（解耦设计保证，详见《数据规范·解耦三原则》）；
- 写入审计日志（`supplier_delete`）。

### 联系方式方式字典

- **列表 `GET /staff/contact-methods`**（权限 supplier_manage ro）：返回数组按 sortOrder 升序，如 `[{ "id": "1", "name": "微信", "sortOrder": 0, "status": 1 }]`；
- **新增 `POST /staff/contact-methods`**（supplier_manage rw）：请求体 `{ "name": "QQ" }`；`name` 必填 1-50 字符，全局唯一（重复返回「方式「QQ」已存在」）；创建后 sortOrder 默认 0、status 默认 1，写入审计日志（`contact_method_create`）；
- **修改 `PATCH /staff/contact-methods/:id`**（supplier_manage rw）：可选字段 `name` / `sortOrder` / `status`；`name` 唯一（改名不得与既有项冲突）；部分更新，写入审计日志（`contact_method_update`）；
- **删除 `DELETE /staff/contact-methods/:id`**（supplier_manage rw）：删除字典项，写入审计日志（`contact_method_delete`）；已使用的方式作为字符串保留在 `supplier.contacts` JSON 中，不受影响。

### 方式输入框检索 GET /staff/products/suggest?field=contactMethod

联系信息「方式」列通过 `DictRefField`（C61 完整组件：输入匹配引用 + 快速新建 + ▾ 字典管理面板）承载，检索从 `contact_method` 字典表匹配，新增/改名/删除统一收敛在 recordDicts 的 `contactMethodDict` 配置（复用 `createContactMethod` / `updateContactMethod` / `deleteContactMethod` 标准接口）——同一字典配置参数注入差异，禁止各功能各自接线字典 API。

## 保存逻辑

### 创建流程（按名称唯一复用/合并）

```
1. 前端校验：整表单非全空即可（名称可空，业务必填宽松）
2. 调用 POST /staff/suppliers
3. 后端校验：name 可选 1-200 字符（空 → 补默认「面价渠道」），contacts 数组格式校验，
   businessScope/address 最大 500 字符
4. 按名称唯一复用/合并（业务补全层 businessDefaults）：
   - 名称空 → 补「面价渠道」；名称有值 → 直接查
   - 命中已存在 → 复用该记录 + 仅覆盖本次提供的档案字段（未提供不清空）
   - 未命中 → 连同档案字段新建（status=1）
   - 并发同名（P2002）→ 回查复用
5. 写入审计日志（supplier_create）
6. 返回完整供应商对象
```

### 快速新增流程

```
1. 前端校验：name 不能为空，1-200 字符
2. 调用 POST /staff/suppliers/quick-add
3. 后端查询同名供应商
   - 存在 → 直接返回已有记录（幂等）
   - 不存在 → 创建新记录（status=1, remark='待完善'）
   - 并发同名创建（P2002）→ 回查复用，竞态兜底
4. 写入审计日志（supplier_quick_add）
5. 返回供应商对象
```

### 编辑流程

```
1. 前端：表格行内编辑，修改任意字段后失焦即保存
2. 调用 PATCH /staff/suppliers/:id
3. 后端校验：status 若传入必须为 0 或 1
4. 部分更新（仅更新传入的字段）
5. 改名撞已存在名称 → 唯一约束（P2002）→ 报错「供应商名称「XXX」已存在」
6. 写入审计日志（supplier_update）
7. 返回更新后的供应商对象
```

### 停用/启用流程

```
1. 前端点击操作列「停用/启用」按钮
2. 停用：一次确认弹窗 → 调用 POST /staff/suppliers/:id/status { status: 0 }
3. 启用：无需确认 → 调用 POST /staff/suppliers/:id/status { status: 1 }
4. 后端校验 status 必须为 0 或 1
5. 更新 supplier.status
6. 返回更新后的供应商对象
```

### 删除流程

```
1. 前端点击操作列「删除」按钮
2. 调用 GET /staff/suppliers/:id/ref-counts 获取引用计数
3. 弹出二次确认弹窗：
   - 第一次：「确认删除供应商「XXX」？该操作将物理删除档案数据。」
   - 若 totalRefs > 0，追加提示：「该供应商已被 N 条业务记录引用（进价X条、配货X条、成本X条），删除后历史业务记录不受影响，但供应商档案将无法查阅。」
   - 第二次：「再次确认删除？此操作不可撤销。」
4. 两次确认后调用 DELETE /staff/suppliers/:id
5. 后端物理删除 supplier 记录
6. 写入审计日志（supplier_delete）
7. 返回删除结果（含引用计数，用于前端审计展示）
8. 前端从列表中移除该行
```

### 页面结构说明

- **检索条（档案框架 filters 槽）**：左侧防抖关键词（名称/备注）+ 表头升上来的条件词；右侧状态下拉。新建在工具栏。禁止查询按钮、禁止检索条 SuggestInput。
- **表头列筛**：供应商名称、经营范围各一列 HeaderCascadeFilter（placeholder=列名；经营范围 facet 合并分类+品牌）。条件 chip 也叫「经营范围」。
- **经营范围列**：已选 chip + 检索▾；双栏勾选只在 FloatPanel 里展开，不常驻占弹窗高度。
- **操作列（首列 ☰ 更多菜单）**：低频操作收敛到 ☰ 菜单（编辑 / 停用·启用 / 物理删除）——操作必须在前面，字段多或手机端无需翻到最后；
- **字段列**：主营业务/公司地址/备注单元格点击直接输入、失焦即存（范式 A 行内编辑），禁止只读+弹窗双轨；
- **名称列（主标识）**：点击触发集合弹窗（编辑弹窗 = 完整编辑面板，含全部字段），通用稳定规则（详见 [表格与交互规范·AI 工程范式](../架构原则/表格与交互规范.md)）；
- **联系信息列（多记录字段矩阵面板）**：一列显示一条完整记录（默认联系人）+ ▾ 展开**矩阵面板**（表头行 + 数据行含默认星标/删除 + 末尾常驻空行直接输入自动追加），对齐售价/进价面板结构；
- **无分页跳转**：使用标准分页器，支持调整每页条数。

### 表格列定义

| 列名 | 字段 | 宽度(minWidth) | 编辑模式 | 说明 |
|------|------|---------------|---------|------|
| 操作（更多菜单 ☰） | -- | 自动（首列 fixed:left） | 只读 | 菜单项：编辑 / 停用·启用 / 物理删除 |
| 名称（主标识） | `name` | 180 | 点击触发集合弹窗 | 点击打开编辑弹窗（完整编辑面板）；引用/检索默认匹配名称字段 |
| 联系信息 | `contacts` | 200 | 矩阵面板（多记录字段） | 一列一条完整记录（默认联系人）+ ▾ 展开矩阵面板；关闭面板即保存 |
| 经营范围 | 分类+品牌子表 | NAME_L（封顶换行） | ▾ 浮层 | 格子与浮层已选同一套 chip（不分组）；项再多往下折 |
| 地址 | `address` | 180 | 行内编辑（text） | 点击直接改，失焦即存。无值显示「—」 |
| 备注 | `remark` | 120 | 行内编辑（text） | 点击直接改，失焦即存。无值显示「—」 |
| 状态 | `status` | 80 | 只读展示 | 启用（绿色）/ 停用（橙色），切换走首列 ☰ 菜单 |

### 更多菜单（首列 ☰）

| 菜单项 | 显示条件 | 行为 |
|------|---------|------|
| 编辑 | 始终显示 | 打开编辑弹窗（整段编辑全部字段的补充入口） |
| 停用（⏻） | status=1（启用） | 一次确认后调用 `setSupplierStatus(id, 0)` |
| 启用（⏻） | status=0（停用） | 无需确认直接调用 `setSupplierStatus(id, 1)` |
| 物理删除 | 始终显示（danger 置底） | 先调用 `getSupplierRefCounts(id)` 获取引用计数，两次确认后调用 `deleteSupplier(id)` |

### 联系信息默认联系人规则

- 每条联系人可有 `isDefault` 标记（至多一条）；
- 用户指定 → 默认取指定那条；
- 用户未指定 → 全局默认推导规则：取第一条；
- **默认值写入数据表（后端规范化）**：无论用户是否指定，保存时后端将默认标记写入数据表——数据表永远有明确默认联系人，点开面板默认已选中，不会出现"无默认"状态；
- 列表单元格显示**默认联系人**的完整记录（不在单元格内加"默认"图标标注，显示的就是默认那条本身）；将来被单据/发货等功能引用时，默认取默认联系人，其余为备选可切换。

### 状态筛选

| 选项 | 值 | 说明 |
|------|-----|------|
| 全部 | `''`（空字符串） | 显示所有供应商 |
| 启用 | `1` | 默认选项，仅显示启用供应商 |
| 停用 | `0` | 仅显示停用供应商 |

### 行内编辑交互

- 主营业务/地址/备注：点击单元格 → 显示输入框，失焦 / Enter / Tab 即保存（改即生效），Esc 放弃；
- 保存失败显示错误提示并回滚（重新拉取列表）。

### 名称字段（主标识）交互

- 供应商名称列以品牌色下划线链接显示，点击 → 打开编辑弹窗（集合弹窗，含全部字段）；
- 引用/检索默认匹配名称字段（可组合匹配：名称/主营业务/备注）。

### 联系信息列交互（多记录字段矩阵面板）

```
单元格（可编辑）：[王小二·微信·gshhbdnd ▾]   ← 显示的就是默认联系人（无额外图标）
点击 ▾ 展开矩阵面板：
┌─ 默认 │ 联系人 │ 方式 │ 联系方式 │ 操作 ─────────┐
│  ★   │ 王小二  │微信│ gshhbdnd        │ ×    │  ← 数据行：全部可直接编辑，★ = 已选中默认
│      │ 李大翠  │电话│ 15364768585     │ ×    │  ← 行级操作：默认星标 / 删除
│      │         │    │ 输入后自动追加   │      │  ← 末尾常驻空行：直接输入自动追加
│              [+ 添加联系人]                    │
└──────────────────────────────────────────────┘
```

- 一列只显示**一条完整记录**（默认联系人），禁止多条拼接、禁止省略号摘要；
- 必带下拉箭头（语义 = 还有更多记录可展开）；
- **矩阵面板结构**：表头行 + 数据行（默认星标 + 联系人 + 方式 + 值 + 删除，每行全部可直接编辑）+ **末尾常驻空行**（输入有效值自动追加新行，Enter/失焦；无效输入清空空行保留）+ 常驻新增按钮——完全不阻塞，想输多少输多少；
- 默认标记：星标指定默认（isDefault，至多一条）；用户未指定 → 全局规则取第一条；
- 面板关闭时统一保存（dirty 落库），无需额外确认按钮。

### 新增供应商

- 点击工具行「新增供应商」按钮 → 打开**新建弹窗**（完整编辑面板含全部字段）；

## 与其他功能的关联

供应商是跨功能的引用数据源，被进价/配货/成本引用（引用关系见上文「功能概述」表）。

- 引用方式统一：业务表存 `supplierId`(BigInt+索引) + `supplierName` 名称快照；
- 解耦语义（删除不影响历史展示、停用不可作新配货来源）详见《数据规范·解耦三原则》《数据规范·物理删除与停用》；
- 进价面板中供应商选择器走 `quickAddSupplier` 快速新建（交互见《产品管理》）。
