# 单据与状态机

> 顶层依据：详见《顶层设计规范·理念4（表格唯一·交互统一）》《项目设计哲学·约束5（历史单据是法律事实·快照）》《项目设计哲学·原则2（分层隔离·快照解耦）》。

> **职责**：documents / document_lines / view_locks / 单据编号 / 8档状态机的**唯一权威定义**。所有功能文档引用本文档，禁止本地重定义。
> 规模基线：documents、document_lines 均为几千万行级表，检索必须走索引（见各表索引列）。

## 8档状态机（唯一权威）

| 状态 | 含义 |
|------|------|
| demand_pending | 需求待确认：单据已建、报价未完成，需求明细已录未定稿 |
| quote_confirmed | 报价已确认：报价阶段完成，售价已定稿落行 |
| payment_settled | 收款已结算：收款核销完成 |
| allocation_in_progress | 配货进行中：≥此档即可备货/交付履约（交付口径起点） |
| delivery_completed | 交付已完成：全部交付已签收 |
| cost_verified | 成本已核定：成本核算完成 |
| after_sales | 售后处理中：存在退换/售后未完结 |
| archived | 已归档：单据定档归档，只读冻结 |

- **任意双向可逆**：除「相同状态」外任意双向可手动流转，不设单向锁定（canTransition 恒 true）。
- **与报价阶段解耦**：主状态描述单据整体进程；报价阶段状态独立（purchase_quote_status）。
- **交付履约口径**：状态 ≥ allocation_in_progress 即可用（宽松不强制拦截）；签收自动推进 delivery_completed。

## 单据编号（唯一格式）

- 格式：`YY-MM-DD-序号`（2 位年、3 位序号），如 `26-08-11-001`。
- 全库统一；禁止带前缀（如 DOC-）、8 位年份等其他格式。

## 视图锁 view_locks（唯一键名定义）

- 键名统一 snake_case：`payment_reconcile` / `purchase_quote` / `delivery` / `refund_after_sale`。
- 含义：各业务视图进入编辑时的防误触锁定，值为 true/false。
