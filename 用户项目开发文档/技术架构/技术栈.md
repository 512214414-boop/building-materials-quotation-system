> **职责**：技术选型与职责边界的唯一设计依据（用什么、为什么能支撑当前规模）；安装、启动、排障等操作细节见 [部署运维手册.md](./部署运维手册.md)。
> **关联**：前后端职责切分见 [权限与职责规范.md](../架构原则/权限与职责规范.md)；UI 与布局选型（固定画布、表格唯一）见 [表格与交互规范.md](../架构原则/表格与交互规范.md) 与 [视觉与布局规范.md](../架构原则/视觉与布局规范.md)。

> **代码真相源**：依赖版本以 `frontend/package.json`、`backend/package.json` 为准；数据库类型以 `backend/prisma/schema.prisma` 的 `datasource.provider` 为准；运行时依赖以 `backend/src` 实际引用为准。

## 技术选型

**规模口径**：单店自用报价协同系统，面向门店笔记本兼作服务器、局域网与公网并行。真实在线规模：老板 + 2-3 店员 + 几个客户扫码，最多不超过 10 人；单进程 Node 架构有约 50 人余量，不构成瓶颈（详见 [项目设计哲学](../项目设计哲学.md)）。

**选型主线**：

- **服务端仅存与终校验**：算力往前放（前端计算，尤其实时算价），后端只做必要的事——存数据、最终校验，不做高并发架构（见 [项目设计哲学](../项目设计哲学.md)）；
- **固定画布无响应式**：固定画布宽度（min-width: 1200px）、固定 px 尺寸，不做响应式重排——用户用了十几年 Excel，Excel 就是固定画布、所见即所得，固定画布最符合直觉（见 [视觉与布局规范.md](../架构原则/视觉与布局规范.md)）；
- **表格唯一，交互统一**：全系统列表一律使用 `UnifiedTable`，行内编辑即保存，无"统一保存"按钮（见 [顶层设计规范](../顶层设计规范.md) 与 [表格与交互规范.md](../架构原则/表格与交互规范.md)）；
- **轻量基础设施**：未引入 Redis、Nginx——WebSocket 增量同步由单进程 Node 承载，公网映射由 cpolar 完成（见 [部署运维手册.md](./部署运维手册.md)）；
- **性能预算**：性能按笔记本封顶，靠增量同步、前端算价、防抖合并保障；WebSocket 心跳 30s（`WS_HEARTBEAT_MS`），断线自动重连。

## 前端栈

客户端与员工端为两套独立页面程序，代码级隔离（见 [表格与交互规范.md](../架构原则/表格与交互规范.md)）。

> **WebSocket（前端侧）**：前端经 Node 服务代理 `/ws`（与页面同源，地址基于 `location.host` 推导），后端监听 `:3000/ws` 接收单据增量广播（详见后端栈）。本项目**未使用** Redis，前端无对应依赖。

**数据库说明**：`backend/prisma/schema.prisma` 中 `datasource db { provider = "mysql" }`，`backend/.env` 中 `DATABASE_URL="mysql://..."`，开发与生产均使用 MySQL。`backend/prisma/migrations/` 下迁移目录 `migration_lock.toml` 锁定为 mysql provider。

**WebSocket 服务端**：与 HTTP 同端口（`:3000/ws?token=<jwt>`），负责单据增量的实时广播（`document.status_changed`、各标注层 `*.updated` 等事件）。

**构建验收**：前端生产构建统一走 `npm run build:check`（`check:dupe` 源码唯一权威校验 + `tsc -b` + `vite build`），防止重复实现混入；后端构建为 `npm run build`（`tsc -p tsconfig.json`）。

## 职责边界

**细则见** [权限与职责规范.md](../架构原则/权限与职责规范.md)（笔记本兼服务器、多设备访问：能放前端的计算尽量放前端，尤其实时算价；后端只做必要校验与落库）。

- **后端**：认证授权（JWT、授权码、RBAC）、持久化与事务、必要业务校验与状态流转、WebSocket 推送、文件与审计、统一 API；
- **前端**：界面与路由、本地状态与乐观更新、**实时算价与毛利等即时反馈**、表单与实时同步消费。

## 部署架构图

```
店内客户端 / 员工终端
        │  (局域网)
        ▼
┌──────────────────────────────────────────────┐
│  前端 Node 服务（统一登录入口）               │
│        │  /api → 后端 API                    │
│        │  /ws  → 后端 WebSocket              │
└──────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────┐
│  后端（Node 单进程）                         │
│  ├─ Express API (/api)                       │
│  └─ WebSocket Server (/ws，同一端口)         │
└──────────────────────────────────────────────┘
        │
        ▼
   MySQL 8.0+  +  backend/uploads/ 文件存储

外出员工 / 客户（公网）
        │
        ▼
   cpolar http 8080  →  前端 Node 服务（公网 URL）
```

- **公网映射**：cpolar（由 `./dev.sh` 自动启动 `cpolar http 8080`），免费版 URL 每次重启变化；
- **前端地址规则**：本机回环（localhost/127.0.0.1）走前端 Node 服务代理转发；公网地址走前端直接请求；前端无论何时支持局域网访问（详见 [部署运维手册.md](./部署运维手册.md)）；
- **端口约定与启动方式**：后端 3000、前端日常访问 8080（生产构建）、前端开发 8081（HMR）等全部操作细节见 [部署运维手册.md](./部署运维手册.md)，本文档不重复。
