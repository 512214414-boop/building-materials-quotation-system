# 技术栈

> **版本**：v10.1（2026-08-09）
> **文档定位**：单店自用报价协同系统的技术选型与部署边界。面向门店笔记本兼作服务器、局域网与公网并行。真实在线规模：老板 + 2-3 店员 + 几个客户扫码，最多不超过 10 人（见 [项目设计哲学](../项目设计哲学.md)）；单进程 Node 架构有约 50 人余量，不构成瓶颈。属架构级文档。
> **关联文档**：前后端职责切分见 [权限与职责规范.md](../架构原则/权限与职责规范.md)；部署运维见 [部署运维手册.md](./部署运维手册.md)。

> 本文与代码事实保持一致：依赖版本以 `frontend/package.json`、`backend/package.json` 为准；数据库类型以 `backend/prisma/schema.prisma` 的 `datasource.provider` 为准；运行时依赖以 `backend/src` 实际引用为准。

## 职责划分

**细则见** [权限与职责规范.md](../架构原则/权限与职责规范.md)（笔记本兼服务器、多设备访问：能放前端的计算尽量放前端，尤其实时算价；后端只做必要校验与落库）。

- **后端**：认证授权（JWT、授权码、RBAC）、持久化与事务、必要业务校验与状态流转、WebSocket 推送、文件与审计、统一 API。
- **前端**：界面与路由、本地状态与乐观更新、**实时算价与毛利等即时反馈**、表单与实时同步消费；权限入口体验见 [权限与职责规范.md](../架构原则/权限与职责规范.md)。

## 部署架构

```
店内客户端 / 员工终端
        │  (局域网)
        ▼
┌──────────────────────────────────────────────┐
│  前端 (日常访问 preview :8080 / 开发 dev :8081)│
│        │  /api  → 反向代理到后端             │
│        │  /ws   → 反向代理到后端 WebSocket   │
└──────────────────────────────────────────────┘
        │
        ▼
┌──────────────────────────────────────────────┐
│  后端 (Node :3000)                           │
│  ├─ Express API (/api)                       │
│  └─ WebSocket Server (/ws，挂载于同一 HTTP)  │
└──────────────────────────────────────────────┘
        │
        ▼
   MySQL 8.0+  +  backend/uploads/ 文件存储

外出员工 / 客户（公网）
        │
        ▼
   cpolar http 8080  →  前端  (公网 URL)
```

- **公网映射**：cpolar（`./dev.sh` 自动启动 `cpolar http 8080`），免费版 URL 每次重启变化。
- **WebSocket 地址**：基于当前访问 host 自适应（与页面同源，经 Vite proxy 代理 `/ws`），后端监听 `:3000/ws`（详见后端章节，前端侧不直连 `:3000`）。
- **静态托管**：日常访问用 `npm run preview -- --port 8080`（`./dev.sh` 自动启动）；开发热更新走 `npm run dev -- --port 8081`。端口约定详见 [部署运维手册.md](./部署运维手册.md)。

## 资源与性能约束

- 单进程 Node 即可覆盖约 50 人并发；性能预算按笔记本封顶（增量同步、前端算价、防抖合并）。
- WebSocket 心跳 30s（`WS_HEARTBEAT_MS`），断线自动重连。
- 首屏、单据切换、检索、配货同步等指标以局域网为主、公网略放宽；弱网支持乐观更新与重连。
