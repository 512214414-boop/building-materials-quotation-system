# 部署运维手册

> **职责**：安装、启动、内网穿透、备份、故障排查的唯一操作源；技术选型与职责边界见 [技术栈.md](./技术栈.md)。
> **适用形态**：单店笔记本电脑部署（服务器与员工终端共用），局域网与公网穿透均可。

## 环境要求

- Node.js 18+（推荐 20 LTS）
- MySQL 8.0+
- 现代浏览器（Chrome / Edge / Safari / Firefox 最新版）

## 端口约定

全项目统一（与 `./dev.sh` 顶部注释一致）：

| 端口 | 用途 |
|------|------|
| 3000 | 后端 API + WebSocket |
| 8080 | 前端日常访问（生产构建 preview，本机 / 局域网 / 公网统一走它） |
| 8081 | 前端开发热更新（dev 模式 HMR，供开发调试） |

日常访问统一走 8080 生产构建；8081 只给改代码时热更新用。

## 首次安装

```bash
# 数据库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS bm_quotation DEFAULT CHARSET utf8mb4;"

# 后端
cd backend
cp .env.example .env
# 编辑 .env：DATABASE_URL、JWT_SECRET，可选 AI_API_KEY
npm install
npx prisma db push
npm run seed          # 写入演示账号与样例数据
npm run build         # tsc 编译

# 前端
cd ../frontend
npm install
npm run build:check   # check:dupe 源码唯一权威校验 + tsc + vite build
```

## 已有门店升级（单位改成全店共用）

已在使用的库必须跑迁移，不能只当新装。单位从「跟着某个规格」改成「全店一本字典」：某个规格去掉「米」不影响别的产品；改「米」的名字全店一起变。


## 一键启动

```bash
cd /Users/mac/Desktop/建材报价系统

./dev.sh          # 启动全部（默认，同 start）：后端 + 8081 + 8080 + 公网
./dev.sh start    # 同上
./dev.sh reload   # 刷新 8080 生产包，公网地址不变（改完代码用这个）
./dev.sh restart  # 全部停掉再起，公网地址会变
./dev.sh tunnel   # 只重建公网（8080 要已在跑）
./dev.sh stop     # 全部停下
./dev.sh status   # 健康检查 + 全部访问地址
```

`./dev.sh` **一定**把四件事都拉起来，所以启动结束能打出真实可用的本机 / 局域网 / 公网地址（公网映射 8080）。效率来自：缺依赖才装、生产包没变就跳过打包、不清 Vite 缓存、不每次 migrate；不是把 8080 或公网关掉。

| 命令 | 做什么 | 什么时候用 |
|------|--------|------------|
| `./dev.sh` / `start` | 停旧进程后起 3000 + 8081 + 8080 + cpolar，并输出全部地址 | 日常开机、完整重启 |
| `./dev.sh reload` | 重启前后端、强制重打 8080，**保留公网隧道** | 改完代码要刷新日常访问/公网 |
| `./dev.sh restart` | 全部停掉再起，公网地址会变 | 隧道或进程彻底乱了 |
| `./dev.sh tunnel` | 只重建 cpolar（映射 8080） | 公网地址失效 |
| `./dev.sh stop` | 停应用和公网 | |
| `./dev.sh status` | 健康检查后再次输出全部访问地址 | 排查 |

### 启动成功输出（四种访问方式都必须有真实地址）

```
  本机访问（生产构建，秒开流畅，日常用）:
    登录页: http://localhost:8080/login
    首页:   http://localhost:8080/
    后端:   http://localhost:3000/api/health

  开发模式（HMR 热更新，改代码自动刷新，8081）:
    登录页: http://localhost:8081/login
    首页:   http://localhost:8081/

  局域网访问（同 WiFi 下手机/其他电脑，生产构建）:
    登录页: http://<局域网IP>:8080/login
    首页:   http://<局域网IP>:8080/

  公网访问（外网可访问，生产构建版）:
    登录页: https://<cpolar域名>/login
    首页:   https://<cpolar域名>/
```

登录页内可切换员工 / 客户身份。日常用 8080；改代码看 8081；公网走 8080。代码改完执行 `./dev.sh reload`，公网地址不变。

## 手动与生产启动

### 手动启动（不走脚本时）

```bash
# 终端1：后端（端口 3000）
cd backend && npm run dev

# 终端2：前端生产构建（端口 8080，日常访问）
cd frontend && npm run build && npx vite preview --port 8080 --host

# 终端3：前端开发模式（端口 8081，HMR 热更新）
cd frontend && npm run dev -- --port 8081 --host

# 终端4：公网穿透（映射 8080）
cpolar http 8080 -log stdout
```

> **注意**：手动启动前需先检查端口占用并停止旧进程，否则会产生端口冲突。

### 生产启动

建议用 `pm2` 或系统服务常驻后端；前端日常访问用 preview 服务（8080）。日常开发请直接用 `./dev.sh` 一键启动，本示例仅用于非常规场景。

```bash
# 后端（默认 :3000）
cd backend && npm start

# 前端日常访问（8080，生产构建 preview）
cd frontend && npm run preview -- --port 8080

# 前端开发热更新（8081，HMR）
cd frontend && npm run dev -- --port 8081
```

### 默认账号（seed 后）

请以 `backend/prisma/seed.ts` 为准。常见店长/管理员账号若未自定义，请登录后立即改密。

### WebSocket

- 路径：`/ws`（与页面同源 `location.host`）；
- 断线会自动重连；员工工作台可切换单据或刷新页面手动同步。

## 前端地址规则

后端地址策略（源自 `frontend/src/config/index.ts`，绝不硬编码 IP 段识别规则）：

| 访问来源 | 规则 |
|---------|------|
| 本机地址（localhost / 127.0.0.1 回环） | 前端 Node 服务代理转发（相对路径 `/api`、`/uploads`、`/ws` → 后端 3000） |
| 公网地址（其他所有地址） | 前端直接请求（`VITE_API_BASE_URL` 显式配置后端完整 URL） |
| 局域网地址（同 WiFi 设备） | 前端无论何时都支持局域网访问（相对路径走代理，无需额外配置） |

- 未显式配置 `VITE_API_BASE_URL` 时默认走前端代理（本机后端）；
- `VITE_WS_URL` 未配置时 WebSocket 基于 `location.host` 推导（`ws(s)://<当前host>/ws`）；
- 内网穿透映射的是前端 8080 端口，不属于项目本身。

## cpolar 内网穿透

使用 **cpolar** 做公网映射，用于手机远程访问测试。配置文件位于 `~/.cpolar/cpolar.yml`，已预配置 3 个隧道：

| 隧道名 | 协议 | 本地端口 | 用途 |
|--------|------|----------|------|
| `website` | http | 8080 | 前端生产构建 preview（公网访问） |
| `backend` | http | 3000 | 后端 API（调试用，一般不需单独映射） |
| `ssh` | tcp | 22 | SSH 远程 |

### 自动启动（推荐）

`./dev.sh`（默认 start）会自动完成公网穿透。启动后公网 URL 直接打在本机 / 局域网 / 公网那一组地址里，无需手动查找。

### 手动启动与公网 URL 获取

> **关键**：cpolar 启动后**不会**把公网 URL 直接输出到终端。必须加 `-log stdout` 参数，从日志中解析 `Tunnel established at` 行获取。

```bash
# 正确方式：带 -log stdout 启动，日志写入文件便于解析
cpolar http 8080 -log stdout > /tmp/cpolar_dev.log 2>&1 &

# 等待约 3 秒后，从日志解析公网 URL（取 https 版本）
grep "Tunnel established at" /tmp/cpolar_dev.log | grep -oE 'https://[a-z0-9]+(\.[a-z0-9]+)*\.cpolar\.(cn|top)' | tail -1
```

输出形如：`https://7b29179f.r6.cpolar.cn`

> **错误方式（勿用）**：
> - `cpolar http 8080` 但**不加** `-log stdout` → 进程静默运行，无法获取公网 URL；
> - 扫描 9200/4040/9090 等端口找管理 API → cpolar 免费版管理界面端口不稳定，不可靠；
> - `cpolar status` → 会报 `missing port in address`，非查询命令。

### 公网访问路径

cpolar 映射前端 8080 端口（preview 模式，生产构建，公网加载快）。后端 API 由前端 preview server 的 `/api`、`/uploads`、`/ws` 代理转发到 localhost:3000，无需单独映射后端。

| 入口 | 路径 |
|------|------|
| 统一登录页 | `https://<公网域名>/login` |

> 登录页内提供「员工登录 / 客户登录」切换，提交后按身份路由分流至 `/staff/*` 或 `/gate/*`。

### 白屏排查

公网访问白屏时，按以下顺序排查：

- **确认 cpolar 隧道是否在线**：`curl -s -o /dev/null -w "%{http_code}" https://<公网域名>/` 应返回 200；
- **确认本机前端服务正常**：`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/` 应返回 200；
- **浏览器强刷清缓存**：Cmd+Shift+R（Mac）/ Ctrl+Shift+F5（Win）；
- **查看浏览器控制台**：F12 → Console，看是否有资源加载失败（4xx/5xx）或混合内容拦截；
- **查看 cpolar 日志**：`tail -50 /tmp/cpolar_dev.log`，确认无连接错误。

> **常见原因**：
> - cpolar 重启过程中（旧隧道已断、新隧道未建立）访问 → 等待 3 秒后重试；
> - 浏览器缓存了旧 cpolar 域名的失败状态 → 强刷或换无痕窗口；
> - 本机前端/后端服务未启动 → `./dev.sh stop && ./dev.sh` 重新拉起全部（含 8080 与公网）。

> **注意**：
> - cpolar 免费版 URL 每次重启会变化，需以 `./dev.sh` 输出为准；
> - WebSocket（`/ws`）经前端代理，与页面同源，无需额外配置；
> - 授权码有效期与防爆破仍生效（见系统管理）。

## 部署后验收冒烟清单

部署完成后按以下清单验收（部署后业务验收）：

- 客户 Gate 准入 → 采购清单加行；
- 员工采购报价实时可见 → 识别订单追加原始行；
- 确认报价 → 客户端见真实单价；解锁 → 回「待报价」；
- 工作台状态下拉可推进/回退 8 档；
- 收款核销可自动到 `payment_settled`；配货录入可到 `allocation_in_progress`；
- 定档归档 Tab 店长可用（需重新登录刷新 JWT 权限）；
- 收货地址 CRUD 可用。

## 备份恢复

```bash
# 备份
mysqldump -u root -p bm_quotation > backup_$(date +%Y%m%d).sql

# 恢复
mysql -u root -p bm_quotation < backup_YYYYMMDD.sql
```

上传文件目录：`backend/uploads/`（一并备份）。

## 故障排查

| 现象 | 处理 |
|------|------|
| 定档显示无权限 | 店长重新登录，使 JWT 含 `archive` |
| 客户一直「待报价」 | 确认员工已「确认报价」；检查 WS / 刷新清单 |
| 图片识单失败 | 配置 `AI_API_KEY`，或改用文字粘贴 |
| WS 连不上 | 检查反代是否转发 `/ws` Upgrade |
| 公网白屏 | 按「cpolar 内网穿透 → 白屏排查」顺序处理 |
| 端口冲突 | `./dev.sh stop` 后重新 `./dev.sh`；或 `lsof -ti :3000,8080,8081` 手工确认占用进程 |
