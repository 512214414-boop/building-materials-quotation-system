# 建材报价系统 — 部署与运维手册

> **版本**：v14.1（2026-08-09）
> **文档定位**：面向单店笔记本电脑部署（服务器与员工终端共用）。局域网与公网穿透均可。属架构级文档。
> **关联文档**：技术栈选型见 [技术栈.md](./技术栈.md)；前后端职责见 [权限与职责规范.md](../架构原则/权限与职责规范.md)。
> **变更定档（v14.1）**：性能优化（移除 StrictMode、UnifiedTable memo、弹窗骨架化）后，调整端口架构——日常访问 8080 改为生产构建（React 生产版，交互级 <600ms 秒开），开发热更新迁至 8081（dev 模式 React 开发构建固有开销较大，不用于日常访问）。

## 环境要求

- Node.js 18+（推荐 20 LTS）
- MySQL 8.0+
- 现代浏览器（Chrome / Edge / Safari / Firefox 最新版）

## 首次安装

```bash
# 数据库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS bm_quotation DEFAULT CHARSET utf8mb4;"

# 后端
cd backend
cp .env.example .env
# 编辑 .env：DATABASE_URL、JWT_SECRET，可选 AI_API_KEY
npm install
npx prisma db push
npm run seed          # 写入演示账号与样例数据
npm run build

# 前端
cd ../frontend
npm install
npm run build
```

## 启动（开发模式·一键启动）

### 设计原则

- **先停后启**：每次启动前必须先停止旧服务，避免端口冲突和缓存残留
- **端口架构（v14.1）**：日常访问 8080 = 生产构建（preview，React 生产版，秒开流畅）；开发热更新 8081 = dev 模式（HMR）；公网 cpolar 映射 8080
- **说明**：dev 模式 React 开发构建固有开销较大（首屏/弹窗 1 秒级），不用于日常访问；日常访问统一走 8080 生产构建（实测弹窗 288-522ms、面板 350-440ms、控制台 0 报错）

### 一键启动

```bash
cd /Users/mac/Desktop/建材报价系统

./dev.sh start    # 启动全部服务（后端+前端+cpolar 公网穿透）
./dev.sh stop     # 停止全部服务
./dev.sh restart  # 重启全部服务
./dev.sh tunnel   # 只重启公网穿透（不重启后端/前端）
```

#### `./dev.sh start` — 启动

| 步骤 | 动作 | 说明 |
|------|------|------|
| 1 | 停止旧服务 | 杀掉占用 3000/8080/8081 端口的进程 + 旧 cpolar 进程 |
| 2 | 清理缓存 | 删除 `frontend/node_modules/.vite`，确保热更新生效 |
| 3 | 启动后端 | `npm run dev`（端口 3000），健康检查等待就绪 |
| 4 | 启动前端 dev | `npm run dev`（端口 8081，开发热更新），健康检查等待就绪 |
| 5 | 构建+启动 preview | `vite build` + `vite preview`（端口 8080，日常访问），60 秒超时 |
| 6 | 启动公网穿透 | `cpolar http 8080`（映射生产构建），输出公网 URL |
| 7 | 输出访问地址 | 本机地址 + 局域网地址 + 公网地址 + 进程 PID + 日志路径 |

#### `./dev.sh tunnel` — 只重启公网穿透

不重启后端/前端，只杀旧 cpolar 进程并重新建立隧道。前提：前端 preview（8080 生产构建）已在运行。

#### `./dev.sh stop` — 停止全部服务

杀掉占用 3000/8080/8081 端口的进程 + 所有 cpolar 进程。

```

  本机访问（生产构建，秒开流畅）:

    后端API:  http://localhost:3000/api

  开发模式（HMR 热更新）:
    统一登录: http://localhost:8081/login

  局域网访问（同 WiFi 设备，生产构建）:
    统一登录: http://192.168.1.6:8080/login   （页内切换员工/客户身份）

  公网访问（手机远程测试）:
    统一登录: https://xxxxxx.r6.cpolar.cn/login   （页内切换员工/客户身份）

  停止服务: ./dev.sh stop
```

### 手动启动（不走脚本时）

```bash
# 终端1：后端（端口 3000）
cd backend && npm run dev

# 终端2：前端生产构建（端口 8080，日常访问）
cd frontend && npm run build && npx vite preview --port 8080 --host

# 终端3：前端开发模式（端口 8081，HMR 热更新）
cd frontend && npm run dev -- --port 8081 --host

# 终端4：公网穿透（映射 8080）
cpolar http 8080 -log stdout
```

> **注意**：手动启动前仍需先检查端口占用并停止旧进程，否则会产生端口冲突。

## 公网穿透（cpolar）

本项目使用 **cpolar** 做公网映射，用于手机远程访问测试。配置文件位于 `~/.cpolar/cpolar.yml`，已预配置 3 个隧道：

| 隧道名 | 协议 | 本地端口 | 用途 |
|--------|------|----------|------|
| `website` | http | 8080 | 前端生产构建 preview（公网访问，秒开流畅） |
| `backend` | http | 3000 | 后端 API（调试用，一般不需单独映射） |
| `ssh` | tcp | 22 | SSH 远程 |

### 自动启动（推荐）

`./dev.sh` 会自动完成公网穿透。启动后公网 URL 会直接打印在终端输出中，无需手动查找。

### 手动启动与公网 URL 获取

> **关键**：cpolar 启动后**不会**把公网 URL 直接输出到终端。必须加 `-log stdout` 参数，从日志中解析 `Tunnel established at` 行获取。

```bash
# 正确方式：带 -log stdout 启动，日志写入文件便于解析
cpolar http 8080 -log stdout > /tmp/cpolar_dev.log 2>&1 &

# 等待约 3 秒后，从日志解析公网 URL（取 https 版本）
grep "Tunnel established at" /tmp/cpolar_dev.log | grep -oE 'https://[a-z0-9]+(\.[a-z0-9]+)*\.cpolar\.(cn|top)' | tail -1
```

输出形如：`https://7b29179f.r6.cpolar.cn`

> **错误方式（勿用）**：
> - `cpolar http 8080` 但**不加** `-log stdout` → 进程静默运行，无法获取公网 URL
> - 扫描 9200/4040/9090 等端口找管理 API → cpolar 免费版管理界面端口不稳定，不可靠
> - `cpolar status` → 会报 `missing port in address`，非查询命令

### 公网访问路径

cpolar 映射前端 8080 端口（preview 模式，生产构建，公网加载快）。后端 API 由 Vite preview server 的 `/api`、`/uploads`、`/ws` 代理转发到 localhost:3000，无需单独映射后端。

| 入口 | 路径 |
|------|------|
| 统一登录页 | `https://<公网域名>/login` |

> 登录页内提供「员工登录 / 客户登录」切换，提交后按身份路由分流至 `/staff/*` 或 `/gate/*`。

### 白屏排查

公网访问白屏时，按以下顺序排查：

- **确认 cpolar 隧道是否在线**：`curl -s -o /dev/null -w "%{http_code}" https://<公网域名>/` 应返回 200
- **确认本机前端服务正常**：`curl -s -o /dev/null -w "%{http_code}" http://localhost:8080/` 应返回 200
- **浏览器强刷清缓存**：Cmd+Shift+R（Mac）/ Ctrl+Shift+F5（Win）
- **查看浏览器控制台**：F12 → Console，看是否有资源加载失败（4xx/5xx）或混合内容拦截
- **查看 cpolar 日志**：`tail -50 /tmp/cpolar_dev.log`，确认无连接错误

> **常见原因**：
> - cpolar 重启过程中（旧隧道已断、新隧道未建立）访问 → 等待 3 秒后重试
> - 浏览器缓存了旧 cpolar 域名的失败状态 → 强刷或换无痕窗口
> - 本机前端/后端服务未启动 → `./dev.sh stop && ./dev.sh start` 重启全部

> **注意**：
> - cpolar 免费版 URL 每次重启会变化，需以 `./dev.sh` 输出为准
> - WebSocket（`/ws`）经 Vite proxy 代理，与页面同源，无需额外配置
> - 授权码有效期与防爆破仍生效（见系统管理）

## 备份与恢复

```bash
# 备份
mysqldump -u root -p bm_quotation > backup_$(date +%Y%m%d).sql

# 恢复
mysql -u root -p bm_quotation < backup_YYYYMMDD.sql
```

## 验收冒烟清单

- 客户 Gate 准入 → 采购清单加行
- 员工采购报价实时可见 → 识别订单追加原始行
- 确认报价 → 客户端见真实单价；解锁 → 回「待报价」
- 工作台状态下拉可推进/回退 8 档
- 收款核销可自动到 `payment_settled`；配货录入可到 `allocation_in_progress`
- 定档归档 Tab 店长可用（需重新登录刷新 JWT 权限）
- 收货地址 CRUD 可用

## 故障排查

| 现象 | 处理 |
|------|------|
| 定档显示无权限 | 店长重新登录，使 JWT 含 `archive` |
| 客户一直「待报价」 | 确认员工已「确认报价」；检查 WS / 刷新清单 |
| 图片识单失败 | 配置 `AI_API_KEY`，或改用文字粘贴 |
| WS 连不上 | 检查反代是否转发 `/ws` Upgrade |
